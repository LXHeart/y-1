## 设计决策（已定死，勿另起方案）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **聚合 = 权威表上的按需 SQL 聚合**（`date_trunc` 月粒度 + GROUP BY），不建物化账单表 | 当前量级下实时聚合永远与明细一致；一致性由「聚合 == SUM(区间明细)」IT 锁死 |
| D2 | **月切按北京时间（Asia/Shanghai）自然月**，请求参数 `month=YYYY-MM`，后端展开为 `[start, end)` | CN 业务；UTC 切月会把 31 号晚上的流水算进下月 |
| D3 | 推荐官统计在 **finance**（`wallet_ledger` 是权威）；按任务明细输出 `engagement_ref`，**任务标题由前端 join marketplace 的 my-applications**，不做 finance→marketplace 反查 | database-per-service；前端本来就要拉历史任务列表，一次 join 两用 |
| D4 | 商家账单在 **finance**（journal/posting 双录是资金真相源），科目分解按 `journal_type` + FEE posting；**实际枚举以代码写入为准（Stage 0 核查后定型）** | V5 注释列了 DEPOSIT/RESERVE/RELEASE/CAPTURE/REVERSE/WITHDRAW/OPENING，commerce 可能另有类型 |
| D5 | 历史任务端点挂 `/api/tasks/my-applications`（复用既有 `/api/tasks/**` edge 前缀，不加新前缀） | fail-closed 语义下新增公网前缀成本高 |
| D6 | **头像走 intelligence media**，完整复用 merchant-attachment 模式：前端三步上传（ticket→直传→confirm，新 `MediaPurpose`）→ identity PUT 时经 identity-only 契约复验 owner/purpose/active → profile 存 `avatar_media_id` → 公开读由 identity 换短 TTL presigned GET URL | 代码库已两次走通该模式（KYB 附件、履约附件），不发明新机制 |
| D7 | 收入统计/月度账单是**私有数据**：推荐官 self-scoped、商家 org-scoped；公开 profile 只新增非敏感字段 | 收入是隐私 |
| D8 | 前端共享「月份选择器 + cents→¥ 格式化 + 分组汇总表」composable/组件，推荐官与商家两面板复用 | 合并立项的复用落点 |

## Stage 1 — finance：两个聚合读端点

**推荐官收入统计**（self-scoped，断言解 account）：

```
GET /api/finance/wallets/me/statistics?from=YYYY-MM&to=YYYY-MM   // 含端月，跨度上限 12 个月
→ { "months": [ { "month": "2026-08",
      "taskPayoutCents": 0, "commerceCommissionCents": 0,        // 按 Stage 0 实际类型定型
      "withdrawalCents": 0, "clawbackCents": 0,
      "grossCents": 0, "feeCents": 0, "netCents": 0 } ],
    "byEngagement": [ { "engagementRef": "...", "payoutCents": 0, "feeCents": 0, "count": 1, "lastAt": "..." } ] }
```

- 月聚合 `date_trunc('month', created_at AT TIME ZONE 'Asia/Shanghai')`（D2）；`amount_cents` 带符号直接 SUM；gross = amount + fee 只对入账类
- `byEngagement` 同区间内 GROUP BY engagement_ref（null 的提现行不进该表）
- 空 区间 → 空数组/全 0，不 404

**商家月度账单**（org-scoped，镜像 Stage 0 找到的 org-self guard）：

```
GET /api/finance/organizations/{orgId}/monthly-bill?month=YYYY-MM
→ { "month": "2026-08", "flows": [ { "type": "DEPOSIT", "label": "充值", "amountCents": 0 }, ... ],
    "platformFeeCents": 0, "netEscrowDeltaCents": 0 }
```

- 按 journal_type GROUP + FEE posting 单列；科目 label 中文映射放前端或响应皆可（选一处，别两处）
- 一致性不变式（IT 锁死）：`Σ flows == Σ 该 org 该月 journal 关联 posting 的 ESCROW 腿净额`，且对账端点（既有 reconcile）交叉验证

**守卫**：self 端点解析断言 account 且 orgId 不参与；org 端点验调用者属于该 org（跨 org 404）。测试：多类型/多月种子数据的聚合正确性、**月界时区**（UTC 8-31 23:30 的流水归 9 月）、跨度上限 400、guard 404、聚合==SUM(明细) 不变式、空月全 0。

## Stage 2 — marketplace：历史任务记录

```
GET /api/tasks/my-applications?status=&cursor=&limit=   // 登录即可，self-scoped
→ { "items": [ { "applicationId", "taskId", "taskTitle", "taskStatus",
```

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`
- **金额带符号**：`wallet_ledger.amount_cents` 入账正/提现冲正负——聚合时别再按类型手工加符号；毛额 = amount + fee 只对入账类成立
- **时区**：月聚合必须 `AT TIME ZONE 'Asia/Shanghai'` 再 date_trunc；请求参数 YYYY-MM 由后端展开区间，前端不传时间戳
- Jackson 3：请求 record 可选数值字段必须包装类型；`is` 前缀无参方法会被序列化成属性（派生态加 `@JsonIgnore`）
- Reactor：`switchIfEmpty` 副作用包 `Mono.defer`；presigned URL 换取是 IO，别在事务内做
- identity 无全局 SecurityWebFilterChain：每个新端点显式 guard，漏=无鉴权；仓储层跨租户 SQL 必须带归属条件
- edge fail-closed：本任务不新增公网前缀（D5），但 Stage 0 仍须核对既有前缀的匹配粒度
- intelligence 无全局 ObjectMapper bean（持服务本地实例）
