## K04 幂等、事务、状态与资源回收

持久键固定`(owner_account_id,kind,request_id)`，requestId为UUID；payloadHash=版本化canonical JSON SHA-256（键字典序、UTF8、明确null，所有实现使用同一fixture）。先验证归属，再查receipt；同hash重放原资源/进度，异hash409。失败确认无副作用时原key仍回失败；用户主动新操作才换key。不能把超时当无副作用。

会话与轮次的有限状态机：

| 当前 | 合法触发→目标 | 必须的副作用 |
|---|---|---|
| preparing | 检查通过→queued/connecting；拒绝→failed；end→ending | 先记录owner与operation；预检查不派发provider |
| queued | 获槽→connecting；60秒/取消→ending | FIFO创建时间+id；出队原子占slot；max10 |
| connecting | runtime已就绪且media-ready→ready；90秒→failed；end→ending | 首次ready写expiresAt；重连不重置 |
| ready | text/greeting→responding；audio.auth→listening；pause→paused；end/idle→ending | 只有一个活动turn；role配置冻结 |
| listening | audio.end→responding；abort/空音频→ready；pause→paused | 关闭采集缓冲；STT只在end后派发 |
| responding | 完成→ready；interrupt→connecting；pause→paused；错误可恢复→ready；致命→ending | turnEpoch取消，媒体reset；不能旧事件覆盖新turn |
| paused | 30秒内resume→connecting；到期→ending | pausedUntil不可延长，普通heartbeat不能取消暂停 |
| reconnecting | 30秒内resume→connecting；超期→ending | 不自动重发任何turn；恢复时epoch递增 |
| ending | runtime确认关闭且slot已释放→ended；强制超时→failed | worker独立lease过期必须自停；账务可pending |
| ended/failed | 只读、保存残留窗口、删除；不得恢复→新session | 原run结算继续，迟到ready丢弃 |

runtime Worker心跳与浏览器心跳分开：browser最后心跳30秒失联，进入reconnecting时截止=最后心跳+30秒，不能在检测时再加30秒；reaper5秒扫描并在45秒目标内释放。Worker从Java获取30秒执行租约，每10秒续；Java不可达时到期自行停推理/peer，无限重连禁止。正常end最多5秒目标；异常终态必须保留cleanupPending，不把账务pending等同第三方会话/媒体资源未释放。

leaseEpoch控制浏览器/Worker所有权；turnEpoch控制生成代次；mediaEpoch控制浏览器peer。interrupt使旧turn取消、mediaEpoch+1并关闭旧peer；前端立即停旧srcObject/音轨，建立新的recvonly peer，收到media-ready后才允许新turn。保守重协商保证未标注epoch的RTP旧帧不会在新轮播放；不宣称原生RTP包含turnEpoch。可随后单独优化无缝打断，本期不能删这个隔离步骤。

锁顺序：account lifecycle SHARE → dh_session FOR UPDATE → dh_turn/recording → invocation/operation → media挂载。所有写入口与注销prepare共享账号锁；不得持DB事务等待HTTP/provider/远端会话建立。配置或授权撤销先置拒绝新任务，发停止意图；后台原租约不可续。两个结束/接管请求只允许一个CAS成功，重复返回同终态。

内容缓冲：独立不持久化Redis实例（禁AOF/RDB/备份）存`dh:buffer:{sessionId}:{contentEpoch}`，会话最长10分钟+终止10分钟TTL，最大256KiB UTF8；原音频只内存最大1.92MB；abort/异常断开立即销毁，正常end已接受则将该内存buffer所有权移交唯一STT任务，调用结束/取消/deadline后销毁，不因正常WS关闭误取消已受理转写。保存文本后仍可清缓冲；本文不承诺进程崩溃后恢复未保存内容。协调lease可在DB/Redis，但DB session是事实权威；Redis丢失关闭连接，不能默认恢复拥有权。

新表触发器使用独立`dh_guard_personal_write`，调用相同account gate初始化/SHARE锁规则，不改V86/V87历史函数。只允许冻结后同owner、原id、单向terminal收尾与内容清空；不能泛放所有UPDATE。未知费用脱敏留审计，内容清理不得因未结费用无限保留正文。

## K07 音频、RTC、内部通道与背压

WS路径`/api/digital-human/sessions/{id}/audio`同源wss。Nginx只把此精确形状升级到wrapper；其他数字人路径仍到Edge，wrapper未挂上游原生API。Origin精确比对批准AI origin；IP限流；5秒内首帧JSON ≤4096bytes：`{v:1,type:'auth',grant,leaseEpoch,requestId,format:'pcm_s16le',sampleRate:16000,channels:1}`。成功回`{v:1,type:'accepted',turnId,turnEpoch}`，认证前二进制立即关闭4401。

二进制帧=8byte header + PCM：uint32 big-endian sequence从0递增；uint32 big-endian sampleCount；后跟little-endian int16单声道，sampleCount≤1600（100ms），payloadBytes=sampleCount×2，总帧≤3208bytes。默认20ms=320samples；浏览器AudioWorklet把实际44.1/48kHz持续重采样到16k，不能只改metadata。尾包允许不足20ms但偶数字节；重复/跳号关闭4400并废弃本段，不能乱拼音频。

末帧`{v:1,type:'end',nextSequence,totalSamples}`必须与累积一致；abort帧`{v:1,type:'abort'}`无STT派发。总量1.92MB/60秒双检查。wrapper队列最多100个20ms等效chunk=2秒；满时关闭4429、报dh_capacity_full并清缓冲，不无限queue。浏览器bufferedAmount>64000暂停发送并显示网络拥堵，持续2秒即abort，不能静默丢采样继续识别。idle连接5秒无chunk终止；按键停止/权限中断关闭tracks。

资格30秒、32随机字节base64url；服务端只存SHA256+owner/session/leaseEpoch/channel/Origin/expiry，原子一次核销。wrapper通过mTLS内部HTTP调用Java核销，拒绝前不占渲染槽；不得把grant放query/subprotocol/log。close code4401认证、4403origin、4408过期/超时、4409旧lease、4413大小、4429容量、1011依赖故障；音频片段失败后需新的requestId，仅当旧段确认无派发时用户可重录。

RTC只接收数字人音视频：浏览器recvonly音频+视频transceiver、createOffer→setLocalDescription→等待ICE complete（最多10秒）→API16→setRemoteDescription；不经RTC上传麦克风。iceServers来自短期TURN资格，默认有效120秒，会话重协商重新签发；服务端绝不接受客户端自带iceServers。所有使用者轮次共享独立连续ProgramClock，生成时钟不得在录制段内归零。

内部接口：mTLS独立端口，不进入Edge公开route。Java→wrapper `POST /internal/v1/sessions`（session/lease/mediaEpoch、无secret配置Binding），`POST /internal/v1/sessions/{id}/commands`（create/startTurn/interrupt/pause/resume/end）、`POST .../webrtc-offer`、`GET .../state`。wrapper→Java `POST /internal/digital-human/grants/consume`、`POST /internal/digital-human/events`、`POST /internal/digital-human/invocations/{id}/execute`。每条控制command包含commandId+payloadHash+leaseEpoch，wrapper内有限receipt；HTTP超时只查state/原键，不创造第二次会话。

wrapper提交LLM/TTS请求携带scope固定的短期execution grant（30秒核销、执行deadline≤90秒），Java从持久invocation定位owner/stage及冻结provider（render的远端会话与媒体资格见K14，不受单次文本/配音90秒deadline替代整场租约）；body只允许已绑定输入，不接受新baseUrl/model/key。流连接中每10秒复核lease，到期中止。STT由wrapper将内存WAV直接给Java内部multipart接口，不创建media_reference/speech_transcription任务，不使用上游临时WAV实现。

## K08 用量、稳定经济键与重启恢复

用量事实`UsageUnits {inputTokens:number|null,outputTokens:number|null,audioInputMs:number|null,audioOutputMs:number|null,textCodePoints:number|null,renderMs:number|null,providerRequestId:string|null,quality:'confirmed'|'pending'}`。STT/TTS按既有价表centsPerSecond核算成本，用ceil(ms/1000)映射旧ai_run.videoSeconds槽位但capability必须voice/video_tts、DH展示必须语音秒；不是将audio成本伪装为video_generation。chars仅观测，当前价表不支持的字符价模型拒绝用于收费而非自行换算。

Java新增`prepareRealtimeExecution(RealtimePreparation command, Function<RealtimePreparedBinding, Mono<Void>> bindPrepared)`，command携带稳定operationId/accountId/organizationId固定null/capability/feature/冻结ProviderResolution/冻结priceTableVersion/estimatedInputTokens/estimatedOutputTokens/estimatedSeconds。在既有reserveAndCreateRun同事务内调用bindPrepared写dh_invocation(ai_run_id,budget_snapshot)，提交后既有credits流程；既有方法签名与行为不变。网络/credits不能放DB事务内。新业务operation唯一由dh_invocation约束，旧ai_run普通索引不冒充全局唯一。

准备之前事务CAS reserved→preparing，并在对应operation记录lease_owner/lease_until；重复只查原invocation。崩溃时：无run绑定且事务未提交可原键重新prepare；绑定存在则查原run/charge恢复，绝不能再生成一个run。persist `budgetId,reservationDate,reservedTokens,reservedCents,priceTableVersion,creditsCentsPolicyVersion,feature,provider metadata`，不存明文key；pending补偿沿既有worker。跨财务步骤用既有operationId核销。

| 点位 | 状态/结算 | 重试规则 |
|---|---|---|
| 未派发取消 | cancel-before-provider，释放/退款既有预留 | 原键terminal，不调用provider |
| HTTP/WS写请求已发出后用户打断 | handleCancellation，现有预留口径不退 | 后续到达usage记录但不重结第二笔 |
| 明确provider拒绝/失败 | handleFailure，既有补偿 | 原调用失败，不自动另换模型 |
| 正常结束+完整usage | settleSuccess，冻结价格实际核销 | 账务写失败只重试结算 |
| 断流、无usage、派发结果不明 | unknown/reconciliation_pending，保留经济事实 | 不自动重放推理/退款；支持provider状态查询才核对，否则治理人工确认 |

新增`TextStreamEvent(type:'delta'|'usage'|'done',delta,providerRequestId,inputTokens,outputTokens)`与`TextCompletionClient.streamMeteredMessages`；首期只允许openai-completions/compatible，请求stream_options.include_usage=true，合法usage终帧在[DONE]前读取。旧streamMessages仍返回ChatChunk，不影响其他方言。缺失或负usage不可计算为0，不用估计tokens冒充实量。ThinkingContentFilter逐订阅隔离；安全审核的句段才送TTS。

STT用`SpeechProviderRegistry.require(...).transcribe(Command)`的byte[]接口，platform voice解析与execution prepare先行；不调用SpeechTranscriptionService.create（会写用户上传与任务）。TTS新增专用Java PCM streaming adapter，复用受信origin与DNS pinning；固定`audio/speech`相对路径，输入已审句段，voice来自catalog，model冻结，PCM采样率由批准配置固定24000Hz并在Python受控重采样；若真实端点不支持该协议，catalog不可选，不改成异步MiniMax轮询。

安全：输入/persona与输出按既有ContentSafetyService.checkShallow策略检查，severity=high的finding拒绝TTS；现有词库只有high/medium/low，不发明blocked级别；遇未知severity按策略不可用拒绝；medium/low可显示提示但不上报正文。命中high时发出dh_content_blocked（422，追加受控错误）；句段最多120码点，优先中文/英文句末切分，连续无句末到120也审查；带前一段尾32码点做跨段检测，后段不重复播尾巴；不能使用自动修复/外部检索。平台需要更强的安全策略时必须在真实开放前配置，不能把词库检查宣传为完整内容合规保证。

session总额度是invocation平台成本的加总授权限制：已知平台成本+所有未结预留不得超过preflight.platformCostCapCents；confirmedCents单独只汇总用户收费的成本基数；第三方渲染进入ai_run/预算/成本结算，纳入同一session cap；存储仅计资源用量，不加新金融扣款功能键。个人own只影响LLM；STT仍按现有AI_RUN_VOICE扣平台积分；首期TTS按既有video_tts的feature=null补贴口径，不扣用户积分但计平台预算和成本，UI须逐项显示并在开始前确认。preview与greeting同TTS成本结算，不能漏记成本。

Preflight.billingItems固定四项llm/stt/tts/render，字段={stage,modelSource,modelLabel,chargeTo:user/platform/provider_direct,priceTableVersion,unit:token/second,estimatedCents:number|null}。own用provider_direct且estimatedCents=null（平台不知道供应商自有账单），展示平台收费0并提示自有账单；不能说外部免费。Preflight.estimatedMaxCents=300为本场允许派发的平台收费成本基数上界，不是预计实际账单；platformCostCapCents=300同时约束补贴TTS及第三方渲染成本。UI文案为“本场成本授权上限3.00元，积分换算按已展示政策；配音/渲染当前补贴；按实际调用结算”，如果所有用户收费项均0，estimatedMaxCents=0，但平台cap仍300。credits实际数量通过既有冻结转换政策算，不能直接把cents当credits。

预估输入token不是实量：组装完整messages JSON后UTF8字节数+每条32token协议余量，上界maxContextUtf8Bytes=65536，输出预留1024；超过模型上下文时在派发前拒绝。STT预留ceil(actualDurationMs/1000)，TTS每段预留90秒，输出pcm达到90秒即停止并标truncated，实际按样本数结算；有完整真实usage的模型优先用其一致用量。若某供应商不能提供有界输出/计量协议，不列为approved。session锁内先计算全体pending预留+已确认成本+本调用新预留，超过300返402，不预先整场扣300。实际成本超预留时停止后续派发、标核对异常并按既有账务义务处理，不隐瞒成本或声称供应商硬性不会超额。试听不挂session，有独立每账号每天30分平台补贴成本上限（UTC日，pending也占用），同库事务按preview invocation聚合；额度不足402。

bindPrepared回调参数采用专用无密钥 `RealtimePreparedBinding(runId,operationId,budgetId,reservationDate,reservedTokens,reservedCents,priceTableVersion,creditsCentsPolicyVersion,chargeRequired)`，在createRunRecord后同事务执行；不能传尚未形成的ExecutionContext（其charge在提交后创建）。完整方法返回Mono<ExecutionResult>，后续派发只在财务预留完成且context.allowed=true时执行。恢复先读ai_run/原经济operation，查既有charge/补偿/settlement状态并重建同run上下文，凭据通过被冻结引用重新解密；凭据撤销/价表不可读禁止派发，不随机换模型。

## K09 形象、录制、保存与删除

上传复用现有media票据/finalize，不修改原上传全局阈值；dh avatar追加真实decode、像素、单人、许可检查。预处理在独立job，本地只做解码/格式/尺寸检查，涉及模型的检测与形象准备只能使用已配置第三方服务（K14）；key只能由owner/avatar/revision生成，manifest列全部源/派生object引用与sha256，不接受用户提供本机路径/zip。缓存可重建不代表可漏清理。

录制通过ProgramOutputManager新增独立recording branch，连续ProgramClock；采集输出音频与视频，永不接用户mic。start绑定recordingId和startProgramMs，0点=该段起点；先验支持再创建。录制队列max2秒媒体，超限停止该段并标partial=true、dh_recording_overflow，不阻塞对话；无可解码音画失败。并发录制/停止通过DB幂等控制，不调用上游会清空session目录的start。

封装目标MP4 H.264/yuv420p + AAC、音频采样率48000、faststart；尺寸使用批准档位且偶数，fps25，输入不足不得伪造质量通过；具体codec可用与分发许可属于A/H证据。录制段最大300秒/200MiB；每段单独临时目录，由wrapper分配，不接受路径入参。异常中断能封装则partial并提示，否则failed；ffmpeg子进程有截止/kill/wait/stderr脱敏与重启扫描。

字幕取实际输出音频区间的已审文本，以段为单位，不声称字级对齐。中断取消尚未输出的text；时间裁剪到[0,durationMs]，严格start<end、不负数、序号从1、UTF8。SRT同时可下载；保存视频后字幕作为附属media在保存后挂到asset；保存前由recording持有授权和生命周期，不假造现有素材库已经支持独立SRT类别。删除独立视频asset后附属字幕失去挂载，交给GC；删除session不删已保存视频/附属字幕。

保存必须服务端ffprobe验证实际container/codec/音轨/duration/size/checksum后创建media_reference和content_asset；先预分配assetId写operation，重试同id。保存与GC共同持既有media引用锁/claim，完成挂载后才可把临时对象标可删。不得让浏览器下载后重新上传绕过归属，不把未经验证URL直接写content_asset。

录制acknowledgement明确授权保留该段已实际输出的文字以生成SRT；它不等于同意保存整个聊天。用户不保存transcript时，录制段字幕仅在recording有效期内、随该段临时/已保存资产生命周期保留。

字幕删除立刻content_deleted=true、contentEpoch+1、停后续保存，清易失buffer和runtime history；已保存录制视频含声音文字，是独立用户产物，UI明确不会连带删。账号注销需全部个人profile/revision/transcript/avatar/临时recording/bundle/cache/runtime文件逐项处理；已转组织/受保留策略保护资源沿现有规则，不能根据历史作者误删。

### K13.4 状态、幂等和副作用补充

会话状态state_entered_at仅合法迁移时变更，heartbeat不变它；queued/connecting超时依据该列。last_activity_at仅受理用户turn、实际输出完成或显式resume更新，不能因为10秒heartbeat而永不空闲；持续responding不按idle结束，但受总10分钟期限约束。session.next_turn_epoch事务单调递增用于分配turn；interrupt对目标turn的取消事实持久化，后续新turn分配更大epoch。greeting按session建立独立一次受理标记/operation kind=greeting，失败要重试只能同requestId查原结果；重新开始一场才再次允许，避免隐式重复计费。

会话总槽数必须由DB同一锁保证，不能COUNT后无锁INSERT：C01锁dh_catalog singleton作为队列/slot分配锁，固定顺序account gate→catalog容量锁→session；占用state为connecting/ready/listening/responding/paused/reconnecting/ending且cleanup_pending或worker lease未确认释放时仍计槽；queued不占。跨账号reaper每场单独按相同锁序，不一次锁多个账号再逆序；DB索引限制owner活动场与turn活动，单全局锁保证max1。元数据cleanup可保pending，只有worker停止事实或过期自停边界已确认后释放slot，不能为了腾位先假定停止。

空音频、用户abort且未end：turn=interrupted、session→ready、provider请求0；已end受理后即使WS正常关闭，原turn继续，UI查原turn/session事件。出错重录需要新的用户动作，不能自动提交第二段。recording start/stop使用已有dh_operation requestId，不对外暴露start_command_id；数据库该列存最初requestId。

session resume收到客户端controllerId与expected epoch后原子轮换；controllerId仅内存意味着刷新不能识别旧页是否自己，必须显式提示接管并takeover=true，不能偷偷接管别的标签页。普通页内pause/resume持同controller但也轮换epoch；显示确认与服务器租约不同概念。transcript saved不含用户mic文件，只有最终文字；保存字幕不自动同意录制。

令牌grant、preflight等易失缓存清空时先关闭受影响媒体/等待受控重新授权，不从浏览器本地token恢复；提供新资格只能绑定同一有效权威session，不能延长总时限。requestId重复键保留至少24h且直到关联非终态/费用/cleanup全收口；仍可查询的asset/session写receipt继续保留，无需24h一到立即删。用户/账号删除后只保脱敏防重与必要审计，正文按墓碑即清。

公开错误补充：不兼容冻结配置/撤销凭据=`dh_configuration_changed`(409)；预检过期=`dh_preflight_expired`(410)；文本保存墓碑=`dh_content_deleted`(409)；需要接管=`dh_takeover_required`(409)。统一日志只code/phase/脱敏id，不抄原provider错误。

### K13.5 保存资产附件与清理SQL事实

现有ContentAsset只有一个mediaReferenceId，没有通用SRT附件关系；不能只写“复用素材库”就假定附件已受保护。F媒体迁移明确新增`dh_asset_attachment`：id UUID、owner_account_id TEXT、asset_id UUID、media_reference_id UUID、kind TEXT CHECK kind='subtitle'、created_at/updated_at、version，UNIQUE(asset_id,kind)、UNIQUE(media_reference_id)。asset指既有content_asset，media指既有media_reference；应用事务同时校验三个owner及personal scope。

### K14.2 远端媒体、凭据与执行边界

render在session connecting阶段由Java创建一次invocation（INTERNAL07的render只允许读取/核验该已有记录，runtime不能凭任意session新增），resourceId=sessionId、segmentIndex=0、turnId=null，稳定经济键沿K08。render远端deadline以业务expiresAt为上界并持续受30秒执行租约约束，不能套用STT/LLM/TTS单次90秒期限；首次ready之前以connectTimeoutMs限制准备期。先预留建连准备期加整场最大时限的渲染成本，绑定原ai_run后CAS dispatched；Java以被冻结控制面凭据调用第三方创建会话/取得临时媒体资格。供应商会话id保存在原invocation.provider_run_id并由owner/lease关联，断线未知不重复创建收费会话。

INTERNAL08对render返回独立`RenderConnection`响应（不是TTS NDJSON）：`{invocationId,providerSessionRef,mediaEndpoint,connectionGrant,expiresAt,deadlineAt}`。长期密钥只在Java执行期解密；mediaEndpoint必须来自已批准配置/供应商受控响应且通过受信origin、DNS pinning、重定向校验。connectionGrant仅有该供应商会话的媒体权限、有效期不超过30秒且不超过当前执行租约、不入DB/日志/trace/浏览器；runtime只在内存使用。普通HTTP/SSE仍不代理视频帧；runtime通过此受控短期资格直接传送PCM并接收远端视频，再输出现有下行RTC/录制。供应商不支持此凭据隔离方式时不予批准，不能把长期key交Python。

新增内部INTERNAL14：runtime→Java `POST /internal/digital-human/render-invocations/{id}/control`，mTLS，body=`{requestId,sessionId,leaseEpoch,action:interrupt|close,turnId:null或Id,turnEpoch:null或Epoch}`；interrupt必须带目标turn代次，close为null。响应=`{accepted,state:pending|closed|unknown}`；按原invocation幂等调用远端取消/关闭，未知先查询原供应商会话，禁止新建。media reset/resume若原远端session仍可用则沿用；供应商无法恢复时结束当前场，用户重新开始才建新经济键。独立lease reaper同样通过Java关闭远端会话；远端停止未证实保留cleanupPending与预留事实。短期媒体资格续期由服务端按当前lease与同一供应商session更新，不延长业务时限。

媒体资格初次签发后，INTERNAL08执行资格仍不可复用。如需续期，新增内部INTERNAL15：runtime→Java `POST /internal/digital-human/render-invocations/{id}/connection-grants`，body=`{requestId,sessionId,leaseEpoch}`，mTLS且校验原invocation/session存活，返回同形RenderConnection，只续同一供应商会话的短期媒体资格，不能再create或新建run。

远端用量/关闭状态由Java适配器按providerSessionRef查询或校验可信供应商响应，不采信runtime自报金额或媒体帧数作为账单。第三方协议、短期资格、取消/查询、计量和输出AV能力均须实际证明；服务不可用显示dh_runtime_unavailable，配置版本失效dh_configuration_changed，不降级到本地推理。
