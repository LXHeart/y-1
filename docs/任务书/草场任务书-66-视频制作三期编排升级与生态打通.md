## 1. 目标与范围

**一句话目标**:平台分钟级 AI 异步长任务全量迁入 Temporal 编排;成片可导出剪映草稿(A 轨)与通用素材包(B 轨);新增按 infinite-canvas 设计的画布式分镜导演台(专业模式);候选挑选升级为视觉质检评分推荐;参考视频分析结构化映射进分镜。

**范围内(明确交付)**:
- A 线:视频成片管线(含等待挑选的挂起信号)、语音转写、图卡批量出图、视频复刻场景图批量,统一 Temporal workflow;灰度开关、双写对账、legacy worker 清零
- B 线:两轨导出端点与 zip 产物(B 轨通用包;A 轨剪映草稿目录,锁定剪映版本区间)
- C 线:静态交互原型(用户确认门)→ 画布基建 → 导演台面板与快速/专业双模式互切、分镜分组与版本分支
- D 线:`video_qa` capability 评分服务、take 评分字段、推荐升级为评分最高、前端徽标标签
- E 线:参考视频分析输出结构化(镜头结构/节奏/钩子位置)注入分镜生成

**范围外(明确不做,遇到也不处理)**:
- 不做数字人口播、自动发布、多语言成片(PRD 观望项)
- 不迁移非 AI 生成类的 outbox(媒体审核投递等,维持现状)
- A 轨草稿不做剪映移动端兼容承诺;不做剪映格式逆向的全量字段(只做视频/音频/字幕三轨可编辑最小集)
- C 线不嵌入 infinite-canvas 代码、不引 React;画布不引入前端新依赖(自研 pointer events;原型评审后确需手势库走返工决策)
- D 线评分不做自动拦截(恒 advisory)

@WorkflowInterface

  @WorkflowMethod void run(VideoTaskSpec spec);              // generating→(signal 等待)→composing→settle

### 卡 A1:Temporal 基建 + 视频管线 workflow
**背景**:拍板全迁;视频管线最长且含「等待用户挑选」的挂起环节,是 Temporal 价值最大的一条,先迁。

**改动文件**:
- 新建 `INT/orchestration/`(VideoProductionWorkflow/activities/worker 配置/TemporalWorkerConfig)
- 修改任务创建与 select/reroll/cancel/compose 入口(开关为 temporal 时改投 workflow signal)
- `RES/application.yml` 加 `ai.video-production.orchestration: legacy`

**开始前检查**:#65 卡8 已验收;marketplace/trust 的 temporal 依赖版本已确认(照抄版本号)。

**参考代码**(Temporal 接口签名见第 3 节;activity 薄壳调 #64 的 TTS/take/compose 既有服务,不改其内部逻辑)。

**做法**:
1. 引 temporal-sdk(版本对齐既有服务);worker 与 server 连接配置照 marketplace 先抄。
2. workflow:生成阶段并行 activity(TTS/take)→ 等待 submitSelections signal(超时 48h→failed)→ compose activity → settle;cancel signal 走补偿(activity 调既有 handleFailure)。
3. 双入口:HTTP 端点按开关分派 legacy 旧链路 / temporal workflowId=`video-task-{taskId}`;**默认 legacy**。
4. IT:开关两路各跑 sandbox 任务全通;temporal 路含「挑选前重启 worker,恢复后继续」用例(TestWorkflowEnvironment)。
5. 双写对账:对账任务比对两路状态终态一致(抽样字段:phase/finalMediaId/settledCents)。

**边界**:不动 STT/图卡/复刻(A2/A3);不删 legacy worker(A4)。

**验收**:`gradle test --rerun` 全绿;对账任务抽样零差异。
