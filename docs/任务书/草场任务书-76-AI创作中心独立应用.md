# 草场任务书 #76：AI 内容创作中心独立应用

背景：商家工作台「AI 与治理」（组织 AI 预算）与 AI 创作中心「运行记录」（个人 AI 预算）两处 token 上限入口让用户产生「重复设置」的困惑，根因是 AI 创作中心在产品心智上挂在草场平台的身份/组织概念下。2026-09-04 拍板：把 AI 内容创作中心独立成自己的应用，推荐官、商家、任何注册账号登录即用，游客可试用。

## 一、决策表（2026-09-04 七拍板，已定死）

| # | 决策点 | 定案 |
|---|---|---|
| D1 | 独立程度 | 独立应用：独立 origin、自己的导航壳与登录；不出现商家/推荐官身份概念，任何注册账号登录即用，游客可试用（GuestTrialPanel 保留） |
| D2 | 部署形态 | 同仓第三入口 `ai.html`，完全复刻 `ops.html` 模式：vite 第三 input + nginx 第三 server 块 + compose 宿主端口。不建独立仓库 |
| D3 | 跨应用登录 | 一次性 token 免登：跳转方（已登录）签发短时效一次性 token，目标方核销后建立本 origin 会话；未登录/过期/已核销则落目标方登录页。草场⇄AI 双向对称同一端点 |
| D4 | 任务创作通路 | 创作面双份（产品面）：任务创作留在草场内嵌创作面，AI 应用不做任务创作。工程红线：共享组件单实现、两应用双挂载，禁止复制视图代码 |
| D5 | 门店创作 | 入口收进商家工作台；创作过程深链跳 AI 应用，锁定门店上下文（执行走组织预算），锁定态不可改组织/门店 |
| D6 | AI 应用自由路径 | 无组织/门店选择器、无身份徽标——纯个人心智；个人 AI 预算、个人素材库、个人模型密钥全在 AI 应用 |
| D7 | 个人 AI 预算 | 留在 AI 应用「运行记录」板块（个人预算管无组织上下文的独立创作）；组织预算留商家工作台「AI 与治理」（任务/门店组织上下文创作）。两处文案互链说明分工 |

## 二、全局锚点（动手前必读，均已核对 2026-09-04 main）

### 2.1 双入口先例（照抄模式，勿发明）

- `vite.config.ts` rollupOptions.input 现为 `main`(index.html)/`ops`(ops.html)；加第三 `ai: ai.html`。manualChunks 的 vendor 拆分三入口共享，勿动。
- `ops.html` 形态：`data-app="ops"` 属性 + 防 FOUC 内联脚本。**该内联脚本的 sha256 hash 被 nginx CSP script-src 登记并被 `test/deployment/edge-entrypoint.contract.test.ts` 锁定**。`ai.html` 内联脚本必须与 index.html/ops.html 逐字节一致，并把契约测试扩为三入口锁定。
- `nginx.conf` 两个 server 块（80 用户端 / 81 治理台）的注释铁律：「/api、/csp-report、/health 的转发配置严格镜像，server 块之间不共享 location，改动一侧必须同步另一侧」。第三 server 块（listen 82）必须完整镜像：`/api` 转发、`^~ /assets/` 的 404 + chunk-reload 自救（c0d9cc28 闭环）、CSP/HSTS 头组、`/health`。**漏镜像 assets 404 配置会复现「旧 chunk 静默导航失败」线上事故。**
- `docker-compose.yml` 端口模式：`FRONTEND_PORT:-8080→80`、`OPS_FRONTEND_PORT:-8083→81`。新增 `AI_FRONTEND_PORT:-8084→82`。

### 2.2 会话与一次性 token（identity-service 新能力）

- 两 origin 打的是**同一个后端**（nginx 各 server 块镜像转发 /api 到同一 edge BFF）——会话不共享纯粹因为浏览器 cookie jar 按 origin 隔离。所以 token 换会话 = identity 在核销端点上 set-cookie，无跨服务问题。
- token 设计（定死）：
  - 签发：`POST /api/auth/cross-app-tokens`，要求已登录会话；返回不透明随机串。
  - 核销：`POST /api/auth/cross-app-tokens/exchange`，body 带 token；原子核销（见下）成功即按绑定账号建立会话 cookie。
  - 存储：Redis nonce（`SETNX` + TTL 5 分钟）绑定 accountId。**Redis 在本项目的既有定位就是防重放与游客限流，nonce 是同场景直接先例**，不要为此建表。
  - 单次核销：exchange 用 `GETDEL`（或 Lua 等价原子操作）保证重放即失败；过期/不存在返回 401，前端落登录页。
  - 不绑目标应用：同后端同会话机制，目标维度无差别；草场⇄AI 双向跳转共用同一对端点。
  - 审计：签发与核销各落一条审计日志（账号、时间、来源），**日志禁止落 token 明文**。
- 前端核销后必须 `history.replaceState` 清掉 URL 中的 token 参数，防浏览器历史/分享泄漏。
- Reactor 陷阱（本项目两次实锤）：`switchIfEmpty` 的参数在装配期求值，副作用调用必须包 `Mono.defer`。
- Jackson record 陷阱：请求 record 可选字段一律包装类型（primitive 缺失直接 400）；`is` 前缀无参方法会被序列化成属性，禁止。

### 2.3 前端依赖面（已逐点核实）

- `AiCreationCenter.vue` 对壳的依赖只有三点，AI 应用壳需自配前两点：
  1. `request-login` 事件 → 登录弹窗（现由 DefaultLayout 持有 LoginModal）；
  2. 积分余额展示 + `CreditsPackagesModal` 充值（credits store 可直接复用）；
  3. `entry` prop（进程内 creationEntry handoff + `KeepAlive :key="creationContextEpoch"`，均在 DefaultLayout）。
- 九板块清单（`AiCenterNavigation.vue`）：create/assistant/speech/image-studio/image-gen/video-studio/runs/library/keys。
- 工具视图七枚路由是工作流落地目的地：`/video` `/image` `/article` `/moments` `/comedy` `/video-production` `/video-canvas`。**双份创作面 = 两边路由挂同一组件**，URL 路径两边保持一致。
- 组织/门店选择器位置：create 板块 `store-fields`（`sourceType==='store' && !taskSourceLocked` 时渲染）。AI 应用自由路径不得渲染；门店深链锁定复用既有 `entry.source=store` 机制（`hydrateStoreContext` 现有 API，无需新后端）。
- 草场任务 handoff 现链路：工作台 `emit('open-creation')` → DefaultLayout `handleOpenCreation` 存 creationEntry → 跳 `/ai-center`；任务上下文来自 `getTaskContext(applicationId)`（已有）。
- 草场创作面（卡 D）板块定死：**只保留 create（任务锁定态）+ library（素材库）两板块**；assistant/speech/image-studio/image-gen/video-studio/runs/keys 是个人能力，只在 AI 应用。

### 2.4 执行与预算（零后端改动，勿碰）

- `AiExecutionService` 的 budgetScope 分流（`orgId != null ? orgId : "u:"+accountId`）已覆盖两种创作面：AI 应用自由创作走个人预算、门店深链锁定走组织预算。本任务书不改执行环。
- 创作扣积分走执行环 `executeIndependent*` 族，两应用触发同一后端，无感。

### 2.5 e2e / CI

- e2e 假域名 DNS pinning 固定表机制已有（契约已锁），AI 应用新 origin 入表。
- 本地 macOS 跑不了完整 e2e 栈（既定事实），e2e 在 CI 跑；既有走草场 `/ai-center` 的用例需全量改锚（先 grep 清点再动手）。
- 冒烟环境注意（既定坑）：admin 密码不覆盖、配额/积分/权益 3s 超时、CDN 截图 hash。

### 2.6 UI 规范

- AI 应用沿用根 `DESIGN.md`（grassland-design，Stripe 系），不新建规范文件。如确需与草场壳差异化，用 `[data-app="ai"]` CSS 变量作用域，禁止复制组件。
- 改任何 UI 前读对应 DESIGN.md；token-only；每页明暗双主题截图自查。

## 三、卡片

### 卡 A：一次性 token 跨应用免登（identity + edge）

1. 端点：签发 `POST /api/auth/cross-app-tokens`（需登录会话）+ 核销 `POST /api/auth/cross-app-tokens/exchange`，按 2.2 设计（Redis nonce、TTL 5min、原子单次核销、审计、不落明文）。
2. edge RouteManifest 登记两路由（未登记 = fail-closed 404，本项目路由铁律）。
3. 共享 composable：`useCrossAppToken()`——签发 + 拼 URL（`?xat=…` 参数名定死）+ 核销 + `history.replaceState` 清参。两应用共用。
4. IT 必备用例：签发需登录；核销成功建会话；同 token 二次核销 401；过期 401；核销后原会话不受影响。
5. 验收：curl 双端点全链 + IT 全绿。

### 卡 B：ai.html 第三入口与 AI 应用壳（前端基建 + 部署）

1. `ai.html`（内联脚本与 index.html 逐字节一致，`data-app="ai"`，标题「草场 · AI 创作中心」）；`src/ai/main.ts` + `src/ai/router` + `src/ai/AiAppLayout.vue`（品牌头部、主题切换、账号区含积分余额+充值入口、板块导航、「打开草场」外链按钮——外链走卡 A 的 token 免登）。
2. vite input、nginx 第三 server 块（82，全量镜像，见 2.1）、compose `AI_FRONTEND_PORT:-8084`、`edge-entrypoint.contract.test.ts` 扩三入口。
3. AI 应用路由：九板块（AiCreationCenter 挂 `mode="personal"`）+ 七枚工具视图路由 + 游客（未登录 GuestTrialPanel + 登录后刷新）。
4. 登录态：AI 应用自带登录（复用 LoginModal + auth store）；URL 带 `xat` 时优先核销换会话。
5. 验收：镜像重建后独立 origin 明暗双主题可浏览；游客→登录→板块可用；断网/错 token 落登录页不白屏。

### 卡 C：AI 应用创作面（自由创作 + 门店深链锁定）

1. `AiCreationCenter` 参数化 `mode: 'personal' | 'platform'`：personal 下 sourceOptions 只留 independent/hot-topic/reference（视频 reference 流保留），store/task 选项与 store-fields 不渲染；platform（草场，卡 D）只留 task 锁定态。
2. 门店深链：URL `?entry=store&org={organizationId}&store={storeId}`（+`xat` 免登）→ AI 应用路由层组装 entry（`source.type='store'`）→ 既有 hydrateStoreContext 拉门店上下文 → UI 锁定态显示「门店上下文 · 来自草场工作台」，不可改组织/门店。
3. 深链参数校验：org/store 不属于当前账号可及范围时拒绝（服务端已有权限判定端点，前端按错误落提示页，勿静默放行）。
4. 工具视图 handoff：AI 应用内自建简化 creationHandoff（自由创作 → 工具视图），机制照抄 DefaultLayout 的 entry + KeepAlive epoch，勿发明新状态机。
5. 验收：自由创作全流程（选平台→形式→来源→工具视图产出）与改造前行为一致（对照现存 e2e）；门店深链进入锁定、执行记录归属组织预算侧计量。

### 卡 D：草场侧收口（内嵌创作面 / 外链 / 旧链接 / 门店入口）

1. 草场内嵌创作面：新路由 `/creation`，挂 `AiCreationCenter mode="platform"`，板块只留 create+library；DefaultLayout `handleOpenCreation` 改跳 `/creation`（进程内 creationEntry 机制原样保留）。工作台领单「去创作」全链回归。
2. 主导航「AI 内容创作中心」tab 改外链：点击→签发 token→`window.open`/跳转 AI 应用 origin（环境变量注入 AI 应用地址，dev 用 vite 端口）；未登录先弹登录（现有行为）。
3. 旧链接兼容：草场 `/ai-center` 路由保留为重定向——已登录签发 token 跳 AI 应用对应路径，未登录直接跳（AI 应用落登录页）。`/image-gen` 重定向链保持不断。
4. 门店创作入口：商家工作台门店媒体库页签头部加「从门店创作」按钮→确认门店→签发 token + 深链跳 AI 应用（卡 C 锁定态）。
5. 草场侧工具视图七路由保留挂载（任务创作需要）；DefaultLayout 中 AI 中心专属的 props 分发（ai-center 分支）迁移到 `/creation`。
6. 验收：推荐官领单→创作→提交凭证全链不跨应用；商家门店创作深链全链；旧 `/ai-center` 链接不 404。

### 卡 E：PRD 改写 + e2e 连坐

1. PRD 改写点（逐处，勿漏）：
   - §2 身份表与 §11.1/§11.2：「AI 内容创作中心是双方共享的公共能力/不是独立身份或独立注册入口」→ 改为独立应用（独立 origin）、共享草场统一账号体系、应用内无身份概念；分层图中从「共享平台能力」子层移出为并列独立应用。
   - §四 开篇「草场内置的共享创作工具…根据当前活动身份提供不同的默认上下文」→ 独立应用 + 上下文只来自门店深链/自由选择；任务创作小节移至草场侧创作面表述。
   - §11.6 进入方式/负责范围：三入口改写（AI 应用直进=独立创作；商家工作台=门店深链；推荐官任务工作区=草场内嵌创作面）。
   - 「根据当前活动身份自动带入商家、门店、任务、素材和个人风格上下文」类表述全仓清查改写（grep「活动身份」核对）。
2. e2e：新增跨应用免登、门店深链锁定、AI 应用游客试用三条链；既有草场 `/ai-center` 用例全量改锚到 `/creation` 或 AI 应用。DNS pinning 表加 AI 应用 origin。
3. `docs/产品/草场使用说明.md` 中 AI 中心入口表述连坐。
4. 验收：PRD 无「内置共享能力/活动身份带入」残留表述（grep 验证）；e2e CI 绿。

## 四、集成验收

1. 后端门禁：`./gradlew check` 全绿（含新 IT）；Flyway 如有迁移一律幂等（IF NOT EXISTS）。
2. 前端门禁：vitest 全量 + 既有契约测试（三入口锁定）。
3. 部署验证：镜像 clean 重打（gradle UP-TO-DATE 指纹会失灵，疑似旧 jar 就 clean；unzip+grep -a 内容探针验真）→ compose 起 AI 端口 → 双主题截图自查（AI 应用首页/创作面/运行记录）。
4. 全链手工冒烟清单：
   - 游客：AI 应用可试用、可注册登录；
   - 草场已登录→主导航外链→免登落 AI 应用（URL 无 xat 残留）；
   - AI 应用「打开草场」→反向免登；
   - 推荐官领单→草场 /creation 任务锁定创作→提交凭证（不跨应用）；
   - 商家工作台门店入口→深链→AI 应用锁定态创作→组织预算计量可见；
   - 个人自由创作→运行记录用量 + 个人预算读写（AI 应用内唯一预算入口）；
   - token 重放/过期/改 URL 篡改深链参数→拒绝且不白屏。
5. 提交拆分：按卡 A/B/C/D/E 语义拆 commit（项目惯例：按逻辑边界多 commit，不打包一坨）。

## 五、明确不做

- 不改执行环/预算分流后端逻辑（2.4 已覆盖两种创作面）。
- 不动治理台 ops.html 与「AI 与治理」页签（组织预算/组织 BYOK/主体审计原地保留）。
- 不做跨应用消息总线/状态共享——两应用通过 URL 深链 + 各自 API 拉取交互。
- 不引入新 DESIGN.md 或新组件库；复用根规范与共享组件。
