## 1. 目标与范围

**一句话目标**:成片管线在一期基础上补齐实时进度推送、无图镜头 AI 补图、15–180 秒与 16:9 场景、成片后单镜局部重跑、治理台视频任务监控。

**范围内(明确交付)**:
- 后端:storyboard 校验放宽(15–180s/镜头≤30)与 resolution 参数贯通(校验→分镜提示词→provider ratio→合成分辨率→字幕边距)
- 后端:AI 补图端点(平台资助执行环、媒体审核、anchorSource 标记)
- 后端:任务 SSE 事件推送端点(直推不落库,30s 心跳)
- 后端:成片后单镜重抽 + 段缓存重合成 + 重结算幂等
- 后端:治理台 metrics 端点
- 前端:时长滑杆 15–180、平台比例联动、补图按钮与「AI 生成」标记、SSE 消费与轮询降级
- 治理台:「视频任务」监控页签

**范围外(明确不做,遇到也不处理)**:
- 不做竖版平台长时长硬限制(仅软提示文案)
- 不做 SSE 推送的落库事件表(快照为准,事件不持久化)
- 不做监控页签的干预操作(只读;干预走既有模型/价目面板)
- 不做三期全部内容(Temporal/剪映导出/画布/质检评分/参考分析深化)
- 不动一期已定死的计费口径(一口价按实际秒数;补图成本平台消化)

## 3. 接口契约(本节内容为最终代码,直接照抄进项目,不得修改)

```ts
// —— SSE 事件帧(GET /api/video-production/tasks/{id}/events,登录,Accept: text/event-stream)
export type TaskEvent =
  | { type: 'phase'; phase: 'generating' | 'selecting' | 'composing' | 'succeeded' | 'failed' | 'cancelled' }
  | { type: 'shot';   shotId: string; status: 'pending' | 'generating' | 'done' | 'failed' }
  | { type: 'take';   shotId: string; takeId: string; status: 'queued' | 'generating' | 'succeeded' | 'failed' }
  | { type: 'audio';  shotId: string; status: 'pending' | 'generating' | 'succeeded' | 'failed' | 'skipped' }
  | { type: 'compose_progress'; percent: number }   // 0..100,每镜合成完发一帧
  | { type: 'heartbeat' }                            // 每 30s 一帧
// 帧格式沿用既有 SSE 逐帧 JSON(#64 storyboard 契约同款 data: {...}\n\n);
// 'selecting' = 全部 take 与 audio 终态后首次进入等待挑选时发一帧。

// —— AI 补图(POST /api/video-production/shots/{shotId}/anchor:generate,登录)
// req  {}   (参考图 = 该任务全部用户上传图;提示词 = 该镜 visual;风格一致性优先参考图)
// resp 200 { mediaId: string, shot: ShotView }
//      409 该镜 anchorSource='user' 且未手动解除 / 任务 phase 不在分镜编辑期
//      503 image_generation 未配置(reason 见 capabilities)
// ShotView 新增字段: anchorSource: 'user' | 'ai';  anchorMediaId?: string
// 视频生成与合成的首帧取图规则: anchorMediaId 非空 → 用其对象存储字节;否则用户图[anchorImageIndex]。

// —— 时长与分辨率(storyboard 契约扩展)
// ScriptRequest.targetDurationSeconds: 15..180,步进 5(非 5 的倍数 400)
// ScriptRequest.resolution?: '1080x1920' | '1920x1080'(缺省按平台:bilibili→1920x1080,其余→1080x1920)
// 分镜约束行(#64 4.2 第 10 条)改为:「总 plannedSeconds 尽量贴近 {N} 秒(±10%);镜头数 3–30」
// provider: MiniMax aspect_ratio / Seedance ratio 按 resolution 映射('9:16'|'16:9')
// 合成 normalize 目标: 1080x1920(字幕 MarginV=60) / 1920x1080(MarginV=40)

// —— 成片后单镜重抽(POST /api/video-production/tasks/{id}/shots/{shotId}/reroll,登录)
// req  {}   (仅 phase=succeeded 任务;重抽该镜 defaultTakes 个候选,旧 take 软删)
// resp 202 { takes: TakeView[] }
// 之后走既有 select + compose;compose 复用未变镜头的段缓存,仅重 normalize 该镜。

// —— 监控(GET /api/admin/video-production/metrics?window=7d,治理台 requireRole)
export interface VideoTaskMetrics {
  window: '7d' | '30d'
  taskCount: number; successRate: number; cancelRate: number
  avgPipelineSeconds: number
  providers: Array<{ provider: string; taskCount: number; avgSeconds: number; failureRate: number }>
  costVsRevenue: { costCents: number; revenueCents: number }
  degraded: { slideshowRatio: number; noVoiceRatio: number }
  retryRatio: number; rerollRatio: number
}
```

**背景**:拍板支持成片后改单镜,其余段缓存复用、重结算幂等。

**改动文件**:
- 新建 `INT/videoproduction/SegmentCacheService.java`
- 修改 `CompositionService.java`(合成时逐镜段落 `segments/{taskId}/{shotId}.mp4`,已存在且未失效直接复用)

**做法**:
1. reroll:仅 phase=succeeded;旧 take 软删、按 defaultTakes 新建;任务回到 selecting(phase 流转复用 #64 状态机)。
