## 1. 产品需求、目标与范围

### 1.1 一句话目标

让知乎、小红书、大众点评笔记和朋友圈使用真实材料及作者自己的表达习惯生成、修改内容，减少强制模板腔，防止个人分享、商家、商业合作身份串用。

### 1.2 背景与价值

依据 [现状调研](../reviews/去AI味现状与四平台改进建议-2026-10-04.md)。已有三套全局规则、创作简报及图片评价改稿学习，不需要再叠第四套全文规则。主要缺口是平台模板冲突、账号级偏好不分身份、学习直接落库和范文事实污染风险。本任务把这些能力接通，并保留自然原文和修改前版本。

### 1.3 范围内

### 1.4 范围外与已知不处理项

不承诺绕过 AI 检测、涨流量、自动发布；不微调、不爬取范文、不新增向量库、不更新上游项目版本声明。不改变价格、免费/付费属性、角色权限、组织共享可见性、自动扣退、图片评价现有 2/3 阶段或其他平台流程。减少自动改写轮次仅作后续实验建议，不进入本次产品默认行为。数字人 #105 与 Hypit #107 已有改动/未完成验收不在本书修复范围。治理台保留现有规则管理 UI，不增加管理者读取个人档案的权限。

### 1.6 用户、入口与限制

登录用户在现有文章、图片评价、朋友圈创作入口使用；用户端任务创作和 AI 创作端自由创作均覆盖。文风身份是写作视角，不是系统授权角色。资料整理者沿用 researcher，不能强行归入消费者。商家档案仍属该账号私人数据，不变为组织资产、不共享给同事。未确认身份和旧客户端行为见 RULE-004。所有现有任务快照、门店与平台锁定优先。验收例外仅限已核实的文档基线：2026-10-04全仓docs:links有109项错误，均位于两份既有调研报告（OpenTalking复刻复审与本书引用的去AI味调研）；这两文件本任务只读。授权规划者将其列为既有无关链接债，不阻塞本任务，但必须保留全仓失败结果、证明本次任务书/索引零新增错误，不能称全仓链接全绿。业务验收无豁免。

## 4. 目标行为

### 4.1 用户流程

- F-01：选已有表达身份 → 展开“我的文风” → 读取该槽位 → 默认不使用，主动勾选后生成；只将选择写回已有 inputs.brief，档案内容留在服务端。切平台只改变样例选择，切身份清空在途 UI，再读新槽位。
- F-02：现有编辑保存照常可用；另点“从改稿提取文风”，选择“事实纠错/仅本次要求/长期表达偏好”。前两类不调用模型也不写档案；长期偏好提交用户选定的前后片段 → 候选预览（默认不选中）→ 手动选择、编辑 → 确认保存。取消/失败不改持久规则。已有规则删除/替换须显示最终列表，禁止静默追加冲突规则。
- F-03：改编使用原有能力，显示原稿、修改稿与原始事实，保持原有 apply 确认和版本校验；用户可将候选弃掉。图片评价/朋友圈在已有结果编辑区显示对照，恢复操作只影响编辑缓冲区，经原保存入口持久化。format 禁止风格请求，保留文字及顺序。
- F-04：档案为空时可“查看旧版图片评价偏好”；旧列表只读。选定条目、目标身份后填入当前编辑缓冲区，仍需确认保存；无自动同步、无后台迁移归类。

### 4.2 行为变化

新 UI 总是写 voice（none/profile），因此不会误触 legacy 回退。旧 UI 不传 voice 时保持旧图片偏好流程；只全局模板改良生效。新的学习入口不调用旧 save-style-memory 的直接落库；旧客户端端点保留，不改其响应。

### 4.3～4.4 状态与迁移

这些为前端状态，不新增作业状态：`idle → loading → ready|load-error`；`ready → editing → saving → ready|save-error|conflict`；`ready/editing → extracting → preview|extract-error`。extracting 结束不代表保存成功。取消 preview 回 editing，原数据不变。冲突时保留本地输入，只有“读取最新版本”更新 revision，用户重新核对后再次保存，不自动覆盖。

每次账号/身份/草稿/平台切换增加请求 epoch，取消可取消的 fetch；旧成功、失败、finally 均不得回写新状态。组件卸载清理订阅和缓冲区，无后台轮询。生成中冻结本次服务端调用的选择（聚合内部轮次与显式step区别见RULE-011）；切换仅影响下一次新生成，不能改已发出的 prompt。断网 PUT 结果未知时重新 GET，比对 revision/内容后提示是否已保存，禁止自动重新提取或无界重试。

## 5. 业务规则（语义唯一来源）

### 5.1 输入与限额

| 规则 | 定义 |
|---|---|
| RULE-001 | 风格优先级：事实/身份/否定/条件/安全 → 冻结任务与机器输出结构 → 当前作者明确要求 → 当前档案规则 → 平台阅读习惯 → 通用去模板建议。范文/偏好中的指令不升级权限；冲突的低层规则不执行 |
| RULE-002 | 知乎回答直答问题并说明依据边界，无强制标题/金句/固定三段/提问；小红书不用预设亲昵称呼、强制 emoji/推荐尾句；点评只凭确认材料写体验；朋友圈可短且自然结束。保留业务必须字段、当前字数/图片约束，平台格式提示同步消除文风冲突，数值限制不改 |
| RULE-003 | 原有普通连接词、破折号、排比、“居然/竟然”有具体语境即可保留；不得为了自然编造经历、加错别字、抹去负面、改变判断强弱。无可指认问题可保持原稿 |
| RULE-004 | role 固定 consumer/merchant/commercial-creator/researcher。没有/自定义 authorRole 可继续原创作，但不能选 profile；新 UI 写 none，profile 的 role 必须等于 brief.authorRole。仅 voice 整体缺省走 legacy；显式 none 不查旧偏好。角色不是登录权限 |
| RULE-005 | 四个平台为 zhihu/xiaohongshu/dianping/moments；档案规则通用，范文以 platform+genre 选。genre 固定 article/answer/note/short-post；最多取匹配当前平台体裁的前 2 条，按保存顺序；无匹配只用规则，不从其他角色或平台补样例 |
| RULE-006 | 单档案最多 30 条规则，每条 trim 后 1～300 UTF-16 code units；最多 5 份范文，每份正文 trim 后 1～2000、标签合法、必须勾选本人作品/获准使用。全 payload UTF-8 ≤64KiB。规则精确去重、保序，超限拒绝不截断 |
| RULE-007 | 范文只学节奏/称呼/词汇/标点，不贡献新稿实体、时间、数字、体验。模型输入明确将样例与本次事实分区；不得拼入 facts/sourceRefs，也不把样例作为用户确认体验。写入前提醒清除私密信息 |
| RULE-008 | 提炼片段 original/edited 各 1～12000 UTF-16 code units；两者相同不调模型返回空候选。只处理选择的长期表达片段，结果最多 10 条、每条按 RULE-006，模型格式错/超限报错不落库；事实改价、单篇联系方式删除不能自动学成规则 |
| RULE-009 | 不自动使用或合并候选；PUT 为最终完整档案 CAS 替换。撤销持久规则用编辑/删除后保存；清空是 PUT 空列表且 enabled=false，保留 revision 槽位防 ABA，不保留范文历史副本 |
| RULE-010 | 选择 profile 后按提交的 revision 精确读取；缺槽/版本不符/已停用不默默退回旧规则。新生成开始前报错让用户重新读取。读取失败不得当空档案；旧全局 humanize 的 fail-open 仍保留且只记降级元数据 |
| RULE-011 | 每次服务端生成调用冻结同一档案内容、revision 与样例摘要；单次聚合 analyze 的后续内部轮次不重读档案。显式 step/draft、step/optimize、step/style-refine 是不同请求，各自重新校验所传 revision；过期返回冲突，用户重新读取后继续，不承诺跨请求保留已删除的档案快照。记录模板策略版本及全局规则真实版本/摘要；不以种子版本冒充当前库内容 |
| RULE-012 | 不改变既有价格、计费粒度、轮次、ai_run/退款、任务锁与安全链。档案 CRUD 不调用模型；提炼与旧偏好 optimize 同模型路由/调用限制，不新设付费项；不为评估额外自动生成 |
| RULE-013 | format 不运行文风生成/改写；确定性排版原文字、数字、专名、顺序不变。adapt 使用已有确认应用、保留原稿；复核是辅助，不宣称算法已验证全部事实正确 |

体裁映射固定：文章 answerMode=true→answer，否则article；图片评价→note；朋友圈→short-post。平台取服务端已校验/任务锁定值。新面板仅在上述四平台可用；切到其他平台时显式设置voice.none且保持旧功能，不带profile请求到未支持平台。服务端在这四条创作链遇profile与非支持平台组合以VOICE_INVALID_INPUT拒绝；不改变视频等未接入链路。

### 5.2 校验顺序

先解析可信 caller/现有任务权限，再验证类型与长度、role/platform/genre、profile revision，最后解密与组装。在账户屏障冻结时不得写/提炼/新解析私人档案。未知字段在新增 API 拒绝；旧 brief 其他现有扩展保持兼容，voice 出现时严格校验。null 不等同缺省 voice，必须拒绝。语义长度与传输类型见 §6。

### 5.3～5.4 权限和不变量

RULE-014：账户仅来自 IntelligenceCallerResolver，所有 SQL 带 account_id+role；新 API 不接受 accountId/organizationId，拒绝伪造而非忽略。管理员、同组织成员也无权代读。账号注销擦除档案、摘要及密文；账号冻结与写入通过同事务 gate 行锁串行化，不能仅前端隐藏。草稿共享不携带档案正文；每位调用者只解析自己的槽位，不能使用草稿作者的私人档案。旧草稿中的选择引用不赋予访问权；读不到时按 RULE-010，不扩大可见范围。

RULE-015：不把生成或范文渲染成未净化 HTML；复用既有 Markdown/sanitizer。日志只存 request/run 关联 ID、role、revision、模板版本、规则 code/version/hash、状态、耗时及数量；不写文本、样例 hash 对应的原文、密钥、cookie、完整请求。截图用合成内容。

## 6. 接口与模块契约

### 6.1～6.3 新增 API

公共前缀 `/api/creation-voice`，由 Edge 精确 method/path 代理 intelligence，沿用现有 image-analysis 的认证/CSRF 与启用条件；不放开任意前缀透传。成功信封沿用 `{success:true,data:...}`，时间为 UTC ISO8601，revision 为非负安全整数。

| API | 方法/路径 | 请求 | data |
|---|---|---|---|
| API-001 | GET `/{role}` | role 按 RULE-004，无 body | Profile |
| API-002 | PUT `/{role}` | `{expectedRevision,enabled,rules,samples}`，全部必传 | Profile |
| API-003 | POST `/{role}/preview` | `{original,edited,reason:"style",platform,genre}`，全部必传 | `{candidates:string[]}`；不落库 |

Profile = `{role,revision,enabled,rules:string[],samples:Sample[],updatedAt:string|null}`；缺行 GET 返回 revision=0、enabled=false、空数组、updatedAt=null，不是错误。Sample = `{id:string,platform,genre,text:string,consent:true}`，id 为客户端 UUID，单档案内唯一；不接受 null/false consent。rules/samples 空数组合法，enabled=true 至少有规则或范文；enabled=false 可保留内容。expectedRevision=0 仅首次建槽；相同目标内容重放返回当前值，其他旧 revision 为冲突。

API-003 reason 只有 style；fact/one-off 由前端直接跳过，若绕过前端调用以 400 拒绝。相同片段返回 candidates=[]。请求串行一次，不自动重试；失败不产生持久候选或更改档案。

### 6.4～6.5 错误与恢复

| HTTP/code | 条件 | 消费行为 |
|---|---|---|
| 400 / INVALID_CREATION_BRIEF、STUDIO_INVALID_INPUT（既有） | format误入普通生成或TextProposal改编 | 不执行模型/改写，回原文排版；对应入口分别使用这两个既有码 |
| 400 / VOICE_INVALID_INPUT | 字段、类型、限额、role/平台/体裁/consent 非法 | 保留输入，定位字段；不调用模型/写库 |
| 401 / 现有认证错误 | 无会话/过期 | 走既有登录，清私人缓冲；不显示其他账号数据 |
| 409 / VOICE_REVISION_CONFLICT | PUT 不同内容旧 revision；解析 profile 缺行/停用/过期 | 保留输入，读最新并明确再次确认 |
| 409 / VOICE_ROLE_MISMATCH | 请求 profile 与 authorRole 不一致 | 要求重新选择，不生成 |
| 409 / 现有账号生命周期屏障错误 | frozen/erasing/erased | 沿用既有屏障响应/恢复，不能另开写入旁路 |
| 503 / VOICE_UNAVAILABLE | 新档案读写/解密不可用 | 保留输入，允许手动重试；不得返回空成功 |
| 502 / VOICE_EXTRACTION_FAILED | 提炼模型错误、超时、空/损坏 JSON | 留在预览前，用户可重试或放弃；零档案写入 |

不改旧 API 的状态与信封。profile JSON 在 64KiB 内；边缘请求总量限制沿用现有值，服务校验负责本限额。

### 6.6 brief 与内部调用

在 `CreationBrief` 增可选判别联合 `voice?: {mode:'none'} | {mode:'profile',role:Role,revision:number}`。none 不能附 role/revision；profile revision≥1。缺省只为旧兼容；新 UI 首次写 none。通过原 JSON brief 或 multipart brief 字符串传输，草稿仅保存这一选择；不改变现有公开结果字段。

新增服务 `CreationVoiceService.resolve(accountId, platform, genre, brief)` 返回不可变 `ResolvedVoice(role, revision, appendix, sampleHashes, policyVersion)`；mode none/legacy 的无新档案返回 revision=0、appendix 空；旧偏好是否回退由图片 Controller 按 RULE-004 明确分支。role/profile 错误先于模型调用。账户、平台与体裁来自已校验 caller/当前服务任务上下文，客户端不得提供解析后的 appendix。调用者在一次运行内复用对象，显式传给后续阶段，不建立全局账号缓存。

全局注入额外提供结果元数据的内部返回形式供四平台调用者记录，原 injectCreative/injectForFeature 签名保留为委托适配；不把字符串 marker 当跳过安全策略的凭证。元数据包含 activeCode/version/contentHash/status=applied|disabled|degraded，必须来自同次读取，不再查一次库拼版本。固定策略版本 `voice-policy-108-v1`。不新增 API 字段承诺，也不保存完整 prompt 到新表；TextProposal 继续既有加密捕获。

### 6.7 流式、上传、异步

文章 SSE 仍按原 content/error/safety 帧；不新增 token 帧类型。profile 解析失败发生在开流前；开流后错误遵循原通道，不伪装成功或重启计费。图片 multipart 字段白名单不加独立 profile 字段。无新后台任务；提炼超时 60 秒，响应迟到以 epoch 丢弃，服务端无持久候选。已有生成取消与退款规则照旧，关闭预览不声称取消已完成的上游模型费用。API-003先鉴权并核验屏障；模型返回后再次核验账户gate，已冻结时丢弃候选并返回既有屏障错误，不把新结果交还已冻结用户。

## 7. 数据模型与迁移

### 7.1～7.2 存储

V94 新建 `creation_voice_profile`：`account_id text NOT NULL`、`role text NOT NULL`（CHECK 四值），联合主键；`revision bigint NOT NULL CHECK(revision>0)`、`enabled boolean NOT NULL DEFAULT false`、`encrypted_payload text NOT NULL`、`payload_hash text NOT NULL`、`updated_at timestamptz NOT NULL DEFAULT now()`。payload 为 §6 rules/samples 的规范 JSON，沿用 EnvelopeEncryption，hash 为包括 enabled 在内的规范目标内容 SHA-256。不存 organization_id，不新增可公开读取字段。UTC 存储/显示依现有时间工具。GET 解密失败必须报错，不能替换成空数组。

### 7.3 兼容与规则更新

旧 `intelligence_style_preferences` 不搬移、不删除、不自动贴 role；旧 API 继续旧表。F-04 手动导入是对新槽位的正常 PUT，旧规则 >30 条时必须用户选到限制内，不静默截断。

V93 仅条件更新 `humanize_skill` 中与本书基线种子原内容及元数据一致、updated_by 为空的三项；WHERE 同时约束 code、旧 prompt 全文、旧描述/来源、version，更新 prompt/description 并 version+1。管理员编辑过或未知版本的行保持原样。`humanize_config`/enabled/激活项不变；新库种子直接用新文本。升级 SQL 内携带基线旧字面文本，不依赖本机运行时文件；回滚通过精确新版匹配的补偿 UPDATE，恢复旧文本并继续增加 version，不能降版本/覆盖更新后的自定义行。迁移和种子同源由测试逐项比对。没有升级到的自定义规则照旧，运行元数据如实标其 hash，不声称全库都用新版。

### 7.4 事务、并发与生命周期

PUT：先确保账户 gate 行存在并按现有生命周期机制取得锁，再取 profile 行锁；不存在使用唯一键保障一次创建。比较当前 hash/实际规范内容相同则幂等返回；不同内容必须 expectedRevision 一致，再写 revision+1。数据库回滚则密文、hash、revision 同时不变。所有持久写不得 `.block()` 或手动 subscribe。

V94 为新表增加专用 BEFORE INSERT OR UPDATE 屏障触发器，复用 V86/V87 的 gate 锁语义但不重写共享函数；先序列化 gate、冻结态拒绝，防直接 SQL 绕过。应用 PUT 和预览同样核验账户生命周期；解析在授权检查之后，已运行任务沿既有取消/注销机制，不引入新的持久活动作业。

新表登记 personal/erase-with-owner；非作业资源无阻塞活动状态，按登记簿既有无活动项编码记录。PersonalDataErasureRepository 增批次删除/剩余计数。派生物是浏览器内存、提示词运行上下文及已有加密 proposal；不得复制到组织草稿。清空档案以空密文覆盖并递增版本，无历史表；账号正式擦除物理删除所有槽位。无新事件，不改事件消费者登记。

### 7.5 演练与回滚

真实 PostgreSQL 验证空库、新档案创建/升级、自定义旧规则、部分种子、已有 active、disabled、规则并发管理修改。Flyway 重跑 no-op；不修改 V2/V58/V85～V92。应用回滚可回到不认识新表的旧版本，旧偏好仍可用，新表暂保留；不自动 DROP 数据。本地新测试卷仅守卫 fresh 确认后允许 reset；存量/开发库只 stop。

#### TC-C02-002：CAS 与结果未知

准备同一账号同一role revision=1、内容X。客户端甲/乙都读rev1，用屏障同步发不同内容Y/Z。先释放甲事务，甲200/rev2；再释放乙，乙409，不得以旧明文回填。数据库仅Y、rev2，解密内容及hash一致。反向提交顺序结果对称。甲响应丢失后重发原PUT，应200/rev2不再写；若期间乙已合法写rev3不同内容，则甲重放409不回退。两个首次rev0不同写只能一个建槽成功。事务注入异常时不得留下仅更新hash或密文的半行。清空后旧写不得复活旧内容。所有账号有效、权限相同、payload合法，确保拒绝来自revision而非另一校验。

#### TC-C02-003：权限与注销的双向交错

A/B均登录且账户active，同一组织，分别存同role不同canary。B读取只得B数据；body/query伪造A owner不得返回A，管理员同理。先持gate冻结事务，再发A PUT及直接SQL INSERT/UPDATE；冻结提交后这些写必须拒绝且无行增长。反向先提交PUT再冻结允许先前行存在，随后运行真实擦除批次直到count=0，密文/hash/旧偏好均按owner删除。B行及其他组织资产不受影响。触发器拒绝不能来自非法role、缺密钥或revision；这些前置全部有效。浏览器已有A数据时登出、注销或切B必须清空，并拒绝A迟到回调恢复数据。新表为非活动配置资源，不为注销新增永远无法结束的job。

#### TC-C04-002：A→B→A 与旧 finally

冻结A1 GET和preview；切B完成B GET，再切A形成A2请求并成功读取新revision；最后释放A1成功、失败与finally三种结果分别测试。A2数据、error、loading、候选列表不能被任何A1回调改写；只比较accountId的实现应被此用例击败。同账号consumer→merchant→consumer重复一次。卸载后完成PUT，服务端可以已成功，但前端不得重建组件状态/显示已保存；重新进入须GET确认。读请求可abort，写操作以结果核对恢复，不能假设abort=服务端撤销。

#### 证据分层

静态模板/关键词测试证明规则文本与接线存在，不证明生成不编造。PG/HTTP测试证明权限、锁、数据和传输；WireMock/本地provider证明真实服务发送了正确请求，不证明文案质量。UI单元可mock；最终E2E不得route.fulfill自家业务API。真实模型及本人盲评才可判断自然度/本人声音；保持原始输出、模型参数与盲评结果，不能由另一模型评分冒充本人。样例和现成测试都不能当成已执行证据。
