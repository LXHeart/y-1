# 任务书与交付报告索引

任务书是“为什么做、边界是什么、怎样验收”的设计与执行合同；完成报告是“实际做了什么、证据在哪里”的交付记录。当前开放项仍以[续接指南第四节](../草场开发进度与续接指南.md#四当前未完成开发与生产门禁按优先级)和 [`docs/status.yaml`](../status.yaml) 为准。没有完成报告的任务书不等于未实现，也不等于已完成，需回到代码、测试和最近复核记录核对。

## 阅读规则

- 新任务使用未占用编号。既有相同编号的配套文件中，带“完成报告”“交付报告”或“交付记录”的文件是结果记录，另一个是规格/设计；历史重复编号的特例见下一条。
- `#74` 有两个独立主题： [争议小法庭重构](草场任务书-74-争议小法庭重构.md) 和 [举报投诉场景化改造](草场任务书-74-举报投诉场景化改造.md)，不要合并引用。
- `#92`、`#96`、`#97` 是分卡批次；先读总规格，再按卡号读完成报告。
- `AI内容中心改造-01/02/03` 是独立的 AI 创作批次，不与 #92 的分卡报告互相替代。
- 历史设计和计划见[设计与计划对应表](../superpowers/README.md)；以本页和对应任务书为入口，这类文档不能覆盖当前代码事实。
