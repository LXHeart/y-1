## 4. 目标行为与状态

### 4.1 两条主流程

内容/体验：发布 → 报名 → 接受并确认条款 → 供样/预约（如有）→ 草稿/成品/发布凭证 → 核验 → 商家验收或到期 → 观察/争议窗口 → 结算。

套餐推广：取得资格 → 生成推广链接 → 消费者下单并冻结订单快照 → 支付 → 核销 → 48 小时冷静期 → 售后窗口结束 → 分账；结束推广只阻止新触达，不改变既有订单。

### 4.2 合作状态

`pending → accepted → terms_confirmed → in_progress → submitted → under_review → remedial → confirmed → observing → payable → settled`；可从 `accepted/terms_confirmed/in_progress/submitted` 进入 `withdrawn`、`cancelled_by_merchant` 或 `disputed`，每次迁移必须记录责任方、原因、截止时间和资金动作。`referral` 订单状态沿用现有订单状态，不与内容状态混用。

## 5. 业务不变量

- 客户端输入永远不能改变订单快照中的 `recommenderShareBps`、固定佣金额、平台费和商家净额。
- 任一支付、退款、分账、冲正事件按幂等键只产生一次经济事实；余额、账本、订单可对账。
- 已提现但退款导致钱包不足时，进入独立应收/未来收益抵扣记录，不伪造负余额。
- 取消补偿以可举证履约阶段和冻结 policy 为准；未开始合作不支付创作补偿。
- 商家要求新增范围或第三次补证必须创建新约定或争议，不得无限延长原合同。

## 6. 接口与数据契约

### 6.1 归因

保留订单查询接口；将 `POST /api/v2/orders/{id}/attribution` 的消费者语义改为申诉创建，成功返回 `caseId/status=under_review`，请求只允许 `reason`、证据引用和可选触达标识，不接受佣金比例。治理台提供受权限保护的审核动作，动作结果引用订单冻结 policy 并写审计事件。

### 6.2 履约与体验

新增/扩展的请求必须包含 `engagementRef`、动作、`expectedVersion`、原因及证据引用；响应统一返回 `status`、`allowedActions`、`blockedReason`、`nextActionDueAt`、资金摘要。体验记录必须以 engagement 归属校验，敏感地址不进入公开响应。

### 6.3 兼容

旧客户端省略新增字段仍可读取历史记录；旧订单按原 policy 结算；新增字段采用可空列和兼容读路径。错误沿用现有 400/401/403/404/409/422/503 信封。

## 11. 任务卡

### C93-01 归因申诉与订单佣金冻结

输入为现有订单和推广资格，输出为不可由消费者改写的订单分配及可审计申诉。修改 `CommerceController/Service/Repository`、消费者归因视图、DTO 和 IT。移除最终分成参数；复用订单 policy snapshot；审核动作校验资格、自购、订单状态和退款比例；重复申诉幂等。覆盖未登录、非本人订单、无资格、自购、固定佣金、部分退款和并发改绑。AC：消费者提交比例返回 400/422 且商家应收不变；合法申诉进入审核；审核结果可追溯；旧订单可读。

### C93-02 核验、确认、结算与应收

输入提交、核验三态、确认窗口和争议状态，输出唯一结算资格。修改 `EngagementDecisionService`、`EngagementVerification*`、`ConfirmationActivityImpl`、`SettlementExecution`、`SettlementWindowPolicy`、Finance 应收/抵扣和测试。自动确认只接受充分证据；`inconclusive`/缺失进入人工复核；可支付时间取合同保护窗口、观察期和争议窗口最大值；资金事件幂等。AC：失败/存疑不支付；Lv5 T+1 不早于 48 小时保护窗口；已提现退款创建应收而非负余额。

### C93-03 履约期限、退出、取消与补偿

输入 accepted 合作、责任方和截止时间，输出确定状态迁移、提醒、名额与预留释放。修改 `ApplicationLifecycleService`、`EngagementSubmissionService`、`TaskController`、workflow dispatcher、迁移和 IT。新增确认/交付/补交/延期/主动退出/商家取消命令；按阶段快照计算补偿；商家无成果取消仍区分未开工与已投入。AC：接单后长期无交付可恢复终结；商家已有草稿/成品取消支付约定阶段；双方同意取消不扣未使用资金；第三次补证被拒或转争议。

### C93-04 体验权益与押金兑现

输入体验模板和 engagement，输出权益、预约、供样/接待、兑现事实。修改 marketplace freebie/taskcatalog、finance escrow、前端体验状态和测试。商家未供样/接待时暂停时钟；到期无责退出退押金；押金扣除必须有责任与金额证据；敏感地址按权限返回。AC：预约取消、样品未到、商家失约、已消费未交付、推荐官无责退出均可审计；不得因低播放或负面评价自动没收押金。

### C93-05 声誉、匹配与数据来源

输入历史履约、分销订单、责任结论和账号指标，输出分离的内容履约率、分销表现、商家信用和带来源画像。修改 `ReputationRepository/Stats/Policy`、响应 DTO、匹配查询、管理端/工作台看板及测试。未到期和免责事件排除失败分母；套餐只计分销；粉丝数显示自报/验证/平台事实及采集时间；保留历史口径版本。AC：10 个完成+5 个进行中仍为 100% 内容完成率；套餐核销不降低内容率；来源标签可查询。

### C93-06 工作台、推广链接与集成验收

输入服务端动作投影、资格和订单，输出三端统一待办、opaque `referralLinkId`、可解释归因和经营指标。修改 `src/views/grassland/**`、`src/views/commerce/**`、`src/ops/**`、Commerce link API、E2E。首期只实现下单会话归因；结束推广停止新触达而保留历史订单；统计显示退款、净佣金、待结算和数据来源。AC：刷新/乱序不串账号；链接失效原因可查；暗亮主题截图通过；任务、订单、钱包、声誉四者金额/状态一致。
