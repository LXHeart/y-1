## 1. 目标与范围

### 1.1 一句话目标

### 1.2 背景与价值

FACT：`/Users/LXH/claude/y-1/src/views/grassland/GrasslandWorkbench.vue:558` 的账号 watcher 会先清理状态，再等待 `initForAccount()`；`/Users/LXH/claude/y-1/src/views/grassland/composables/useWorkbenchSession.ts:221` 起的初始化包含身份 bootstrap、组织/范围并发读取、组织后续门店/资金/任务加载和钱包异步 continuation。当前代码已有部分 `AccountTicket` 检查，但 `loadOrganizations()` 在子加载返回后仍可能无条件继续 `refreshTasks()`，组件 URL 恢复仍只比较 `currentUser.value?.id`，任务列表本身的 `refreshTasks()` 也在 `Promise.all` 后缺少账号票据提交检查。

价值：在快速切换账号、A→B→A、慢请求、错误响应或组件生命周期变化时，界面和内存状态只反映当前账号，且不重复发起旧会话动作。

### 决策记录

#### D-84-01：账号切换判定

唯一判定是 `AccountTicket` 的 `accountId` 与 `epoch` 同时由 `session.isCurrent(ticket)` 验证；不得只看 `currentUser.id`。

#### D-84-02：写入与续发边界

异步域操作必须遵循“捕获票据 → await → 验票 → 写入/续发”的顺序。父级 continuation 即使子 loader因旧票返回，也必须在下一步前再次验票。

## 4. 目标行为

### 4.1 用户流程

1. 账号 A 登录进入工作台，初始化按既有顺序加载身份、组织、门店、资金账户、任务和推荐官钱包。
2. 任一请求未完成时切到账号 B；A 的状态先由现有 reset 清理，B 可启动自己的初始化。
3. A 的任何旧响应随后到达：A 的组织/门店/账户/钱包/任务/当前组织/URL 恢复均不再写入或续发；B 的状态不受影响。
4. A→B→A 时，第一轮 A 的 ticket 与第三轮 A 不相等；第一轮 A 的迟到响应不能写第三轮 A。
5. 当前账号请求正常成功、空列表、账户不存在、网络错误时，保持现有结果和错误展示。

### 4.2 行为变化表

| 场景 | 当前风险 | 目标行为 | 验收 |
|---|---|---|---|
| 组织/范围回包后切号 | 旧链继续门店/账户/任务 | 旧票据终止全部后续 | AC-84-01 |
| 门店慢回包 | 不得写旧门店，也不得继续任务刷新 | 不写、不续发 | AC-84-02 |
| 账户慢回包 | 不得写旧资金账户 | 不写、不发 notice | AC-84-03 |
| 钱包慢回包 | 不得写旧钱包余额 | 不写，保留当前 reset 值 | AC-84-04 |
| 任务并发慢回包 | 旧任务可能覆盖 `tasks` | `Promise.all` 后验票再写 | AC-84-05 |
| A→B→A URL 恢复 | id 相等会误恢复第一轮 A | 仅当前 ticket 可恢复 | AC-84-06 |

| AC-84-02 | 门店或组织后续请求失效后，旧链不写门店/当前组织，不调用旧账户、任务或更名 continuation。 |
| AC-84-03 | 资金账户迟到成功/失败不改变当前账号 `account`、notice 或错误展示；当前账号 `null` 语义不变。 |
| AC-84-04 | 钱包迟到成功/失败不改变当前账号 `walletBalanceCents`；推荐官正常钱包结果仍可写入。 |
| AC-84-05 | 任务 `Promise.all` 的旧回包不写 `tasks`、不 clearError、不续发；当前账号完整/空/null 结果保持既有规则。 |
| AC-84-06 | URL 恢复只接受当前 `AccountTicket`；A→B→A 时第一轮 A 的旧 query 不会恢复，第三轮 A 可恢复自己的入口 query。 |

### 4.4 状态定义

- `AccountTicket` 当前：由 `accountId` 和 `epoch` 定义；票据失效不代表请求一定被物理中断。
- 旧链：捕获票据后任一时刻 `session.isCurrent(ticket) === false` 的异步调用及其 continuation。
- 当前链：捕获票据后每个提交点均通过 `session.isCurrent(ticket)` 的调用。
- 空数据、未加载、失败语义沿用现有 refs；不得以空数组或 `0` 替代未加载/失败。

### 4.4 状态迁移规则

| 前置 | 事件 | 状态变化 | 禁止副作用 |
|---|---|---|---|
| A 初始化中 | auth 变 B | A ticket 失效，现有 reset 清空工作台域 | A 后续不得写任何私有 ref 或恢复 URL |
| A 初始化中 | auth 变 B 后 A 响应到达 | 丢弃响应 | 不续发门店/账户/任务/更名请求 |
| A→B→A | 第一轮 A 响应到达 | 仍丢弃 | 不得按 id 相等恢复旧 query |
| 当前账号初始化 | 真实空列表/账户不存在 | 保持现有空态 | 不把正常空结果视为失败 |

## 5. 业务规则

### 5.1 输入规则

| 输入 | 类型/来源 | 规则 |
|---|---|---|
| 账号票据 | `AccountTicket`，`account-session.ts` | 只由 `capture()` 生成；不得手造 epoch。 |
| 初始化入口 | `initForAccount(ticket?)` 或等价内部签名 | 默认调用仍支持无参数；组件 watcher 需要把本轮 ticket 传入。 |
| 任务组织 id | 当前 ref 快照 | 保持既有 `activeOrgId` 读取和组织代次规则；本任务不改组织选择产品规则。 |
| URL query | 进入 watcher 时的 `entryQuery` 快照 | 只有当前 ticket 可恢复；不信任 query 作为账号身份。 |

### 5.2 校验规则

1. **RULE-84-01**：每个异步返回提交前 MUST 通过 `session.isCurrent(ticket)`。
2. **RULE-84-02**：票据失效 MUST 直接 return，不写 ref、不调用 `clearError()`、不发 notice、不调用后续 loader。
3. **RULE-84-03**：`refreshTasks` 必须在所有并发任务结果都返回后、`tasks.value = ...` 前验票。
4. **RULE-84-04**：正常当前账号结果为 `null`/空数组时，按既有 `useGrassland.run` 和空态语义处理，不因新增票据检查改变展示。

### 5.3 业务判断规则

```text
ticket = session.capture() 或父级传入的当前 ticket
await loadSomething()
if session.isCurrent(ticket) 为 false:
    return
写入当前域 ref 或发起明确属于同一 ticket 的后续调用
```

### 5.4 权限与业务不变量

| 主体 | 允许 | 禁止及结果 | 测试 |
|---|---|---|---|
| 当前已登录账号 | 读取自己有权限的组织/门店/钱包/任务/资金账户 | 不改变后端权限或资源范围 | TC-84-001 |
| 已切换到新账号的用户 | 启动新账号初始化 | 旧 ticket 不得写新账号状态或续发旧动作 | TC-84-002/003 |
| 匿名用户 | 保持既有匿名空态 | 不发账号私有初始化请求 | TC-84-004 |

不变量：同一旧 ticket 最多只能发出它已经进入的既有请求，不能因迟到回包新增后续请求；旧 ticket 不产生当前 UI 可见状态变化。
