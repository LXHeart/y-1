## 1. 实现结果

按 D97-04/05/06/07 落地双向协商退出：

1. **V59 迁移** `exit_request`（IF NOT EXISTS 全量）：partial unique `uq_exit_request_open(application_id) WHERE status='pending'`（V55/V56 惯例）+ 超时扫描索引 + role/status CHECK。
2. **数据访问** `EngagementExitRequestRepository`：insertPending（唯一冲突→empty→409）、respond（pending→confirmed/rejected，`respond_deadline_at > now()` 烧入 WHERE——超时失效与响应的竞态单边胜出）、cancelByInitiator（仅发起方 pending）、cancelPendingByApplication（终态先到收口）、expireOverdue（dispatcher 扫描）、listByApplication。
3. **领域状态机** `ApplicationLifecycleService`：
   - 发起（双方对等，reason 必填 5–500）：accepted + 非套餐推广 + 无开放争议（DisputeChecker，先走争议）+ 无开放申请 → pending，响应窗 `marketplace.engagement.exit-response-hours`（缺省 72h）；不暂停任何既有计时。
   - 确认（仅对方）：三段编排——①事务一抢 application 终态（`exitNegotiated`：withdrawn + `exit_kind=negotiated`，仅守卫 status='accepted'——观察期合作同样可协商终止；与超时终结/商家取消共用前置形成终态竞态单边胜出）+ 抢申请 confirmed + 名额回收；②资金腿（事务外幂等）：有确认里程碑 → `captureVerified(预留, 里程碑合计)` + `release` 余款（C96-02 settleCancelledEngagement 同构），无里程碑 → 零补偿全额释放（同开工前取消）；押金原路退推荐官；③事务二：里程碑金额回填（recordSettlementAmounts，引用行 id 可对账）+ outbox `EngagementExitedNegotiated`（确定性 eventId）。确认后资金腿失败的续传：请求已 confirmed 时重入直接续跑 ②③（幂等收敛）。
   - 拒绝/撤回：申请关闭，合作照常（`EngagementExitRejected`/`EngagementExitCancelled` 事件）。
   - 超时失效：`EngagementExitExpireDispatcher`（@Scheduled 扫描 → expired + `EngagementExitExpired` 事件；照 C96-01 dispatcher 范式）。
   - 列表：每行附 `settlementPreview`（computeSettlement 服务端算——按已确认里程碑 + 合同取消条款，前端不复算，§5.3）。
4. **终态先到钩子（D97-05）**：无责退出（`exitNoFault` 同事务）、商家取消（`resolveCancellationForAccepted` 分支后）、超时有责终结（`DeliveryLifecycleActivityImpl` 同事务）三处将残留 pending 置 cancelled。
5. **端点（§6）**：`POST .../exit` kind=negotiated（409 占位解除，返回 `{exitRequestId,status,respondDeadlineAt}`，201）；`POST .../exit-requests/{exitId}/confirm|reject`（仅对方——发起方 403、无关第三方 403）；`POST .../exit-requests/{exitId}/cancel`（仅发起方）；`GET .../exit-requests`（双方）。身份裁决 `resolveEngagementParty`：推荐官限本人报名、商家限本组织任务（requireScope manager）。Edge：`/api/tasks` 前缀路由天然覆盖（fail-closed 语义不变），`JavaRouteManifestGateTest` 增三行显式断言。
6. **动作契约（§6）**：`EngagementActionContract` 新增 `exit_pending_confirm`（对方视角，dueAt=响应窗倒计时）与 `exit_await_response`（发起方视角，blockedReason=`exit_request_open` 互斥标记）；位于 settled/ended/held 之后、observation 之前（开放申请是进行中合作的最高优先级待办）。推荐官「我的任务」分组按 nextActionLabel 服务端标签驱动，新组自动出现。
7. **前端**：`EngagementExitActions` 组件（双面板共用）：进行中合作显示「协商退出」发起入口（reason 弹窗，GlModal persistent）；对方视角「确认退出/拒绝」——确认弹窗展示服务端预演金额（脚本/交付/发布/合计，≤ 已预留赏金）与条款说明；发起方视角「撤回退出申请」。接入 `RecommenderEngagementsPanel`（推荐官我的任务）与 `TaskApplicantsPanel`（商家报名列表，非套餐推广行）。

## 5. 资金/事件证据

- **结算引用里程碑行（§4.3）**：确认路径 `computeSettlement(app, task)` → 每类取最高已确认版本行、金额 = floor(预留×bps/10000)、总额夹到预留内；`recordSettlementAmounts` 一次性回填 `engagement_milestone.amount_cents`（IT 断言 300）；事件 payload 引用 milestoneIds 与金额。
- **幂等/单边胜出**：申请响应 `respond` 条件 UPDATE（pending + 响应窗内）；终态 `exitNegotiated` 条件 UPDATE（status='accepted'）——两步同事务，任一 0 行整体回滚或收口；资金腿幂等键沿用 finance escrow 既有（capture/release/freebieRefund）；outbox 事件确定性 eventId（`type:exitId`）。
- **事件族**：`EngagementExitRequested` / `EngagementExitedNegotiated`（含 settlement）/ `EngagementExitRejected` / `EngagementExitCancelled` / `EngagementExitExpired`。
- **声誉口径（D97-06）**：终态 `withdrawn + exit_kind=negotiated` 同无责退出——不进完成率/失败分母（C96-01 已有的聚合排除语义，无需改口径）。

## 6. 偏差

0. **白名单邻接说明**：为落地 D97-05 终态，`TaskApplicationRepository.exitNegotiated`（application 终态 SQL 的唯一归属，与 exitNoFault/markDeliveryTimedOut 同族）与前端 API 层 `useGrasslandMarketplace.ts`（四个新端点的客户端方法）虽未在 §9.1 逐字列出，但属任务书精神的必然落点（配套数据访问与前端接线）；新增 `EngagementExitRequestRepository`/`EngagementExitExpireDispatcher` 为 V59 配套。已在此如实登记，请主程确认。
1. **争议侧互斥的硬闸（§13 记录）**：D97-07 后半句「已有开放协商申请时不可发起争议」的 DB 级守卫须改 `DisputeAuthorizationController`（trust 开争议前的授权端点）——该文件不在 §9.1 白名单。本卡已落地的互斥：协商发起侧查开放争议（409 先走争议）+ 动作契约 `blockedReason=exit_request_open`（前端互斥提示）；争议入口的 marketplace 侧硬闸留待主程扩白名单后补（3 行守卫）。
2. **confirm 的续传语义**：确认成功但资金腿失败时，重调 confirm 对已 confirmed 请求续跑资金腿（幂等）而非 409；拒绝路径对已处理请求 409——不对称是收敛设计（钱侧必须可重试）。
3. `resolveEngagementParty` 商家侧用 requireScope(manager)（组织管理层均可发起/响应），较 `DisputeAuthorizationController` 的 owner-only 更宽，与既有 merchant 端点惯例一致（§5.1「商家限本组织任务」）。
4. IT 造数：商家视角结算契约经 `/api/applications/{id}/settlement`（C96-06 契约视图）；里程碑行 SQL 直插（confirmed 双签终局态），结算金额断言经 finance mock verify + DB 行回填双重锁定。
