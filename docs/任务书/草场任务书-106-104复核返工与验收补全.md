## 3. 已定技术决策（DECISION）

### D01：在任何破坏性步骤之前拦截冲突

复用 `conflictsByKind`、manifest `needs_review`、现有账号生命周期锁及事务，不新增迁移。新 manifest 与未完成旧 manifest 在执行首批、续跑批次及对象清理之前，先在现有生命周期串行化边界内核对归属冲突。发现冲突则：manifest=needs_review，erased=false，verifiedAt 不新增，账号保持 erasing，当前调用不执行后续行删除、物删或配额释放。

门闸必须同时覆盖 `process`、`processPending`、直接 `eraseNextBatch`，不能只在 Controller、第一次 plan 或最后 verify 防护。冲突时 `eraseNextBatch` 返回无可继续推进的 false，process/worker 不得把 false 当成允许物删；回执仍为 needs_review。verify 对 needs_review 的保留不能被 allSucceeded/residue=0 覆盖。已有对象清理入口不能绕过此条件。

采用保守的“本 manifest 本次暂停全部后续破坏性动作”，不只保留冲突子行而删除证明其归属的父链。冲突解除后显式重试应重新检查并按原步骤/租约幂等续跑，不强制篡改步骤为 succeeded；worker 不循环空转 needs_review。

继续保留组织/共享优先的既定规则：存在可证明组织保护链的记录不因额外个人链而误认个人待删；多条个人父链账号冲突才阻断。其他未知 kind 仍独立阻断。补测所有当前 `conflictsByKind` 家族，不依赖第二种冲突兜底。

此前已经物删的父链不能重建；本书不对无法证明的历史清单承诺恢复。测试旧清单续跑时必须从仍有可核验父链的未完成状态开始。

### D02：缓存会话是显式授权，不由任意登记切换

对外签名不变。模块按账号保存必要的撤销信息，显式激活实例具有身份；释放回调只能释放自己创建的实例，不能撤销同账号后续新激活。只允许从未显式建立/撤销、且未被当前另一账号会话占用的初始兼容路径建立默认会话；已 clear、release、远端失效或被换号撤销的账号，迟到 register 一律回收写入，不覆盖当前账号或其 onInvalidate。

收到通知时读取当前墓碑，与当前显式激活捕获的 generation 比较；通知 operationId 仅用于去重，不用作覆盖墓碑。墓碑已前进且当前会话仍持旧代次才失效一次；当前会话已在当前墓碑重新激活时，晚到通知只清 stale 记录，不能使其 inactive 或调用失效回调。接收模式 clear 不再无条件废弃当前会话。

墓碑写失败但收到新的 BC 清理消息时，接收页仍须尽力清理并撤销消息之前的会话；该降级不能伪装成全页持久代次成功。无法持久区分的通知标记为降级，采取保守禁止旧写策略；正常墓碑乱序与墓碑失败分别测试，不能用前者放行后者。

`readAccountKey` 必须同时核验账号会话仍有效、捕获代次与墓碑一致、元数据 owner/area/key 一致；不得通过读取绕开已失效写资格。storage 不可读视为未知而不是初始空代次；返回 null，内存业务继续。保留 v1 无墓碑导入、两种已知旧键格式与非本人/主题保护。

### D03：存储失败不丢清理债务

`clearAccountCache` 的 number 只统计当前页此前存在且已确认物理删除的内容键，不包含元数据。内容删除失败时不计数、不删除其元数据；维护按账号/area/key 的内存待重试集合，元数据写失败且内容也删失败时同样加入。收尾扫描不能把失败键的最后线索扫掉。

墓碑写成功才用新代次过滤；写失败时主动清理必须强制遍历本页已知键，不用旧墓碑保护本次待清值。仍广播操作通知并撤销旧资格；不宣称未收到通知的其他页已清干净。元数据删除失败但内容已删可计数一次，后续清扫元数据不重复计数。

下次 clear / 显式激活 / 恢复读取重试已知残留；失败重试记录按代次核对，不能删除重新激活后的合法新值。禁用不可可靠登记的持久缓存但保持内存功能；所有 Storage 获取、get/set/remove/key/length 异常均不得使登出或换号抛出。存储完全不可访问且标签页随后关闭时不能保证跨重启重试，必须记录这一真实限制，不能宣称物删成功。

每次 register 只确保监听存在，不增加永不释放的引用计数；监听归实际激活实例，release/dispose 后无孤儿通道或重复回调。不能恢复 500 条截断。

### D04：登记版本与机器引用严格解析

两登记文件顶层 `version` 必须为数值 2；缺失、1、字符串或未知版本均失败，不从 entry 是否含某字段推断版本。resource 必须有 derivedRefs 数组（无依赖允许 []）；event 必须有非空 producerRefs/consumerRefs。条目 null、错误类型、缺字段都返回可定位违规，不吞异常当空簿。

consumerRefs.tc 与条目顶层 tc 使用同一真实仓库内测试文件校验：非空、常规文件、真实路径位于仓库内、测试路径/后缀符合现有布局；越界（含绝对路径和符号链接逃逸）、目录、生产文件均拒绝。source/handler 路径同样限制仓库内真实源码。

复用 JDK25 编译器树扫描器，增加方法声明清单，不使用 `String.includes(methodName)` 或注释命中作为符号存在证据。符号为实际声明类名与 `methodSignature` 参数类型序列，保留现有 producer symbol 表示法；校验路径+属主+方法名+参数。识别嵌套类型，重载不能靠同名方法通过，注释/字符串不算声明。handler 的 path/symbol 同样查声明。

只扩展 inventory 返回的声明集合并由 TS 校验器消费，不更改旧事件生产识别/摘要算法，避免无关 baseline 重写。现有登记若包含简写错误，按实际声明修正机器引用并逐条记录；不得用 note 替换原来可验证的 table/handler 依赖。required 集合及历史豁免保持不变。

### D05：轮询发起与续排共用活动门闸

refresh 发起前要求非 disposed、非 hidden、非 deactivated、target 非空、有有效非匿名账号票据（现有无 Pinia 单测兼容），不满足则不请求、不置 loading、不排 timer。每次新 refresh 启动先清旧 timer；同目标在途仍只共享一个请求。

成功 pending/processing/retry_wait 才在完成后 5000ms 续排；失败/空结果/终态撤销已排 timer，保留错误前资金快照并停止自动查询。手动刷新或重新活动后允许恢复。abort 不显示业务错误。隐藏/失活期间 target 可更新，但恢复只查询最新目标一次；当前请求晚回不写状态、不复活 timer。

### D06：真实浏览器验证分两条可重复路径

1. 新增测试专用 Vite harness（§9 W06），直接 import 当前生产 cache 模块、账号 store、真实 funds composable 和 Vue KeepAlive；同源两 Page 有独立 sessionStorage、共享 localStorage、真实 BC/storage 事件。harness 只能组装/暴露测试按钮与状态，不复制缓存/轮询算法，不把 helper 注入生产入口。
2. 既有完整隔离栈运行修正后的 task104 两 spec，证明真实登录/路由/资金组件消费及治理台 HTTP 错误反馈。harness 的 fetch 经实际浏览器网络发出，以 Playwright route 延迟/失败控制；既有应用必须断言实际组件/请求，不能只看首页 body 非空。
