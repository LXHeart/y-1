# 后端职责拆分与恢复回归

日期：2026-10-06。来源：用户要求继续按业务职责拆后端大类，先明确 Intelligence 模块边界，补充状态转换、响应乱序和失败恢复测试。

## 1. 范围

- TaskController 从 1,419 行拆为命令/查询 HTTP 入口，以及草稿、发布、修订、取消、推广和读侧服务。
- Intelligence 以版本化包归属、无环允许方向和精确存量例外确立边界；本轮不改变其生产业务实现或部署单元。
- 修复取消部分结算时，报名终态、里程碑金额和 outbox 缺少共同事务的问题。
- 工作区已有合同规则统一、数字人下线及其他批次改动全部保留。

## 2. 验收标准

1. 原有任务 HTTP 路由、鉴权、响应结构、历史快照和乐观锁行为保持兼容，路由零重复。
2. 控制器不直接依赖持久层、资金客户端和事务；命令服务不反向依赖控制器/查询服务。
3. 取消事件失败时，任务可保持 cancelled，但未提交结算的报名必须仍为 accepted；重试补齐金额与唯一事件。
4. 修订重审事件失败时，任务版本、历史版本、报名同意状态共同回滚；重试成功，旧请求不可回退状态。
5. Hypit 仅在构建结束且输出就绪时成功；旧 attempt/旧租约响应不覆盖新观察，失败后退避并恢复原 build。
6. Intelligence 所有生产包有且仅有一个归属；新越界依赖失败，已修复例外必须移除。
