## 1. 目标与范围

### 1.1 目标

用户可以在同一个视频创作项目中恢复布局、编辑分镜、比较并采用候选、制作和导出成片；随后可以关联素材与交付物、把自有素材真正用于成片、派生独立方案，并让 AI 对明确选中的内容提出和应用修改。

## 3. 技术决策

| DECISION | 唯一方案与原因 |
|---|---|
| D01 复用架构 | Vue/TypeScript + intelligence Java；前端、Java 均不增加第三方依赖 |
| D02 选片 | 普通请求原子合并局部选择；useRecommended 明确替换整份推荐选择。返回完整选择与单调版本，客户端只叠加未确认操作 |
| D03 编辑并发 | storyboard 增 edit_version；所有相关编辑与提交共享分镜行锁。新客户端传期望版本；旧请求兼容但同样提升版本 |
| D04 布局 | 首期 `workspace.inputs.videoCanvas`，不保存媒体/历史/候选副本；多媒体阶段迁入独立 canvas 文档，按修订号保存 |
| D05 项目关系 | 一个分镜唯一关联一个视频草稿；旧 storyboard 深链由服务端幂等补关联，来源从可信分镜/快照恢复 |
| D06 运行 | 快速/专业共享账号级 task session；画布布局和连线变化不创建 ai_run，不触发生成 |
| D07 媒体来源 | 每镜 generated 或 own-media；自有图像/视频经既有私有媒体服务读取，音轨规则显式选择 |
| D08 价格 | 保持成片一口价。全自有素材强制采用现有 slideshow-v1 本地制作价；混合素材含生成镜头时沿用现有模式解析与整片单秒价；不新增折扣/分镜计价，不增加单独素材费用 |
| D09 独立方案 | 每次派生新草稿、新分镜和新镜头；共享媒体引用，复制必要输入，不复制运行、候选选择或已交付结果 |
| D10 AI | 有界上下文 → 结构化计划 → 版本校验后应用；媒体提交通过既有生成动作。无浏览器直连、任意脚本或任意 HTTP 工具 |
| D11 编排 | 业务进现有 worker/service；Temporal activity 保持薄层，保留现有 workflow 方法/事件。新媒体来源在 activity 调用的域服务内处理 |
| D12 交付 | 交付草稿版本与成片 task/recomposeSeq 必须一致。改封面/配文不重新制作视频；导出失败只重试导出 |

这组目标决策使后续执行者无需选择“局部或全量选片”“同一或独立分镜”“直接或后台生成”等实现分支。

## 4. 目标流程与状态

1. 从最近项目、快速模式或旧深链进入，校验账号及项目关联，恢复来源、草稿、分镜、制作任务和布局。
2. 编辑镜头时只记录真实输入；切镜保存当前编辑，保存失败停留原镜头并保留内容。切模式先 flush，失败保留当前页面。
3. 在画布预览候选；选择立即以“保存中”回显，服务端确认后成为已保存选择。存在未确认选择时禁用合成。
4. 生成栏显示本次任务、冻结价格和提交状态；成功受理不等于生成完成。后台继续工作，返回时恢复同一任务。
5. 素材栏可添加引用、查看失效原因；“制作来源”选择决定实际取用媒体，普通参考连线不自动改变制作。
6. 独立方案可切换比较；AI 针对当前明确选择给出差异计划。用户采用计划后复查受影响节点，再使用已有生成/合成动作。

| 状态域 | 完整值集与行为 |
|---|---|
| 页面读取 | idle → loading → ready/empty/error；刷新失败保留上次内容及错误；无权限清除该资源内容 |
| 保存 | 沿用 idle/pending/saving/saved/conflict/error；未来 schema 为 readonly。冲突显式载入远端，不能自动覆盖本地稿 |
| 分镜 | 既有 draft/committed；committed 仅允许查看、选片及既有任务动作，修改内容必须派生方案 |
| 制作任务 | 保留 queued/generating/voicing/composing/succeeded/failed/cancelled；“待挑选”仅是界面派生状态，不新增数据库 phase |
| 候选 | 保留 queued/submitted/processing/succeeded/failed/cancelled；是否可采用以服务端 selectable 为准 |
| AI 计划 | preparing → ready/clarify/failed；ready → applied/expired；失败不执行部分动作，重复 apply 返回同一结果 |

所有异步读取使用账号 epoch、draftId、storyboardId、taskId 和请求序号识别当前上下文。切换账号清空会话/撤销栈/未发请求；旧响应不落入新账号。页面失活释放消费者；最后一个消费者释放时停止 SSE/轮询，不取消服务端任务。

## 5. 业务规则与安全不变量

| 规则 | 确定行为 |
|---|---|
| R01 身份 | 账号由既有会话/内部断言解析；跨账号资源统一 404，匿名 401。前端传 owner、organization、store 不能形成授权 |
| R02 任务来源 | 新建关联、派生方案和 AI 计划均复用 contextSnapshotId 绑定；不把任务来源降级成 independent 绕开约束 |
| R03 先校验 | 参数、版本、素材归属/状态、制作能力在生成或预留前校验；失败不产生 provider 调用或新的扣费 |
| R04 版本 | draft.version、storyboard.editVersion、task.selectionVersion、canvas.revision 各管自己的实体，不互相代替 |
| R05 精度 | 计费整数分沿用 money 工具；裁剪为整数毫秒；日期为服务端 UTC ISO-8601；UI 按既有时区显示 |
| R06 媒体引用 | mediaId/assetId 稳定保存，URL 只在访问时取；新增不可用引用拒绝，历史失效引用可保留位置并显示不可用，不可生成/导出 |
| R07 撤销 | 布局最多 50 步/2 MiB，拖动一次一条；不把远端运行、退款和媒体删除放入本地撤销。重新加载/换账号清空栈 |
| R08 幂等 | 创建 workspace、variant、AI plan 先查账号+操作键，再校验重放参数摘要；同键异参 409。应用 AI plan 以 planId 唯一 |
| R09 终态 | 成片后重抽沿用 reroll，非终态沿用 regenerate；自有素材镜头不能随机重抽，只能在新方案中改来源 |
| R10 价格表 | 缺 slideshow-v1 价格配置返回 503；不填 0、不临时创建价目。混合一口价在提交前明确展示，不承诺按复用镜头数量折扣 |
| R11 输入文本 | 新增标题 trim 后 1～60 Unicode code points；AI 指令 1～2000；备注最多 1000。HTML 作为纯文本或经既有 sanitizer 渲染 |
| R12 依赖图 | 顺序/派生线由业务数据生成；用户参考线仅表示参考。禁止自环、重复线及引用环，最多 200 节点/500 条用户线 |

布局数值必须有限：scale 为 0.25～2.5，panX/panY、节点 x/y 为 -100000～100000；客户端钳制交互，服务端拒绝 NaN、Infinity、字符串冒充数字及越界值。首期最多 30 个镜头位置；schemaVersion 缺省视为 1，明确未知版本只读而非强写。

| 编号 | 方法/路径 | 请求与响应增量 | 原子性与客户端行为 |

API-01：selections 为 1～30 项，shotId 不重复且属于该 task 的分镜，takeId 与 shotId 匹配且 selectable。`useRecommended=true` 时 selections 必须缺省或为空；显式 false 等同普通选择。先在事务内锁任务行，再验证当前 phase 和候选，执行 `COALESCE(selection,'{}') || patch` 并提升 selection_version；推荐分支替换整个集合。允许写入的 phase 是 queued/generating/voicing；composing 和终态返回 409。只有提交成功才发送 workflow 信号，信号携带完整选择。

同一镜头的点击在客户端串行发送，期间允许改变期望选择，但每镜最多一个请求在途，完成后只发送最新尚未保存值。响应或轮询的 selectionVersion 小于已接收版本时忽略；仅未确认的本地操作可以覆盖读取结果。请求失败撤回该次乐观覆盖并保留“保存失败/重试”，不把旧缓存永久盖在服务端上。

API-03/04：本任务统一可观察行为——显式修改 visual 时将生成用 prompt 同步为新 visual；只修改旁白/时长/运镜不覆盖 prompt。新版本面板解释“画面描述用于生成”，没有另一套隐含提示词。一个原子编辑批次只提升一次 editVersion，无实际变化不提升。创建制作任务对分镜的冻结与这些写入使用同一分镜行锁；网络/模型/积分调用不得放在持有数据库锁的事务内，沿用已存在的预留失败与补偿流程。

兼容边界：旧单镜PUT/增镜/分组接口未携带expectedEditVersion时，保留原来的null/空白归一、时长钳制和缺省字段行为；新增批量端点及带版本的新客户端执行§6.1严格校验。visual→prompt同步是本任务明确改变的生成正确性行为，旧接口显式修改visual也适用，必须更新对应回归断言，不能说成行为零变化。纯读取不改变版本。

### 6.5 自有素材制作契约

- generated 是缺省来源；own-media 仅接受当前可读且已就绪的自有图片/视频 mediaId，或已有授权素材经现有服务产生的合法媒体引用。拒绝任意 URL、data URL、临时签名地址和文件系统路径。
- 图片 trimStartMs/trimEndMs 必须均为 null；audioMode 仅 narration/mute。按 plannedSeconds 展示，沿用现有图片成片渲染。
- 视频要求整数 `0 ≤ trimStartMs < trimEndMs ≤ 实测时长`，截取长度必须等于 plannedSeconds×1000。UI 默认从 0 开始截取该镜时长；源不足直接报错，不循环、不补假帧。边界校验使用 ffprobe 结果而非浏览器声称的时长。
- 单个制作来源文件不超过现有视频归档的200MiB上限；先查媒体元数据并复核实际读取大小，超限返回CANVAS_LIMIT_EXCEEDED。媒体读取/probe通过已有工作线程边界执行，不阻塞WebFlux事件循环。
- audioMode=source 保留选定视频区间原音，跳过该镜 TTS；素材没有音轨时拒绝该模式。narration 使用现有旁白/TTS 并静音原片；mute 保持静音并跳过 TTS。原音不冒充已转写字幕；该镜没有真实字幕时不编造 SRT。
- 尺寸沿用目标 resolution，保持比例并补边，30fps/H.264/AAC/48k stereo；使用现有 MediaProcessRunner 和工作目录。素材权限在保存来源、建任务和 worker 读取时均核对。
- own-media 镜头不请求视频生成 provider、不请求 AI 质检，不显示生成分数；可用性和技术规格检测继续做。一个确定片段显示“使用自有素材”，不伪装成多候选。
- 全自有素材走既有 slideshow-v1 一口价执行上下文，仍完成预留/结算/失败补偿；混合素材继承解析出的 video/slideshow 模式及整片价。UI 展示“成片制作费用”并说明是否仍有待生成镜头；不可承诺按镜头抵扣。
- 修改来源只允许 draft；已制作内容通过独立方案修改。成功后文件实际时长、音轨、采用片段和输出版本必须可验证。

每个计划只有一个顶层 action。edit 允许 1～12 个 update-shot/append-shot；更新只能命中明确选中的镜头，append 仅末尾追加并受 30 镜限制；不支持删除镜头、调整任意资产权限或执行脚本。variant 复用 API-11。prepare-generation 只准备已有动作：initial 的 shotId 为 null 且分镜为 draft；regenerate/reroll 必须指向一个生成来源镜头并满足既有阶段。模型不得决定价格、权限、素材可用性和成功状态。

计划保存后 30 分钟内可用。apply 先处理已应用重放，再校验归属、未过期、draft/edit/canvas 三版本和当前资源状态；edit 原子更新并只升一次 editVersion，variant 在同域事务中调用派生服务，prepare-generation 只返回准备结果。任一动作非法整批不写。模型返回未知工具、字段、ID 或错误类型直接失败，不“尽量执行”合法前半批。用户通过现有“生成/重抽”按钮启动媒体请求；apply 不调用媒体提供者。

```ts
export declare function useVideoTaskSession(taskId: Ref<string>): VideoTaskSession
```

空taskId不发请求；acquire同consumerId幂等，release未知ID无副作用；taskId改变先释放旧会话再绑定。上述写方法失败落taskError并保留已确认数据；不能仅吞掉异常再将按钮标成成功。账号epoch变化清除所有句柄；最后消费者release停止浏览器资源。分镜生成、图片上传、初始建任务仍由useVideoProduction/画布适配在明确用户动作中调用既有端点，服务端返回id后更新该引用。

### 7.2 事务规则

- 选片事务锁 task 行；读取当前阶段/候选可用性后原子更新选择及版本，返回完整选择。取消/compose 与它竞争同一行锁，不能“先校验后跨事务覆盖”。
- 编辑事务锁 storyboard 行，检查 expectedEditVersion/draft 状态，再更新镜头或来源并提升版本。删除镜头同步删除来源行、整理镜序、剔除 grouping 悬空引用；画布上的旧引用读取时标不可用，不伪造另一镜头。
- 创建制作任务先按 account+operationId 查询重放，再对新的创建执行分镜冻结与本地任务持久化；同一分镜已有初始任务时返回已有合法任务或 409，不能创建第二套共享 takes。保留既有 ai_run 预留、失败标记和补偿路径；本地事务与 finance 调用分开，不宣称跨服务原子事务。
- workspace 关联锁分镜与目标草稿，校验来源和版本，原子创建/关联；旧草稿需要写版本时沿用 appendVersion+save。允许独立项目 organizationId 为 null，任务快照按原关系保留。
- 画布 PUT 按 draft 归属和 revision 更新；expectedRevision=0 与 UNIQUE(draft_id) 保证首次创建并发只成功一个。草稿本身未改时不得提升 draft.version。
- variant 在一个 intelligence 事务内锁根方案、校验数量/源版本，以一致快照复制草稿、分镜、镜头、素材来源、必要 grouping 和画布引用映射，建立关联及操作记录；不调用模型、finance 或对象存储写入。不复制 takes、selection、runIds、resultRefs、delivery 媒体与旧 productionTaskId。
- AI apply 锁计划行，重放已存 apply_result；未应用时按 draft→storyboard→canvas 固定顺序锁定/校验全部版本，执行唯一顶层动作并保存 apply_result/status。任何失败整体回滚，无部分更新。
- 编辑/关联/派生也按 draft→storyboard→canvas 顺序取需要的锁，源/根涉及多行时按 UUID 字典序锁；避免死锁。仅选片锁 task，不在持有 task 锁时再向上取 draft 锁。

### 7.3 布局升级与恢复

首期布局保存到 inputs.videoCanvas；schemaVersion 仍为 1，整体 workspace 仍 ≤65536 UTF-8 字节，结果资产/运行 ID 上限各 20。不能把布局误嵌进每次重建的 inputs.video，不能将候选预览地址存入草稿。

旧草稿无 videoCanvas：按服务端镜序确定性布局。旧数据无来源行：generated。无 variant 行：根方案。未知 canvas schema：只读展示可安全理解的基础信息，保存按钮禁用。恢复不会自动补生成/合成请求。

### 8.2 输入和交互

- 节点内 video、button、input、textarea、select 和链接都不能启动拖拽；拖拽手柄独立。空白画布左键/中键平移，滚轮按既有机制缩放；pointercancel/lostpointercapture 终止手势且不提交半次拖拽。

- Ctrl/Cmd+Z 与重做只处理当前布局栈；删除键不删除业务镜头。镜头删除继续通过明确带对象的既有按钮，尊重分镜 draft 状态。

- 改配文/标题/封面只更新交付字段。视频依赖变化需要重新制作时保留旧成品并明确标注来源版本，不静默覆盖已有可下载结果。

字段有 label，错误用 aria-describedby；保存、生成、失败使用 live region；选中节点有 aria-selected/可读名称，焦点可见。抽屉/模态复用焦点限制、Escape 和关闭后焦点返回。视频只在用户播放时启动，失焦/离屏暂停，尊重减少动态效果。
