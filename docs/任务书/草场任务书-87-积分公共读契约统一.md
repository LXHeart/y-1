## 1. 目标与范围

### 1.1 一句话目标

积分业务域的四个公共 HTTP 端点统一为 `{success, data}` 信封（`/api/credits/balance`、`/api/credits/history` 从裸对象改为信封，与既有 `/api/credits/packages`、`/api/credits/purchase-orders` 对齐），前端积分 store 改用严格信封的 `request()`，新增 `requestRaw<T>()` 作为唯一受认可的裸 JSON 读取口，并用「IT 字段级断言 + 前端 fixture 同形 + 真实栈 e2e」三层契约测试锁死前后端形态一致。

### 1.2 背景与价值

同一积分业务域并存两种响应协议：购买侧（packages/purchase-orders）走 `{success,data}`，读取侧（balance/history）走裸对象，前端被迫用 `fetchApi()` 手写解析；`src/App.test.ts:253` 的 mock 已经用了信封而真实后端返回裸对象（形态漂移实锤），后续维护者极易误判。统一后：前端全部积分消费走 `request()` 一条路；「裸 JSON 必须走 requestRaw」成为成文规则；三层契约测试让 mock 与真实接口形态不一致在 CI 内即被拦截。受益方：积分功能的前后端维护者与测试作者。本书同时清偿 #80 遗留的 C80-01/C80-02（基线刷新后重出）。

### 2.5 当前行为（FACT，2026-09-06 核验）

1. 后端：`balance()` 直接 `.map(CreditsController::balanceBody)` 返回裸对象 `{"balance":n,"totalEarned":n,"totalSpent":n}`；`history()` 返回 `{"history":[…]}`（每条 `id/amount/balanceAfter/type/feature/note/createdAt`，`createdAt` 有 null 分支；上限 50，Repository 按 `created_at DESC`，同秒无二级排序保证）；未断言 → `FinanceCallerResolver` 抛 `FinanceException(401,"未登录")` → advice 包 `{"success":false,"error":"未登录"}`。
2. 前端：`credits.ts` 用 `fetchApi()` 手写 `response.json() as CreditBalance` / `as {history:…}`；`loadBalanceOnce` 内 401 → `balance=null` 静默返回，其余失败 → `error='获取积分失败'`；`loadHistory` 任何非 2xx/异常 → 返回 `[]`；全程票据守卫（`session.capture()`/两次 `isCurrent` 检查，含 `json()` await 之后）；`pendingBalance` 并发去重（同 owner 并发 `loadBalance` 只发一次）。
3. 同域购买侧：`useCreditsPackages.ts` 已用 `request<T>()` 消费 `/api/credits/packages`、`/api/credits/purchase-orders`（信封）。
4. 测试现状：`credits.test.ts` 与 `AiAppLayout.test.ts:162-177` 的 fixture 是裸形态（与后端一致）；`App.test.ts:253` 的 mock 是信封（与后端不一致——漂移实锤，该用例未断言余额值故未爆雷）。
5. `CreditsService.balance()` 对未建户账号 `defaultIfEmpty(new CreditsAccount(accountId,0,0,0))` 返回全 0 且**不建行**（纯读）。
6. 徽标渲染：`creditBalance===null` 时 `creditsError ? '获取失败' : '…'`；成功时 `` `${currentBalance} 次` ``。

### 决策记录

#### D-01：新增 `requestRaw<T>()` 作为唯一裸 JSON 读取口（继承 #80 D80-01，用户已确认）

- 决策：在 `grassland-http.ts` 导出 `requestRaw<T>(url, init?, options?)`——运输与非 2xx 语义复用 `fetchApi`/`readError`（非 2xx 抛 `GrasslandHttpError` 保留状态码），2xx 解 JSON **原样返回不判 `success`**，2xx 坏 JSON（含 204 空体）抛 `GrasslandHttpError(status, fallbackError || '响应格式错误')`；JSDoc 写明「非信封端点必须走此口，禁止手写 fetchApi+json 判断形态；SSE/流/预签名上传不适用」。本书不为它迁移任何既有调用方（它当前无消费方，是前瞻规则落地的基建，由协议测试覆盖）。
- 原因：把「禁止调用方自行判断响应形态」从口头约定变成有唯一出口的成文路径。
- 放弃方案：让 `request()` 自动嗅探信封/裸（拒绝——弱化严格契约，正是本次要消灭的歧义）；不建 helper 等下一个裸端点出现再建（拒绝——丢失 #80 已批准决策）。
- 允许执行模型修改：否

#### D-02：两公共读改 `{success:true,data}` 信封，字段/单位/排序/上限零变化（继承 #80 D80-02，用户已确认）

- 决策：`balance()` → `success(balanceBody(acct))`；`history()` → `success(Map.of("history", …))`（复用既有静态 `success(Object)`，不双层 data）；前端 store 改 `request<CreditBalance>` / `request<CreditHistory>`。
- 原因：积分域单协议；购买侧已信封，读侧对齐。
- 放弃方案：购买侧改裸（倒退）；双格式响应窗口（见 D-03）。
- 允许执行模型修改：否

#### D-03：单栈单次切换，无兼容窗口（闭合 #80 B80-01 的遗留参数）

- 决策：前后端改动在同一交付批次落地、同一 Compose 栈同批重建部署（FACT：`docker-compose.yml` 的 `frontend`（nginx 静态镜像）与 `finance-service` 同栈）。不实现双格式、版本嗅探或内容协商。部署后未刷新的旧标签页：余额徽标显示 `0`、`loadHistory` 返回 `[]`（旧 JS 裸解析新信封的既定降级——无报错弹窗、无任何写副作用、刷新自愈）；反向残局（新前端+旧后端）显示「获取失败」。回滚 = 同批回退前后端到上一镜像（回到裸协议一致态）。

- 允许执行模型修改：否

#### D-04：契约用「IT 字段级断言 + 前端 fixture 同形 + 真实栈 e2e」三层锁定

## 4. 目标行为

行为型任务。用户可见交互零变化（徽标三态、文案、时序不变）；变化全部在 wire 契约与解析层。

### 4.1 用户流程

1. 用户进入 AI 创作中心（`ai.html`）并登录。
2. accountId watch 触发 `loadCreditBalance()`（每账号一次）。
3. store 经 `request<CreditBalance>` 请求 `GET /api/credits/balance`（携带会话 Cookie 与票据 signal）。
4. Edge 校验会话并签发用户断言；finance `resolve()` 得 accountId（不信任任何请求体/参数）。
5. 成功：200 `{"success":true,"data":{…}}` → `request` 解包 → 徽标显示 `` `${balance} 次` ``。
6. 失败：401 → `balance=null` 徽标「…」（无错误文案）；500/断网/格式错误 → 「获取积分失败」徽标「获取失败」。

### 4.2 行为变化表

| 场景 | 当前行为 | 目标行为 |
|---|---|---|
| 正常（登录、有账户） | 裸 JSON → 手写 json() → 徽标 `N 次` | 信封 → `request()` 解包 → 徽标 `N 次`（**渲染结果不变**） |
| 未登录/会话过期 | Edge 401 → `balance=null`，「…」，无文案 | 同左（401 分支语义逐字保持） |
| 无权限 | 不存在此维度（accountId 只取自断言）；伪造断言 401 | 同左 |
| 数据为空（未建户） | 裸 `{0,0,0}` → 徽标 `0 次` | 信封 `data:{0,0,0}` → 徽标 `0 次`；history 空数组同形 |
| 请求失败（500/断网） | 「获取积分失败」/徽标「获取失败」 | 同左 |
| 响应格式异常（200 裸形态=旧后端残局） | 裸解析成功但值为 undefined → 显示 `0`（静默错误） | `request` 抛格式错误 → 「获取积分失败」（**新护栏：拒绝裸协议**） |
| 重复提交/并发 | 同 owner 并发 `loadBalance` 只发一次（pendingBalance） | 同左（去重机制不动） |
| 账号切换/迟到响应 | 票据守卫丢弃旧账号结果（含 json() 解析期） | 同左（守卫在 `request` await 之后同样生效） |
| 刷新/离开 | 每账号重拉一次；离开不发新请求 | 同左 |

### 4.3 状态定义（积分徽标，既有状态保持）

| 状态 | 进入条件 | 可执行操作 | 展示内容 | 离开条件 |
|---|---|---|---|---|
| `null`（未加载） | 初始/账号切换同步清空/401 | 点击徽标开积分弹窗 | `…` | 加载完成 |
| `loaded` | 请求成功 | 同上 | `` `${balance} 次` ``（0 也显示） | 账号切换 |
| `error` | 非 401 失败/格式错误 | 同上（弹窗内可重试购买流，徽标本身不自动重试） | `获取失败` | 账号切换 |

history 无 UI 状态（`loadHistory` 返回值直接给调用方，失败 `[]`）。

### 4.4 状态迁移规则

```text
null  -> loaded：request<CreditBalance> 成功且票据 isCurrent
null  -> null：401（静默，无 error 文案）
null  -> error：非 401 异常（网络/5xx/格式错误）且票据 isCurrent
任意态 -> null：账号 watch 同步 resetForAccount（不发网络，清 pendingBalance）
loaded/error -> 丢弃：await 返回时票据已非 current（含 request 内部 json() 解析期换号）
```

并发乱序：`pendingBalance` 保证同 owner 单飞；旧账号迟到结果（成功/失败/finally）一律静默丢弃。刷新恢复：不持久化，重新每账号拉一次。全部只在内存保存。

### 6.3 成功响应（EXAMPLE 值为合成数据）

### 6.5 错误处理原则

- MUST NOT 把服务端原始错误堆栈展示给用户。
- 未知错误统一按「获取积分失败」处理（store 现有 fallback 文案保持）。
- 请求失败后是否允许重试：用户显式操作（刷新/重进）可重试；无自动重试。
- 请求进行中重复触发：`pendingBalance` 单飞（既有机制，等价于按钮禁用语义）。
- 请求进行中允许离开/切换账号：票据守卫静默丢弃（既有机制）。

```ts
export async function request<T>(
  url: string,
  init: RequestInit = {},
  options: RequestOptions = {},
): Promise<T> {
  const response = await fetchApi(url, init)
  if (!response.ok) {
    throw new GrasslandHttpError(
      response.status,
      await readError(response, `请求失败（${response.status}）`),
    )
  }
  // 刻意用 json()+catch 而非 text() 再 parse：与既有测试的 fetch mock（仅提供 json()）兼容，
  // 同时对非 JSON 成功体（网关错误页/空 202）容错为格式错误，不抛 SyntaxError。
  let body: GrasslandResponse<T> | null
  try {
    body = await response.json() as GrasslandResponse<T>
  } catch {
    body = null
  }
  if (!body || typeof body.success !== 'boolean') {
    throw new GrasslandHttpError(response.status, options.fallbackError || '响应格式错误')
  }
  if (!body.success) {
    throw new Error(body.error || options.fallbackError || '请求失败')
  }
  return body.data as T
}

export async function fetchApi(url: string, init: RequestInit = {}): Promise<Response> {
  return fetch(url, {
    credentials: 'include',
    ...init,
    headers: shouldDefaultJsonContentType(init.body)
      ? { 'Content-Type': 'application/json', ...(init.headers || {}) }
      : init.headers || {},
  })
```

```ts
  error.value = ''
  try {
```

```ts
async function loadBalanceOnce(ticket: AccountTicket): Promise<void> {
  loading.value = true
  error.value = ''
  try {
    const data = await request<CreditBalance>('/api/credits/balance', { signal: ticket.signal }, { fallbackError: '获取积分失败' })
    if (!session.isCurrent(ticket)) return
    balance.value = data
  } catch (cause) {
    if (!session.isCurrent(ticket)) return
    if (cause instanceof GrasslandHttpError && cause.status === 401) {
      balance.value = null // 401 不留旧余额，也不写错误文案
      return
    }
    balance.value = null
    error.value = '获取积分失败'
  } finally {
    if (session.isCurrent(ticket)) loading.value = false
  }
}

async function loadHistory(): Promise<CreditHistoryItem[]> {
  if (!ownerAccountId.value) return []
  const ticket = session.capture()
  try {
    const data = await request<CreditHistory>('/api/credits/history', { signal: ticket.signal })
    if (!session.isCurrent(ticket)) return []
    return data.history ?? []
  } catch {
    return []
  }
}
```
