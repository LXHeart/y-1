## 1. 目标与背景

**一句话目标**:知乎从「只会产独立文章」升级为「回答 / 文章双模式」——回答模式围绕「目标问题」生成首屏开头钩子→大纲→正文,文章模式保留现有五步流但 prompt 按知乎体全面重写;同时风格三选(标题套路/体裁/文风)向知乎开放,skill 库获得平台归属维度与 7 条知乎专属种子;商家任务表单可携带「目标问题」以派发回答形态任务。

**产品依据**(2026-08-31 调研,结论已拍板):
- 知乎推流优先级「想法 > 回答 > 文章」,回答挂在问题下继承问题页流量;文章吃搜索长尾。双轨都要。
- 知乎体 = 论证体系不是修辞:结论前置、三段配比、每句信息增量、角色感/利益相关、每 800 字一个可截图金句。
- 现状拧巴:`ArticlePrompts.ZHIHU` 三段自我定位全是「回答写手」,但产品流没有「问题」概念,实际产的是文章。
- `contracts/platform-format-rules.json` 的 zhihu 条目早已写「区分回答与文章两种格式」——本任务书就是把它实现掉。

### 3.2 platform 值陷阱(知乎无此坑,但别踩别的)
`zhihu` 是唯一值,不像 xiaohongshu 双平台共用(抖音也走 `xiaohongshu` ArticlePlatform 枚举)。**不要**在 `ArticlePrompts.Platform` 加新枚举值——双模式靠请求参数区分,不靠 platform 值。

### 3.3 humanize 叠加关系(勿动)
文风 skill 注入发生在 `ArticlePrompts` 业务 prompt 内;去AI味 skill 由执行环(`FrozenTextExecutionService`/免费流)最后注入且自带「最高优先级」句。两者天然叠加,回答模式无需任何 humanize 改动。

### 3.4 智能注入无 ObjectMapper bean
intelligence-service **没有 ObjectMapper bean**(注入即炸整个 Spring 上下文)。新代码需要 Jackson 一律自持 `new ObjectMapper()` 实例(照 `ArticleCreationContext.java:19` 姿态)。

### 3.5 迁移幂等铁律
所有新迁移一律 `ADD COLUMN IF NOT EXISTS` / 幂等 DDL,否则 `OutboxRepositoryIT`/`TaskLifecycleMigrationTest` 重放挂。**注意各服务独立 Flyway 历史表,版本号只跟本服务序列**:
- intelligence:下一版本 **V59**(V58 已被 #61 humanize 占用)
- marketplace:动手前 `ls marketplace-service/src/main/resources/db/migration/` 取最大号 +1

### 3.6 测试基建惯例
- 自建 WebTestClient **必须带 30s responseTimeout**(无门禁靠惯例)
- WireMock stub 的 JSON body 用 python json.dumps 生成再转 text block,手写转义必错
- 自备容器 IT 新表/新列双处补 DDL(共享表按 3.5)
- Jackson record:可选字段用包装类型;is 前缀无参方法会被序列化成属性(派生态加 @JsonIgnore)

### 3.7 链接解析判死实录(为什么 P2 是纯手输)
2026-08-31 实测:`curl`(带完整浏览器 UA/Referer/Accept-Language)、WebFetch、web_reader 三路抓取 `zhihu.com/question/{id}` 及 `api/v4/questions/{id}` **全部 403**。返回的是 650 字节 zse-ck JS 挑战壳页(要求浏览器执行 JS 算 cookie 重放)。绕过手段(逆向签名/无头浏览器农场/存用户知乎 cookie)全部否决。**执行期任何人不得 reintroduce 链接抓取**;questionId 只做本地正则提取。

要求:

### 4.2 风格种子扩充(7 条新种子 + 归属标注)

| category | code | name | promptContent |
|---|---|---|---|
| TITLE_FORMULA | question | 疑问型 | 标题是一个与读者真实相关的具体问题。要求:问题指向读者真实的困惑或决策,不用反问修辞堆砌;问题里包含读者会搜索的关键词。例:「为什么大厂都在弃用 Kubernetes?」 |
| TITLE_FORMULA | story | 故事型 | 公式:身份 + 时间跨度 + 反常见闻。要求:身份和时间建立可信度,后半句给出与身份预期相反的见闻制造信息差。例:「我在医院做护工 16 年,没见过一家子女抢着孝顺」 |
| TITLE_FORMULA | counter-intuitive | 反常识型 | 公式:A 却 B。要求:前后两端形成认知冲突,且后端必须是真的、正文能兑现;不写纯猎奇。例:「他只有小学文化,却比博士赚得多」 |
| GENRE | opinion | 观点评论文 | 议论文结构:开篇亮明观点 → 2-3 个论据分层论证 → 主动回应最强的反方观点 → 收束为可执行的判断。要求:观点必须鲜明,论证为主、叙事为辅;回应反方是必备环节,不回避。 |
| GENRE | explainer | 科普解释文 | 结构:类比开路 → 层层展开 → 边界说明。要求:先用生活类比建立直觉,再逐层加深引入准确概念,最后说明适用边界与例外;每个类比都要与被解释物在关键机制上同构。 |
| STYLE | zhihu-casual | 说人话风 | 像跟聪明的朋友讲事:短句为主,用口语连接词,允许「其实」「说白了」这类自然语气;专业名词第一次出现用一句话解释;每段只说清一件事;不用书面套话、排比与形容词堆叠。 |
| STYLE | analytical | 理性分析流 | 结论先行,论据分层;多用数字与对比,少用形容词;把因果链讲清楚——不止说「是什么」,还要说「为什么」;语气冷静克制,让证据说话。 |
