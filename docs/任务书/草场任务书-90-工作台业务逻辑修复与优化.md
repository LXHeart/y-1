## 4. 目标行为

### 4.1 主流程

1. 商家发布任务；关键修订进入审核。
2. 推荐官报名时保存任务版本和条款快照。
3. 接受前检查任务仍可招募、报名状态和 reconsent；名额 claim 与状态更新同事务。
4. 资金型接受走 Saga；取消或失败执行幂等补偿。
5. 套餐任务关闭招募不终止已接受推广；显式结束推广或 promotionEndsAt 才停止新归因。
6. 消费者下单时由服务端验证资格并保存佣金金额快照。
7. 履约确认后进入 T+N 结算，前端显示已确认和预计到账，后台异步更新。
8. 账号切换时旧响应不写状态、不报错、不续发。

### 4.2 状态

招募：draft、pending_review、published、closed、cancelled。
报名：pending、reconsent、reserving、accepted、refunded、rejected、withdrawn。
履约：awaiting_submission、submitted、verification_failed、resubmission_required、awaiting_confirmation、confirmed、disputed、completed。
资金：none、reserving、reserved、held、captured、released、refunding、refunded、reconciliation_required。

### 4.3 不变量

- cancelled 任务不得产生新的 accepted/reserving。
- 相同幂等键最多一条 reservation、一次 payout、一次结算事件。
- 仅允许的履约/争议终态动作能触发 capture/release。
- 旧 AccountTicket 结果不得写当前账号。
- 钱包余额、流水、订单/报名状态可通过业务 ID 对账。

## 5. 业务规则与权限

1. merchant 只能管理本人组织；recommender 只能访问本人报名、推广和收益。
2. accept 仅允许 task published、application pending、reconsent=false；任务关闭/取消返回 409。
3. 套餐归因要求 accepted 推广报名、推广未结束且买家不是推荐官本人；无资格降级自然流量。
4. 关键金额、押金、平台、门店、交付要求变化触发 reconsent；推荐官未重新确认不得扣款。
5. 分页 limit 默认 20、最大 50，返回 items、nextCursor、hasMore；本人过滤在 SQL LIMIT 前。
6. 金额单位 cents，时间 UTC ISO-8601，字符串 trim 后校验，非法枚举 400。

| 角色 | 允许 | 禁止及结果 |
|---|---|---|
| 商家 | 本组织任务、报名、履约处理 | 直调资金终态，403 |
| 推荐官 | 报名、撤销 pending、履约、查看本人收益 | 跨账号/组织访问，403/404 |
| marketplace 服务 | 受控 reserve/release/capture | 伪造金额/收款人，409 |
| trust 服务 | 争议终局 reverse/reconcile | 越权改报名，403 |
| dispatcher | 达标自动接受 | null actor、取消/过期任务，拒绝 |

## 6. 接口契约

既有接口保持 {success,data,error} 信封和当前身份断言。修复接口：

- POST /api/finance/reservations/{engagementRef}/release：商家 403；服务身份校验组织和 reservation 状态。
- POST /api/finance/reservations/{engagementRef}/capture：仅 marketplace；未到结算窗口或争议中 409。
- POST /api/tasks/{id}/cancel：返回 pendingCancelled、refundedCount、compensationPending。
- POST /api/tasks/{id}/revise：关键变更返回 pending_review 版本，不替换公开版本。

批准新增接口（必须登记 Edge RouteManifest）：

- GET /api/v2/merchant/promotions
- GET /api/v2/recommender/promotions
- GET /api/tasks/{id}/applications/{applicationId}
- POST /api/tasks/{id}/applications/{applicationId}/reconsent
- POST /api/tasks/{id}/end-promotion
- GET /api/applications/{id}/settlement

状态码：400 参数错误；401 会话失效；403 无权限；404 不存在；409 状态/幂等/版本冲突；422 语义错误；503 下游暂不可用。不得返回堆栈、凭据或原始 SQL。

## 11. 任务卡

### C90-01 资金闸门与结算对账

修改 finance 端点仅接收服务断言，marketplace 客户端区分成功、已处理和异常；结算事件只在 capture 确认成功后写出。新增 reservation 状态/金额/收款人不变量 IT。禁止商家直接终态操作。验收：商家 403；不存在或已 release 不发 settled；重复 capture 一次 payout；争议中 held。

### C90-02 取消、接受并发、条款重确认

新增统一条件闸门和版本校验。cancel 将 pending 终态化，reserving 走补偿并阻止 Saga 激活；已提交履约按继续补交或争议策略处理。报名保存 task version/terms snapshot，关键修订设 reconsent。验收：取消后单条/批量 accept 409、无新资金；Saga 晚到不激活；未确认新条款不能扣款。

### C90-03 套餐推广资格与结束

分离 recruitment closed 与 promotion ended；资格查询接受已接单且未结束推广。下单保存单归因佣金快照，自购为 0，无资格降级自然流量；新增商家/推荐官 promotions 查询并接入推广卡。验收：满员后已接单者有佣金；结束后新单无佣金、既有订单不变；无手输套餐 ID。

### C90-04 自动通过系统身份

新增 marketplace.system-actor-account-id 配置和固定 UUID，迁移/查询/审计统一使用；dispatcher 复用 accept 内核，双实例、名额、等级、截止和资金不足冷却可验证。验收：无 null actor；达标接受、不达标保留；并发只一次；余额不足可恢复且不空转。

### C90-05 修订审核、分页、结算契约

关键字段修订生成 pending_review；报名 SQL 先筛选后 keyset 分页；详情按 applicationId 直查；返回 confirmedAt、settlementEligibleAt、settlementStatus、holdReason、allowedActions；统一显式 null 与缺省。验收：第 201 条可达；旧公开版本不被覆盖；T+2 不报失败；付费模式合法互转。

### C90-06 工作台状态、收益视图、集成
