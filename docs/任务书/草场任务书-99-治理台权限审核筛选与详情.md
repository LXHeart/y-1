### 3. 行为与接口

**3a. 列表筛选**

- 输入：`status` 可选 query 参数，白名单 `pending`（默认，缺省/空串回落）、`reviewed`、`all`；trim + 小写归一后非法值 → `IdentityException(400, "无效的筛选状态：" + 原始值)`（对齐 KYB `normalizeQueueFilter`）。
- 语义与排序（镜像 KYB `QueueFilter` 写法——白名单常量拼 SQL 片段，不拼接用户输入）：
  - `pending` → `WHERE status IN ('pending','under_review') ORDER BY (review_deadline < now()) DESC, review_deadline, created_at`（= 现 `findPending` 的排序，逾期优先）；
  - `reviewed` → `WHERE status IN ('approved','rejected') ORDER BY decision_at DESC NULLS LAST, created_at DESC`（刚审结的在前）；
  - `all` → 无 WHERE 条件，`ORDER BY created_at DESC`（最新提交在前）。
- 输出：不变 `{success:true, data:[toBody...]}`。**不加分页**（刻意取舍：保持既有数组契约与前端兼容，权限申请量级远小于订单类数据；如未来需要再演进为 PageEnvelope）。

**3b. 详情增强**

- `GET /api/admin/permission-requests/{id}` 在现有 `toBody(req)` 全字段基础上**追加两个 key**：
  - `organization`：`organizations.findById(req.organizationId())` → `{id, name}`；组织行缺失时 `{id: req.organizationId(), name: null}`（容错，不 404——申请行还在就该能看详情）。
  - `attachments`：数组，按 `req.attachmentIds()`（JSON 字符串，形如 `["uuid","uuid"]`）**原有顺序**解析，逐个在 `merchant_attachment` 里找「同 org 且 id 匹配」的行，输出 `Map`：`id`、`attachmentType`、`mimeType`、`sizeBytes`、`ocrStatus`、`uploadedAt`（Instant→`toString()`，null 传 null）。**缺失的附件 id 跳过**（附件可能已被媒体留存策略清理，不能让一条脏数据挡住整个详情；这是与 KYB 快照 409 语义的刻意差异，KYB 有完整快照、权限申请只有 id 列表）。`attachmentIds` 为 null/空数组/坏 JSON 时 `attachments` 为空数组（坏 JSON 容错，参照 `parsePermissionMaterials` 前端哲学：详情不因脏数据整块炸）。
- 解析 helper：控制器内新增 `private static List<String> parseAttachmentIds(String json)`（try/catch Jackson，坏 JSON → 空列表）。

**3c. 附件下载 URL**

- `GET /api/admin/permission-requests/{id}/attachments/{attachmentId}/download-url`：
  1. admin 门禁（`accounts.requireAdmin`）；申请不存在 404「申请不存在」。
  2. `attachmentId` 不在 `parseAttachmentIds(req.attachmentIds())` 内 → 404「审核材料不存在」（防越权拉同 org 其它附件）。
  3. `attachments.findByOrganization(orgId)` 中找 `id.toString().equals(attachmentId)` → 找不到 404「审核材料不存在」。
  4. `mediaClient.issueDownloadUrl(item.mediaReferenceId(), req.organizationId())` → 200 `{success:true, data:{downloadUrl: "<uri字符串>", expiresAt: "<instant或null>"}}`（`KybMediaDownload.downloadUrl()` 是 `URI`，须 `toString()`）。
- 接口示例：
  ```
  GET /api/admin/permission-requests/8f.../attachments/a1.../download-url
  → 200 {"success":true,"data":{"downloadUrl":"https://media.../dl?sig=...","expiresAt":"2026-09-10T12:00:00Z"}}
  → 404 {"success":false,"error":"审核材料不存在"}
  ```
