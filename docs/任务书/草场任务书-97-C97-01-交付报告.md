## 1. 实现结果

按 D97-01/D97-02 落地统一已结算退款闸门与结算防御纵深：

1. **统一守卫** `CommerceService.requireNotSettled`：结算事实 = `consumer_order.split_completed_at` 已落账（订单佣金分账完成标记，#75 D3 语义），不以钱包余额或订单状态推断；三路径共用：
   - 买家退款 `requestRefund`（paid/partially_refunded 状态检查后接入）；
   - 售后争议裁定退款 `resolveAfterSalesDispute`（refund 分支接入；reject 不受影响）；
   - 管理端资金动作 = 归因纠错 `correctAttribution`（service 层接入统一 409+blockedReason；repository 层 `split_completed_at IS NULL` 条件保留为并发双保险）。
2. **错误信封扩展**：`MarketplaceException` 新增可选 `blockedReason`，`MarketplaceErrorHandler` 在非空时于既有 `{success:false,error}` 信封附加 `blockedReason` 键（结构不变）。拒绝消息：「订单佣金已结算，不支持退款；售后申请须在售后窗口内提出」。
3. **结算防御纵深（D97-02）**：`attemptSplit` 在执行 finance.split 前**重查最新订单状态**——捞单到执行之间开放售后争议（status 已迁 after_sales_disputed）或他路已分账时跳过本次（defaultIfEmpty 原快照返回），使「结算后无退款」在时序上成立；finance.split 幂等键（`commerce-split:orderId`）封住重复执行竞态。售后争议开案/驳回的状态机阻断（pendingDispatch 不挑 after_sales_disputed）为既有语义，经 TC97-004 直调验证。
4. **前端禁用态（§8）**：`orderBody` 在 `splitCompletedAt` 非空时输出 `refundBlockedReason="settled_no_refund"`（服务端驱动，前端不推断）；消费订单页退款按钮禁用 + 说明文案。

## 5. 资金/事件证据

- **结算事实引用**：守卫判据 `order.splitCompletedAt() != null` ↔ DB `consumer_order.split_completed_at`（#75 D3 分账完成信号；与 `correctAttribution` SQL 守卫同源）。
- **退款幂等键沿用现状**：`commerce-refund:{orderId}`（首次全额）/`commerce-refund:{orderId}:{uuid}`（部分）——`requestRefund` 未改动幂等键生成逻辑（回归由 AC-97-04 用例锁定）。
- **闸门行为**：结算后退款在进入 `requestRefund`/`requestDisputeRefund` SQL 之前被拒——不产生退款请求行、不触发 `finance.refund`（`verify(finance, never()).refund`）、`refundedAmountCents` 零变动（用例断言）。
- **事件**：被闸门拒绝的路径无新事件（拒绝在状态迁移前）；驳回路径 `ConsumerOrderAfterSalesDisputeRejected` 照旧。

## 6. 偏差

1. **既有缺陷顺带修复**：`CommerceRepository.rejectAfterSalesDispute` 的 UPDATE 语句未声明表别名但 RETURNING 使用 `o.` 前缀 → BadSqlGrammar 500（售后驳回路径此前从未被 IT 覆盖，本卡 TC97-002 补测时暴露）。已修（`UPDATE consumer_order o SET ... WHERE o.id ...`）。属卡内测试边界内的普通编码缺陷，非阻塞。
2. **「管理端资金动作」的解读**：任务书未给出该路径锚点。按 §5.1「管理端退款/纠错走既有 admin 鉴权」与白名单（marketplace CommerceService），实现落在 `POST /api/admin/commerce/orders/{id}/attribution-correction`（管理端可变更订单分成归属与金额快照的资金动作）。若主程另有所指（如 identity adjust-credits），需重新界定——该路径不针对订单、无「已结算」判定语义，不适用本闸门。
3. **已结算订单的退款按钮可见性**：`redeemed` 单本就不满足 `canRefund`（paid/partially_refunded）而不显示按钮；禁用态针对的可达态是「分账后售后部分退款」的 `partially_refunded + settled`（IT 亦按此造态）。
