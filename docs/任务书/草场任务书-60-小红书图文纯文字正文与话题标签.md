## 1. 目标与范围

**现状**（帮助你理解在改什么，不要求另行验证）：
- 创作中心选「小红书 + 图文」进入 `/article` 五步流：主题→标题→大纲→正文→**配图**。
- 后端正文生成本来就是纯文本（`ArticlePrompts.java` 无任何配图指令）；「正文配图」完全是前端第五步：按段落拆图槽、选图后由 `contentWithImages` 把 markdown 图片拼进正文。
- 小红书图卡面板（CardSeriesPanel）已挂在正文/配图两阶段外层，走 `/api/card-series/plan`（拆卡）+ `/generate`（生图）。

**一句话目标**：小红书图文改为「纯文字正文（末尾自动生成 # 话题标签行）+ 小红书图卡」，去掉正文配图这一步；话题标签默认由 AI 生成，用户在正文里直接改。

**范围内（明确交付）**：
- 后端小红书 CONTENT prompt 增加一条要求：正文最后一行输出 3-5 个 # 开头的话题标签。
- 前端小红书（非抖音）五步流砍为四步（去掉「配图」），正文流完成后停留在正文阶段，正文阶段新增「完成」按钮与说明提示。
- 图卡拆卡请求、配图图槽拆分这两处，在处理正文前先剥离末尾的话题标签行（防止 # 行被拆成卡片要点 / 生成配图槽）。
- 前后端测试补齐（后端 prompt 断言、前端工具单测、3 个视图用例）。

**范围外（明确不做，遇到也不处理）**：
- 抖音流程不改：仍走配图阶段、步骤条仍五步。注意抖音与小红书共用后端 `platform=xiaohongshu` prompt，因此抖音正文也会带话题标签行——这与抖音既有提示「结尾带话题标签」（`platform-mode-hint`）方向一致，属顺带对齐，**接受、不处理**。

### 3.2 `src/lib/article-hashtags.ts`（新建，全文照抄）

```ts
/**
 * 小红书图文（任务书 #60）：正文末尾的话题标签行（# 开头）由 AI 默认生成、用户可在正文里改。
 * 图卡拆卡与配图槽拆分前需剥离这些行——话题属于笔记正文，不应被拆成卡片要点或配图槽。
 */

/** 剥离文本末尾连续的「以 # 开头」非空行（容忍行首空格、一行多个标签；尾部空行一并去掉）。 */
export function stripTrailingHashtagLines(text: string): string {
  const lines = text.split('\n')
  while (lines.length > 0) {
    const last = lines[lines.length - 1].trim()
    if (last === '' || last.startsWith('#')) {
      lines.pop()
      continue
    }
    break
  }
  return lines.join('\n')
}
```
