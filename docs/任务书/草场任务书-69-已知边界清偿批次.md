### 卡 A:剪映 A 轨验证闭环
**背景**:#66 交付的剪映草稿导出(三轨 JSON)锁定 6.0–6.9 区间,但「实机验证+登记小版本」未闭环,且无任何机器可验的契约测试兜底。本卡把机器能验的验掉、人工路径写成指引。

**改动文件**:
- 新建 `platform-java/services/intelligence-service/src/test/java/com/grassland/intelligence/videoproduction/VideoJianyingDraftContractTest.java`(纯单测,不起容器——builder 是纯构造)
- 新建 `docs/测试/附录-剪映草稿导出实机验证指引.md`
- 修改 `JianyingDraftBuilder.java`(仅 javadoc 与外显方法,不改生成逻辑)
- 修改 `src/views/video-production/VideoProductionView.vue`(仅导出入口按钮与版本提示,若已存在入口则只补提示)

**开始前检查**:`grep -rn "jianying\|export/jianying\|export/bundle" src/ --include='*.vue' --include='*.ts' | grep -v test`——确认前端是否已有剪映/B 轨导出入口;读 `JianyingDraftBuilder` 全文与 `VideoExportBundleIT` 学习构造入参与既有断言风格。

**做法**:
1. **契约自检测试**(单测):以最小合法任务形态(≥2 镜、含旁白、含成片)构造,断言:
   - draft_content.json 三轨存在且轨道类型正确(视频/音频/文本);
   - 所有素材引用为**相对路径**(绝对路径在部分版本=损坏草稿);
   - 微秒时间轴一致:每轨素材区间首尾相接、无重叠无空洞,末尾=任务实际时长;
   - `version` 字段与 `SUPPORTED_JIANYING_RANGE` 的主版本一致(6.x → 360000 档);
   - draft_meta_info.json 必填键齐备(draft_id/duration/platform_version 等,以 builder 现产物为准逐键断言)。
   - 缺旁白/缺成片等**降级形态**各补一例断言(轨道缺省时的结构仍合法)。
2. **版本区间外显**:`JianyingDraftBuilder` 加只读方法 `supportedRange()` 返回常量;后端在 export 端点响应头 `X-Supported-Jianying-Range` 带出(响应体/草稿目录**不动**——目录加文件=损坏草稿风险)。
3. **前端导出入口**:若开始前检查发现剪映/B 轨导出无前端入口,在合成完成区(`VideoProductionView.vue:532-543` result-area 的 action-row)补两个次级按钮「导出剪映草稿」「导出素材包」,分别 GET 对应端点触发浏览器下载,剪映按钮旁用 `.gl-hint` 展示「适配剪映专业版 6.0–6.9」(值从响应头或写死常量同步——取后端响应头优先);已有入口则只补版本提示行。
4. **实机验证指引文档**,内容定死七节:①适用版本区间与下载入口;②导出步骤(选哪个任务、点哪个按钮);③实机打开步骤(草稿目录放置路径按剪映 6.x 的默认 draft 目录写,注明以实测为准);④逐项检查清单(三轨可编辑/旁白对齐/字幕文本可改/素材相对路径不丢失/微秒时间轴不错位);⑤常见损坏形态排查(绝对路径、多余文件、version 不符);⑥**登记规则**:验证通过后把「剪映专业版 6.x.y(实测日期)+ 结论」登记进本文档表格与 `JianyingDraftBuilder.SUPPORTED_JIANYING_RANGE` javadoc;⑦失败反馈路径(在本文档登记失败形态,锁定区间收窄)。

**背景**:任务事件 SSE 的 sink 是单实例内存,多副本部署时非本实例的任务事件会缺(契约靠轮询兜底)。本卡加 Redis pub/sub 广播通道,默认 local 行为不变,多副本部署时切 redis。

**做法**:
1. 配置:`ai.video-production.events.transport: local`(默认,注释写明 local=现状逐字节不变、redis=跨实例广播)。
2. `VideoTaskEventStream` 改造:
   - local:现有逻辑不动;
   - redis:①`emit*` 在投本地 sink 的同时,经 `ReactiveRedisTemplate.channel().send(topic, frame)` 发布到 `grassland:video-events`(payload = `{"taskId": "...", "frame": "<原帧字符串>"}`,序列化照仓内惯例);发布失败仅 WARN 不阻塞(subscribe 于后台/独立调度,严禁卡 emit 调用方——Reactor 陷阱:side-effect 发布用 `Mono.defer` 包裹后异步订阅,避免装配期求值);
   - ②启动时 `reactiveRedisTemplate.listenTo(ChannelTopic.of("grassland:video-events"))` 订阅,收到的帧按 taskId 找本地 sink(`computeIfAbsent` 已存在才投,无订阅者丢弃——与契约一致),订阅流常驻(应用关闭时取消,用 Disposable + @PreDestroy 或 SmartLifecycle);
   - ③自己发布的消息会被自己订阅到——需要**回环抑制**:发布时在 payload 带实例标记(instanceId=UUID 启动生成),订阅侧跳过自己发的帧(本地 sink 已在 emit 时投过)。
