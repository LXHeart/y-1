## 1. 目标与背景

**现状问题**(当日核实):「举报投诉」是顶部一级导航页签(`DefaultLayout.vue:126-139`,登录后可见),点进 `/complaints` 是一张通用表单——对象类型下拉 + **手填对象 ID**("任务 ID / 帖子链接 / 订单号")+ 原因 + 描述。两个病灶:低频治理动作占了一级导航位;平台自己知道的上下文(任务 id、报名 id、账号 id)推给用户手抄。

**一句话目标**:撤掉一级导航页签;举报主通道改为业务卡上的场景化按钮(预填对象、弹窗提交);「我的投诉」列表与兜底手填表单收进 #73 的个人设置弹窗第三节。

**举报对象矩阵**(已拍板,产品语义基准):

| 对象 | 推荐官 | 商家 | 典型场景 |
|---|---|---|---|
| 任务 task | ✅ 大厅任务行 | —(自己发的) | 虚假任务、诱导线下、违规行业、骗稿 |
| 履约交付物 submission | —(自己的) | ✅ 交付物块 | 抄袭洗稿、AI 垃圾蹭赏金、广告法风险内容 |
| 用户 user | ✅(本期无挂载点,走兜底) | ✅ 报名行 | 薅羊毛、账号异常、辱骂骚扰 |
| 内容 content | ✅ 走兜底 | ✅ 走兜底 | 抄袭自己作品、冒用品牌(平台暂无公开内容广场,无场景化挂载点) |
| 订单 order | ✅ 走兜底 | ✅ 走兜底 | 结算异常、发票问题(弱场景) |
| 争议 dispute | ❌ 分流 | ❌ 分流 | 驳回/酬金纠纷走既有争议流程(48h 审判),**不走举报** |
