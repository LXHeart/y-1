# Hypit 跨管线分片渲染

## 1. 目标与范围

保留视频复刻、动画、模板与 Studio，把能够严格识别的普通媒体画面从 HyperFrames 浏览器逐帧渲染迁到 FFmpeg。第一轮复用 Hypit 执行环境中的媒体工具链与 Resource 存储。第二轮已接入 Java 共用 silent visual renderer 与账号隔离的跨作品缓存；没有增加第二套队列或常驻媒体 worker。

## 2. 已接入路径

通过补丁 `platform-hypit/patches/0006-media-segments.patch` 修改原生编译与 `renderHyperframesVisual` 的实际执行入口。上游源码保持不变，生成目录仅为补丁的物化产物。

编译器附加可重放的 Composition / ProgramSpace 元数据。执行器重新编译并比较完整文档（HTML、素材依赖、画布和时钟），一致后才分流；旧文档、不匹配元数据继续走原路径。元数据仅存在于惰性 HTML 注释，不执行作者代码。

按 Present 可见区间的整数帧边界拆片，最多 128 片，串行执行：

- 单一、无父容器、无动画、无额外属性、铺满画布的 PNG/JPEG → FFmpeg；透明、动画 PNG、显式色彩配置或方向信息暂回退。
- 同样布局的 MP4 → 探测确认单 H.264 / yuv420p 画面、同帧率、无旋转元数据、源帧足够后执行。仅支持原速连续采样和整数帧裁剪；变速、循环、多采样段回退。
- 字幕、叠层、遮罩、动画或未知样式 → 原生 HyperFrames。含浏览器自定义程序的作品整体使用原路径，避免程序的全局样式/事件影响其他片段。

原生片段保留原时间轴，只移除与选定区间完全无交集的 Present，避免已经离场的视频在浏览器内等待加载。音频计划、混音与最终 mux 仍由原生图统一处理；分片只输出无声画面。

## 3. 边界与资源

素材只能从当前 Runtime 的 Resource store 读取，不接受作者路径或远程 URL。优先流式读写；非流式读取受内存预算约束。FFmpeg 参数使用数组、限制协议、单线程执行。统一超时/取消信号覆盖素材准备、原生渲染、转码与输出存储；临时目录在 finally 中释放。

每片及最终输出均用 ffprobe 验证帧数、帧率、画布、H.264 和无音轨。多片输出逐片解码为 RGB 帧，经有背压的管道交给单一编码器，从统一时钟生成时间戳，避免 H.264 分片时间基、B 帧重排序造成缺帧；同一时刻仅一个解码器，且核对原始帧字节总数。单片直接复用文件，不额外编码。多片最终重新编码，存在额外一次有损编码；不声明像素无损或已经完成性能收益测量。

原图级缓存仍保留，编译元数据自然进入请求内容。第二轮新增普通媒体分片的跨作品持久缓存，具体边界见第二轮章节；复杂浏览器程序/动画沿用原有 Hypit 缓存，不宣称任意局部编辑都只重渲染一片。设置 `HYPIT_MEDIA_SEGMENTS=0` 可停用分流；已缓存的结果不因此失效，需要新的构建请求进行效果对照。

## 第二轮：Java 共用管线与跨作品缓存

内部桥使用 Runtime 实际执行的 engine build ID，Java 联查工程取得账号，禁止从请求声明账号或缓存键。只允许有效工程与非终态构建，缓存命中也先校验身份。普通自有素材制作和 Hypit 分片共用 Java silent visual renderer；音轨仍在各自上层合成。

缓存位于既有对象存储 `shared-visual-segments/v1/` 下，账号散列隔离，以源字节、完整渲染参数、算法与工具链版本作指纹。单对象原子保存创建时间、完整性摘要和视频，7 天过期，账号总量上限 1GB；写失败按 advisory 降级。此次没有增加新的常驻媒体服务。
