## 3. 技术决策

| 编号 | 决策 |
|---|---|
| D96-01 | 每个等待状态定义「责任方 + 截止 + 超时动作」三元组；截止时刻随事件快照落行（沿用 payment_deadline/split_eligible_at 快照惯例），改配置不影响存量。 |
| D96-02 | 到期/终结复用 Temporal Timer + dispatcher 补启范式；领域命令走幂等键（`engagement-timeout:{applicationId}:{kind}` 一类），行级条件 UPDATE 单边胜出。 |
| D96-03 | 履约阶段是**事实记录**不是状态机重构：新增 engagement_milestone 行（kind=script/deliverable/published、证据引用、双方确认），展示与结算从事实派生；禁止把 application.status 拆成更多中间态。 |
| D96-04 | 取消补偿按「已确认里程碑 + 合同冻结的取消条款」计算；试点默认模板=已确认脚本 20%/合格成品 60%/按约发布 20%（评审 §7.2 讨论值，配置可调），补偿上限=已保障金额。 |
| D96-05 | 体验权益单独立成表（experience_benefit），关联 engagement；商家失约=推荐官侧举证发起 + 商家限时回应（默认 72h，可配），到期未回应自动成立，暂停交付计时、允许无责退出、押金全退。 |
| D96-06 | 发布前审稿是新 submission 形态（draft：允许仅附件无公开链接），发布证明仍用既有形态；审稿窗口默认 72h、补交 48h、修改上限随合同字段（缺省沿用全局 2）。 |
| D96-07 | 历史合同不回填：无里程碑证据的存量 accepted 不能自动记为「已开工」；新规则只对规则生效后接受的报名生效（policy 版本列）。 |
| D96-08 | 动作契约扩展只加字段不改闭集语义：`blockedReason`（为何不可用）+ `nextActionDueAt`（下一动作截止）；前端禁止自行拼装业务判断。 |

## 4. 目标行为

### 4.1 主流程（内容合作，第二批次后的完整形态）

1. 商家发布（可选发布前审稿、交付截止、取消条款）→ 平台审核 → 推荐官报名（记录条款版本）→ 接受（冻结条款+资金）。
2. 若合同要求审稿：推荐官提交草稿（附件，无需公开链接）→ 商家 72h 内批/退（限次）→ 批准后发布。
3. 发布后提交凭证 → 核验（C02 门槛已在第一批落地）→ 商家验收或到期自动确认 → 观察期/争议窗口 → 结算（C11 下限已落地）。
4. 任一等待状态超时：提醒 → 有限补救 → 按责任方终结（推荐官有责=按已确认阶段结算+释放余款；商家有责=阶段结算+补偿；免责=全额退）。
5. 双方任一方可在规则内主动退出/申请延期：开工前协商取消零补偿；有里程碑后按 D96-04 结算。

### 4.2 新增/扩展状态（全部从事实派生，不新增 application.status 枚举值）

- 合作视角（读模型）：in_delivery（accepted 未交付）、under_review（草稿审稿中）、observation（验收后观察/争议窗口内）、terminating（退出/终结中）、terminated:{reason}。
- 体验权益：pending_booking、booked、fulfilled、merchant_defaulted、cancelled。

### 4.3 不变量

- 超时终结与手动确认/取消并发：条件 UPDATE 单边胜出，同一报名最多一种终结。
- 阶段结算金额 ≤ 已预留金额；每笔结算/退款幂等键唯一。
- 里程碑确认后不可静默删除；取消结算必须引用里程碑行。
- 商家失约成立前推荐官交付计时暂停（deadline 顺延可解释：暂停区间可查）。
- 存量数据零迁移改写（D96-07）。

## 5. 业务规则与权限

1. 推荐官可在 accepted+未提交任何里程碑前无责退出（记 exited_no_fault，不进完成率分母）；已有确认里程碑后退出走协商/争议。
2. 商家取消：无确认里程碑=全额退（现状）；有确认里程碑=按 D96-04 部分结算，差额退商家；记录取消责任方。
3. 交付超时（默认值 `marketplace.engagement.delivery-deadline-days`，试点 7 天，可配；合同字段优先）：到期提醒（前 24h）→ 逾期进入 limited_remedy（默认 48h）→ 仍无交付按推荐官有责终结。
4. 体验权益失约回应窗默认 72h（`marketplace.engagement.benefit-response-hours`）；成立后押金全退、交付计时暂停、推荐官可无责退出。
5. 发布预览页数据全部来自服务端读模型（条款快照+预计到手计算复用既有金额拆分逻辑），前端不复算钱。
6. 权限矩阵沿用现状：商家限本组织、推荐官限本人、治理台客服/风控可看终结与补偿记录；无新角色。

## 11. 任务卡

### C96-01 交付期限与退出/延期规则

接受时快照 delivery_deadline_at（合同字段优先，缺省配置）；到期前提醒、到期进 remedy 窗、仍无交付按推荐官有责终结（按已确认里程碑结算、释放余款、名额回收）。新增推荐官无责退出（无确认里程碑时）与延期申请/批准。Temporal Timer+dispatcher 照 ConfirmationWindow 范式。验收：接单不交付有提醒-补救-终结链；无责退出不进完成率分母；终结与手动确认并发单边胜出。

### C96-02 履约里程碑与取消补偿

engagement_milestone 事实表：脚本/成品/发布三类，双方确认制；商家取消时按已确认里程碑+取消条款部分结算（D96-04 默认模板），差额退商家；结算引用里程碑行可审计。验收：已有脚本确认后取消→20% 结算；无里程碑取消→全额退（现状保持）；补偿不超已保障金额；存量 accepted 不回填。

### C96-03 体验权益单与失约处理

experience_benefit 表+预约/兑现确认流；商家失约=推荐官举证主张+限时回应，成立则暂停交付计时（暂停区间落行）、押金全退、可无责退出。验收：失约成立后押金全退且交付 deadline 顺延可解释；未消费退出与已消费不履约分开；权益单与押金字段解耦展示。

### C96-04 发布前审稿与期限可配

draft submission 形态（附件可无公开链接）+ 商家审稿窗口（默认 72h 可配）+ 限次退改（合同字段优先、全局缺省 2）+ 补交期限（默认 48h）；发布后验收流程不动。验收：草稿送审不要求公开链接；审稿超时动作明确（提醒→自动通过进入发布或转人工，按合同 review_timeout_policy，缺省转人工）；退改次数耗尽走争议/退出。

### C96-05 发布预览与完整条款
