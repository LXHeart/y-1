## 1. 目标与范围

### 1.1 一句话目标

注册弹窗中《用户协议》《隐私政策》两个链接从「新标签页打开 SPA 后空白」变为「打开用户端两条公开法律路由的占位版正文页」；同时为用户端补上未知路由的 404 内容页，并把用户端/AI 端注册弹窗的协议链接统一指向草场用户端 origin。

### 1.2 背景与价值

`src/components/LoginModal.vue:189` 写死了 `/docs/user-agreement` 与 `/docs/privacy-policy`，但仓库既没有 public 静态文件也没有用户端路由（`src/router/index.ts` 无 catch-all）；nginx `try_files` 把未知路径回退到 `index.html` 后，Vue Router 无匹配即渲染空白。这是注册流程的实际功能断点（P1）。本任务书 #79 曾立项同口径修复（C79-06），当时阻塞在「法务正文审批」；本次用户已明确拍板：先由规划方出一版**占位法律正文**上线到本地项目，正式版等上线前再替换。本任务实施 C79-06 的范围并以其为依据关闭该卡。

### 决策记录

#### D-01：SPA 路由方案，否决 public 静态 HTML

- 决策：法律页与 404 页做成用户端 SPA 路由（DefaultLayout 子路由），不建 `public/docs/*.html`。
- 原因：静态 HTML 绕开设计系统（token/双主题/fontsource 字体链）与净化管线，且需独立维护样式；SPA 方案让正文走 `?raw` + `renderSafeMarkdown` 净化、主题/导航天然一致，正式版替换只改 md 文件。
- 放弃方案：`public/docs/user-agreement.html` 静态页（虽然 public 目录被三 origin 共享可直接命中，但脱离设计规范与主题体系，且 CSP `script-src 'self'` 下静态页无法复用 SPA 字体与运行时）。
- 允许执行模型修改：否

#### D-02：正文为仓库内 Markdown，`?raw` 导入 + renderSafeMarkdown 渲染

- 决策：两份正文放 `src/content/legal/*.md`，`legal-docs.ts` 以 `import x from '...*.md?raw'` 静态导入，视图 `v-html="renderSafeMarkdown(meta.bodyMarkdown)"`。
- 原因：复用既有净化管线（白名单标签，防注入）；正式版只替换 md 文件不动组件；`tsconfig` 已含 `vite/client` 类型。
- 放弃方案：正文写在 Vue 模板里（替换正式版要改组件）、组件内拼 `import()` 路径（D-03 否决动态路径）。
- 允许执行模型修改：否

#### D-03：kind 固定联合类型 + 静态映射，禁止动态路径

- 决策：`type LegalDocKind = 'user-agreement' | 'privacy-policy'`；`LEGAL_DOCS: Record<LegalDocKind, LegalDocMeta>` 由两条字面量路由以 `props: { kind: '...' }` 挂载。MUST NOT 用路由参数拼 import 路径或读任意文件。
- 原因：#79 C79-06 既定（「kind 不从任意 URL 拼导入」）；类型收口使非法 kind 不可达，组件兜底仅防御性。
- 允许执行模型修改：否

#### D-04：三端链接统一 `grasslandAppHref`，rel 升级 `noopener noreferrer`

- 决策：LoginModal 两个 `<a>` 改 `:href="grasslandAppHref('/docs/user-agreement')"`（隐私政策同理），`rel="noopener noreferrer"`，`target="_blank"` 保留，MUST NOT 附加 `?xat=` 等任何身份参数。
- 原因：#79 C79-06 既定；生产 AI origin 下相对路径会被 AI catch-all 吞掉，必须绝对指向草场 origin；法律页是公开文档，不携带跨应用免登 token。
- 放弃方案：保持相对路径（AI 端会落到 AI 创作首页，错误）。
- 允许执行模型修改：否

#### D-05：catch-all 作为 `'/'` 的最后一个 child + NotFoundView 不回显路径

- 决策：在 `routes[0].children` **末尾**追加 `{ path: ':pathMatch(.*)*', name: 'not-found', component: NotFoundView }`（照 `src/ai/router.ts:58` 的仓库先例）；NotFoundView 文案为固定常量，MUST NOT 回显 `route.fullPath`/URL，MUST NOT 自动跳转或外跳 AI。
- 原因：vue-router 4 子级 repeatable 参数可匹配多段路径（AI 路由已实证）；挂在 DefaultLayout 下获得站点导航；不回显不可信 URL 是 #79 既定安全口径。
- 放弃方案：顶层 `/:pathMatch(.*)*` 独立路由（丢失 DefaultLayout 外壳，与站点观感不一致）。
- 允许执行模型修改：否

#### D-06：首登改密守卫最小豁免 = 仅两条法律路由名

- 决策：守卫条件追加 `PUBLIC_LEGAL_ROUTES.has(to.name as string)`，集合为 `new Set(['user-agreement', 'privacy-policy'])`（模块级常量）。`first-password` 既有豁免与其余路由的 428/拉转硬闸不变；`not-found` **不豁免**（首登用户撞未知路径仍被拉去改密，与现状一致）。
- 原因：#79 C79-06 既定「首登改密仅两法律路由豁免」；首登改密用户需要能读自己「已同意」的协议。
- 允许执行模型修改：否

#### D-07：占位标识的三件套（横幅 + 版本行 + 生效状态）

- 决策：`legal-docs.ts` 的 meta 含 `placeholder: true` 与固定横幅文案（C-01 逐字给定）；视图在标题下方渲染占位提示横幅（`role="note"`）；版本行固定渲染 `v0.1-placeholder · 未生效（占位预览）`。正文内 MUST NOT 出现具体生效日期、运营主体名称、可联系的邮箱/电话（联系章节统一写「正式版本中公布」）。
- 原因：用户拍板「占位版不得冒充正式协议」（#79 决策延续）；三件套让任何读者一眼可辨占位状态，也方便正式版替换时统一拆除。
- 允许执行模型修改：否

#### D-08：e2e spec 移出本任务

- 决策：本任务不建 `tests/e2e/*.spec.ts`；真浏览器验证用根目录 `smoke-85-legal.mjs`（dev server 即可跑）。
- 原因：本机跑不了完整 e2e 栈（隔离 Compose + 浏览器矩阵）；冒烟脚本覆盖同等断言（路由可达、匿名可读、明暗主题、AI 端链接 href）。正式版替换任务再补 e2e（登记于 §1.4/进度指南）。
- 允许执行模型修改：否
