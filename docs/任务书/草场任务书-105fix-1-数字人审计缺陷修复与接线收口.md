### 决策记录

#### D-01 worker 默认开启而不是跟 DH 开关族

- 决策：三 worker 默认 enabled=true，独立 env 键；不挂到 `DH_ENABLED`。
- 原因：reaper/结算兜底是数据面卫生（契约 L180 要求独立于浏览器回收），dh_* 表为空时一次 SELECT 空转成本可忽略；挂功能开关会让「功能关闭但历史残留行永不回收」。
- 放弃方案：绑定 DH_ENABLED；默认关闭（修复无效，违背 REQ-001）。
- 允许执行模型修改：否

#### D-02 Fake 档音频 turn 走进程内管线而不是假 INTERNAL08 服务端

- 决策：`DH_REAL_PROVIDERS_ENABLED=false` 时 runtime 进程内 `RuntimeSession` 执行，不回环调 Java。
- 原因：Fake 的意义是隔离外部依赖并保持零出站（`fakes.py` 模块头约束）；Java 侧 executeInvocation STT 真实现由 Java IT 用沙箱 speech provider 直测，不需要 Python 回环参与。
- 放弃方案：Fake 档也走 bridge+Java 假端点（回环网络与双端时序脆弱）。
- 允许执行模型修改：否

#### D-03 e2e 媒体连通断言分层

- 决策：完整对话流用例必需断言=API16 200+answer SDP 可解析+会话 ready+文字 turn+打断；浏览器 RTCPeerConnection 媒体轨真连通降为独立 SHOULD 用例（失败不阻塞卡验收，如实记录测试栈 host candidates ICE 拓扑结论）。
- 原因：Playwright 在 macOS host、runtime 在 docker，ICE 连通取决于端口发布拓扑，属环境属性而非代码正确性；不能让环境属性阻塞代码接线验收，也不能假造连通。
- 放弃方案：媒体连通为必需（环境依赖验收）；完全不做（丢失信号）。
- 允许执行模型修改：否

#### D-04 真实档 STT 后的收尾语义

- 决策：真实档 STT 返回后因 LLM/TTS stage 未接线，WS 以既有 1011 `dh_runtime_unavailable` 收尾并 WARN；不新增 wire code。
- 原因：错误码纪律（§5 不新增错误码）；真实档完整闭环本就归 REAL_NOT_RUN 门禁。
- 放弃方案：新错误码 `dh_stage_not_wired`（发明契约）。
- 允许执行模型修改：否

## 4. 目标行为与状态

### 4.1 用户流程（变化部分）

1. 用户开始会话（既有流程不变）→ 前端发起 API16 offer → 200 answer（不再 503）→ 会话 ready → 文字/打断交互照旧。
2. 用户按键说话→松开（audio WS end）→ Fake 档：turn 在 runtime 内完成转写与说话（WS 收到 turn 完成事件，不再 1011）；真实档：STT 真实派发到 Java 并返回转写后按 §3 D-04 收尾。
3. 用户浏览器崩溃/断网 → 45 秒目标内会话被 reaper 自动回收（不再需要管理员手工 terminate）。

### 4.3 状态迁移（本任务触点）

```text
dh_session: connecting -> ready：connectReady 单向 CAS（API16 answer 成功后）
dh_session: connecting -> failed+cleanup_pending：reaper 超时回收（既有语义，本任务补驱动）
dh_invocation: dispatched -> succeeded：executeInvocation STT 结算完成（既有状态机，本任务补执行体）
```

并发规则：connectReady 与 end 并发时 CAS 保证单向（end 先行则 offer 得 409 dh_state_conflict，不返回 answer）；重复 offer 已 ready 幂等成功（answer 重放由 runtime 端 peer 复用承担）；三 worker 调度上一轮未完成则本轮跳过（running CAS），不排队。

## 5. 业务不变量

1. 调度：reaper 单轮 limit=100、cleanup 单轮 limit=100、reconcile 单轮 limit=200（沿用各方法既有上限夹取）；enabled=false 时方法体首行 return。
2. API16：校验链语义不变（requirePersonal→validateLeaseRequest，失败照旧 401/404/409）；runtime 错误透传映射照 runtime handler 既有 status 表（L215-218：dh_lease_stale/dh_media_epoch_stale→409、dh_invalid_input→422）；connectReady 通过后才返回 answer，失败不返回；SDP ≤65536 UTF8 bytes、type='offer'、非 trickle（runtime 端既有校验，Java 不重复实现）。
3. INTERNAL08 STT：multipart 两 part 缺一→422；meta 非法 JSON→422；wav>1.92MB→422；grant 核销一次（GETDEL），重放已核销→401 dh_grant_invalid；NDJSON 帧序 meta→delta（≥1）→usage→done，每行 ≤128KiB（K07.1），HTTP 200 后失败走 error 终结帧；不创建 media_reference/speech_transcription 任务（契约 L254），mediaId=invocationId；Fake 档零出站（OutboundGuard 语义维持），真实档唯一出站=bridge 固定 authority。
4. 错误码不变量：不新增任何错误码，全部使用既有 `dh_runtime_unavailable`/`dh_not_found`/`dh_state_conflict`/`dh_grant_invalid`/`dh_invalid_input`/`dh_lease_stale`/`dh_media_epoch_stale`。
5. 资金：reconcile 只重放结算不重推理（既有语义）；STT 结算走既有 prepare 时预留的原经济键；失败不能新增隐藏扣费。
