## 4. 目标行为与状态

### 4.1 完整用户流程

1. 从旧深链、最近项目或快速模式进入，恢复已授权的草稿、分镜、task 与独立画布；项目标题、来源和保存状态可见。
2. 画布移动、缩放、分支变化、撤销/重做最终落在独立文档；刷新与 A→B→A 恢复各自状态。
3. 用户明确选择镜头或参考节点，在助手中看到将发送的数量、名称；输入文字就是请求 instruction，空选择不默认整项目。
4. 服务端检查状态、绑定、版本、选中节点和一跳引用，按快照执行一次文本计划；计划展示前后差异及受影响对象。
5. 应用时重新在锁内验证三版本，全部成功或全部回滚。编辑更新生成 prompt；派生打开新方案；准备生成只装配既有动作，不发媒体请求。
6. 用户经既有运行栏/候选按钮明确生成或重抽。成片后修改交付文字/封面，保存并导出精确版本，不重生成视频。
7. 引用素材、备注和参考线可创建、移动、编辑、删除与重选；自有片段有可播放的裁剪预览，实际成片与导出保持一致。
8. 离开、切方案、浏览器历史切换先排空编辑/来源/文档/交付；失败停留并聚焦错误。失活停止浏览器资源，后台已受理任务继续。

### 4.2 状态机

| 域 | 状态与行为 |
|---|---|
| 读取 | idle/loading/ready/empty/error；同项目刷新失败保留上次内容；新项目载入先清旧项目；401/404 清除相关私有内容 |
| 保存 | idle/pending/saving/saved/conflict/error；readonly 独立布尔值；冲突不得宣称 saved；保留本地快照与重试入口 |
| 计划 | preparing/ready/clarify/failed/applied/expired；空选择 clarify 固定引导且 runId=null；过期按服务端时钟；状态不等于媒体已生成 |
| 提交结果未知 | 保留原 operationId 和完整参数；查询/用户原键重试，不重新造键。编辑输入改变时不能把新参数套到旧键 |
| 已应用 | edit 刷新受影响镜头并保留布局；variant 导航新 draft/storyboard；prepare-generation 定位现有动作并显示对象与费用，仍需用户点击 |
| 只读 | 草稿归档/删除、未来 schema、来源不能可信恢复、分镜 committed 分别处理；允许读的对象保留可读内容和具体下一步 |


只读判定必须分层：draft归档/删除限制项目写入；storyboard committed只禁镜头内容/来源，允许合法派生和交付；仅canvas未来schema限制画布编辑/AI/无法理解的派生复制，不因此禁止独立的已知schema交付文字。既有后台task按自己的权限/阶段继续，可取消动作沿原task守卫；归档或离页不自动取消任务。

### 4.3 生命周期

- 登录状态来自既有认证会话/应用壳，禁止硬编码authenticated=true；游客显示既有登录引导，不绑定/升级服务端文档。
- 进入新上下文递增 generation，取消上一上下文的未发写入与读取；旧请求完成只可处理旧对象的已受理结果，不得覆盖当前 ref 或触发当前导航。
- 内部跳转和 beforeRouteLeave/beforeRouteUpdate 共用 `flushBeforeLeave(): Promise<boolean>`；绑定后补 draft query 是同一项目规范化，不触发重复创建/保存。
- account epoch 改变立即清空选择、计划、布局历史、编辑稿与队列。KeepAlive 失活释放消费者/计时器；激活重新安装键盘监听并权威读取。
- beforeunload 仅使用浏览器原生未保存提醒；不依赖卸载时异步 PUT 保证保存，不使用 sendBeacon 绕过 CAS。

### 6.3 独立画布与来源引用

- 保留 `CanvasDocumentBody` 的 schemaVersion/storyboardId/viewport/nodes/edges/activeBranchId；schemaVersion=1。节点字段固定 id/kind/refType/refId/label/text/x/y；边固定 id/kind/fromNodeId/toNodeId。
- canonical ID：brief:{draftId}、delivery:{draftId}、shot:{shotId}、take:{takeId}；用户节点 media:{uuid}、note:{uuid}。id 字符 `[A-Za-z0-9:_-]`、1～96；媒体的节点 UUID 是节点身份，refId 是媒体或内容资产身份，二者不要求相同。
- kind/refType：brief、delivery→draft；shot→shot；take→take；media→media/content-asset；note→note 且 refId=null。非 note 的 text=null。参考节点 label 1～60 或 null，备注 text 0～1000；其他长度沿 §5。
- 初始文档包括 brief、权威 shot 和可用交付/候选引用；新业务节点同步时合并现有节点位置，不能重置用户布局。sequence/derived-from 不入用户 edges。
- 同一refType/refId再次点击“加为参考”定位已有节点，不默默创建重复节点；重新选择可保持原节点ID并改变refId。
- 服务端 PUT 比对现有文档：新增/变更的 media/content-asset 引用必须当前可用且授权；历史失效引用只允许保留引用和调整布局/备注，不允许新连到执行目标。批量验证，不以浏览器 authorized/status 字段授权。
- GET 结果必须区分 success(null) 与 error。首次无文档可 revision=0 创建；并发首建409读取胜出版本；普通更新409保留本地并要求显式载入，不能采用首建冲突策略覆盖用户编辑。

### 6.4 AI 执行、应用与后续动作

| action | 准备及 apply 校验 | 成功结果与禁止副作用 |
|---|---|---|
| edit/update | patch 命中明确选中且当前存在的镜头；三个版本一致；分镜 draft；复用严格编辑验证与写入内核 | visual 同步 prompt，旁白单独改不动 prompt；整批只提升一次 editVersion；affectedShotIds 完整且去重 |
| edit/append | 五个字段完整合法；总镜头≤30；锚图索引在当前请求图片范围内 | 新 UUID、末尾 seq、prompt=visual；新 ID 进入 affectedShotIds；不冒用上一镜内容或候选 |
| variant | 非空选中镜头子集，顺序明确；title 1～60；数量/源版本在同事务中复验 | 用 plan.baseEditVersion/baseDraftVersion 派生；新方案与 apply_result 同事务。返回 variant 内新身份并导航新方案 |
| prepare/initial | shotId=null；draft 分镜；无已有初始任务；父资源可写 | nullable map 正确序列化，preparedGeneration={mode:'initial',shotId:null}；0 task/0生成/0预留 |
| prepare/regenerate | shotId 是选中的 generated 镜头；当前 task 与镜头匹配，阶段沿用既有 regenerate 守卫 | 只装配对应镜头的既有重抽动作，不提交 |
| prepare/reroll | 同上且沿用既有成片后 reroll 阶段守卫；own-media 拒绝 | 只装配现有 reroll 动作，不合成、不另计费 |

共同约束：已应用的重放返回已保存结果，不再次写入；重放仍校验当前账号归属，已删除父资源不泄露内容。并发 apply 在同一计划锁后重读，不把第二请求当普通陈旧计划返回409。无实际变化的 edit 保持 editVersion；plan 可标 applied。prepare 不写任何草稿/分镜版本。前端不得在 onApplied 中调用 beginProduction/regenerate/reroll。

计划创建按有界授权上下文执行：选中优先，再按节点 ID 加一跳引用；节点必须真实存在于当前 canvas，不接受任意 shot: 前缀拼接；媒体只发送已授权元数据/已存在分析，不声称看过未分析画面。任务要求/平台规则来自冻结快照并作为约束发送，不发送未选中镜头正文。预算包括明确截断标记和摘要，超出选择本身总预算400。

`FrozenTextExecutionService.executeTraced` 新增带 `Duration timeout` 的重载，保留旧签名并委托新重载：参数依次为 ServerWebExchange、UUID snapshotId、List<ChatMessage>、int maxTokens、CreditFeature、Duration、Function<TextCompletionResult,T>，返回 Mono<Traced<T>>。本书传90秒，沿用当前执行/用量/补偿内核；不要在执行环外额外消费或退款。解析失败必须进入既有失败路径并准确记录 failed/errorCode/runId；不得预先标文本运行成功后吞掉计划校验异常。

90秒模型时限由文本客户端在执行环内产生504失败；计划服务归一为CANVAS_AGENT_TIMEOUT。禁止在执行环外包裹更早触发的同值timeout，把系统超时误分类为用户取消。真正用户取消仍沿原有不退款规则，系统失败沿原失败补偿规则。

### 6.5 交付与导出版本

- VideoTask 的 `finalMediaId:string|null`、`srtMediaId:string|null`、`recomposeSeq:number` 与服务端对齐；seq 为非负整数。仅 succeeded 且媒体可用时形成已完成产物引用。
- `CreationResultRef` 增可选 `recomposeSeq:number`。画布新写入的 role=video 引用必须含 id=finalMediaId、refType=media、storyboardId、productionTaskId、recomposeSeq；对应 subtitle 使用 srtMediaId。其余工作流旧引用不强制新增字段。
- 新增/修改视频引用由 CreationResultReferences 校验任务归属/分镜绑定/seq/媒体 ID；是否为绑定画布先查询服务端 binding，不允许通过省略或替换 workspace 标记进入旧工作流兼容分支。未绑定旧工作流即使带inputs.video也不强制补版本字段；显式提供任务/seq的引用仍须完整校验。旧已确认引用原样保留。导出读取保存版本里的引用与媒体，不用 task 最新 finalMediaId 替换历史引用。
- 交付文字/封面保存只改 delivery 和显式选择的结果引用，保留其他 inputs/brief/source/runIds。成功收到草稿新版本后才解除“保存中”，导出前复用同一队列 flush，失败不下载。
- 任务 bundle/jianying 新客户端传 expectedRecomposeSeq；在同一个一致快照内确定 task/selection/source/产物 ID，导出过程中检查版本是否漂移，漂移409且不返回混版文件。事务锁内不做对象存储或 FFmpeg I/O。包内 manifest/原有 metadata 记录 taskId/recomposeSeq/finalMediaId，不增加会破坏剪映结构的自定义顶层文件。
- 旧历史草稿没有成片引用三元组时，不猜测属于当前成片：允许按既有可验证字段导出，manifest 明示视频版本引用缺失；当前项目可在显式保存/导出 flush 时补入服务端校验后的引用。不得重写旧 draft_version 或把旧输出宣称为新 seq。

manifest-only导出保留既有“不可用项”标记行为且不得返回坏下载链接；必需主片不可用时成片包/剪映导出必须拒绝，不交付缺主片的成功文件。

### 6.6 前端会话契约

新 `useCanvasProjectSession` 负责项目身份、generation、beforeRouteLeave/update、资源清理；新 `useCanvasSelection` 负责单一选择集合；其他复用既有 composable。允许保留旧调用签名的兼容包装，但 VideoCanvasView 只装配。

```ts

  accountEpoch: number
  draftId: string
  storyboardId: string
  generation: number

export type CanvasLoadOutcome = 'loaded' | 'missing' | 'error' | 'stale'

  selectedNodeIds: string[]
  focusedNodeId: string | null
}
export type CanvasDetailMode = 'shot' | 'reference' | 'assistant' | 'variants'
```

`useCanvasDocument.load(): Promise<CanvasLoadOutcome>`；`save(next): Promise<boolean>` 按版本排队；`flush(): Promise<boolean>` 等待所有属于当前 generation 的本地写；`adoptLatest(): Promise<boolean>` 只在明确放弃本地后执行。`flushBeforeLeave(): Promise<boolean>` 顺序排空镜头编辑→来源编辑→canvas→交付/草稿，任一失败即停。返回 false 不等于已保存，也不能在调用方忽略。

绑定请求的operationId只与该次完整请求绑定：结果未知时保存原键/原参数，成功后不把同键用于带不同draft参数的新请求。URL补draft不重复提交；冷重入按现有唯一关联恢复，不能因expectedDraftVersion已更新而混用旧创建参数。

`useCanvasAssistant` 接收实际 instruction ref 和 selectedNodeIds ref；submit 使用它们的不可变快照，先 flush，再取确认后的 editVersion/revision。面板和请求来自相同集合；刷新或换项目清空选择，不自动全选。apply 成功后按结果 kind 调整当前页面，不能借 reload 丢失未确认本地修改。

### 7.1 锁与可写性
