## 4. 目标行为
### 4.1 用户流程
现有AI登录→余额/历史按新信封读取→展示数值；旧模型设置使用者收到退役指引，不静默切换或扣费；用户从草场跳AI→签发目标绑定token→目标页面立刻清参→兑换并装载本人会话；失败落既有登录入口，不循环签发/兑换。
### 4.2 行为变化表
| 场景 | 目标 |
| --- | --- |
| 正常 | 积分统一信封；xat exchange返回user；显示不丢余额/字段 |
| 未登录 | 签发401；兑换允许无本地会话但必须有效nonce/目标；协议错误不自动提升身份 |
| 无权限 | 原服务403、被停用账号仍拒绝；ops无新免登入口 |
| 空 | 积分0正常、history=[]正常；非JSON200不是空成功 |
| 失败/延迟 | URL在请求前清参；失败现有中文错误，不留secret；无自动写重试 |
| 并发 | 同nonce并发仅一次成功；错误目标不能重试同token再成功 |
| 旧客户端 | 仅按审批窗口切换；无窗口不发布，无隐藏容错 |
### 4.3 状态定义
裸JSON请求：loading→success/error；不新增UI状态枚举。xat：absent/issued/consuming/exchanged/failed；nonce：v2存在→GETDEL消耗或TTL到期。旧v1不兼容为明确拒绝，不落成v2有效身份。
### 4.4 状态迁移
签发失败直接按现有不带token跳转；consume在读token后、任何await前strip xat，成功/失败都不恢复query；重复导航不重放。进入目标前已有会话时仍以明确兑换结果处理，失败不得把旧账号冒充兑换账号，具体登录壳保留已批准#79失效规则。Redis不可用503，绝不退为无防重放会话。

## 5. 业务规则
### 5.1 输入规则
积分GET无body、不接受accountId；数值仍整数积分，不转换现金分；history固定50条、createdAt为string|null。requestRaw入参url:string、init:RequestInit={}、options:RequestOptions={}；只处理JSON。token生成32字节，形态40–60字符仍保留；audience仅小写grassland/ai，缺/null/空白/未知不默认。Origin必须与获批配置的scheme+host+有效端口精确匹配；不从任意returnUrl派生可信目标。
### 5.2 校验规则
签发必须已有有效账号；exchange必须token形态有效、v2 payload字段齐全、目标origin/audience一致、来源为允许反向应用、账号当前可用。浏览器参数不是服务端权威。旧settings body顶层features不得继续影响模型路由；未知顶层/feishu字段按D80-03当前契约拒绝，例外矩阵按已批准的保密字段规则冻结。
### 5.3 规则编号
R80-01至05对应§1.3五目标；R80-06“不降资金/AI闸”由TC80-02B/03B，R80-07“错误兑换消耗nonce”由TC80-04B，R80-08“发版前无原始xat日志”由TC80-04B/05B。
### 5.4 权限与不变量
游客积分401；当前用户只能读取自己的CreditsCaller账户；internal/credits/**仍按service principal白名单，不给浏览器写入。平台凭据列表仍管理员授权和DNS pinning，不为兼容旧settings开放公共baseUrl/apiKey。token不是后台角色凭据，exchange仍按UserLookup/AccountFlag返回真实角色/首登状态；签发和兑换审计不包含token明文。
