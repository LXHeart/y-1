## 1. 目标与范围

### 1.1 一句话目标

将用户级 Pinia store、模块级 composable 和账号相关组件状态统一绑定到当前 `accountId`，使登出、换账号、账号快速切换和组件卸载都不会泄漏旧余额、配置、通知、组织、门店、钱包、AI 预算或购买记录，也不会让旧异步请求污染新账号。

### 1.2 背景与价值

当前仓库已在工作区包含任务 #79 的部分账号票据、分析设置、积分、模型来源和工作台修复，但通知、预算、购买记录以及部分模块级状态仍需要统一生命周期审计。典型风险是账号 A 的 `loaded=true`、Feishu `appId`、积分余额、组织/门店/钱包或预算响应在账号 B 登录后仍被展示，甚至被 B 的保存动作带回服务端。该任务把“清空旧值”和“阻止旧异步回写”作为同一个安全不变量处理。

### 2.5 当前行为（FACT）

1. `auth.currentUser` 由 `src/stores/auth.ts` 管理；工作区已有 `account-session` 通过同步 watch 将账号变化转成递增 `epoch` 和 AbortSignal。
2. 分析设置与积分当前工作区版本已有 `owner`、`resetForAccount()`、票据保护；`owner` 尚未统一作为公开的 `ownerAccountId` 状态契约，需核验实现是否完整覆盖所有分支。
3. Feishu 表单当前按会话清空本地输入，并在打开/提交后验票；其加载条件仍依赖分析设置的 `loaded`，必须证明 `loaded` 不会跨账号复用。
4. `useModelSource` 当前有模块级 `ref`、局部 `requestEpoch` 和 `reset()`；需要补充与账号 owner 的明确绑定和自动换号行为。
5. 通知 store 已有 `reset()` 和轮询句柄，但请求 `run()`、`refreshUnreadCount()`、翻页和标记已读路径仍需统一验证账号票据，避免旧响应覆盖新列表。
6. `useActiveIdentity`、`useWorkbenchSession` 当前已有部分账号/组织代次保护；本任务要求把身份、组织、门店、钱包、资金账户、更名和草稿的“清理 + 旧请求不可回写”作为可验证闭环。
7. `useCreditsPackages` 是每个弹窗实例的 composable；套餐目录为公共数据，购买记录和购买中状态为账号私有，账号切换时不能让 A 的订单或成功回调进入 B。
8. `useDouyinSession` 是模块级单例（FACT：`state/loading/polling/error` 定义于模块顶层，`let pollTimer/latestRequestId` 驱动 2 秒扫码轮询）；现有保护只有 request-id 乱序丢弃与组件卸载 bump，没有账号 owner/reset——A 的 `authenticated` 会话态、二维码和轮询在换号后仍对 B 可见。已并入 C82-01。
9. 扫描排除项（FACT，2026-09-06 全仓 `.ts` 模块级 `ref/reactive/let` 扫描）：`useGuestTrial.ts` 的 quota 为 IP 级游客额度（任务书 #36 / ADR-D14），非账号私有，判 N/A；`useMomentsCreation.ts` 的 `imageSequence` 为纯递增计数器，判 N/A；`src/stores/theme.ts` 为公共主题偏好，判 N/A。
8. `PersonalAiBudgetCard` 与 `AiOrgBudgetPanel` 将预算响应保存在组件局部 refs；组件可能因 KeepAlive 或入口常驻而不重挂载，必须在账号/组织变化时清空并验票。

### 2.6 当前问题

- 现状：多个状态只以模块或组件生命周期为边界，不以账号为边界；有的只有 `loaded`/`reset`，没有 `ownerAccountId` 或票据。
- 问题：账号 B 可能短暂看到 A 的私有值，B 的保存/购买/预算提交可能携带 A 的表单或版本，A 的迟到响应还可能覆盖 B。
- 影响：配置泄漏、错误账号写入、积分展示错误、通知误读、组织/门店越权视觉误导和 AI 预算误操作。
- 根因：账号变化清理未集中；模块级单例、KeepAlive 组件和轮询没有共同的 owner/epoch 约束；异步完成分支不总是验票。

### 决策记录

#### D82-01：统一使用账号票据，不新增全局事件总线

- 决策：所有账号边界由既有 `account-session` 的 `AccountTicket`/`epoch` 负责；各状态模块自行实现 `ownerAccountId`、reset 和票据守卫。
- 原因：避免新增跨应用事件总线、隐式依赖和全局神型 store，同时覆盖同步清理与异步乱序。
- 放弃方案：在 `auth` 中广播字符串事件，由所有模块自行订阅且不保留票据。
- 允许执行模型修改：否。

#### D82-02：公共数据与私有数据分开处理

- 决策：套餐目录可以跨账号复用或重新加载；购买记录、购买中状态、成功余额回调和错误必须按账号隔离。通知、预算、积分、分析设置、身份、组织、门店、钱包全部按账号清理。
- 原因：避免为了清理私有数据而不必要地清空公共静态目录，也避免把公共目录误当作私有缓存。
- 放弃方案：所有 ref 一律清空但不保护旧请求。
- 允许执行模型修改：否。

#### D82-03：不通过隐藏 UI 解决泄漏

- 决策：UI 可以在账号切换瞬间显示中性加载态/空态，但根修复必须是清理 owner 数据并阻止旧响应写入；按钮显隐不替代服务端鉴权。
- 原因：防止 B 保存时仍携带 A 字段，也防止隐藏旧值造成假安全。
- 放弃方案：仅在渲染层用 `v-if` 或遮罩隐藏旧值。
- 允许执行模型修改：否。

## 4. 目标行为

### 4.1 用户流程

1. 用户 A 登录，模块读取当前 `AccountTicket(accountId=A, epoch=n)` 并加载 A 的私有数据。
2. 用户退出、换账号或认证账号变为 B；session 同步递增 epoch、使 A ticket 失效，并触发各模块 `resetForAccount(B)`。
3. 所有私有状态立即清空或回到中性未加载态；轮询停止/重启归 B，A 的旧请求不得改变 B 的状态。
4. B 首次访问模块时，以 B ticket 发起一次新加载；同 B 同 epoch 的并发读取可去重，不能复用 A 的 pending/快照。
5. B 保存或购买时，提交体只来自 B 当前表单快照；A 的字段、错误、版本、成功回调和 notice 不得进入 B。
6. 页面卸载时释放局部 watcher、轮询和回调；已经发出的服务端业务不回滚，但响应不得回写已销毁组件。

### 4.2 行为变化表

| 场景 | 当前行为 | 目标行为 |
|---|---|---|
| A 正常加载 | 读取并展示 A 数据 | 保持；owner=A，成功后 `loaded=true` |
| A→B | 部分模块可能保留 A 的 loaded/value | 所有私有状态同步清空，B 重新加载 |
| A→登出 | 某些模块可能留余额、通知或表单 | owner=null；私有值、错误、轮询全部清理 |
| A 请求迟到 | 可能覆盖 B 或设置 B 的 loading/error | 静默丢弃，不能写任何 B 状态 |
| 匿名访问 | 公共页面可用，私有请求由各模块自行处理 | 私有 load 不发请求；展示中性空态；写操作仍由原服务端 401 裁决 |
| 余额为 0 | 可能与未加载混淆 | 成功 0 显示 `0 次`；未加载/失败显示 `…`/原失败文案 |
| 组织 O1→O2→O1 | 旧组织响应可能覆盖当前选择 | 每次切换递增 revision，旧组织响应失效 |
| 购买/预算提交中换号 | 旧成功可能修改 B | 旧结果仅可返回调用方的过期结果，不得更新 B UI/余额/订单 |
| 组件卸载 | 局部请求 finally 可能回写已销毁 state | 不回写、不重新打开、不显示 notice；释放 timer/watch |

### 4.3 状态定义

| 状态 | 进入条件 | 可执行操作 | 展示内容 | 离开条件 |
|---|---|---|---|---|
| `anonymous` | `ownerAccountId=null` | 公共操作；私有写由服务端裁决 | 空态/登录入口，不展示私有旧值 | 账号变为有效 ID |
| `idle` | 当前 owner 已清理且未加载 | 发起当前账号加载 | 空态或中性占位 | 发起请求 |
| `loading` | 当前 ticket 发起请求 | 禁止同 owner 重复请求或按既有去重 | 加载态 | 当前请求成功/失败或账号失效 |
| `success` | 当前 ticket 成功 | 查看、编辑、提交 | 当前账号数据 | 账号变化、重新加载或保存 |
| `empty` | 当前账号成功返回空 | 公共操作/重新加载 | 空列表/未配置文案 | 有数据或账号变化 |
| `error` | 当前账号请求失败 | 按既有规则重试 | 既有错误文案 | 重试成功、重置或账号变化 |
| `stale` | ticket/epoch/组织 revision 不匹配 | 不得写状态或续发动作 | 不单独展示旧错误 | 由新账号/新 revision 请求取代 |

### 4.4 状态迁移规则

```text
anonymous/任何私有状态
  -> anonymous：账号变为 null；清私有值、错误、loading、游标、表单、轮询
  -> idle：账号变为有效 ID；owner=当前 ID，清旧值但不自动把旧 pending 认作当前

idle
  -> loading：当前账号发起私有请求并捕获 AccountTicket
  -> idle：匿名调用，不发私有初始化请求

loading
  -> success/empty：响应到达且 ticket、owner、组织 revision 均匹配
  -> error：当前 ticket 的实际错误
  -> stale：账号、epoch、组织 revision 或组件 scope 已失效；静默终止

success/empty/error
  -> loading：当前账号显式重试或首次加载
  -> idle：resetForAccount 清理

任意状态
  -> stale：旧账号响应、旧组织响应、旧购买/预算回调或卸载后的 finally 到达
```

并发规则：同一账号同一 epoch 的同一资源允许复用一个 pending；账号变化后不得复用旧 pending。A→B→A 时第一次 A 的旧 epoch 仍失效，即使账号字符串再次相同。刷新只恢复认证状态和公共页面，私有内存状态必须重新加载；不新增私有 localStorage。重复通知事件、轮询和加载不得叠加 timer 或请求。

## 5. 业务规则

### 5.1 输入规则

| 字段 | 类型 | 必填 | 默认值 | 允许范围 | 空值处理 | 示例 |
|---|---|---:|---|---|---|---|
| `ownerAccountId` | `string \| null`，内存 | 是 | `null` | 非空字符串或 `null` | 空白/非 string 归 `null`，不得作为有效账号 | `"account-b"` |
| `accountId` | `string`，ticket | 是（发起私有请求时） | 无 | 由 `auth.currentUser.id` 规范化 | 无有效账号则不发私有初始化请求 | `"account-b"` |
| `organizationId` | `string` | 组织请求时是 | 当前选择 | 当前账号可及组织 | 空字符串表示未选择，不发组织私有请求 | `"org-b"` |
| `expectedVersion` | `number` | 预算保存时是 | 当前预算 version 或 `0` | 既有非负安全整数 | 不因换号沿用 A 的版本 | `3` |
| 预算上限字段 | `number \| null` | 预算保存时是 | `null` | 非负安全整数或 null | 空字符串/纯空白→`null`；`0` 保留为真零 | `1000` |

### 5.2 校验规则

1. 账号 ID 必须来自现有认证状态和 session ticket，不接受表单、URL 或响应正文提供的 owner。
2. 账号切换清理必须发生在后续消费方读取新状态之前；旧 ticket 的 `catch`/`finally` 不得写新 owner 的 error/loading。
3. Feishu 提交沿用既有掩码语义：密钥省略表示保持，空白清空；提交体不得补回 A 的 `appId`、folder 或 secret。
4. 预算沿用既有六字段校验：每次/每日/每月分别满足单次 ≤ 每日 ≤ 每月；输入非法不发请求并保留当前账号输入。
5. 预算 409 沿用原冲突文案，不把冲突当成功，不用 A 的响应覆盖 B。
6. 任何当前账号校验失败只影响当前 owner；旧 owner 的失败静默丢弃。

### 5.3 业务判断规则

```text
IF session.isCurrent(ticket) is false
THEN 丢弃响应、错误、finally 状态和后续动作，不修改当前模块状态

ELSE IF ownerAccountId is null
THEN 保持匿名中性状态，不发私有初始化请求

ELSE IF 请求成功且组织 ticket 与当前 organizationId/revision 匹配
THEN 写入当前账号/组织数据并标记 loaded=true

ELSE IF 是当前账号的业务错误
THEN 保留既有错误文案，允许按既有规则重试

ELSE
THEN 按原调用方错误语义处理，不新增错误码或伪造成功
```

### 5.4 权限与业务不变量

| 主体/角色 | 组织/门店/资源关系 | 允许操作 | 禁止操作及服务端拒绝结果 | 测试编号 |
|---|---|---|---|---|
| 已登录账号 B | B 自己的私有设置、积分、通知、个人预算 | 读取/保存自身资源 | 不得读取或提交 A 的字段；服务端仍按原 401/403/业务错误拒绝 | TC82-02-01、TC82-04-01 |
| 商家/主体成员 | 当前账号可及组织和门店 | 查看/操作既有权限范围 | A 的组织/门店/账户响应不得写入 B；越权仍由服务端拒绝 | TC82-03-01 |
| 组织管理员 | 当前组织 AI 预算 | 按现有权限读写预算 | 换组织/换账号后不得用旧 version 保存；409 保持冲突 | TC82-04-02 |
| 匿名 | 无私有 owner | 浏览公共入口、打开登录 | 不发私有初始化请求；写动作不绕过服务端认证 | TC82-01-02 |

不变量：同一 owner 同一资源最多一个去重加载；旧 ticket 不产生任何本地写入/notice/续发；余额和购买记录不跨 owner；钱包/资金金额仍使用现有 `formatYuan`/`formatCents`/`yuanToCents`；前端清理不代表服务端业务回滚。

## 6. 接口契约

### 类型与调用签名

```ts
import type { Ref } from 'vue'

export interface AccountTicket {
  accountId: string | null
  epoch: number
  signal: AbortSignal
}

export interface AccountScopedState {
  ownerAccountId: string | null
  loaded: boolean
  resetForAccount: (accountId: string | null) => void
}

export interface AccountSessionStore {
  ownerAccountId: Readonly<Ref<string | null>>
  epoch: Readonly<Ref<number>>
  capture(): AccountTicket
  isCurrent(ticket: AccountTicket): boolean
}
```

上段是本任务的声明契约，不要求新建公共类型文件；执行者应优先复用 `src/stores/account-session.ts` 中现有 `AccountTicket`，避免重复定义。各状态模块可按实际是否有加载语义返回 `ownerAccountId`、`loaded`、`resetForAccount`；不持有数据的纯 API wrapper 不强行伪造 store，而由调用组件使用 ticket。

### 6.1 请求信息

- 既有请求保持：`GET/PUT /api/settings/analysis`、`GET /api/credits/balance`、`GET /api/credits/history`、通知列表/未读/已读、身份/组织/门店/钱包、`GET/PUT /api/ai/me/budget`、组织预算、`GET /api/credits/packages`、`GET/POST /api/credits/purchase-orders`。
- 是否需要登录：沿用既有 endpoint；公共套餐目录沿用现状，个人记录/余额/预算/通知/身份/钱包仍需既有认证。
- 所需权限：沿用服务端现有账号、身份、组织和角色校验；本任务不新增权限。
- 重复请求：同 owner 的读请求按现有去重或局部组件规则；写请求不新增自动重试，购买/充值沿用既有幂等和服务端结果。
- 身份传递：继续使用 Cookie→Edge 的既有链路；禁止信任浏览器自带 account header。
- 超时/取消：优先传递 `ticket.signal`；取消仅阻止本地回写，不撤销已在服务端提交的业务。

### 6.2 请求参数

请求体保持真实现有契约；以下均为合成示例，不是新增字段：

```json
{"integrations":{"feishu":{"appId":"qa-app-b","folderToken":"qa-folder-b"}}}
```

```json
{"expectedVersion":3,"maxTokensPerRun":100,"maxTokensDaily":1000,"maxTokensMonthly":10000,"maxCentsPerRun":1,"maxCentsDaily":10,"maxCentsMonthly":100}
```

| 参数 | 类型 | 必填 | 说明 | 默认值 | 示例 |
|---|---|---:|---|---|---|
| `accountId` | ticket 内存字段 | 否（不进 HTTP body） | 仅用于本地 owner 判定 | 当前 session | `account-b` |
| `organizationId` | path/query | 按既有 endpoint | 仍由调用方当前组织选择传入 | 无/当前选择 | `org-b` |
| `integrations.feishu` | JSON body | 按既有保存语义 | 不新增字段；secret 掩码/空值规则不变 | 无 | `qa-app-b` |
| `expectedVersion` | JSON body number | 预算保存必填 | 只取当前账号/组织预算版本 | 当前数据 version 或 0 | `3` |

### 6.3 成功响应

成功响应、字段、信封和空列表语义保持现有 endpoint 契约；账号隔离只改变“何时允许写入本地状态”，不改变 wire response。例如积分成功 0 仍是成功值，购买记录空列表仍是空列表，预算 `usage` 的 null 仍表示未计量。

- HTTP 状态码：沿用现有端点；本任务不新增状态码。
- `data` 是否可能为空：按各既有 endpoint；不以空值代替旧账号失效。
- 成功后前端动作：仅当前 ticket/组织 revision 匹配时更新当前模块；旧结果静默丢弃。
- 契约参照：对应现有 composable、`src/types/`、测试和 #80 已批准的协议收敛范围。

### 6.4 错误契约

| HTTP 状态/无响应 | 实际错误字段与值 | 触发条件 | 用户文案 | 调用方动作/可重试性 |
|---|---|---|---|---|
| `401` | 沿用现有响应 | 未登录/会话过期 | 沿用当前文案或匿名空态 | 当前状态清理；可重新登录 |
| `403` | 沿用现有响应 | 无权限/跨组织 | 沿用当前文案 | 当前账号显示失败；不得重试到其他账号 |
| `409` | 预算/模型来源既有冲突响应 | version 冲突 | 沿用当前冲突文案 | 当前 owner 重载；不覆盖表单为成功 |
| `4xx/5xx` | 沿用现有 `error` 字段或读取逻辑 | 业务/服务端失败 | 沿用原错误语义 | 当前 ticket 可重试；旧 ticket 静默 |
| 无响应 | 无服务端错误码 | 断网/取消/卸载 | 当前账号沿用原网络错误；旧账号不展示 | 不自动跨账号重放 |

### 6.5 错误处理原则

- MUST NOT 把服务端堆栈、secret、token、完整请求体或旧账号错误展示给当前账号。
- 旧 ticket 的异常必须静默终止，不得修改当前 `error`、`loading`、`notice`、弹窗、余额或订单。
- 当前请求进行中重复点击沿用现有按钮禁用/去重；不新增写请求重试。
- 弹窗/页面可以在账号变化时关闭或显示中性加载态；不得保留旧表单值。

### 6.6 契约不变量与观测要求

- 不变量：A ticket 失效后，本地私有状态写入次数为 0；对应 TC82-01 至 TC82-04。
- 状态码不变量：不新增/修改 HTTP 状态码、错误字段或原错误文案；对应 TC82-02/04。
- 字段不变量：Feishu secret 不回显；预算空白/null/0 的既有语义保持；对应 TC82-02-01、TC82-04-01/02。
