## 4. 目标行为

### 4.1 推广链接生命周期

资格成立 → 推荐官生成 rlid 链接（active）→ 消费者经链接进入购买页（触达落行）→ 7 天内下单：last-touch rlid 归因、订单冻结 policy 版本 → 结束推广/到期/手动失效：链接 ended/expired，新触达不再归因，**既有订单不受影响**（#90 end-promotion 语义保持）。

### 4.2 不变量

- 客户端输入不得改变归因结果与订单分配（rlid 解析全服务端）。
- 触达、归因、标记、暂扣、解除均为幂等事实行；暂扣与确认、确认与解除各自幂等键唯一。
- 自动标记永不直接碰钱（flagged ≠ held）。
- 归因窗口、信用阈值、暂扣阈值全部配置化且改动不影响已落行事实（快照随行走 D96-01 惯例）。

## 5. 业务规则与权限

1. rlid 发放仅限资格成立的推荐官本人（403 越权）；链接可由本人失效（ended），不可删改他人。
2. 归因解释对消费者、推荐官、治理台三端可见，字段一致（rlid 短码、触达时间、窗口口径）；治理台可按 rlid 查全生命周期（发放/触达/订单/失效）。
3. 信用与暂扣阈值修改走治理台既有配置权限；看板与队列仅治理台可见。
4. 暂扣处理期限默认 72h（可配）：到期未处理进超时视图（复用 #96 C96-06 机制）。

## 6. 接口契约

既有信封与身份断言不变。新增（登记 Edge RouteManifest）：

- `POST /api/v2/promotion/links`：发放，返回 `{referralLinkId, url, expiresAt}`；`GET /api/v2/promotion/links`：我的链接列表（含 status 与失效原因）；`POST /api/v2/promotion/links/{id}/end`：本人失效。
- `POST /api/v2/orders`：请求体新增可选 `referralLinkId`（与旧 `recommenderAccountId` 互斥，两者同传 400；解析失败/失效/过期 → 422 带可解释 reason，订单仍可无归因创建）。
- `GET /api/v2/orders/{id}/attribution-explain`：归因解释读模型（rlid 短码、touched_at、窗口口径、失效原因或归因成立依据）。
- identity 推荐官画像读接口：social_accounts 项增 `source`、`collectedAt`（兼容：缺省 self_reported + null 采集时间）。
- 商家信用：`GET /api/merchants/{orgId}/credit`（指标+标签+口径版本）；任务列表/详情响应内嵌商家信用摘要。
- 看板：`GET /api/admin/commerce/ops-dashboard`（指标+数据来源标注+统计窗口）；`GET/POST /api/admin/commerce/order-holds`（队列/确认暂扣/解除，admin 鉴权）。

状态码：400 参数/互斥；401 未登录；403 越权；404 不存在；409 幂等/状态冲突；422 rlid 解析不可归因；503 下游不可用。
