## 3. 已定技术决策

### D01：资源归属由持久父关系决定

优先级：可证明的组织/共享引用 → 他人个人父对象 → 本人个人父对象 → 明确本人 owner 的无父孤儿 → 归属未知。前两类保留；本人个人和已证明本人孤儿清理；未知/互相矛盾的 owner 或父链不删除并阻止该 manifest 被标记 verified。不得把所有“查不到父”默认为公共，也不得仅凭作者清组织子表。

同一行有多条父链时任何存在的组织/共享父均须保护；两个存在的个人父账号不一致属于冲突，不能靠 JOIN 内连接悄悄漏数。无 owner 且父已缺失的行不猜账号，不加入某个人清理；若已有该 manifest 的对象条目指向它，按不明归属失败记录处理。正常保留的组织记录不算个人残留。现有财务审计脱敏规则不变。

### D02：既有组织密钥维护是窄例外

只在 ai_provider_key 的 UPDATE、OLD/NEW organization_id 均非空且相等、id 与 owner_account_id 不变时，允许合法服务调用维护原记录。可变列固定为已核对仓储实际 SET 的 `base_url`、`model`、`encrypted_key`、`key_version`、`masked_hint`、`enabled`、`updated_at`；其中 enabled 只允许不变或 true→false，不能借例外重新启用。其余 OLD/NEW 列必须相同，包括 capability、provider、created_at。迁移用去除上述可变列后的行比较实现，不能只比较四个字段而放行任意列。

V87 不对所有 org 行 RETURN NEW、不放开 INSERT、不放开改 owner/org、不改变创建者审计记录。数据库触发器不代替当前操作者鉴权；沿用组织控制器与 IdentityOrgAuthorizationClient。组织管理员 B 的会话与权限正常才可维护；已注销 A 不能凭此新增任务或维护个人密钥。

### D03：缓存登记不再依赖共享整对象 RMW

保留对外 `registerAccountKey/clearAccountCache` 签名。新增 `activateAccountCache(accountId, onInvalidate?)` 与 `readAccountKey`（完整签名见 §6.2），由账号 store 对有效会话激活，释放函数在换号/销毁时调用；注册也幂等确保通知监听，不要求“先清一次才订阅”。onInvalidate 只失效当前账号旧票据，不能回调 clear 形成通知环。

- v2 每键元数据：local 区缓存的元数据写 localStorage，session 区写本标签页 sessionStorage；每条一个 storage key，采用 JSON 编码的 `[accountId, area, key]` 加固定版本前缀，禁止通过模糊 startsWith 匹配账号。记录 `{version:2, accountId, area, key, generation}`，不存内容。
- 每账号 localStorage 一个 `clear generation` 墓碑，值为独立操作 UUID；激活捕获 generation，注册前后均核对，清理代次变化即删除本次缓存而不登记。广播/`storage` 事件中的远端清理使该会话的旧写资格失效，必须等下一次显式账号激活才恢复；订阅回调使同账号旧 AccountTicket 失效，保留 auth 数据本身，不冒充登出。
- `clearAccountCache` 先生成/写入新墓碑，再清本页拥有的键；广播 `{version:2,type:'clear',accountId,operationId}`，接收端只清不转发。`storage` 事件为无 BroadcastChannel 的同源回退；操作 ID 去重。接收端用自己的 session 登记，不读已被别人删掉的 shared 表。
- 不再使用 500 条丢弃上限。任一持久化登记失败，删除刚写的实际值并禁用该次持久缓存，业务内存态继续；storage.removeItem 本身失败时保留内存重试信息，不能声称物理删除成功。无法访问 storage 的浏览器无法保证删除，测试与结果必须如实记录。
- 注册与删除按“值/元数据/墓碑”前后复查，清理同步任务末尾再扫本账号元数据；并发写的旧代次记录在清理接收、恢复读取和激活时均被清除。恢复读取不得绕过 generation 验证。
- 返回值仍为本标签页实际移除且此前存在的私有内容键数量，不含元数据、其他标签页、主题；重复清理返回 0。不广播缓存内容、凭据或草稿文本。

首次有效登记可建立默认缓存会话以兼容原调用者，但已失效会话不能由迟到 register 自动重新激活。`readAccountKey` 是两处实际消费者恢复值的入口，只接受与当前已激活 generation 相符的元数据；v1 只在尚无清理墓碑时导入，存在墓碑时旧值删除而不猜它是新缓存。收到延迟/乱序 clear 时读取当前墓碑，删除 stale 代次，保留已在当前代次重新激活写入的新值；不以晚到的旧 operationId 覆盖当前墓碑。

`clearAccountCache(...,{broadcast:false})` 为只清本页的接收模式：不写新墓碑、不发送 BroadcastChannel、不重复触发账号失效回调；事件入口按 operationId 调用一次失效，再使用当前墓碑清 stale 值。默认主动清理才创建新 generation。墓碑写失败时仍尽力删除本页已知值并广播该次操作，但不能宣称未收到通知的其他页已完成清理；记录降级边界，不悄悄当作全成功。

### D04：轮询只在活动且有目标时存在

`disposed` 一经置 true 永不恢复；pause/换目标递增请求代次并 abort 只读请求、清 timeout。使用请求完成后 5,000ms 的单次 setTimeout，不使用 setInterval；同一目标 refresh 在途只返回同一 Promise，不重叠请求。目标以 tuple 捕获，不用 `split('|')` 还原业务 ID。

活动条件为非 hidden、非 KeepAlive deactivated、非 disposed、当前账号票据有效且 target 非空。隐藏与失活分别记录；显示页面不能激活仍处于 deactivated 的组件。重新活动立即查询一次，成功 pending/processing/retry_wait 才继续；succeeded/needs_review/空结果停止。失败保留已有资金快照、显示错误并停止自动轮询，由手动刷新或重新活动恢复；abort 不显示业务错误。target(null) 清资金、错误与 loading。

### D05：真实清单扫描采用可检测边界，未知形式失败

表清单扫描 `database-bootstrap/src/main/resources/db/bootstrap` 与 identity/marketplace/finance/trust/intelligence 五服务的 `src/main/resources/db/migration`，均在 `platform-java/services/` 下。只处理实际 SQL 文件，记录相对路径与版本；按迁移顺序解释 CREATE TABLE（含 IF NOT EXISTS、引号、schema、分区声明）、ALTER TABLE RENAME、DROP TABLE；同逻辑表多次幂等声明保留来源集合，不重复计资源。默认 schema=public，规范键 `schema.table`，service 是登记属性，不靠表名前缀猜。

Java 采用 JDK 25 自带编译器树 API 解析生产 `src/main/java`（五服务及 `platform-messaging`）；新增 `LifecycleJavaInventory.java` 只 parse，不编译/执行业务、不解析依赖。识别 record/class 信封的 eventType 参数、构造点、outbox append 调用、返回/转交信封的工厂。覆盖已存在的 EventEnvelope、IdentityEventEnvelope、TrustEventEnvelope 与私有 EventEventEnvelope；工厂按实际返回类型和调用关系识别，不能仅白名单几个类名。

字面量、静态常量、有限条件分支及工厂参数沿调用点传播，输出事件类型、真实生产方法及工厂链。无法静态解析的生产点输出 `unresolved-production-site` 并失败。显式动态解析条目必须指定确切文件+方法签名+调用表达式 token 摘要、有限 eventTypes、依据与守卫 TC；修改该生产点/相关调用点使摘要失效。禁止 `any`、通配符、仅按类名存在或任意字符串扫描宣称完整。SQL 动态建表/不支持的 DDL 同样报未解析，不静默跳过；纯触发器函数不应被当新表。

静态门禁保证的是已声明 SQL/Java 生产边界内无未解释项，不是所有运行时行为的形式证明。新增未支持语法必须扩展识别器及反例或精确登记；不扩展到前端缓存/Kafka Topic/外部库自动扫描。

### D06：历史豁免精确而不可自动续期

新增 `lifecycle-inventory.baseline.json`，包含 `version:1`、`baselineHead`、`requiredResources`（当前 18 条规范键）、`requiredEvents`（当前 31 类型）、`legacyResources`、`legacyEvents`、`dynamicEventSites`。required 数组逐项从当前登记冻结；不得只写 >=18 / >=31。原登记中的资源/事件不能转入历史豁免。

历史未登记项可以逐项列入 legacy，必须有完整 id、真实源码锚点、规范化 token SHA-256、明确 reason 与关联跟进说明；空理由、重复、与正式登记重叠、悬空源码、摘要漂移均失败。一个事件新增生产点不能被该类型原来的历史条目覆盖。首次基线采集允许本地生成候选，但逐项审阅后入库；正常 `quality:lifecycle` 绝不写基线。对风险不明的旧项说明“存量未建生命周期契约”，不得伪造为无需清理。

resources/events 与真实清单双向核对：发现减登记/加真实表或事件、登记指向不存在的活跃对象、producer 不匹配、consumer 方法不存在、未知派生表均非零退出。retired 需要理由及实际 DROP/生产代码已移除证据，单填 retiredNote 不足以放过仍活跃资源。此批不新建任何业务事件或改变消费行为。

### D07：HTTP 错误解析只消费一次

真实 Response 优先 `text()` 一次，再 JSON.parse；不先 json 再 text、不 clone 两份。仅旧测试对象缺 text 且有 json 时允许单次 json 分支；新增测试必须用真实 Response。两入口共用 `readErrorDetails`。保留 status/code/blockedReason；error 为空或非 string 时仍保留合法机器字段、message 使用 fallback。

trim 后显示文本最多 500 个 Unicode code point，超长截断并加省略号（总长不超过 500）；去除除换行/tab 外的控制字符。空体、读取失败、看似 HTML/XML（Content-Type 或起始标签）、以 `{`/`[` 开头却损坏的 JSON、合法非错误 JSON 均使用 fallback；普通纯文本保留。不记录原始错误 body，不使用 v-html。成功信封、成功 raw/text/SSE/上传协议不改。

### D08：格式与验收分离

格式卡只接触 §9 W08 的 30 个既有文件以及本批已授权的 Java 改动文件；用现有 Eclipse Spotless，不改 formatter/ratchet/阈值。不以全量 apply 引入未授权文件。集成测试必须包含修复前会失败的反例；缓存命中、只跑 Chromium 或只做源码字符串断言都不能称最终通过。
