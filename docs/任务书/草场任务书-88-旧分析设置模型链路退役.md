## 1. 目标与范围

### 1.1 一句话目标

删除 intelligence-service 中已无任何调用方的旧分析模型接口（`POST /api/settings/analysis/models`、`POST /api/settings/analysis/verify-model`）与 `ModelListingService` 的用户侧旧读取链，并让 `/api/settings/analysis` 的 GET/PUT 对存量 `user_settings.features` 配置「API 双向不可见、存储原样保留」，使模型解析的唯一真相收敛到 AI 控制面（`/api/ai/keys` BYOK + 治理台平台凭据/平台模型配置）。

### 1.2 背景与价值

前端模型配置已于 2026-08-26（commit `598fcedd`，任务书 #47 S7c）收敛到「AI 创作中心 → 模型密钥」+ 治理台平台模型配置，生成路由已由 `RoutedTextCompletionService` 统一（commit `f90352cf`，不读 `features`）；但后端仍保留旧模型列表/验证接口、`SettingsSchemaGuard` 仍白名单放行 `features.*` 读写、`ModelListingService` 仍从旧 settings 读未掩码凭据。这是历史兼容债务：旧数据继续被读取却已无可视化管理入口，且与新控制面存在双真相风险。本任务完成 sunset 收尾。

### 2.5 当前行为（2026-09-06 核验）

1. 前端 `src/stores/analysis-settings.ts` 只对 `/api/settings/analysis` 发 GET（加载）与 PUT（`saveFeishuCredentials`，载荷只含 `integrations.feishu`）；全仓（`src/`、`test/`、`scripts/`、e2e）对 `/api/settings/analysis/models` 与 `/verify-model` **零调用**（grep 核验；`src/views/image/ImageAnalysisView.test.ts:197` 反向断言该视图不调用 settings）。
2. 生成路由统一走 `RoutedTextCompletionService` / `FrozenTextExecutionService`（BYOK 开关 → `ai_provider_key`，否则平台控制面），**不读** `user_settings.features`（`"features"` 在 main 代码的命中仅在 settings 包与 Runner）。
3. `POST /api/settings/analysis/models`：`requireFeature` 校验 body 的 `feature` → `callers.resolve` 鉴权 → `ModelListingService.listModels(accountId, feature)` → `resolveProviderConfig` 从 `user_settings` 读**未掩码** `features.<feature>.baseUrl/apiKey` → `pinnedClient`（HTTPS + DNS 钉扎）GET `{baseUrl}/models`。
4. `POST /api/settings/analysis/verify-model`：同上，POST `{baseUrl}/chat/completions`（`max_tokens=1`）验证。
5. `GET /api/settings/analysis`：`AnalysisSettingsService.get` → 读行 → `SettingsSchemaGuard.normalize`（白名单含 `features.{video,image,article,imageGeneration,videoProduction}` 与 `integrations.feishu`）→ `maskSecrets`（apiKey/apiToken/appSecret → `****`+末4位）→ 响应 `{success:true,data}`。
6. `PUT /api/settings/analysis`：读当前行 → normalize → `mergeAnalysisSettings`（掩码感知：缺字段=保留、掩码=保留、空串=清空、明文=更新；features 五节 + feishu 都参与 merge）→ 再 normalize + `validate`（features 坏值如枚举外 provider/私网 baseUrl → 400；整包 ≤8192 字节）→ upsert 整行 → 返回 masked。
7. `ModelListingService.listModelsAt(baseUrl, apiKey)`：不经用户 settings，供治理台 `GET /api/admin/ai/credentials/{id}/models`（`PlatformProviderCredentialController.listUpstreamModels`）实时列上游模型；SSRF 口径与用户侧共用 `pinnedClient`。
8. `LegacySecretMigrationRunner`（启动期 ApplicationRunner，默认开）：把 `features.video.apiKey` 迁入 `ai_provider_key`（capability=text，幂等跳过条件=已有 enabled text 个人密钥；`provider=coze` 或无 baseUrl 不迁）+ 给 `integrations.feishu.appSecret` 旁路加密；**不删明文**（注释称清空留给「V51」，实际 V51 已被平台凭据模型表占用，清空迁移从未创建，当前最大版本 V67）。

### 2.6 当前问题

- 现状：旧模型接口无任何调用方但仍在服务端存活；`features.*` 仍可经 PUT 写入、经 GET 读出（掩码后）；`ModelListingService` 仍从旧 settings 读未掩码凭据调上游。
- 问题：新 AI 控制面（`/api/ai/keys` + 平台凭据/模型配置）与旧链路双真相并存；旧数据被读取但无管理入口；`resolveProviderConfig` 是全链路最后一个「读旧配置调上游」的点。
- 影响：用户误以为改旧配置生效（实际不生效——路由已不读）；旧明文密钥持续驻留可写路径；维护面翻倍。
- 根因：2026-08-26 前端收敛与 2026-08-31 路由统一后，后端 sunset 收尾未做。

### 决策记录

#### D-01：旧端点直接删除，不做保留期代理层或 410 过渡

- 决策：删除两个 `@PostMapping` 及其辅助方法，请求落到 Spring 默认 404；sunset 日期 = 本任务发布（2026-09），记录进 README 与契约矩阵。
- 原因：需求原文要求「完成存量迁移后删除旧模型列表/验证接口」；存量迁移由 `LegacySecretMigrationRunner` 持续完成（幂等、已上线数周）；且全仓零调用方（§2.5 第 1 条），「保留期内只读+打日志」的观测对象（旧端点流量）不存在，代理层纯属负担。
- 放弃方案：返回 410 Gone 的显式 sunset 端点；Edge 层拦截。二者都要为不存在的调用方维护代码。

#### D-02：`listModelsAt` 保留在 `settings` 包原位、原签名

- 允许执行模型修改：否

#### D-03：`features` 采用「API 双向不可见 + 存储原样保留（preserve-on-write）」

### 5.1 输入规则（`PUT /api/settings/analysis` 请求体）

| 字段 | 类型 | 必填 | 默认值 | 允许范围 | 空值处理 | 示例 |

- 未知顶层键：静默丢弃（既有守卫行为不变）。
- `GET` 响应字段：仅 `integrations.feishu.{appId,appSecret,folderToken}`（密钥掩码形态）。

### 5.2 校验规则

1. `integrations.feishu` 已知键坏值（非字符串/超长）→ 400（既有，保持）。
2. 整包序列化（**含被保留的存量 features**）> 8192 字节 → 400「设置内容过大（上限 8192 字节）」（既有，保持；存量行经 V27 归一后均 ≤8KB，触发概率≈0，见 C-02/E22）。
3. `features` 不再有任何值校验（请求侧被忽略；存量侧原样透传不校验）。
4. 校验失败 MUST：不落库、返回 400、存储保持请求前状态。

### 5.3 业务判断规则

```text
IF 请求方法+路径命中已被删除的旧端点（models / verify-model）
THEN Spring 路由不匹配 → 默认 404（不进入任何 handler）

IF PUT 请求体含键 "features"（值为任意）
THEN 记一条 WARN（含 accountId，不含任何 features 内容）
    且该键不参与 merge、不落库、不出现在响应

IF 存量行 settings_json 含非空 "features" 对象
THEN 写路径将其 deepCopy 后原样放回待写 JSON（含未知键，不归一、不校验其内容）
    且响应映射中移除该键

ELSE（无 features 或非对象）
THEN 待写 JSON 不含 "features" 键

IF GET
THEN normalize 后 features 必然缺席 → 直接掩码 integrations.feishu 返回
```

### 6.4 错误契约

被删端点（A/B）：

| HTTP 状态/无响应 | 实际错误字段与值 | 触发条件 | 用户文案 | 调用方动作/可重试性 |
|---|---|---|---|---|
| 404 | Spring Boot 默认错误体（`{"timestamp":...,"path":...,"status":404,"error":"Not Found"}` 类形态；**无** `success` 字段，非站内信封） | 任意 POST 到已删路径 | 无前端文案（无调用方） | 不可重试；调用方不得按 `{success,error}` 信封解包 |

保留端点（C/D）错误完全不变（FACT，现状）：

| HTTP 状态/无响应 | 实际错误字段与值 | 触发条件 | 用户文案 | 调用方动作/可重试性 |
|---|---|---|---|---|

### 6.5 错误处理原则

- MUST NOT 把服务端原始错误堆栈展示给用户（既有，无变化）。

- 请求失败后是否允许重试：是（PUT 幂等于整行最终状态）。

```java
public Mono<Map<String, Object>> update(String accountId, Map<String, Object> partial) {
    if (partial != null && partial.containsKey("features")) {
        logger.warn("Legacy analysis features payload ignored on settings update (account={})", accountId);
    }
    return repo.findByAccountAndType(accountId, SETTINGS_TYPE)
            .map(this::parseJson)
            .flatMap(raw -> {
                Map<String, Object> current = SettingsSchemaGuard.normalize(SETTINGS_TYPE, raw)
                        .isEmpty() ? defaultAnalysisSettings()
                        : SettingsSchemaGuard.normalize(SETTINGS_TYPE, raw);
                Map<String, Object> merged = mergeAnalysisSettings(current, partial == null ? Map.of() : partial);
                Map<String, Object> stored = new LinkedHashMap<>(merged);
                Map<String, Object> preserved = preservedFeatures(raw);
                if (!preserved.isEmpty()) {
                    stored.put("features", preserved);
                }
                String serialized = toJson(stored);
                SettingsSchemaGuard.validate(SETTINGS_TYPE, merged, serialized);
                return repo.upsert(accountId, SETTINGS_TYPE, serialized)
                        .thenReturn(maskSecrets(merged));
            });
}
```

  （提示：避免重复调用 `normalize` 两次——先 `Map<String,Object> normalized = ...normalize(...)` 再判空选默认；上式为语义规格。）
- 输入：`partial` 为 controller 透传的 JSON body（可能含 `features`）；输出：masked 可见映射（无 features）；副作用：一次 `upsert`（整行，含 preserved features）。
- 不变条件：响应永不含 `features` 键；`stored` 中的 `features` 与 `raw` 中的 `features` deepCopy 等价；`validate` 收到的 `serialized` 是实际写库串（8KB 检查对真实写入生效）。
- 清理与失败：`validate` 抛 400 时不 upsert（Reactor 链天然短路，与现状一致）。
