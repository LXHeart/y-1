## 1. 目标、范围与交付

### 1.1 一句话目标

让用户在现有 AI 创作中心中，从真实资料或已有原稿出发，完成可编辑、可恢复、可追溯的图文策划、图片制作、文章排版和实际文件交付，并可将确认过的公众号文章存入自己绑定账号的草稿箱。

### 1.4 明确不做

- 不恢复独立信息图／SVG 创作品类。历史[任务书 #55](草场任务书-55-信息图生成.md)文首明确记录“品类取消”；其遗留 migration 不代表功能仍有效。

- 不做通用 skill 上传／执行市场，不执行用户提交的脚本、`SKILL.md` 或任意 HTTP 工具。
- 不接入非官方 Gemini Web、X Cookie 接口、本机个人 Chrome 登录态或微信群摘要。
- 不新增 X／微博／YouTube 发布平台，不做翻译、漫画、PPT、自动检索、通用网页采集、一稿多平台自动分发。

### 1.6 用户与入口

## 4. 用户流程与状态

### 4.1 场景入口

在“开始创作”的现有平台／形式区域旁提供“从已有内容开始”，打开内嵌来源区；不新增顶级导航。四个模板：

| recipeId | 用户名称 | 适用平台／形式 | 模式 | 进入位置 |
|---|---|---|---|---|
| `social-card-series` | 攻略／知识图卡 | 小红书、抖音 graphic | create、adapt | 文章页图卡区 |
| `article-visuals` | 文章封面与配图 | 公众号、知乎 graphic | create、adapt、format | 文章页配图区；format 可加图但不改文字 |
| `article-format` | 原稿排版 | 公众号、知乎 graphic | format | 原稿编辑＋排版预览 |
| `cover-only` | 单张封面 | 上述四平台 graphic；既有视频封面工具可读取预设 | create、adapt、format | 现有配图／封面区域，不修改视频制作流程 |

模板版本均从 `1.0.0` 开始。未知组合返回不可用原因，不静默切换平台。大众点评和朋友圈保留原有专用流程；不得把普通图卡模板当成真实体验证明。

### 4.2 主流程

1. 保留已锁定的任务、门店、平台与形式，选择本次加工方式。
2. 输入主题，或粘贴／选择原稿；检查可用事实、身份及已有素材。
3. 导入后进入正文编辑。format 跳过标题、大纲和正文生成；adapt 允许直接拆卡或提出全文改编建议。
4. 选择模板，系统提出一套视觉计划。逐页展示目的、对应原文、关键文字、布局、插图说明和画幅。
5. 保存计划并确认版本；查看费用估算与模型参考能力。默认“先生成封面”，也可明确选择“生成整套”。
6. 展示每项真实阶段和候选，允许比较、单项重做、采用；采用后才更新交付媒体。
7. 完成正文与媒体联合预览，核对声明和发布字段，保存指定版本。
8. 下载文件；已连接且具备权限的公众号账号可存入草稿箱并回读结果。

|---|---|---|
| 原稿输入 UI | empty、editing、saving、saved、error | saving 禁重复导入，error 保留原文；已创建文档不可变，重新导入创建新 ID |
| 文本建议 | preparing、ready、failed、unknown、applied | ready 可看差异并应用；unknown 只读取确认，不自动再生成 |
| 视觉计划 | preparing、ready、failed、unknown；另有 revision、confirmedRevision、stale | ready 可编辑；修改使 confirmedRevision=null；stale 不允许生成或采用 |
| 视觉父任务 | queued、running、succeeded、partial、failed、cancelled、unknown | 成功／部分成功可查看候选；unknown 有待核实子项，不当成普通失败 |
| 视觉子项 | waiting_anchor、queued、prepared、dispatching、generated_unsettled、succeeded、failed、cancelled、unknown | dispatching 后无确定结果不得重新派发；generated_unsettled 只恢复结算，不重生成 |
| 导出记录 | building、ready、failed | ready 可重新签发下载链接；过期文件可按相同不可变快照重建，不调用 AI |
| 公众号连接 | unverified、active、invalid、disconnected | 校验成功后 active；断开后不能新建同步，已存在同步仍可读 |
| 公众号同步 | preparing、uploading、submitting、verifying、succeeded、failed、unknown、cancelled | succeeded 必须有草稿 ID 且回读一致；unknown 只核实，不盲重发 |

`CreationProjectStatus` 与 `CreationRunState` 现有枚举保持不变。细粒度任务状态由专用 API 返回；workspace 只写这些对象的引用及必要摘要，不能添加新枚举值绕过旧校验。

### 4.4 关键迁移

- 计划编辑成功：revision+1，清除旧确认；已生成候选保留但不自动迁移到新计划。
- 草稿正文／平台／brief 相关事实变化：当前内容摘要与计划基线不同，stale=true；变更发布描述或非正文标题显示不自动重生成图片。
- 生成封面成功：先保存原始媒体与结算结果，再允许后续图片使用该 artifact；用户另选封面不触发后续重做。
- 子项已全部结束：若存在 unknown 则父任务 unknown；否则全部成功为 succeeded，成功与失败／取消混合为 partial，无成功且全取消为 cancelled，其余为 failed。
- 取消：未派发项 cancelled；已发出的供应商调用继续核实结果与结算，不承诺立即停止外部计算或自动退回所有成本。
- 关闭／KeepAlive 失活：停止当前视图轮询与 UI 更新，保存本地编辑；后台视觉任务按已接受操作继续。账号 epoch 改变后丢弃所有旧响应、订阅和缓存。
- 微信 submitting 响应丢失：unknown；拿到 media_id 后进入 verifying；验证失败不显示“已存草稿”。

## 5. 业务规则与不变量

### 5.1 输入上限（NEW）

本表是产品和服务保护上限，不宣称是外部平台的全部限制。当前 Brief 的既有约束继续生效。

| 输入 | 范围／默认 | 超限或非法处理 |
|---|---|---|
| 新原稿 | 非空，最多 30,000 Unicode code point 且 UTF-8 ≤128 KiB；只接受 TXT／MD 文本 | 400 STUDIO_LIMIT_EXCEEDED；不截断、不先覆盖旧稿 |
| 原稿块 | 顶层段落／标题／列表／引用／表格／代码块，最多 500；块 ID 由服务端生成 | 400；不把嵌套块重复计为原文 |
| AI 输入选择 | 最多 200 个不重复块，合计最多 8,000 code point | 400，并要求用户选择处理范围；未选择部分保留且显示未覆盖 |
| 图卡／插图 | 图卡 1～9；文章插图 1～8（含封面）；cover-only 恰好 1 | 400；不沿用上游 10 张作为新增限制 |
| 图卡文字 | title ≤60、bullets 0～5 条且每条 ≤80、caption ≤500、purpose ≤200、illustration ≤1,000 code point | 400；数字和专有名词不得通过静默截短适配 |
| 样式 | styleId/layoutId/paletteId 取本地既有目录；计划的每项可覆盖 layoutId | 未知 ID 400；旧合法 ID 保留 |
| 引用媒体 | PNG／JPEG，真实解码，单张 ≤10 MiB 且 ≤25MP；原生图片编辑实际发送参考图 ≤5 MiB | 无法满足时先做可检查的确定性压缩；超限 400，不丢弃参考图继续生成 |
| 结果与工作区 | 现有 resultRefs/runIds 上限 20、workspace 64 KiB 不变 | 候选历史放服务器；不裁掉工作区字段以求保存成功 |
| ZIP | 最多 20 媒体项；源文件合计及最终包分别 ≤100 MiB | 400，列出超限项；不返回缺图但标完整的包 |
| 列表 | limit 默认 20、范围 1～50，cursor 为不透明 keyset | 非法 cursor 400；无结果 items=[]、nextCursor=null |
| 公众号正文 | 渲染 HTML UTF-8 ≤1 MiB；title 1～64 字，summary ≤120 字，author ≤32 字 | 按本地上限拒绝，不自动删改；若账号 API 更严格则失败并展示可行动原因 |
| 公众号图片 | 初版最多 20 张，正文上传产物每张 ≤1 MiB，封面 ≤2 MiB；均 JPEG／PNG | 先按 §6.8 压缩验证；达不到则返回对应图片错误 |
| 请求 ID | UUID；旧图卡接口原 requestId≤128 字规则不变 | 新 API 缺失／非法 400；旧 API 保持既有可选语义 |

新 code point 计数不修改历史接口采用 UTF-16 长度的规则；前后端新 DTO 使用相同计数方法和合成边界样例。正文只统一 CRLF/CR 为 LF；不做 NFKC、数字替换、全角半角转换或自动删除空格。

### 5.2 来源、事实与任务

1. 新来源 doc 归属 draft 的 owner，导入不改变 `sourceType/taskId/taskVersion/storeId/contextSnapshotId`。`inputKind` 只说明文字输入形式，不能代替任务来源。
2. 任何任务声明存在时，生成前按现有 `GraphicTaskCreationContext`／`ArticleCreationContext` 核实冻结快照和平台。缺少快照或字段互相冲突时拒绝，不静默降为独立调用。
3. 素材在选择、计划确认、worker 读取、采用、导出和渠道上传时重新核对归属、授权、删除／隔离状态。只保存 ID，不信任浏览器给出的签名 URL／文件路径／owner。
4. 原稿中的链接先作为来源或文本保存；不自动抓取，也不自动下载远程图片。内嵌图片需用户映射到已授权素材。
5. 仅已确认的用户经历可写成第一人称；价格、日期、地址和引用有明确来源。上游示例的“90%”“99%”等数字不得作为默认事实。

### 5.3 原文排版与改编

- format 的正文源为已经保存的当前草稿版本；渲染不调用 LLM、不替换标题、不生成摘要、不改词句。缺少发布元数据时提供手工填写或单独的“生成标题／摘要建议”。
- Markdown AST 可改变 HTML 结构，但解码后的文本 token 序列、数字和引用内容必须保持；换行和标签变化按规范化比较，代码块内容逐字保留。
- 原始 HTML 块作为转义文本显示并给出提示；不执行／直接注入。外链保持受控链接，远程图片显示待绑定占位，不进行网络访问。
- adapt 的 AI 结果存为 TextProposal，展示原文／候选差异与变更摘要。应用前验证 draftVersion 和正文 hash，一次原子写入正文及适用元数据；旧稿仍在历史版本中。
- 图卡拆解允许压缩表达，但来源段落与关键事实可追溯。不能把“摘要拆卡”标成“原文不变”。

### 5.4 计划、生成与采用

- 推荐结果必须符合请求的平台／形式、页数、合法样式和来源块集合；未知 ID、重复 cardId、无来源支撑的关键文字、模型返回可执行标记均不能直接采用。
- 一套计划共享 style/palette，每项独立 layout；position 是展示顺序，itemId/cardId 是身份，拖动或删除不重新编号身份。
- 计划确认锁定 revision、contentHash、recipeVersion、材料引用和执行能力指纹；新输入或模型配置变化后重新估算，不自动发起付费调用。
- `reference-image` 仅在原生参考协议可用时开放。`prompt-only` 明确显示使用文字风格约束。MiniMax `character` 参考只服务人物一致，不能冒充整体构图参考。
- 默认先生成封面；生成整套时首项成功后再做后续项，首项失败则后续 waiting_anchor 项停止派发。后续并发最多 2，仍服从现有模型并发门禁。
- 已成功候选作为不可变 artifact 保存。单项重做建立新 attempt 和新操作；只重做请求选中的项，不覆盖其他结果。
- 采用操作仅替换所选 item 对应的已采用引用，其余已授权结果保留；每项最多一个当前采用结果。采用不生成新图、不重新结算。

### 5.5 费用与未知结果

| 动作 | 现有计费入口 | 规则 |
|---|---|---|
| 原稿导入／保存、模板选择、编辑计划、format、采用、导出、渠道同步 | 无 AI 调用 | 不扣 AI 积分，不生成 AI run |
| 改编正文 | ARTICLE_GENERATION | 平台／BYOK 按既有策略；完整文稿只算一次本次调用 |
| 标题摘要建议、文章配图策划 | CREATION_ASSISTANT | 一次请求一个建议／计划；不在后台循环优化 |
| 图卡策划 | CARD_SERIES_PLAN | 一套方案一次调用；用户再选其他策略才有新的调用 |
| 图片制作 | image_generation，feature=null | 保留当前 cents 预算与成本记录，不新增用户图片积分扣费规则 |
| 既有内容深检 | 既有安全服务 | 不旁路既有计费／平台资助规则，不把安全检查假装为免费生图 |

费用估算必须区分 `userCredits` 与 `platformBudgetCents`；BYOK 的外部费用不能显示为“完全免费”。估算失败时不伪造 0 元，生成按钮保持可解释的未就绪状态。

**重试不变量**：外部请求尚未发送可恢复派发；已收到确定失败可让用户重做；已发送但没有可核实结果为 unknown，不能按新 requestId 自动重发。图片已保存但结算未确认时，只恢复既有结算，不再调用图片供应商。公众号 `draft/add` 同理；所有失败补偿沿用现有执行／补偿服务，禁止其他服务直写 finance 表。

### 5.6 并发、时限与资源

- 普通 JSON 读写客户端 30s；策划／改编 120s 客户端上限、模型调用 90s；渲染／导出 120s；图片 API 单项 180s；视觉 workflow 总时限 30min。
- 视觉租约 240s，每 30s heartbeat；租约过期仅回读状态并核实，不据此自动重发 dispatching 项。
- 编辑防抖 800ms；同一 draft 与同一 plan 各一条保存队列。新 UI 通过共享 draft session 执行服务端应用后的 adopt，不创建第二个草稿写计时器。
- 非付费 GET 自动重试最多两次，间隔 1s／2s；401/403/404/409 不自动重试。写请求不自动换键；重复 key 的读取不计算新调用。
- 视觉任务轮询：2s，达到 60s 后 5s；隐藏／失活暂停，激活立即读取，持续 30min 后停止并提供“刷新状态”。未知状态不靠无限轮询隐藏。
- ZIP／图像处理同时最多 2 个工作线程任务／实例，队列 20，超出返回 429；WebFlux event loop 不做 ImageIO、压缩或文件 I/O。
- 源文档、plan、quote、job、artifact 的 UUID 与 account/draft 组合校验；不因 UUID 难猜就省掉 owner 检查。

## 6. 接口、类型与执行契约

### 6.1 通用 wire 规则

所有 NEW JSON 端点沿用 `{success:true,data}`／`{success:false,error,code?}`；HTTP 状态由 ResponseEntity 正确设置。身份沿用 `y1.sid` → Edge → 内部断言 → `IntelligenceCallerResolver`，不接受请求体的 owner、organizationId、provider URL 或密钥作为生成身份。

所有有副作用的创建／应用命令包含 `requestId`。服务端先核验 owner 与语法，再使用 `(owner, operationKind, requestId)` 唯一记录和规范化 JSON SHA-256 校验相同输入。同键同输入返回原结果，同键异参 409。JSON hash 按键排序，保留数组顺序，缺省值先按 DTO 归一；不将标题、图片 URL 或当前时间当幂等键。

NEW DTO 拒绝未知字段；字段表中 `?` 表示可省略，`null` 表示允许显式空值。未声明 nullable 的字段显式 null 为 400。旧 DTO 的宽容解析规则不批量改变。表中 UUID 均传 JSON string，版本为正整数，hash 为 64 位小写十六进制，时间为 UTC ISO-8601。

### 6.5 计划与草稿应用的详细语义

**来源解析**：CommonMark 启用 source spans，将顶层节点对应到 LF 归一后的原文 code point 区间 `[start,end)`；嵌套列表仍属于一个顶层块。块 ID 在一个不可变 sourceDocument 内稳定，重新导入产生新 document 和新块 ID，不假称跨稿自动匹配。contentHash 对归一后的完整源文本做 SHA-256；正文不因解析告警丢失。

**来源选择**：策划当前正文前，由 API101-03 的 draft-content 分支冻结当前正文，图卡计划绑定这份文档。最初导入的原文仍作为来源保留。若用户修改正文，旧计划的 baseContentHash 不再匹配，必须重建或重新确认新计划，不能把旧块 ID 挪到新段落。

**推荐缺省**：strategy 未指定时，存在用户确认经历且明确选择体验型内容才选 story；选有至少 3 个既有素材且文字≤1,200 字可选 visual；其余 information。itemCount 未指定时：图卡为 `min(6,max(2,1+ceil(非空块数/2)))`；文章配图为 `min(6,max(1,标题块数+1))`；封面为 1。这些是可修改推荐，不能更改用户显式页数。

**计划输出**：social-card-series 第一项 role=cover，后续为 content/summary；article-visuals 第一项 cover，后续 illustration 且 placement.afterBlockId 必须存在；cover-only 只有 cover。所有 item 的 sourceBlockIds 必须属于本次选择；criticalText 逐字出现在至少一个关联来源块中。未知字段、重复身份、超限、错平台、错角色或无效引用，返回 STUDIO_INVALID_PLAN，不用第二次隐形 LLM 调用“修复 JSON”。

**计划编辑**：客户端提交完整 VisualPlanDocument，服务端逐项校验；PATCH 创建不可变 revision 快照并推进 current revision。revision 改变清除 confirmedRevision；来源、模板 id/version 不允许在 PATCH 中切换，切换必须新建计划。删除封面时要求用户指定新的合法封面；position 重新连续排列，itemId/cardId 不变。

**计划确认**：只确认当前 revision，不增加内容 revision；记录 confirmedRevision、确认时 draftVersion、contentHash 和 actor。保存、确认及任务创建共享计划行锁，不能生成半更新计划。

**估算**：按请求 selectedItemIds 算本次实际图片调用数；若整组 reference-image 需要生成封面，封面必须显式包含在选择和估算中。只生成后续页时 anchorArtifactId 必须指向同计划版本已成功且用户选定的封面。估算包含目标尺寸、引用方式、价目和执行配置指纹；创建任务时再次核对，120s 过期或配置漂移返回 STUDIO_QUOTE_EXPIRED，不悄悄提价或换模型。

**正文建议应用**：adapt-body 仅允许 body/title，suggest-metadata 仅允许 title/summary；用户可以选择其中部分非 null 字段。apply 锁草稿并校验 expectedDraftVersion、baseContentHash、来源和有效期，调用同一草稿持久化路径，旧内容写版本历史。同请求再次调用只返回原 appliedVersion，不再追加版本。

**采用图片**：API101-17 每项必须属于当前计划 revision 且 state=succeeded；同 item 不允许多选。使用当前合法的 deliveryMediaRef 更新 workspace.resultRefs 与 delivery 的对应项；保留未涉及的素材。卡片 cover 更新 coverRef，正文图片保留段落绑定。人工已编辑的标题、正文、摘要和分享配文不被图片采用覆盖。

**共享保存队列（NEW 签名）**：`useWorkspaceAutosave` 增加 `runExternalMutation<T>(action:(expectedVersion:number)=>Promise<{project:CreationProject; value:T}>):Promise<T|null>` 和只读状态 `externalMutationBusy`。它先 flush，失败／conflict 就不调用 action；执行期间禁当前草稿编辑；成功用现有 session.adopt 接收服务器版本后恢复 UI；乱序／账号变更不 adopt；无响应先读当前草稿再决定恢复，不盲重放一次 apply。此动作与现有 800ms 队列互斥。

### 6.6 图像协议、持久执行与参考链

新增 `PlatformProviderNames.OPENAI_IMAGE = "openai-image"`，同步 ALL/PATTERN/MESSAGE、凭据选择器和设置帮助。平台与 BYOK 只允许将该 provider 用于 image_generation；绑定 text/video 等能力返回 400。旧 provider 名不迁移、不自动改协议。

| 协议 | 实际调用 | 引用语义 | 上限／行为 |
|---|---|---|---|
| openai-image | 无参考时 `/images/generations`；有参考时 Multipart `/images/edits` | 通用图像参考 | 首版 1 张 PNG/JPEG，≤5 MiB；显式带 image 文件、model、prompt、size、n=1；生成尺寸仅 1024x1024、1024x1536、1536x1024 |
| 既有 minimax | 既有 `/image_generation` | `subject_reference.type=character` | 保留现有第一张合规人物参考逻辑；通用 reference-image 图卡模式拒绝 |
| 其他现有协议 | 既有生成路径 | prompt-only | 维持旧能力，不因模型名含 image 就推断支持参考图 |

Multipart 的 boundary 由 WebClient 构建，不能手拼；API key 来自既有服务端解密与路由。新增协议仍走现有受信 origin、BYOK 全量 DNS 校验和固定地址连接。实际模型若不接受协议参数，返回受控错误；不删掉 reference 后再请求一次。`openai-image` 只声明调用协议，模型可用性和出图质量必须通过 V-LIVE-IMAGE 证明。

**运行拆分（NEW 内部契约）**：增加 `ImageExecutionObserver`，声明 `Mono<Void> prepared(UUID runId)`、`Mono<Void> generated(UUID runId, UUID mediaId)`。为现有独立／任务图片服务增加接受固定 `executionOperationId` 与 observer 的重载；原方法保留并按旧方式生成 ID。observer 由视觉任务持久层实现，禁止将它变为任意回调脚本。

1. 父任务唯一占位并冻结完整计划、selectedItemIds、quote、配置／价格指纹。每项 attemptId 唯一，executionOperationId 由父任务 ID＋itemId＋attemptId 确定性生成。
2. prepareMediaExecution 完成后，先将 runId、executionOperationId、输入摘要写入子项；`prepared()` 成功后才能发送外部请求。登记失败走既有失败处理，供应商调用数为 0。
3. 外部请求发送前持久化 dispatching；拿到图后按固定 objectKey 保存原始媒体，调用 generated() 持久化 mediaId，再进入既有成功结算。
4. 结算完成才标 succeeded；生成图已保存但结算尚未完成标 generated_unsettled，重放仅读取 run 和恢复既有结算流程。不得再次生图或另造扣退流水。
5. 进程崩溃在 dispatching 且无可确认产物时标 unknown。没有供应商受理证据查询能力时保持 unknown；用户可在明确告知可能再次计费后主动重做，该次 API101-13 必须携带旧 unknown attempt ID 的 acknowledgedUnknownAttemptIds；后台不能代填。
6. API／Temporal 重放先读持久状态。activity 超时或 worker 重启都不能当作“请求肯定没发送”。业务模型调用不采用 Temporal 默认自动重试；最多一次派发由数据库阶段守卫决定。

**Temporal**：新 workflowId=`creation-visual-{父操作UUID}`，task queue=`intelligence-creation-visual`，同 ID 拒绝重复工作流。启动失败留下 queued 行，由每 10s 扫描、批次 20 的收养器补起同 ID；不重新创建父操作。activity 只读取领域服务结果，不能直接扣费；现有视频 workflow、queue 和参数保持。

**图片顺序**：整组第一张成功并完成持久化后，最多并发 2 张后续项；reference-image 将原始封面媒体作为实际参考。保存每项 promptHash、anchorArtifactId、配置指纹；完整最终 prompt 仅存在受 owner 保护的执行记录，不返回公共列表。首项失败时后续停止派发；不能用其他项目的旧图自动顶替。

| targetAspect | 衍生图尺寸 | 默认处理 |
|---|---|---|
| 3:4 | 1080×1440 | 等比缩放并补边，保留全部文字 |
| 9:16 | 1080×1920 | 同上 |
| 1:1 | 1080×1080 | 同上 |
| 16:9 | 1920×1080 | 同上 |

供应商原图与衍生图分别保存；UI 先预览结果，不能把原图尺寸显示成目标尺寸。补边颜色从已选择 palette 的定义读取，属于内容数据；不在 UI 组件新增硬编码色值。首版不提供自动裁掉文字的 cover 裁切，也不覆盖生成图上的文字。原图与交付图相同时允许复用同一个媒体 ID，引用数组仍须去重。

渲染支持标题、段落、列表、引用、粗体、斜体、链接、GFM 表格、代码块和绑定图片。数学公式、Mermaid、PlantUML、原始 HTML 与复杂插件首版不执行；按文字／代码保留并列出提示。两个排版主题 standard/compact 使用同一 AST 和内容，差别只有 token 化的段距、标题层次及边距。

HTML 只输出受控元素 `section,h1,h2,h3,h4,p,span,strong,em,ul,ol,li,blockquote,table,thead,tbody,tr,th,td,pre,code,a,img,br,hr`；属性仅允许渲染器生成的必要项。用 jsoup safelist 再校验，移除事件、脚本、iframe、style 标签、任意用户 CSS、data: 和 javascript:。inline style 只由服务端主题枚举生成。浏览器预览再经现有 DOMPurify；不将原文交给裸 v-html。

图片语法 `![说明](media:<UUID>)` 仅为内部文档引用形式；解析为本草稿授权媒体后才可渲染。外部 URL 图片进入 unresolved 提示；不能由导出服务自动下载。普通 HTTP(S) 引用链接允许输出，可选 citeExternalLinks 转为编号引用；转为引用只改变链接呈现，原文文本仍保留。

新文件格式要求：

- markdown：正文与合法 Markdown 元数据；媒体引用改为包内相对路径，单文件有外置资源时明确说明，不能残留 `media:` 私有协议。
- text：保留正文逻辑顺序、链接和引用文本；不是发布描述的截断版本。
- wechat-html：可导入的完整 HTML；本地包使用相对图片路径，公众号同步阶段才替换为微信已上传 URL。单 HTML 下载对必需图片采用受控资源打包规则，见下面 ZIP 清单。
- bundle-zip：至少包含 `README.txt`、`manifest.json`、`article.md`、`article.txt`、`article.html`、`publication.json`、`sources.json` 和有序 `images/01-cover.png`、`images/02-content.png`；扩展名与真实编码一致，没有图片则 images 目录可省略。

wechat-html 和 markdown 在存在绑定媒体时，文件下载的包装为 ZIP（contentType=application/zip，主文件分别为 article.html/article.md，附 images/）；无媒体时可直接下载该文本文件。format 字段表示主内容格式，返回 filename/contentType 准确描述实际包装。完整 bundle-zip 始终提供以上所有文字文件；publication.json 含标题／摘要／话题／声明和平台，不包含内部凭据／prompt／签名地址。

导出使用指定 draftVersion 的不可变快照和当前仍有效的媒体权限；不能混合当前标题与历史正文。文件名过滤路径穿越与控制字符，压缩包条目只能来自服务端命名，禁止用户相对路径。输出 objectKey 由 exportId 确定，sha256 和实际 sizeBytes 从写出的文件计算。

下载 URL 有效期 900s；导出文件保存 7 天，到期按同版本重新构建。权限撤销后不再签发新链接；已经签发的链接仍可能在 900s 内可用，不能声称能立即撤销。缺失／隔离／无法解码的必需媒体令新导出失败并指出项；旧 manifest 的逐项 unavailable 语义保持。

### 6.8 公众号连接与草稿协议

**连接字段**：displayName 1～80 字；appId 匹配 `wx` 加 16 位十六进制；appSecret 为 16～512 位可见字符，不允许换行／控制字符。服务端用 EnvelopeEncryption 加密保存；缺少加密设施时 503，不保存明文。首版同一 appId 仅有一个未 disconnected 连接，避免两个 owner 同时持有同一发布账号。

校验连接是用户单独点击的操作：调用官方 token 接口确认凭据；成功只说明 API 凭据可用，不声称所有内容发布权限均已验证。绑定／轮换后为 unverified，校验失败为 invalid，保留连接供修正。断开清除可用凭据和 token 缓存并取消未提交任务，不删除外部草稿。

生产出站仅允许 HTTPS `api.weixin.qq.com` 和固定 API 路径；不接受用户设置 host、代理或端口，不跟随重定向，不在启动时访问外网。测试通过依赖注入使用 WireMock，而不是给生产接口增加任意 baseUrl 参数。

token 缓存在既有 Redis，key 使用内部连接 ID＋凭据版本；值用 EnvelopeEncryption 加密，TTL=`max(1,expires_in-120)`秒，最长 7,000s。SET NX 锁 TTL30s 控制多实例刷新，释放锁要校验持有者。Redis 不可用时渠道操作返回 503，不影响本地编辑／导出。日志不得打印含 access_token 的完整 URL。

**上传与草稿装配**：

1. API101-26 验证连接 active、凭据版本、草稿 owner、platform=wechat-official、所选 exportId 对应同一 draftVersion 且主格式包含可用 HTML；声明／元数据／封面齐全。
2. 冻结 title、正文 HTML、summary、author、content_source_url、评论选项、封面和图片顺序。记录规范化 payloadHash；同账号＋draftVersion＋payloadHash 有进行中／unknown／succeeded 记录时返回该记录，不创建第二个草稿。
3. 解码并处理图片：优先保持 PNG；需要压缩时按 JPEG quality 90、80、70 与宽度 2048、1600、1280、1024 的固定阶梯尝试，达到限制即停止；透明图需要转 JPEG 时使用选定排版背景，产物保存可核对，不静默丢图。
4. 正文图片调用 `/cgi-bin/media/uploadimg`，封面调用 `/cgi-bin/material/add_material?type=image`；映射表按连接＋凭据版本＋内容 hash＋用途缓存。两种 media_id／URL 语义不得混用。
5. 仅在所有必需素材已准备且再次核验权限／凭据版本后，持久化 submitting，再调用 `/cgi-bin/draft/add` 一次。payload 的 articles 长度=1，article_type=news；title/content/thumb_media_id 必填；digest、author、content_source_url 有值才带；评论两个字段明确传 0/1。
6. 收到 media_id 先持久化再调用 `/cgi-bin/draft/get`；回读文章 title、content、digest、封面和图片顺序与冻结快照一致才 succeeded。

每次微信请求连接超时 5s、响应超时 30s；每个同步总时限 10min。上传和只读请求最多重试 2 次（1s／2s）；draft/add 不因 HTTP 超时、断线、5xx 或解析失败自动重试。已收到确定“token 失效且未创建”的业务错误时可刷新一次 token 后重试，其他错误按表返回。同步使用专用 Temporal workflow，业务状态与 dispatch 标记在数据库；activity 不复制默认重试副作用。

**未知结果核实**：API101-29 通过 `/cgi-bin/draft/batchget` 按 20 条一页最多读取 100 条，返回与当前同步相关的候选和 hasMore。匹配检查正文规范化 token、标题、摘要、图片引用和封面，不能只看标题。用户选择候选后 API101-30 再 draft/get 核实；未找到或多份内容相同，保持 unknown 并让用户选择，不自动 draft/add。人工提供 media_id 走同样 owner/连接/内容比对，不能仅凭字符串标成功。

回读中的 HTML 可以被平台规范化；比对采用受控 DOM token 序列与已保存上传映射，不比较无意义的属性顺序，也不能忽略文本、数字和图片位置。平台对内容做实质改写时返回 STUDIO_CHANNEL_CONTENT_MISMATCH，保持记录可核对。

### 7.3 事务与并发

1. 生成操作占位与 item 创建一个事务；原子确定谁拥有派发权。HTTP 200/202 只能在记录提交后返回。
2. 计划写 revision、推进指针、清确认在一个事务。采用和正文应用锁 draft 行，再验证 plan/source；锁顺序固定 draft → plan → apply，避免交叉死锁。
3. 外部 HTTP／对象存储／Temporal 调用在数据库事务外。先持久化请求意图，后调用，再 CAS 写回结果；不能长时间持锁等网络。
4. 对父操作同键重放先校验本人，然后比较请求摘要；不得因为参数相同就让另一账号读到结果。
5. 图像 run 绑定在外部派发前落库；结果媒体在结算前落库。首次返回丢失、服务重启和 Temporal 重放都从状态继续，不从函数头重新扣费。
6. 草稿应用返回完整项目；冲突不追加版本、不改变结果选择。已有草稿整行保存逻辑不能把其他新字段清空。

### 7.4 旧数据与删除

- 新增列可空或有安全缺省，旧 v1 图卡记录按旧接口原样读取。新版 Controller 不把缺字段旧行当成可继续执行的 v2 job。
- 旧草稿仍可打开、编辑和导出 manifest；原有成功图卡继续可查看。切到新版需显式创建 source 和 plan，保留旧媒体，不自动重新收费。
- `workspace.inputs.studio.schemaVersion=1` 与整个 workspace.schemaVersion=1 分别校验；视频／朋友圈／点评的 workspace 不注入空 studio，不改变其 hash 或保存频率。
- 草稿软删后所有新资源拒绝 owner API 读取，queued 项取消；运行中的外部请求只收尾持久化／结算，不把结果挂给别的草稿。
- 来源、计划、已采用 artifact 随可恢复草稿历史保留；不因 30min quote/建议过期删除原稿。候选原图至少保留 90 天，已采用结果沿用永久媒体策略；未采用候选清理前需核对草稿历史与 anchor 依赖。
- 导出文件 7 天清理，仅删导出副本；已有媒体和 AI run 不随导出过期删除。微信同步记录至少 90 天，断开连接不删除远端内容。

### 7.5 升级与回退演练

在隔离 PostgreSQL 验证：空库到 V83；V76 有草稿、旧图卡操作、视频画布数据时升级；重跑 migration 幂等语句；约束拒绝非法状态；升级后旧 HTTP／旧前端 fixture 正常。既有数据 row count、内容 hash、媒体 ID、旧迁移 checksum 必须保持。

回退使用开关和旧代码，不执行 DROP 新表／列。旧代码忽略新列，已写 studio 的草稿由新读侧保留查看；若旧前端无法理解，明确只读而非用空对象覆盖。生产回退前先停止新写并处理运行中任务；没有排空证据不能直接停 worker。
