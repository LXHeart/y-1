## 目标

给门店挂一套**公开媒体库**，四类素材（任务书 #24 Stage 6 遗留）：

| kind | 中文 | 形态 |
|---|---|---|
| `storefront` | 门头照片 | 图片 |
| `environment` | 环境照片 | 图片 |
| `menu` | 菜单/价目表 | 图片 |
| `video` | 宣传视频 | 视频 |

三条链路：

1. **商家管理**：门店 MANAGER 上传（identity 代开票据 → presigned 直传 → confirm → 绑定门店）、解绑、按类排序
2. **公开展示**：推荐官/游客在门店公开详情页看到分组媒体，图片渲染、视频内联播放
3. **presigned URL 聚合**：公开/管理读端点一次内部调用换整店短时 GET URL，浏览器永不接触对象 key

**本期不做**（防扩散，勿顺手实现）：

- §4.8 商家素材库体系（产品/菜品图、活动素材、素材授权范围/有效期、指定推荐官可用）——那是带授权语义的独立域
- AI 视频制作「从门店素材库选择素材」入口（PRD §4.7，依赖上一条）
- 上传图像/视频内容安全审核（见 D9，风险已登记）
- marketplace feed / 任务详情 / AI 创作上下文嵌入媒体（媒体只在门店公开页按需拉取）
- 删除门店时级联清理媒体绑定（现有门店无删除端点，只有 profile deactivate）

## Stage 1 — intelligence：STORE_MEDIA 用途 + 代开票据 + 批量换 URL 端点

**无 migration**（`media_reference` 现有列够用）。

1. `MediaPurpose` 加 `STORE_MEDIA("store_media")` + javadoc；`MediaController.validate()` 直连黑名单加入（客户端直开一律 400，同 BRAND_LOGO）。
2. 新常量：`STORE_MEDIA_PURPOSE`；`STORE_MEDIA_IMAGE_MIME_TYPES = {image/jpeg, image/png, image/webp}`（≤10MB）、`STORE_MEDIA_VIDEO_MIME_TYPES = {video/mp4, video/quicktime, video/webm}`（≤20MB）。

3. **代开票据** `POST /api/media/store-media-upload-tickets`（照 `createBrandLogoPending` 模板）：
   - `requireServicePrincipal(request, IDENTITY_SERVICE)`；`caller.organizationId()` 必填（服务断言）
   - body record `CreateStoreMediaUploadTicketRequest(String ownerAccountId, String storeId, String contentType, Long sizeBytes)`
   - 校验：ownerAccountId/storeId 必填（storeId 须 UUID 格式）；contentType ∈ 图片∪视频白名单；sizeBytes 1..（图片 10MB / 视频 20MB，按 MIME 分型）
   - 落 pending 时 `domainType='store'`、`domainId=storeId`、`organizationId=断言 org`——这是四重过滤的锚
   - 响应复用 `UploadTicketResponse`
4. **批量换 URL** `POST /api/media/store-media-download-urls`：
   - `requireServicePrincipal(request, IDENTITY_SERVICE)` + org 断言必填
   - body record `StoreMediaDownloadUrlsRequest(String storeId, List<String> mediaIds)`；storeId UUID、mediaIds 非空去重后 ≤50，格式非法 400
   - 每个 id 过滤：`purpose=store_media` ∧ `organization_id=断言 org` ∧ `domain_type='store'` ∧ `domain_id=storeId` ∧ `status=active` ∧ 未过期（照 `brandLogoAsset` 四重过滤）——**过滤失败的项直接不出现在响应里**（子集语义，不逐项报错）
   - 响应 `data.items: [{id, mimeType, sizeBytes, downloadUrl, expiresAt}]`（`expiresAt` 为资产 TTL 非 URL 过期，同 `MediaServiceDownloadResponse` 注释口径）；URL TTL 复用 `downloadTtl`/`downloadDisposition`（图片内联、视频带 attachment filename——照现有 `downloadDisposition` 行为，勿改）

**测试**（`MediaControllerIT` 补用例 + 新 `StoreMediaEndpointsIT` 照现有 IT 风格）：断言缺失 401 / 非 identity principal 403 / 浏览器会话直连两新端点 403；四重过滤各拆一例（错 org、错 storeId、非 active、已过期 → 均不在子集）；MIME/分型大小帽 400；票据落库断言 domain_type/domain_id/organization_id。

## Stage 2 — identity：store_media 表 + 管理端点 + 公开聚合端点

**Migration `V36__store_media.sql`**（`IF NOT EXISTS` 幂等铁律，照 V35）：

```sql
CREATE TABLE IF NOT EXISTS store_media (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL,
    store_id uuid NOT NULL,
    media_reference_id uuid NOT NULL,          -- 引用 intelligence.media_reference，跨服务无 FK
    kind varchar(16) NOT NULL CHECK (kind IN ('storefront','environment','menu','video')),
    position integer NOT NULL CHECK (position >= 1),
    mime_type text,                            -- 快照：媒体删除后仍可展示类型
    size_bytes bigint,
    uploaded_by_account_id uuid NOT NULL,      -- 绑定操作者
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (store_id, media_reference_id)
);
CREATE INDEX IF NOT EXISTS idx_store_media_store ON store_media(store_id, kind, position);
```

**StoreMediaRepository**（R2DBC 手写 SQL，照 `StoreProfileRepository` 风格）：

- 所有写 SQL 按 `(organization_id, store_id)` 双重限定，跨组织统一 404（CLAUDE.md 第二道闸）
- `bind`：批量 INSERT，position = 该 `(store_id, kind)` 当前 max+1 递增；违反 UNIQUE(store_id, media_reference_id) → 409「媒体已绑定该门店」；帽（6/12/12/3）在 INSERT 前 `count(kind)` 校验，超 → 409「该分类数量已达上限」
- `unbind` / `reorder`（整类 `UPDATE ... CASE` 或逐行，包事务；reorder 前置校验请求集合 = 该类当前集合，否则 409）
- `findByOrganizationAndStore`（org-scoped，ORDER BY kind, position, created_at）；`findPublic(storeId)`：`INNER JOIN store s + organization o`，gate `s.status='active' AND o.status='active'`（照 `findPublicProfile:234` 的 join），无需 store_profile 行存在

**StoreMediaClient**（新 `store/StoreMediaClient.java`，镜像 `BrandLogoMediaClient`）：

- `createTicket(orgId, ownerAccountId, storeId, contentType, sizeBytes)` → `POST /api/media/store-media-upload-tickets`
- `downloadUrls(orgId, storeId, mediaIds)` → `POST /api/media/store-media-download-urls`，返回 `Map<String, ResolvedMedia>`（id → {mimeType, sizeBytes, downloadUrl}）；4xx 透传、5xx/超时 → `IdentityException(503, "门店媒体服务暂不可用")`
- 断言头 `IdentityServiceAssertionIssuer.issueForOrganization(orgId, "grassland-intelligence")`

**StoreMediaController**（挂 `/api/organizations/{orgId}/stores/{storeId}/media`，写 MANAGER+、读照 `requireStoreProfileReadable` 的 STAFF+/org MEMBER 回落）：

| 端点 | 方法 | 语义 |
|---|---|---|
| `/media/upload-tickets` | POST | body `{kind, contentType, sizeBytes}`；kind→MIME/帽前置校验（D7 表）；`ownerAccountId=操作者`；调 client.createTicket 透传 |
| `/media` | POST | body `{kind, mediaIds[]}`（1..12 个、UUID、去重）；每个 mediaId 经 client.downloadUrls **fail-closed** 校验：不在返回集 → 400「媒体不可用或类型不符」（未 confirm 的 pending/他人资产/错店资产都落这）；快照 mime/size 从返回值取；返回更新后整组 |
| `/media` | GET | 绑定行 + 每项 downloadUrl（fail-soft：单项被滤置 null，上游整体故障 503） |
| `/media/order` | PUT | body `{kind, orderedMediaIds[]}`；精确集合匹配否则 409；返回更新后整组 |
| `/media/{mediaId}` | DELETE | 删绑定行（D6：不删对象）；未绑定本店 404 |

**StorePublicMediaController**：`GET /api/stores/{storeId}/public-media`（`resolveOptional` 未登录放行，照 `StorePublicProfileController`）：

- gate store+org active 否则 404；无绑定 → 200 `groups` 全空数组（不 404，公开页仍要渲染资料面板）
- 响应 `data = {storeId, groups: {storefront: [...], environment: [...], menu: [...], video: [...]}}`，每项 `{mediaId, mimeType, sizeBytes, position, downloadUrl, urlExpiresAt}`——**不含** uploadedBy/organizationId/createdAt（公开白名单，严禁整行序列化）
- 实现：读 `findPublic` → 一次 client.downloadUrls（整店 ≤33 项）→ 单项被滤**静默跳过**；上游 5xx → 503（D5）

**测试**：repository IT（跨组织查空、UNIQUE 409、帽、reorder 集合校验）；controller IT（未登录 401 / 无门店角色 403 / 跨组织 404 / pending mediaId 绑定 400 / 第 7 张门头 409 / 白名单断言不含 uploadedBy）；public 端点 IT（未登录 200、suspended store 404、上游 503 透传、被滤项跳过）；`StoreMediaClientTest` 照 `BrandLogoMediaClientTest`。

## 验收标准（整体）

1. 商家 MANAGER（门店经理账号，非 org ADMIN）上传门头/环境/菜单图与宣传视频各若干 → 跨组织推荐官（另一账号）在任务详情门店公开页看到分组媒体：图片可看、视频可播；未登录直接 curl `public-media` 也 200
2. 安全闭环：浏览器直连 `POST /api/media/store-media-upload-tickets` 被拒（非 identity 服务断言）；跨组织 orgId/storeId 操作统一 404；绑定 pending（未 confirm）或它店 mediaId → 400；公开响应不含 uploadedByAccountId/organizationId
3. 帽与排序：第 7 张门头 409；删除中间项后顺序稳定（position 空洞不影响展示顺序）；reorder 传缺项集合 409
4. 上游故障注入（client 超时/5xx）：public-media 503、管理 GET 503，**public-profile 仍 200**（D4 解耦验证）
5. identity / intelligence 全量 `./gradlew :services:<svc>:test` 零回归；`npm run test && npm run typecheck && npm run build` 全绿

- identity **没有全局 SecurityWebFilterChain**——每个新端点必须显式 `CurrentAccountResolver` / `OrgAuthorization` / `StoreAuthorization`，漏一行=完全无鉴权；公开端点也要 `resolveOptional`（只为登录态，不做授权）
- intelligence `MediaController` 端点全部自带 caller 校验，新端点照抄 `requireServicePrincipal` 模式，勿裸奔
- Flyway：新迁移一律 `IF NOT EXISTS`（OutboxRepositoryIT 迁移重放测试要求幂等 DDL）；动手前 `ls` 各服务 db/migration 确认最新版本号
- Jackson 3：请求 record 可选数值字段必须包装类型（`Long`/`Integer`），缺失 primitive 直接 400；`is` 前缀无参方法会被序列化成属性（派生态加 `@JsonIgnore`）
- Reactor：`switchIfEmpty` 参数在 assembly 期求值，副作用调用包 `Mono.defer`
- 响应白名单手写 `toBody`（LinkedHashMap），严禁把 repository 行 record 直接序列化进响应
- React/Vue 组件上传文件时，票据体取**真实文件的 type/size**（confirm 按对象 HEAD 逐字节校验，两处必须同源）
- 提交按语义拆分（建议：intelligence 用途+端点 / identity migration+repository / identity client+controller / 前端 / docs 各一个 commit），commit message 中文、`feat(scope):` / `test(scope):` / `docs:` 风格
