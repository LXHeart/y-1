## 1. 实现结果

按 D97-03 停供付费互动（封创建与修订入口，存量零迁移、自然完结）：

1. **后端封死**：`TaskRequirements.validateInteractionBinding`（挂 create（CreateTaskRequest/CreateDraftRequest 构造器）与 update/revise（TaskController.enforceInteractionBinding）三入口）前置停供分支——显式携带 `contentForm=interaction` 的请求一律 400：「付费互动任务已停供：不再接受新建或修订互动形态任务，存量任务将自然完结」；带互动块的非 interaction 请求同样 400（互斥说明更新）。`isValidContentForm` 仍接受 interaction 值（存量数据合法，读侧不受影响）。
2. **存量链路零变更**：展示（feed/详情）、报名、提交（含评论类 commentText）、审稿（草稿审稿/核验）、结算路径不触碰本守卫；存量互动任务的声誉口径、终结路径照旧。
3. **前端表单**：`MerchantTaskForm` 移除「点赞互动」选项（`CONTENT_FORM_LABELS` 与 `contentFormOptions` 两分支）、移除互动目标链接 + 动作类型（点赞/收藏/关注/评论）联动块及 `interactionForm` computed；选项裁剪与自动纠正（`reconcileContentForm`）沿用既有机制。`TaskFormData` 的两个 interaction 字段保留为存量编辑回填的数据兼容位（提交侧块构造条件 `contentForm==='interaction'` 在 UI 不可达后恒 false，防御性保留）。

## 5. 资金/事件证据

停供只封创建/修订入口，无资金路径变更；存量互动任务资金语义（无资金字段、非资金型 accept 直连）未触碰。事件流（ApplicationSubmitted/核验检查事件）照旧——由 TC97-007 与既有用例回归锁定。

## 6. 偏差

1. **存量互动草稿的编辑形态**：编辑存量互动草稿时，`reconcileContentForm` 的既有自动纠正机制会将内容形式落到首个可用形式（image/video）——保存即转为该形式任务（互动块构造条件不再成立）。这是「表单不可达 + 既有纠正机制」的自然结果；任务书未定义该 UX（无新增拒绝路径，保存不会 400）。未做额外拦截。
2. `InteractionTaskFlowIT` 造数改 SQL 覆写（`UPDATE task SET content_form='interaction', requirements=...||jsonb`）：与停供前落库行等价；不写 task_version 快照（该表仅在发布/修订时产生，存量链路用例不涉及）。
