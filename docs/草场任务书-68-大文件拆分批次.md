**已定案的关键决策(执行期不得更改)**:

| # | 决策 | 理由 |
|---|---|---|
| D1 | MerchantKybCard **只拆 script(三域 composable),模板不拆成页签子组件** | 拆页签子组件有三个坑:页签是 v-if,切页签=子组件重挂载会重新拉数据(行为变更);父状态下传需要 ~20 个 props 或单对象 props(v-model 嵌套 props 会触发 `vue/no-mutating-props` lint);改用 v-show 会把隐藏页签内容放进 DOM,可能碰坏测试断言。模板本身按页签分段并不臃肿(最大 240 行),真正的痛点是 script 三域混杂——拆掉即达标 |
| D2 | ArticleCreationView 的 question/topic 两个第一步**不合并**(尽管高度相似) | 二者差异在字段级(问题 textarea+只读锁+链接提取提示 vs 主题 textarea),合并需要 variant 分支,弱模型执行风险大于收益;本批只抽取二者**内部完全相同**的「风格三选」区块 |
| D3 | 拆出的样式**随组件/composable 的消费者走**(scoped 语义不变) | 样式留在父文件对子组件内部是死代码(scoped 不穿透);例外见 D4 |

**为什么测试能零改动**(已核实):三个文件的测试(`ArticleCreationView.test.ts`、`ArticleCreationView.answerMode.test.ts`、`VideoProductionView.test.ts`、`MerchantKybCard.test.ts`)全部在 **fetch 层打桩**(如 `vi.stubGlobal('fetch', …)`/`vi.mocked(fetch)`),不用 `vi.mock` 替换组件或 composable 模块——所以把代码搬进 composable/子组件不影响任何桩;DOM 锚点(data-test/data-testid)在搬移中逐字符保留即可。
