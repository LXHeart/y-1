# 资金异常恢复修复

日期：2026-09-10。基线：`0fa20962d7155f0f2c995c7b1b64a5a446f75b85`，修改位于当前工作区。关联：[项目整体梳理与复核](项目整体梳理与复核-2026-09-10.md) 中的 A / B 两项资金问题。

分账成功回复丢失或本地提交失败时，订单现在保留 `splitting`，继续阻止退款与暂扣，并使用原分账操作键重放收尾。支付重试现在受数据库中的到期时间和领取租约约束；待核对、未到期、租约持有中及已过期的订单不会占据普通支付调度批次。

## 回归覆盖

- 支付失败后，扫描和直接重试入口都遵守 `next_attempt_at`；到期后可成功支付。
- `needs_review`、退避中、租约持有中和已过期订单均不会阻塞后方正常订单。
- 重叠支付尝试只有一个执行者取得租约并发出请求。
- 过期租约可接管；旧执行者的迟到失败不能覆盖新租约或重复计数。
- 后台恢复每次领取只计一次尝试；第八次领取后的失败进入待核对，迟到成功仍可收口。
- 分账回复丢失时，售后与退款被拒绝；同一分账键重放后记录结算事实。
- PostgreSQL 延迟约束触发器模拟 COMMIT 失败，验证外部成功后本地落库失败仍保留保护状态。
- 未知分账之后的明确拒绝、以及另一执行者收尾后的迟到错误，都不会重新开放退款。
- 取消补偿退款同样遵守退避，并按原退款键完成重试。

所有测试使用隔离 PostgreSQL 和受控 Finance 响应，没有调用真实支付。
