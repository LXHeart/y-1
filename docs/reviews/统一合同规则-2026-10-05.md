# 统一合同字段规则 · 2026-10-05

## 目标与实现

修订比较、报名/重新同意、任务版本、接受合同、页面展示共用 [task-contract.v1.json](../../contracts/task-contract.v1.json) 中的 11 项合同字段规则，包含字段来源、空值语义、展示名称与格式，以及接受阶段的冻结来源。9 项嵌套交付要求也在清单中登记。

- Java `TaskContractTerms` 从打包资源读取清单，投影合同值进行比较；任务版本号属于元数据，不触发重新确认。预览接口输出相同的 `contractTerms`。
- 数值读取统一为整数类型，避免空值按清单归零后与显式零金额因 JSON 节点类型不同而误触发重新确认。HTTP 返回普通 Map，避免项目内 Jackson 与 Spring HTTP 序列化版本差异造成字段丢失。
- V68 的 `task_contract_projection` 使用清单生成的规则，供既有报名/重确认/版本触发器及接受触发器共用。接受金额仍以报名的冻结金额为准，要求和目标问题仍优先取对应任务版本。V67 及更早迁移未改，历史快照没有回填或重写。
- 新合同快照为 schema 3：所有登记字段均有键，无目标问题时明确记录 null。普通任务响应仍省略空问题字段；旧版合同快照继续保持原形状。前端区分未约定与历史未记录，类型允许这两种情况。
- 页面按清单生成全部合同字段行，不再为新版预览单独列字段。金额与取消补偿、期限等有效政策解释沿用服务端预览结果，不在浏览器重新推算结算金额。旧版 API 预览保留兼容展示。
- 已接受合作改读既有、经过参与方鉴权的 `task-context` 接口，不再展示当前任务预览。读取失败不退回可变任务；旧快照缺失字段明确显示“本快照未记录”。显式 null 代表平台默认，与缺失字段区分；未冻结的默认数值不按当前配置补造。
- UI 沿用根 DESIGN.md 的 token，没有更改品牌色或主题定义。字段渲染使用文本插值。

## 后续增加字段的入口

1. 在清单中登记合同字段的 `key`、Java JSON pointer `source`、数据库 `column`、`nullValue`、`label` 和 `format`。需要冻结版本列或接受金额覆盖时，登记 `versionColumn` / `acceptColumn`。
2. 若新增任务字段不属于合同，必须在 `nonContractTaskFields` 写明理由。Java 测试核对整个 Task record 的字段集合；新增交付要求必须登记 `requirementFields`。不能通过只加传输/数据库字段绕过分类。
3. 数据库投影有变化时，将清单的 `migration` 指向一个新的迁移名，再运行 `npm run contracts:check -- --write`。生成器只创建不存在的文件，不覆盖已发布迁移；历史快照语义有变化时评估并提升 schemaVersion。
4. 新格式必须实现展示 formatter 并补测试；已有格式的新增字段自动生成展示行。字段集合测试要求每个合同字段都有独立变更用例，并验证变化会进入比较和快照。
5. `npm run lint` 已包含 `contracts:check`，检查清单与 SQL 是否漂移；Java 的真实 PostgreSQL 测试校验报名、版本、重确认及接受快照，前端测试校验展示覆盖与旧快照语义。

约束：清单统一字段归属和投影，不替代资金结算、权限、政策有效值计算。当前任务定义仍保留展示说明与履约要求的既有区分；没有把 title/description 等既有展示字段重新解释成合同义务。

## 9.3 最小服务与清理

- 初始盘点：Compose 项目列表空、无运行容器、无 Java/Gradle/Vite 重型进程；Docker Desktop 已在运行。
- 定向 Java 使用 Marketplace 既有 IT 基座，只启动测试专用 PostgreSQL；Temporal 为内存测试服务器。完整 Marketplace/迁移器回归按套件实际依赖串行运行，禁止另开开发栈。
- 前端单元和静态检查无服务；浏览器组件验证只启一个临时 Vite，使用实际组件与明确的受控 API 响应，不声称真实后端 E2E。桌面/移动、明暗主题、加载/错误/空响应/键盘重试及旧接受快照均检查。
- 通过 local-stack 的 y-1 互斥入口执行重型任务，Vitest/Gradle 单 worker。测试容器由 Testcontainers 清理，临时 Vite 和浏览器在退出时释放，保留原有开发容器、数据卷和 Docker Desktop。
- 浏览器验收结束按 AGENTS 执行超过 24 小时的 builder cache 回收，最终重新盘点并记录。

最终收尾：临时 Vite、浏览器和测试容器均已释放，没有运行中的 Compose 项目、容器或本轮 Java/Gradle/Vite 进程（`final-resources.json`）。浏览器阶段与全部验证收尾均已执行 `docker builder prune -af --filter until=24h`，本轮回收量 0B。预先运行的 Docker Desktop 保留，原开发容器和数据卷未删除；没有启动或恢复全量应用栈。
