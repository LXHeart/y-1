# 稳定性与 CI 门禁修复

日期：2026-09-10。基线：`0fa20962d7155f0f2c995c7b1b64a5a446f75b85`，修改位于当前工作区；承接 [整体复核报告](项目整体梳理与复核-2026-09-10.md) 的 DNS 启动依赖、凭据清理和 Java 覆盖率门禁问题。

固定第三方域名现在在首次连接时解析，DNS 故障不会阻断飞书、搜图和热点等客户端的创建。解析在后台线程执行，设有 3 秒超时；错误不缓存，后续请求可重试；首次成功后固定该客户端的连接地址。

## 修改

- [PinnedOutboundClients.java](../../platform-java/services/intelligence-service/src/main/java/com/grassland/intelligence/ai/PinnedOutboundClients.java) 统一创建延迟解析器，构造阶段只校验基址和 host。
- [PinnedAddressResolverGroup.java](../../platform-java/services/intelligence-service/src/main/java/com/grassland/intelligence/ai/PinnedAddressResolverGroup.java) 在后台执行首次 DNS 解析，共享并发中的解析结果；目标 host 仍须匹配，原始 HTTP Host / TLS SNI 保留。已预先验证的 BYOK / 平台模型连接仍使用固定地址入口，不延后其安全校验。
- [ShotAnchorImageIT.java](../../platform-java/services/intelligence-service/src/test/java/com/grassland/intelligence/videoproduction/ShotAnchorImageIT.java) 只删除没有模型引用的凭据；造数复用同一供应商和地址已有的有效凭据，不改写共享密钥。新增“其他能力引用同一凭据，清理和再次造数都成功”的回归。
- [CI 工作流](../../.github/workflows/ci.yml#L76) 显式运行 `jacocoTestCoverageVerification`；[Gradle 配置](../../platform-java/build.gradle.kts#L91) 将覆盖率验证依赖于对应的 `test`，直接执行验证或 `check` 时也先产生测试结果。

复用现有出站解析与客户端工厂，覆盖飞书、Bing 搜图、60s/ALAPI 热点和抖音热点的调用点。请求目标与配置 host 不一致时仍直接拒绝，DNS 暂时不可用只影响实际使用该上游的请求。
