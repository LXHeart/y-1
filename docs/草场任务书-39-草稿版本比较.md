## 目标（PRD §4.5 图文制作流程第 6 步「多版本比较」/ §4.9.7 草稿版本）

- 创作草稿（creation_draft，智能创作助手）的**版本历史列表、任两版并排比较、从历史版本载入**
- 后端已有每次保存 append 的不可变版本快照（V19），本任务补「读」端点 + 前端比较 UI

**现状**：版本仅用于乐观锁（409 冲突处理 `src/composables/useCreationDraft.ts:49-50`）；controller 只有 POST/GET/PUT/DELETE，**无版本列表/读取端点**；前端只显示 `v{version}` 标签（`CreationAssistantPanel.vue:209`）。

## 决策表

| # | 决策 | 理由 |
|---|---|---|
| D1 | 后端只加**两个只读端点**（版本列表 + 单版本读取）；比较纯前端并排渲染，**不做服务端 diff** | 内容小、字段结构前端已知；服务端 diff 是伪需求 |
| D2 | **版本不可变纪律**：不提供版本的 update/delete 端点 | append-only 是审计面；恢复走 D4 |
| D3 | **列表分页防自动保存灌爆**：keyset by version desc，limit 默认 20、上限 100 | 自动保存 1.5s debounce 长会话可产生大量版本；「内容未变跳过 append」动保存/乐观锁语义，登记后续不首期做 |
| D4 | **「载入此版本」= 前端把旧版本内容回填编辑器，走既有 PUT 保存路径追加新版本**——恢复功能零后端、历史不删 | 与 append-only 自洽；冲突时走既有 409 冲突态 UX |
| D5 | 比较呈现 = **字段级并排 + 变更徽章**（值不同的字段高亮）；词级 diff 仅当 `node_modules` 既有 diff 库才顺手做，否则登记 polish | 词级 diff 引新依赖不值当；字段级已满足「多版本比较」决策需求 |
| D6 | owner IDOR 镜像既有草稿端点守卫；**素材库（content_asset）版本比较不在本任务**（登记） | 范围收紧；素材版本端点已有、比较 UI 另议 |

## 实施阶段

### Stage 1 — intelligence：版本读端点

```
GET /api/creation-drafts/{id}/versions?limit=20&cursor=   → { items: [{version, createdAt, title/name}], nextCursor }
GET /api/creation-drafts/{id}/versions/{version}          → 完整版本快照（与 V19 字段一致）+ version/createdAt
```

- owner 守卫镜像既有端点（他人草稿 404；版本不存在 404）
- keyset 分页（version desc）；列表项带 title/name 摘要便于辨认
- **测试**：IT——多版本草稿列表分页/顺序、单版本内容完整、跨用户 404、版本越界 404、只读（无写端点可断言路由不存在即行为面）

### Stage 2 — 前端

1. `useCreationDraft`（或新 `useCreationDraftVersions`）加 `listVersions` / `getVersion`
2. `CreationAssistantPanel` 草稿条目加「版本历史」入口 → 抽屉/弹层：
   - 版本列表（时间倒序，当前版本标记）
   - 选任意两版 → **字段级并排比较**（按草稿 TS 类型字段注册表渲染；值不同字段加变更徽章；长文本并排滚动区）
   - 每版「载入此版本」按钮：回填编辑器 + 走既有保存（追加新版本；触发既有自动保存/冲突流）
3. **门禁**：`npm run test && npm run typecheck && npm run build` + vitest（列表渲染、两选状态机、变更徽章判定、载入回填）

### Stage 3 — 收尾

1. 全量门禁：`./gradlew :services:intelligence-service:test` + 前端三件套
2. 回写进度指南：#39 标完成、第四批第 15 项划掉、登记「素材库版本比较」与「未变内容跳过 append」两个后续
3. CLAUDE.md：创作草稿路由行补 versions 端点

## 验收标准

1. 编辑同一草稿多次保存产生多版本 → 版本历史按时间倒序分页展示，当前版本有标记
2. 任选两版并排比较：值不同的字段高亮变更徽章，长文本字段并排可读
3. 「载入此版本」把旧内容回填编辑器，保存后生成**新**版本（历史完整不删）
4. 他人草稿的 versions 端点 404；版本号不存在 404
5. 既有草稿自动保存、409 冲突态、乐观锁测试零回归
6. 无新公网前缀（复用 `/api/creation-drafts/**` 既有 edge 路由，确认匹配粒度即可）

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`
- **intelligence 没有全局 ObjectMapper bean**——持服务本地实例
- **IDOR 是本任务最大风险面**：版本端点必须复用既有 owner 校验（先读 controller 现有守卫再动手），漏=他人草稿可读
- 版本快照字段如含派生便捷方法，`is` 前缀的加 `@JsonIgnore`（本库已踩过快照读回报「数据损坏」的坑）
- Jackson 3：record 可选数值字段包装类型
- Reactor：`switchIfEmpty` 副作用包 `Mono.defer`
- 前端：载入旧版本后本地 `version` 只能用服务端回传值覆盖（自增猜测会让后续保存全部 409——既有约定）
