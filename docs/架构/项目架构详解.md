# 草场（Grassland）技术架构详解

> 核对日期：2026-09-15。本文描述当前仓库的实现，依据构建配置、路由、服务源码、迁移与 Compose 文件校准；不代表生产环境已部署或验收。
> 产品规则见 [PRD](../产品/草场产品需求文档.md)，约束与取舍见 [HLD](草场系统技术总体设计（HLD-v0.1）.md) 和 [ADR](../adr/README.md)，当前开放项见[续接指南第四节](../草场开发进度与续接指南.md#四当前未完成开发与生产门禁按优先级)。

## 1. 阅读范围

本文集中维护“代码现在如何工作”。项目定位与阅读顺序见[项目速览](项目速览.md)，文件归位见[目录结构](目录结构.md)。旧版的文件数量、Controller 数量、连接数量和最高迁移版本已移除；这些随开发变化，不作为架构约束。

六服务指 `edge-bff` 加五个领域服务。`database-bootstrap` 与 `release-migrator` 是一次性数据库作业，不是另两个在线业务服务。

## 2. 总体拓扑

```text
浏览器：用户端 / AI 创作端 / 治理台
  ├─ 开发：Vite /api 代理 → localhost:8081（默认宿主映射）
  └─ Compose：Nginx → edge-bff:8080（容器端口）
                         ├─ identity-service:8082
                         ├─ marketplace-service:8083
                         ├─ finance-service:8084
                         ├─ trust-service:8085
                         └─ intelligence-service:8086

服务间：签名身份断言 + 内部 HTTP；Kafka 传播事件；Temporal 编排长流程
基础设施：PostgreSQL · Redis · Kafka · Temporal · MinIO/S3
观测：Prometheus / Alertmanager / Grafana / Loki / Tempo，OTel Collector 按配置启用
```

端口与代理以 [Vite 配置](../../vite.config.ts)、[Nginx 配置](../../nginx.conf)、[Compose](../../docker-compose.yml) 为准。业务服务内部端点不经过公网 `/api` 暴露。

## 4. 服务职责与共享模块

| 服务 | 权威职责 | 源码入口 |
|---|---|---|
| `edge-bff` | 路由、安全过滤、会话/Token 解析、内部断言、SSE/Multipart/Range 代理 | [edge](../../platform-java/services/edge-bff/src/main/java/com/grassland/edge) |
| `identity-service` | 账号、会话、活动身份、组织、门店、成员、准入、KYB、通知和后台角色 | [identity](../../platform-java/services/identity-service/src/main/java/com/grassland/identity) |
| `marketplace-service` | 任务、报名、履约、核验、确认、消费订单与核销、声誉、归因和经营分析 | [marketplace](../../platform-java/services/marketplace-service/src/main/java/com/grassland/marketplace) |
| `finance-service` | 双录账本、资金预留、支付/退款/分账 Sandbox、钱包、积分、对账 | [finance](../../platform-java/services/finance-service/src/main/java/com/grassland/finance) |
| `trust-service` | 争议、举证、审判官、投票、上诉、客服终审、判例和风险投影 | [trust](../../platform-java/services/trust-service/src/main/java/com/grassland/trust) |
| `intelligence-service` | AI 运行、平台模型/BYOK、媒体、素材、创作快照、草稿、图文/视频工作流和内容安全 | [intelligence](../../platform-java/services/intelligence-service/src/main/java/com/grassland/intelligence) |

推荐官声誉的计算与规则位于 Marketplace 的 `reputation/`；Trust 通过内部客户端和事件投影读取，不能按早期蓝图把 Trust 当作声誉计算权威。

共享模块以 [settings.gradle.kts](../../platform-java/settings.gradle.kts) 为准：`platform-crypto`（信封加密）、`platform-storage`（对象存储）、`platform-identity-assertion`（身份断言与 Access Token）、`platform-http`（内部 HTTP）、`platform-reporting`（报表）、`platform-messaging`（事件与 Outbox）、`platform-database`（数据库装配）、`platform-financial`（共享金融政策）。共享基础能力不等于共享业务表的写入权。

## 5. API 与认证边界

路由登记在 [Edge application.yml](../../platform-java/services/edge-bff/src/main/resources/application.yml) 的 `edge.routes`，由 [UpstreamResolver](../../platform-java/services/edge-bff/src/main/java/com/grassland/edge/proxy/UpstreamResolver.java) 按顺序匹配方法、路径、`exact` 与开关。部分条目是方法级精确匹配，部分是前缀匹配，不能仅凭路径前缀推断所有方法都开放。

- 未登记、无启用匹配项或方法不匹配时返回 404；`EDGE_ROUTE_*` 关闭是停用入口，不会切回 Express。
- Web 使用 `y1.sid` Cookie，移动端使用自有 HMAC Access Token。Edge 重新读取账号、角色与活动身份，并签发目标服务断言；领域服务继续校验资源权限。
- 原始 Access Token 在 Edge 消费；刷新/撤销使用各自的 Refresh Token 契约。无效授权不能借 Cookie 回退变成另一个身份。
- 内部断言使用独立的签名/验签配置及 Redis 防重放。可重复用于 API 请求的 Access Token，不等同于一次性内部断言或跨应用免登 Token。
- SSE/媒体响应不整体缓冲，非幂等写请求不自动重试。

HTTP 行为、代表路由和契约测试集中在[旧 API 兼容矩阵](草场旧API兼容契约矩阵.md)；Token 格式、设备撤销和配置集中在[认证方案](移动端刷新token认证方案设计.md)。

## 6. PostgreSQL 与迁移

### 6.1 当前隔离程度

Compose 将同一个 `DATABASE_URL` 传给五个领域服务和 Edge，当前使用同库的业务表与各自 Flyway 历史表。这是代码层的领域所有权与迁移隔离，**尚不是每服务独立库、独立数据库账号的物理/权限隔离**。

[HLD §6.1](草场系统技术总体设计（HLD-v0.1）.md#61-database-per-service) 保留独立逻辑库与账号的目标。拆库前必须处理现存身份表引用、迁移顺序和 Edge 认证读路径，不能只替换连接字符串就宣称完成隔离。

### 6.2 Edge 的身份库只读例外

Edge 的 [SessionIdentityResolver](../../platform-java/services/edge-bff/src/main/java/com/grassland/edge/internalassertion/SessionIdentityResolver.java) 与 [AccessTokenIdentityResolver](../../platform-java/services/edge-bff/src/main/java/com/grassland/edge/internalassertion/AccessTokenIdentityResolver.java) 读取身份域数据，包括 `session`、`app_users`、`identity_session`、`backend_role`、`account_flag`、`identity_profile`、`organization`，移动链路还读取 `refresh_token`。

用途仅限认证和断言装配；Edge 不写任务、争议或账本事实。“只读”描述现有查询行为，不表示共享 `DATABASE_URL` 已落实数据库级只读账号。此例外不能推广成任意跨服务查表。

### 6.3 Flyway 与发布顺序

| 所属模块 | 历史表 |
|---|---|
| database-bootstrap | `database_bootstrap_flyway_schema` |
| identity | `flyway_schema_history` |
| marketplace | `marketplace_flyway_schema` |
| finance | `finance_flyway_schema` |
| trust | `trust_flyway_schema` |
| intelligence | `intelligence_flyway_schema` |

迁移位于各服务的 `src/main/resources/db/migration/`，bootstrap 使用 `db/bootstrap/`；装配逻辑集中在 `platform-database`。版本化 SQL 的发布后内容不可修改，需要增量迁移修复，发布校验见[运行手册](../运维/生产发布与灾备运行手册.md)。

[database-bootstrap](../../platform-java/services/database-bootstrap/src/main/java/com/grassland/bootstrap/DatabaseBootstrapApplication.java) 建立兼容基线表并执行 Schema 校验。它负责建库地基，不取得 `app_users`、`session`、`user_settings` 等表的业务所有权。

[release-migrator](../../platform-java/services/release-migrator/src/main/java/com/grassland/releasemigrator/ReleaseMigratorApplication.java) 按 bootstrap → identity → marketplace → finance → trust → intelligence 顺序执行同源迁移。发布先运行该作业，再滚动服务；服务自身仍保留 `initMethod=migrate`，正常应成为无待执行迁移的检查。不要把“发布先迁移”误写成“服务已删除 Flyway 启动逻辑”。

### 6.4 一致性与不可变数据

- 领域状态与 Outbox 必须在同一本地事务提交，跨服务通过幂等 Command、事件或工作流协调。
- Finance 的 Journal/Posting、业务操作号和数据库约束共同保证账本平衡、幂等与可重建；错误以冲正追加，不覆盖原账。
- 任务版本、订单快照、创作上下文与配置历史保留当时的版本。DB 约束和业务权限各自承担保护，不能把当前配置直接当成历史事实。
- 支付/分账结果未知时先查询与对账，不能仅凭超时认定失败后重复扣款。

## 7. Kafka、Outbox 与消费

### 7.1 事件传输

当前 Kafka 使用 KRaft。五个领域服务默认各有 `grassland.<domain>.events` Topic；值序列化使用 `StringSerializer`，发布器发送 JSON。旧方案的 Protobuf/Schema Registry 尚不是此消息链路的运行前提。

### 7.2 主要消费关系

| 消费者 | 事件来源 | 用途 |
|---|---|---|
| Identity 通知消费者 | identity、marketplace、trust、finance、intelligence | 站内通知及通知投递编排 |
| Marketplace `TrustEventConsumer` | trust | 裁决结果与履约状态协作 |
| Marketplace `OpsDltConsumer` | 配置的 DLT Topic | 死信进入运营处置 |
| Trust `MarketplaceReputationEventConsumer` | marketplace | 声誉与风险投影 |
| Finance `JudgeRewardEventConsumer` | trust | 审判激励入账，遵守对应 ADR 与幂等规则 |

精确 Topic、启停和消费组由各服务 `application.yml` 与 `@KafkaListener` 声明；表中不是永久冻结的完整事件目录。

### 7.3 与同步 HTTP 的分工

需要即时授权、查询或受理结果时使用内部 HTTP；事实传播、通知和本地投影使用 Kafka。异步消费只能提供最终一致性，不能代替 Finance 的本地账本事务。

### 7.4 Outbox 实现与共享边界

业务事务写入 `*_outbox` 后，由服务内调度器驱动发布器：认领批次和租约 → 发送 Kafka → 等待 ACK → 标记已发布；失败退避，租约超时可重新认领。同聚合未发布事件的认领顺序由 Repository 约束。

Identity、Finance、Trust、Intelligence 共用 [platform-messaging](../../platform-java/platform-messaging/src/main/java/com/grassland/messaging/outbox/OutboxPublisher.java)，各服务保留表名、Topic 和调度配置。Marketplace 的 [Outbox 实现](../../platform-java/services/marketplace-service/src/main/java/com/grassland/marketplace/event/OutboxPublisher.java) 包含领域查询与不同失败语义，继续独立维护。

当前没有 Debezium Relay。发送成功与标记完成之间仍可能重投，因此必须有消费幂等，不能宣称端到端“恰好一次”。

### 7.5 消费故障处理

消费者按业务处理结果确认消息，使用 Inbox/稳定操作号消除重复副作用；重试耗尽进入配置的死信处理。Outbox 积压、最老事件年龄和消费滞后由指标与告警观测。数据保留、故障恢复和人工处理仍须按部署配置验证，不能仅据机制存在保证消息永不丢失。

## 8. Temporal 长流程

当前工作流实现分布如下，名称可直接在对应目录定位：

| 服务 | 工作流 |
|---|---|
| [Marketplace](../../platform-java/services/marketplace-service/src/main/java/com/grassland/marketplace/workflow/saga) | `ApplicationReservationWorkflow`、`ConfirmationWindowWorkflow`、`SettlementWindowWorkflow`、`SettlementReconciliationWorkflow`、`MerchantRejectionReviewWorkflow`、`DeliveryDeadlineWorkflow` |
| [Trust](../../platform-java/services/trust-service/src/main/java/com/grassland/trust/workflow) | `DisputeAdjudicationWorkflow`、`CsDirectSlaWorkflow` |
| [Intelligence](../../platform-java/services/intelligence-service/src/main/java/com/grassland/intelligence/orchestration) | `VideoProductionWorkflow`、`CreationVisualWorkflow`、`WechatDraftWorkflow` |

Temporal 保存流程进度；PostgreSQL 保存业务与资金事实。Activity 重试和 Timer 唤醒后仍需检查状态、权限、幂等键及版本。存在实现类不等于相关 Provider 或业务开关已在生产启用。

## 9. Redis 的职责

当前用途包括内部断言防重放、游客试用限流、跨应用一次性免登、视频任务事件分发，以及公众号渠道的 Token 缓存与同步协调。实现入口分别是 `RedisAssertionReplayGuard`、`GuestTrialRateLimiter`、`CrossAppTokenStore`、`VideoTaskEventStream`、`WechatTokenService` 与 `WechatDraftSyncService`。

Web 主会话在 PostgreSQL `session`，移动凭据在 `refresh_token`；Redis 不保存金融事实。不同用途的故障策略由各实现决定，不能笼统当成可随意清空的缓存。

## 10. 对象存储

媒体、凭证、KYB 证照、创作素材与生成产物使用 S3/MinIO；`platform-storage` 提供存取与签名能力，领域库保存元数据、权限和稳定引用。客户端通过受控 `/api/media` 等入口或有时限的签名地址访问，不能假定所有媒体响应都是直接的对象存储 URL。

[deploy/storage](../../deploy/storage) 提供初始化与服务账号策略。具体对象保留、授权及来源追踪规则随业务域维护。

## 11. 可观测性

[观测配置](../../platform-java/deploy/observability) 包含 Prometheus 抓取与告警、Alertmanager、Grafana、Loki、Tempo 等资源。服务通过 Actuator/Micrometer 暴露指标，日志与 Trace 按配置汇入观测组件。

默认 Compose 的观测组件放在 `observability` profile；OTel Collector 使用额外的覆盖文件。仓库存在规则和接线，不等于生产通知接收者、Trace 投递、留存与演练已经完成。部署方式和验收条件集中在[运行手册](../运维/生产发布与灾备运行手册.md)。

## 12. 前端与创作工作区

- 三个应用的路由分别位于[用户端](../../src/router/index.ts)、[AI 创作端](../../src/ai/router.ts)、[治理台](../../src/ops/router.ts)。用户端和 AI 端复用创作视图，治理台独立装配。
- 跨 origin 通过 [CrossAppTokenController](../../platform-java/services/identity-service/src/main/java/com/grassland/identity/auth/CrossAppTokenController.java) 交换绑定目标应用的一次性 Token，建立目标 Cookie 会话；不是跨域共享同一 Cookie。
- 视图负责装配，URL 同步放 `use*UrlState.ts`，业务取数放域 composable，大区块拆子组件；细则与 UI 双主题要求只在 [AGENTS.md](../../AGENTS.md) 维护。
- 创作草稿与工作区复用 `src/views/ai-center/creation/` 的恢复、版本和自动保存能力；图文工作流在 `src/views/article/`，分镜画布在 `src/views/video-canvas/`，快速视频模式在 `src/views/video-production/`。
- 图文工作台的 Java 实现在 `creationstudio/`，覆盖来源、计划、文本、视觉、排版、导出和公众号草稿渠道；模板契约为 [creation-recipes.v1.json](../../contracts/creation-recipes.v1.json)，前端类型为 [creation-studio.ts](../../src/types/creation-studio.ts)。渲染依赖与安全边界见[第三方资源说明](AI创作第三方资源说明.md)。

`EDGE_ROUTE_CREATION_STUDIO_INTELLIGENCE` 与 `EDGE_ROUTE_CREATION_WECHAT_INTELLIGENCE` 在 Edge 默认关闭；服务侧还有各自写入开关。#101 的本地实现与复核不能据此表述为已面向生产开放。

## 13. 部署与运行边界

- 默认 [docker-compose.yml](../../docker-compose.yml) 编排前端、Java 服务和开发基础设施；`database-bootstrap` 成功后才启动依赖服务。
- [docker-compose.production.yml](../../docker-compose.production.yml) 是覆盖文件，要求外部 Kafka/Temporal 及生产凭据；开发 Temporal 使用 SQLite 的 `start-dev` 模式，不构成生产持久化方案。
- `release-migrator` 位于 `release` profile，由发布流程单独运行。数据库备份、已发布迁移校验、密钥物化、镜像检查和回退按[发布手册](../运维/生产发布与灾备运行手册.md)执行。
- Kubernetes、每服务独立库及账号等仍按 HLD 的目标项管理，不从旧蓝图推断已经交付。

## 14. 开发时要守住的约束

1. 金融写入只经 Finance Command；已过账数据只能追加冲正，余额必须可由流水重建。
2. 账号、组织、门店和治理角色由服务端授权；前端显隐与 Token 内的旧角色不能替代实时校验。
3. 任务/创作/订单读取对应的不可变快照，不用更新后的配置改写历史语义。
4. AI 生成、退款和用量调整沿用稳定操作号及现有计费政策；取消不等于无条件退款。
5. Outbox/Inbox、Temporal 和 Provider 调用一起考虑重复、超时、未知结果及恢复，不把中间态当成终态。

业务阈值、例外和变更依据以 HLD 与对应 ADR 为准，本文不再复制一套产品规则表。
