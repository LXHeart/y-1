# 项目目录结构

本仓库包含 Vue 前端、Java 服务和配套的测试、运维、文档。应用入口与工具配置保留在根目录，其余文件按用途归位。

## 根目录地图

```text
y-1/
├── src/                      前端源码
├── public/                   直接复制到构建产物的静态资源
├── platform-java/            Java 多模块工程
├── contracts/                前后端共用的版本化 JSON 契约
├── tests/                    部署契约、工具单测、端到端测试
├── scripts/                  CI、发布、校验、造数及手工验收脚本
├── deploy/                   部署侧安全契约与存储初始化资源
├── config/                   本地工具配置
├── docs/                     产品、架构、任务书、运维和测试资料
├── index.html                用户端入口
├── ops.html                  治理台入口
├── ai.html                   AI 创作中心入口
├── package.json              Node 依赖与统一命令入口
├── package-lock.json         依赖锁文件
├── vite.config.ts            开发代理及三入口构建
├── vitest.config.ts          单元测试与覆盖率
├── playwright.config.ts      浏览器端到端测试
├── tsconfig.json             TypeScript 配置
├── vite-env.d.ts              Vite 类型声明
├── eslint.config.js          静态检查
├── Dockerfile.frontend       前端镜像
├── docker-compose*.yml       开发、生产及可观测性部署组合
├── nginx.conf                三应用的公共入口与代理
├── DESIGN.md                 用户端与共享组件设计规范
├── AGENTS.md / CLAUDE.md      协作约定
└── README.md                 项目入口说明
```

`.env*`、`.gitignore`、`.dockerignore`、`.github/` 及工具自己的隐藏目录使用各自约定的位置。

## 源码怎么找

| 路径 | 职责 |
|---|---|
| `src/main.ts`、`src/App.vue`、`src/router/`、`src/layouts/` | 用户端应用装配、路由与布局 |
| `src/views/<业务>/` | 用户端与创作业务页面；页面子组件、URL 状态和域 composable 就近归位 |
| `src/ops/` | 治理台入口、路由、`admin/` 管理页签、`ops-console/` 运营处置；设计规范在本目录的 `DESIGN.md` |
| `src/ai/` | 独立 AI 应用的入口、路由和布局；创作业务复用 `src/views/` |
| `src/components/` | 复用组件及现有共享面板 |
| `src/composables/`、`src/stores/` | 业务流、数据请求与跨页面状态 |
| `src/types/`、`src/config/`、`src/constants/` | 类型、前端配置和常量 |
| `src/lib/`、`src/utils/`、`src/content/` | 基础能力、纯工具函数与静态内容 |
| `src/style.css` | 全局样式和双主题设计 token |
| `platform-java/services/` | Edge、五个领域服务，以及 database-bootstrap、release-migrator |
| `platform-java/platform-*/` | Java 共享能力模块 |
| `platform-java/deploy/` | Java 平台可观测性资源与已发布迁移校验记录 |
| `deploy/` | 仓库级部署支持文件，含 `security/`、`storage/` |

前端业务测试继续与源码同目录。Java 的 `src/main/`、`src/test/` 和 Gradle 模块布局遵循现有工程约定。

## 新文件归位

1. 先确认能否扩展现有业务目录或复用已有组件；五个大视图继续遵循根 `AGENTS.md` 的分层规则。
2. 脚本放 `scripts/` 的对应分类，自动化测试放 `tests/` 或与前端源码同目录。
3. 文档按 [docs 文档地图](../README.md) 归类；新截图和日志先放 `test-artifacts/<任务>/`。
4. 根目录只增加确有工具或应用入口要求的文件。迁移文件时同步修改引用、测试发现配置和使用说明。
