# 本地启动与资源守卫

本机开发与验收遵循根 `AGENTS.md` 的资源约束。统一入口为 `scripts/local-stack.mjs`，可通过 `npm run stack -- ...` 调用。它是仓库脚本的执行门禁，不是 Docker daemon 的全局策略；直接执行裸 Docker 命令、未接入的外部工具和手工终止守卫仍可能绕开保护。

## 日常开发

从仓库根目录执行，显式指定项目名、Compose 文件和服务。实际环境文件由开发者按项目配置选择；下面使用仓库示例环境，不读取或打印真实凭据。

```bash
# 只启动数据库；已有第二套本项目栈时拒绝执行。
npm run stack -- compose -p y-1 --env-file .env.docker.example -f docker-compose.yml -- up postgres-local

# 构建并启动当前服务及其真实依赖，先打印展开后的服务名。
npm run stack -- compose -p y-1 --env-file .env.docker.example -f docker-compose.yml -- up --build identity-service

# 只停止明确服务，保留数据卷。
npm run stack -- compose -p y-1 --env-file .env.docker.example -f docker-compose.yml -- stop identity-service postgres-local

# 只读检查，不启动、停止、构建任何服务；不能代替实际启动时的带锁检查。
npm run stack -- check --project y-1
```

`up` 不隐式构建镜像，需要构建时显式加 `--build`。依赖从解析后的 Compose 配置展开，按拓扑顺序逐个构建、启动并等待；保留 Compose 自身的 health/completed 检查，不用 `--no-deps` 隐藏必要依赖。`up` 成功后保留开发服务，失败时停止本次新增的运行服务并保留数据。

`frontend` 的当前真实依赖链为 Edge 与五个 Java 领域服务，所以完整公共入口 E2E 仍需要较大运行集。服务清单不能取代业务依赖分析；例如 Hypit runner、数字人、观测组件，仅在相应用例需要时显式加入。

## 守卫检查什么

- 同一操作系统用户共享 `~/.cache/grassland-local-stack/lock`，跨会话、项目、worktree 互斥。验收入口从构建前持锁到测试与收尾完成；子脚本可以继承会话，同一会话内的 Compose 变更另有互斥，不能并行起栈。
- 用容器 Compose 标签、工作目录与 Git common directory 识别同仓库的不同 worktree；兼容旧项目名。发现另一套运行、重启或暂停中的本项目栈就拒绝；相同项目名属于别的目录也拒绝接管。
- Docker 查询/inspect/config 失败即拒绝，不能当作空环境。其他项目或无法归属的容器只报告，不自动停止。
- `up/build/run/start/restart/stop` 要求明确服务；拒绝未知服务、全 profiles、`--no-deps` 和全栈删除。启动时若同一栈还有清单外的运行服务，要求先确认用途并定向停止。专门在既有开发栈上执行的观测冒烟通过 `--keep-existing` 显式保留基线并打印清单。
- 成功、失败、INT/TERM 后只回收本次新增的运行服务，保留复用的既有服务与数据。清理失败返回非零并报告；SIGKILL/断电无法执行收尾，下次会盘点残留栈。
- 不自动恢复旧栈，不换端口避让第二套栈，不做全局 prune。单栈和串行可以减少资源峰值，但不保证任何完整链路都能适配机器内存；本入口没有修改 Docker Desktop 的 CPU/内存配置。

发现残留锁时先查看 `owner.json` 中的 PID、目录与任务，确认进程及其子进程已经结束，再处理该锁目录。守卫不会因超时擅自抢占。不要把 `LOCAL_STACK_TOKEN` 或 `LOCAL_STACK_ENTRY` 写入 shell 配置、环境模板或任务配置；它们只用于当前执行树的短期继承。

## 验收生命周期

需要持锁完成整段工作时，使用：

```bash
node scripts/local-stack.mjs run --project y-1 --docker --cleanup -- bash scripts/acceptance/my-check.sh
```

该命令是新增验收脚本的用法模板，`my-check.sh` 需替换为实际脚本。被包裹的脚本也必须通过守卫调用 Compose。纯静态验证省略 `--docker`，不会为了检查锁连接 Docker。shell 入口可复用 `scripts/lib/local-stack.sh` 的 `local_stack_enter`，重执行后由 Node supervisor 管理信号和最终清理。

隔离 E2E 需要每个浏览器引擎使用全新数据库时，使用 `run --fresh --cleanup`。该模式先拒绝既有容器、项目卷、外部或已存在的目标数据卷；只有在这个会话内，`node scripts/local-stack.mjs reset` 才可以移除本次新建的隔离容器、项目卷和网络。此删除权限不适用于普通开发或复用栈，不等于通用 `down -v`。默认模式始终保留数据。

已接入的入口：

| 入口 | 行为 |
|---|---|
| `scripts/acceptance/hypit-compose.sh` | 显式服务，取消固定全量构建/五服务启动；`stop` 保留数据；`reset` 仅限 fresh 会话 |
| `scripts/ci-e2e.sh` 及调用它的任务变体 | fresh 隔离验收、明确 E2E 依赖与可选 sidecar、串行构建与单 worker、按浏览器重置本次数据 |
| `scripts/acceptance/verify-107-fix-2.sh` | 整段持锁；C02 fresh 验收；C08 只启用 Hypit 链路，不附带 DH；退出回收新增服务 |
| `scripts/acceptance/verify-107-full.sh` | 构建前盘点，拒绝端口避让另起栈，成功/失败/中断均收尾 |
| `scripts/local-observability-smoke.sh` | 在明确已有栈上添加必要观测服务，只回收新增服务 |
| `scripts/local-otel-trace-smoke.sh` | 单一 collector 验收，拒绝与另一套本项目栈并行 |
| `scripts/ci-image-security.sh` | 镜像构建/扫描共用重型任务锁，不启动另一套应用栈 |
| `scripts/acceptance/task-105-chaos.ts` | 必须在 `run --docker --keep-existing` 会话中执行；恢复仅 `start` 已有容器，Compose 变更通过守卫 |

`scripts/production-release.sh` 是生产发布入口，本次没有改变其拓扑或发布流程，不能拿它绕过本地资源约束。启动守卫也不会拦截未接入的外部 Gradle/Testcontainers 命令；本地运行它们应纳入 `run` 会话与相应项目约定。

## 验证守卫本身

```bash
npx vitest run tests/deployment/local-stack-guard.test.ts --maxWorkers=1 --no-file-parallelism
```

测试使用临时 HOME、独立假 Docker 可执行文件和状态文件，覆盖第二套栈、worktree、服务依赖、互斥、失败/信号清理、原有数据保护以及真实 shell 入口接线；不会连接真实 Docker daemon。这些测试证明守卫行为，不代表完整业务 E2E 已验收。
