# 后端模块边界

核对日期：2026-10-06。本文描述同一服务进程内部的职责，部署拓扑保持原状。

## Marketplace：任务目录

`com.grassland.marketplace.taskcatalog` 的任务入口按用例组织：

| 组件 | 职责与事务 |
|---|---|
| `TaskController` | 8 个写路由的请求绑定、调用者解析、HTTP 响应 |
| `TaskQueryController` | 6 个读路由的请求绑定、调用者解析、HTTP 响应 |
| `TaskDraftService` | 草稿创建/编辑，字段检查、套餐关联与草稿事件 |
| `TaskPublicationService` | 创建送审、草稿发布、关闭招募；配额锁与审核写入保持同事务 |
| `TaskRevisionService` | 修订版本、报名重新同意、重审与事件同事务提交；接受/预留中的合作阻止修订 |
| `TaskCancellationService` | 先提交任务取消及待接受报名取消；资金调用在本地事务外，报名终态、补偿金额与事件原子提交；重复取消继续收尾 |
| `TaskPromotionService` | 套餐关联校验、回填/解绑与明确结束推广 |
| `TaskWritePolicy` | 管理权限与写入规则；不负责状态转换 |
| `TaskQueryService` | 列表、详情、preview、用量与经营报表的读编排 |
| `TaskFeedService` | 推荐官筛选、keyset 游标、页内增强和同分排序 |
| `TaskReadAccess` / `TaskReadEnrichment` | 参与者可见性/等级；套餐和商家信用批量增强 |
| `TaskBodies` / `TaskEvents` | 响应投影及事件载荷；资金取消事件使用确定性 ID |
| `TaskContractTerms` | 合同字段投影与修订差异判断，继续使用单源合同定义 |

调用方向为 HTTP → 用例服务 → 规则/仓储/外部客户端。控制器不得直接依赖 Repository、FinanceEscrowClient、Outbox 或 TransactionalOperator。命令服务不得反向引用控制器或查询服务，不返回 HTTP 类型。

HTTP 路径、返回信封、201/200/错误状态码、任务版本与历史快照语义保持兼容。任务取消分两阶段是有意设计：外部资金成功而本地提交失败时，报名仍可被重试扫描，依赖资金接口已有的幂等语义恢复。

## Intelligence：模块归属

包归属和允许方向的唯一机器定义是 [intelligence-modules.v1.json](../../contracts/intelligence-modules.v1.json)。下面只说明职责，避免维护第二份允许依赖列表。

| 模块 | 包及职责 |
|---|---|
| foundation | security、event、config、admin：身份上下文、事件信封和基础配置 |
| execution | ai、credits、guesttrial、settings：模型执行、额度与运行设置 |
| media | media、mediaplatform、speech、douyin、bilibili：素材、媒体处理和平台适配 |
| library | contentlibrary、embedding、hottopic、homepage：内容库、检索与发现 |
| context | creationcontext、creationlineage、creationstyle、creationvoice、humanize：上下文、谱系和风格 |
| content | article、articleimage、moments、imageanalysis、imagestudio、cardseries、comedy、videorecreation：各类内容生成与派生 |
| governance | contentsafety、compliance、verification：安全审核、核验与数据清理 |
| video | videoproduction、orchestration、videostudio：视频制作与 Temporal 编排 |
| creation | creationassistant、creationcanvas、creationstudio：创作会话、画布与发布流程 |
| hypit | hypit：项目、计划、执行、变体与结果归档 |
| legacy-digitalhuman | digitalhuman：下线后的兼容/清理代码，不承接新功能 |
| bootstrap | 根启动类与 smoke：应用装配及探针 |

允许方向必须无环。跨模块只通过应用服务和领域值对象交互；禁止新增对其他模块 Controller、Repository、Worker 及其嵌套 record 的直接依赖。嵌套在仓储中的传输类型也应逐步提取成独立领域类型。

### 存量债务与收敛顺序

这是内部边界的第一步，尚未物理拆包或消除所有循环。ArchUnit 扫描生产字节码，包括全限定名、方法签名和泛型引用；未归属的新包直接失败。首轮逐项审阅登记 **131 条规则违反记录**（53 条方向、78 条内部类型）（方向与内部类型规则可对同一类对分别记账），见 [module-debt.json](../../platform-java/services/intelligence-service/src/test/resources/architecture/module-debt.json)。这不是模块级豁免：新类、新目标或新方向仍会失败；已消失的例外必须删除，不能保留用于后续回退。

| 后续收敛区域 | 具体方向 |
|---|---|
| 素材引用 / 运行记录 | 为 MediaReferenceRepository、AiRunRepository 提供用途明确的应用服务，逐步移除跨域直接写库 |
| 创作上下文 | 对外提供快照读取/冻结接口；模型配置策略归入 execution，消除执行层反向读取创作实现 |
| 画布与视频 | 将 workspace 绑定、版本采用和权限校验形成明确应用边界，减少 video 对画布仓储和 record 的引用 |
| 视觉任务与卡片 | 将 CardSeriesOperationRepository 暴露的作业类型迁至独立领域模型，梳理 VisualJobService 的所有权 |
| Temporal 与发布 | 把创作/公众号 Activities 归回对应业务，保留编排与实现的单向调用 |
| 清理与下线兼容 | 通过清理端口编排各域；数字人仅保留现有兼容清理路径 |

每次修复某条债务，应先补相关状态/失败行为测试，再迁移调用者，最后删除相应例外。门禁只约束 Java 静态依赖；跨模块 SQL、反射、事件字段和运行时调用仍需评审与集成测试。

## 验证入口

在完成 [资源盘点](本地启动与资源守卫.md) 后，通过本地守卫串行执行 Java 测试。纯架构检查不需要容器：

```bash
node scripts/local-stack.mjs run --project y-1 --cleanup -- \
  platform-java/gradlew -p platform-java --no-daemon --max-workers=1 \
  :services:marketplace-service:test --tests '*TaskArchitectureTest'
node scripts/local-stack.mjs run --project y-1 --cleanup -- \
  platform-java/gradlew -p platform-java --no-daemon --max-workers=1 \
  :services:intelligence-service:test --tests '*IntelligenceModuleBoundaryTest'
```

行为回归为 `EngagementMilestoneSettlementIT`（结算事件失败与修订重审回滚）、`TaskControllerIT`（生命周期/权限/接受与修订竞争）、`HypitVariantObservationIT`（12 组状态映射、迟到结果、租约替换、观察失败恢复）。前端结构门禁同时检查 taskcatalog 路由唯一性和拆分类体积。
