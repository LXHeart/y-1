# 资源与事件生命周期接入清单

> 任务书 #103 C103-19（W19/BR-19）：新增持久化资源、后台任务、事件消费者必须先登记再接线。
> 本文档是接入说明；权威登记簿是两份版本化 JSON，由 `npm run quality:lifecycle` 在 CI 早期阶段强制校验。

## 登记簿

| 登记簿 | 路径 | 内容 |
|---|---|---|
| 资源生命周期 | `tests/contracts/resource-lifecycle.registry.json` | 每张受管持久表/资源族的归属、活动状态、终态证明、清理策略、派生物与守卫测试 |
| 事件与消费者 | `tests/contracts/event-consumers.registry.json` | 每个业务事件的 producer、收件人策略、消费者、投递事务与守卫测试；有意不通知必须写 `ignoredReason` |

## 何时必须登记

- 新建任何持久表（迁移里出现 `CREATE TABLE`）——先按下方五类判定 `scope`，未知归属**不能默认 public**，登记不了就说明归属未想清楚。
- 给既有表新增「活动状态」（注销 prepare 会阻塞的状态）——同步更新 `activeStates`（BR-15：不能只数 running）。
- 新增 outbox 事件类型或新消费者——同类型多 producer 聚合为一行。
- 有意退役条目——置 `"retired": true` 并写 `retiredNote`（原因与去向），不允许直接删行抹历史。

## resource 条目 schema

| 字段 | 约束 |
|---|---|
| `table` | 表名（唯一；重复登记失败） |
| `service` | 归属服务 |
| `scope` | 枚举：`personal` / `org-shared` / `financial-audit` / `platform-configuration` / `ephemeral` |
| `ownerResolver` | 账号归属解析路径（直列或 parent 链，如 `operation→owner`） |
| `activeStates` | 非空数组：注销 prepare 视为活动的状态/条件 |
| `terminalEvidence` | 「已终结」的证明口径（费用已结/供应商已核实等） |
| `retentionClass` | 保留策略类别（`erase-with-owner` / `retain-financial-facts` / …） |
| `eraseHandler` | 清理实现入口（服务/批次名）；财务审计类写明不删除 |
| `derivedObjects` | 派生物数组（对象/向量/缓存——没有独立表也要列） |
| `tc` | 守卫测试文件路径（必须真实存在；编造引用会被门禁拒绝） |
| `retired` / `retiredNote` | 可选；退役时必填说明 |

## event 条目 schema

`eventType`（唯一）、`producer`（真实生产类名——门禁会在源码中定位）、`recipientPolicy`（§6.4 矩阵收件人）、
`consumer`、`delivery`（inbox+notification+mail 同事务）、`tc`（守卫测试）、可选 `ignoredReason`（有意不通知的原因，
缺它而「没人消费」即违规——BR-07 不允许静默 IGNORED）。

## 门禁

```bash
npm run quality:lifecycle          # 本地
npx tsx scripts/quality/check-lifecycle-contracts.ts --registry-root tests/contracts
```

校验：schema 完整性、scope 枚举、activeStates 非空、tc 引用真实文件、producer 类名可定位、
retired 必带说明、同名去重。合成负例见 `tests/contracts/lifecycle-registration.contract.test.ts`——
漏登记、悬空引用、编造 producer 都有可复现失败。

## 与 §7.3/§7.4 的关系

登记簿的 `activeStates`/`terminalEvidence` 与任务书 §7.3「创作任务阻塞矩阵」、§7.4「资源与派生数据保留规则」
同源；矩阵更新时登记簿同步更新，注销屏障（V85 gate）按登记语义执行写入防护。
