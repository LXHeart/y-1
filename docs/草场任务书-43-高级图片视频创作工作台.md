## 目标

在 AI 创作中心新增两个工作台，把 PRD 的「高级创作」落成可用工具：

1. **图片编辑台**（image-studio）：裁剪 / 旋转翻转 / 调色 / 滤镜 / AI 抠图 / 换背景 / 主体突出，产物存素材库
2. **视频工坊**（video-studio）：剪辑模板库（带入创作）、字幕工作台（自动分轴 + 校准 + SRT/VTT 导出）、
   BGM 情绪节奏建议（AI）、封面/缩略图工作台（视频抽帧 + 文字模板合成 + AI 生图）

**平台定位（贯穿全部设计）**：AI **建议** + **工具辅助**——平台不做视频剪辑渲染。成片在用户自己的剪辑
工具里完成，本工作台的产物是：处理后的图片素材、SRT/VTT 字幕文件、结构化建议、封面图。

**本期不做**（防扩散，勿顺手实现）：

- 浏览器视频时间线剪辑与成片导出（多轨/转场/渲染）——平台不是剪映
- 视频文件音轨抽取（视频→音频转写）：v1 字幕只收**音频文件**（复用 #33 既有链路）；前端抽音轨另案
- ASR 时间戳升级（provider 返回句级 segments）——#33 转写只有纯文本，见 D5 的诚实做法；改 provider 协议另案
- 字幕 cue 的服务端持久化 / 跨设备：v1 localStorage 暂存 + 文件导出（见 D5）
- 音频 BPM 检测 / 节拍 DSP / 内置 BGM 曲库（版权）
- 剪辑模板运营配置后台：v1 前端版本化静态常量（D8）
- 封面生图的参考图模式（multipart 参考图端点已存在，可后接）
- 素材库图片直接进编辑器（canvas 跨域污染风险，见 D9）
- 移动端适配

| D1 | 平台只做「建议 + 工具辅助」，不做 NLE 剪辑渲染 | PRD §4.4 全部措辞是「建议/推荐」；渲染导出是另一个量级的工程与成本 |
| D2 | 图片编辑器的裁剪/旋转/调色/滤镜/换背景合成/主体突出 = **纯前端 canvas**，零积分零后端 | 确定性像素操作不值得烧模型；用户可无限次调整 |
| D3 | 唯一 AI 图片步骤 = 服务端**抠图**：新平台能力 `image_edit` + `ImageMattingProvider` 接口（Sandbox 实现 + OpenAI 兼容真实实现），经 `AiExecutionService.prepareExecution` 预算闸，**不设积分键**（与 image_generation 现行口径一致） | 换背景/主体突出 = 抠图 alpha 的前端组合，不必每个组合都打模型；预算闸已覆盖 org 成本控制 |

| D5 | 自动字幕 = 复用 #33 语音转写（纯文本）+ **前端启发式断句分轴**（标点切分 + 字数比例分配时长，算法本文定死）+ 人工校准（audio 播放联动）+ SRT/VTT 导出。不做假时间戳 AI、不改转写协议 | PRD 说的是「时间轴**建议**」；比例分轴是可校准的初稿，不是伪造的精确轴 |

## Stage 1 — intelligence 后端：抠图能力 + BGM 建议 + 转写列表

**零 Flyway migration。**

1. **抠图**：
   - 新包 `imagestudio/`；`ImageMattingProvider` 接口：`Mono<MattingResult> matting(MattingCommand)`，`MattingCommand(byte[] image, String mimeType)`，`MattingResult(byte[] pngWithAlpha, String providerModel, boolean sandbox)`
   - `SandboxImageMattingProvider`（provider 名 `sandbox`）：用 `ImageIO` 输出**中央 80% 不透明、边缘 10% 线性渐变 alpha** 的 PNG——保证 IT 可断言（尺寸同源、含 alpha 通道）
   - `OpenAiCompatibleImageMattingProvider`（provider 名 `openai-compatible`）：OpenAI 兼容 images/edits 风格请求，baseUrl/model/apiKey 来自平台模型配置（控制面 capability `image_edit`），错误映射照 `ImageGenerationClient`
   - `POST /api/image-studio/matting`：body `{mediaId}`；caller 解析后校验 media 归属 owner + MIME ∈ image/* + active（读 `media_reference`，照 `MediaController.ownedActive` 的过滤口径，跨账号/非图统一 404）→ `prepareExecution(accountId, orgId, "image_edit", ...)` 预算闸 → provider 执行（并发槽照 `SpeechTranscriptionService.executePrepared` 的 limiter 模式）→ 结果经 `GeneratedImageStore` 落短 TTL（30min，purpose 用生成图现行值）→ 响应 `{imageUrl: "/api/image-studio/matting-results/{id}"}`
   - `GET /api/image-studio/matting-results/{id}`：owner-only + 30min TTL PNG 读端点（照 `ArticleImageController.generated`）
   - 控制面无 `image_edit` 配置时 503「未配置图像编辑模型」（明确报错，不静默降级）；seeder 给 sandbox 种子（照 `seedSandboxCapability`）
2. **BGM 建议**：`POST /api/video-studio/bgm-advice`（`videostudio/` 包）：
   - body `{platform, contentForm, topic, durationSeconds, moodHint?}`（platform/contentForm 白名单校验照 AI 中心前端既有平台枚举；durationSeconds 5..600；topic ≤200 字）
   - `credits.consume(accountId, CreditFeature.VIDEO_STUDIO_BGM)`（新枚举键 `video_studio_bgm`，javadoc 照现有风格）→ 共享文本执行 helper（锚点：`comedy/ComedyController.java:75` 的 text 能力调用形态）→ prompt 定死（见下）→ JSON 输出校验（解析失败 502「建议生成失败，请稍后重试」，照 creationassistant 的结构化解析容错）
   - 响应 `data: {moodDirection: {label, reason, referenceStyle}, rhythm: [{timeRange, intensity(1-5), suggestion}], syncPoints: [{atSeconds, suggestion}], cautions: [string]}`；`rhythm` 2..6 项、`syncPoints` 0..8 项，超限截断不报错
   - prompt（系统段，Qoder 原样落码）：你是资深短视频音频顾问。根据平台、内容形式、主题、时长和情绪倾向，给出 BGM 情绪方向与节奏规划。只输出 JSON，不要输出任何其他文本，字段结构为 {moodDirection:{label,reason,referenceStyle}, rhythm:[{timeRange,intensity,suggestion}], syncPoints:[{atSeconds,suggestion}], cautions:[]}。rhythm 按时间轴顺序覆盖全片；syncPoints 给卡点时机建议；cautions 提示版权与平台风险。
3. **转写列表**：`speech/SpeechTranscriptionController` 加 `GET /api/speech/transcriptions`：owner 最近 20 条，`data.items = [{id, mediaReferenceId, durationMs, status, detectedLanguage, createdAt, transcriptText(仅 completed 且非空时带)}]`，按 created_at DESC

## 验收标准（整体）

1. 图片编辑全链路（sandbox 模型）：本地上传 → 裁剪/调色/滤镜 → AI 抠图 → 换背景（纯色/模糊原图两种）合成 → 下载成功 + 素材库出现该图；两次合成只调一次 matting（预算闸只过一次）

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`；全量 IT 堆已设 2g，单类绿全量挂先查堆/Docker 再怀疑代码
- intelligence **没有全局 ObjectMapper bean**——新 controller 需要 JSON 就持服务本地 `new ObjectMapper()` 实例，注入全局 bean 会炸整个 Spring 上下文
- Reactor：`switchIfEmpty` 参数在 assembly 期求值，副作用调用包 `Mono.defer`；provider HTTP 调用放 `boundedElastic`
- 平台能力执行必须走 `AiExecutionService.prepareExecution` 预算闸 + 并发槽（锚点：speech/articleimage 的执行模式），失败结算（settleFail/finalizeRunFailure）路径照抄，别只写 happy path
- edge fail-closed：新前缀不进 RouteManifest 就是 404；内部逻辑端点不暴露 `/internal/**`
- Canvas 前端：跨域图片 taint 画布后 `toBlob` 抛 SecurityError——编辑器输入只收本地文件（D9）；`ctx.filter` 导出与 CSS filter 预览需同源语法
- 积分键：`CreditFeature` 加枚举无需 migration（legacy feature 列无 CHECK）；扣分失败 402 信封照既有 `InsufficientCreditsException` 处理
- 请求 record 可选数值字段必须包装类型（`Long`/`Integer`）；响应白名单手写 map，勿整行序列化
- 提交按语义拆分（建议：intelligence 抠图 / intelligence bgm+列表 / edge+flag / 前端图片编辑台 / 前端视频工坊 / docs 各一个 commit），commit message 中文、`feat(scope):` / `test(scope):` / `docs:` 风格
