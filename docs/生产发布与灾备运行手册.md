# 生产发布与灾备运行手册

本文对应 GL-P3-PLATFORM-001，规定当前 Compose 生产候选栈的可观测性、密钥、发布、回滚和备份恢复操作。它是执行门禁，不代表当前开发型 Kafka/Temporal 已达到生产高可用标准。

## 一、生产边界

- 公网只暴露 TLS 终止后的 frontend/Edge 入口；Prometheus、Alertmanager、Grafana 和各 Java 服务 management 端口保持私网。
- 真实 PSP 仍受 D-01 渠道准入门禁约束。未接真实渠道时，只能验证内部账务和模拟支付状态。
- Kafka 当前为单 broker KRaft，Temporal 当前为 start-dev + SQLite。两者只能用于开发与功能验证，生产必须由部署侧替换为多副本持久化集群并另行制定备份恢复方案。
- 回滚只恢复应用镜像和路由配置，不自动逆向 Flyway migration。数据库变更必须采用 expand/contract，旧版本须能读取新 schema。
- Redis 中的身份断言 replay key 是短期防重放状态，不纳入业务备份。

## 二、密钥管理

真实密钥由 Vault、云 Secret Manager 或 SOPS 在部署机临时物化。仓库只保留 production-secret-contract.csv 与两个 example 文件。

生产前执行：

~~~bash
chmod 600 /run/secrets/grassland/alertmanager-webhook-url
chmod 600 /run/secrets/grassland/grafana-admin-password
scripts/validate-production-secrets.sh --env-file /run/secrets/grassland/production.env
~~~

生产环境至少需要：

- PUBLIC_FORWARDED_PROTO=https、SESSION_COOKIE_SECURE 不得为 never、SECURITY_HSTS_ENABLED=1。
- Redis replay 防护开启。
- MinIO root 凭据只用于 bootstrap，运行服务使用不同的受限 service account。
- ALERTMANAGER_WEBHOOK_URL_FILE 和 GRAFANA_ADMIN_PASSWORD_FILE 指向权限不高于 0600 的真实文件，不得指向仓库 example。
- 身份断言 17 对密钥及 access-token 签发/验签配置一致。

轮换 access token 或断言密钥时执行三阶段流程：

~~~bash
scripts/rotate-identity-keys.sh plan-access-token access-token-202608
scripts/rotate-identity-keys.sh plan-assertion EDGE_USER_FINANCE edge-user-finance-202608
~~~

先把新 key 放入 verifier 的 previous slot，再滚动 signer/current verifier，等待 TTL + leeway 后移除旧 key。每阶段都重新执行 validate-production-secrets.sh，禁止单边直接替换。

## 三、可观测性

启动私网观测栈：

~~~bash
ALERTMANAGER_WEBHOOK_URL_FILE=/run/secrets/grassland/alertmanager-webhook-url \
GRAFANA_ADMIN_PASSWORD_FILE=/run/secrets/grassland/grafana-admin-password \
docker compose --profile observability up -d prometheus alertmanager grafana
~~~

Prometheus 抓取 Edge、Identity、Marketplace、Finance、Trust、Intelligence 六个 Java 服务。Grafana 自动加载 Platform Overview，包含服务存活、HTTP 请求/5xx、JVM heap 和 process CPU。统一规则覆盖：

- 服务连续 2 分钟不可抓取。
- 5xx 比例连续 10 分钟高于 5%。
- JVM heap 连续 15 分钟高于 85%。
- process CPU 连续 15 分钟高于 90%。
- identity 邮件死信与 marketplace 运营死信领域规则。

生产部署需在私网 ingress 或 VPN 单独暴露 Grafana，不应把 3000/9090/9093 直接发布到公网。每次发布前检查 Prometheus target 全绿、规则 health=ok、Alertmanager receiver 可达。

## 四、发布

生产镜像变量必须固定到 repository digest，例如：

~~~dotenv
RELEASE_IMAGE_FRONTEND=registry.example/grassland/frontend@sha256:...
RELEASE_IMAGE_BACKEND=registry.example/grassland/backend@sha256:...
RELEASE_IMAGE_EDGE_BFF=registry.example/grassland/edge-bff@sha256:...
RELEASE_IMAGE_IDENTITY_SERVICE=registry.example/grassland/identity-service@sha256:...
RELEASE_IMAGE_MARKETPLACE_SERVICE=registry.example/grassland/marketplace-service@sha256:...
RELEASE_IMAGE_FINANCE_SERVICE=registry.example/grassland/finance-service@sha256:...
RELEASE_IMAGE_TRUST_SERVICE=registry.example/grassland/trust-service@sha256:...
RELEASE_IMAGE_INTELLIGENCE_SERVICE=registry.example/grassland/intelligence-service@sha256:...
MIGRATION_COMPATIBILITY_APPROVED=yes
FINANCE_RELEASE_APPROVED_BY=<审批人或工单号>
PUBLIC_HEALTH_URL=https://api.example.com/health
~~~

标准流程：

~~~bash
scripts/production-release.sh --env-file /run/secrets/grassland/production.env preflight
scripts/production-release.sh --env-file /run/secrets/grassland/production.env plan --release-id 2026-08-11.1
scripts/production-release.sh --env-file /run/secrets/grassland/production.env deploy \
  --release-id 2026-08-11.1 \
  --backup-manifest /secure-backups/2026-08-11/manifest.txt
scripts/production-release.sh --env-file /run/secrets/grassland/production.env deploy \
  --release-id 2026-08-11.1 \
  --backup-manifest /secure-backups/2026-08-11/manifest.txt \
  --execute
~~~

不带 --execute 只做预演。真正执行前，脚本会重新校验密钥、migration 兼容性审批、finance 人工审批、Compose 配置和镜像 digest；执行时把旧容器 image ref、image ID、repo digest 写入被 git 忽略的 .release-state/<release-id>/，然后等待 PUBLIC_HEALTH_URL。

发布完成后至少手工验证登录、任务读取、余额只读、媒体读取，并观察 15 分钟 5xx/CPU/heap。涉及真实 PSP 时还需在 PSP 沙箱验证支付、退款、分账、提现、Webhook 和对账各一笔。

## 五、失败回滚

~~~bash
scripts/production-release.sh --env-file /run/secrets/grassland/production.env rollback \
  --release-id 2026-08-11.1
scripts/production-release.sh --env-file /run/secrets/grassland/production.env rollback \
  --release-id 2026-08-11.1 \
  --execute
~~~

先审查生成的 rollback.compose.yml，再执行。脚本使用发布前记录的 repo digest/image ref 和 --no-build 恢复旧容器，并再次等待公网 health。若新 migration 破坏旧版本兼容性，停止自动回滚并按数据库事故流程处置；禁止对生产库直接执行手写逆向 DDL。

## 六、备份与恢复演练

备份依赖 pg_dump 和 mc，输出 PostgreSQL custom dump、MinIO 文件镜像和 SHA-256 manifest：

~~~bash
DATABASE_URL=postgresql://... \
MINIO_ENDPOINT=https://minio.internal \
MINIO_ACCESS_KEY=... \
MINIO_SECRET_KEY=... \
MINIO_BUCKET=grassland \
scripts/backup-restore-drill.sh backup --destination /secure-backups/2026-08-11

scripts/backup-restore-drill.sh verify \
  --manifest /secure-backups/2026-08-11/manifest.txt
~~~

恢复只能指向隔离环境：数据库 host 必须是 localhost 或名称包含 restore/drill/staging，且目标 bucket 必须以 grassland-restore-drill- 开头。命令默认 dry-run：

~~~bash
scripts/backup-restore-drill.sh restore \
  --manifest /secure-backups/2026-08-11/manifest.txt \
  --target-database-url postgresql://restore_user:...@restore-db.internal/grassland_drill \
  --target-bucket grassland-restore-drill-20260811

scripts/backup-restore-drill.sh restore \
  --manifest /secure-backups/2026-08-11/manifest.txt \
  --target-database-url postgresql://restore_user:...@restore-db.internal/grassland_drill \
  --target-bucket grassland-restore-drill-20260811 \
  --execute
~~~

执行恢复使用 pg_restore --clean --if-exists --no-owner，MinIO 镜像写入显式目标 bucket，完成后查询 app_users 和 organization 基本行数。演练还要抽查登录、任务、资金台账只读一致性和媒体对象下载；不得对恢复环境触发真实 PSP、邮件、短信或推送。
