## 一、项目定位

草场（Grassland）：连接商家与推荐官的营销内容撮合平台。
原为 Vue 3 + Express TypeScript 单体，正在按 **Strangler Fig 模式**渐进迁移到 Java 微服务。

- 旧库（根目录 `server/`、`src/`）：仍承载全部业务，**不要改动其行为**
- 新库（`platform-java/`）：草场领域新代码的落点
- 迁移安全机制：`edge-bff` 用 RouteManifest 逐路由切换，每条路由有 `enabled` 开关，可零重启回滚到 Express

### Epic 3 Slice 3B：对象存储（MinIO + platform-storage）
- **MinIO**（minio/minio，API :9000 / 控制台 :9001）已加入 compose，**无 profile 常驻**（与 kafka/redis 一致）+ `minio_data` volume
- **共享库 `platform-storage`**：AWS SDK for Java v2（`software.amazon.awssdk:s3`）+ Spring Boot autoconfigure，消费者"加依赖 + 设属性"即用，无需改主类
  - `ObjectStorageAdapter` 平台端口 + `S3ObjectStorageAdapter` 实现（presign/put/get/head/delete）
  - **双端点签名**（SigV4 签 Host 头，正确性关键）：`S3Client` 用内部 `endpoint`（`http://minio:9000`）；`S3Presigner` 用 `public-base-url`（浏览器可达，本地 `http://localhost:9000`）
  - `@PostConstruct` 幂等 `HeadBucket → CreateBucket`（捕获 `BucketAlreadyOwnedByYou`），受 `auto-create-bucket` 开关控制
  - `@ConditionalOnProperty("object-storage.enabled","true")` 按服务 opt-in，**不带** `matchIfMissing`（避免无关服务启动失败）
  - 测试 18/18：属性校验 / autoconfigure（ApplicationContextRunner）/ Mockito 单元 / testcontainers MinIO 全链路
- **marketplace 首发 consumer**：`POST /storage/uploads`（申请 presigned PUT URL，presign 无 I/O）+ `POST /storage/uploads/confirm`（headObject 校验对象已存在，缺失 404），落地 HLD 三步上传流
- 端到端验证：testcontainers MinIO 三步上传（申请凭据 → HttpClient 直传 → confirm 校验元数据 → 不存在 key 404）✓
- **本轮未做**：对象元数据落库（领域 schema 留后续）、生产专用 service account（当前用 root key，本地便利）

### Epic 3 Slice 3C：Temporal 工作流基础
- **Temporal dev server**（temporalio/cli `start-dev`，gRPC + Web UI 同在 :7233）已加入 compose，**无 profile 常驻** + `temporal_dev_data` volume（sqlite 持久化，零外部 DB 依赖，不打扰 neon）
- **首发 Worker 落 marketplace-service**：`temporal-spring-boot-starter:1.37.0`（GA，官方支持 Spring Boot 4，自 1.34.0；JDK 25 无碍）
  - **demo workflow**（非业务，平台验证）：`GrasslandDemoWorkflow`（`@WorkflowMethod`）→ `prepare` activity（`ActivityOptions` + `RetryOptions`）→ `Workflow.sleep`（Timer）→ `finish` activity；`DemoWorkflowController` `POST/GET /workflow/demo`
  - **关键用法**：workflow 实现类**不加 `@Component`**（Worker 在 workflow 线程实例化；否则 `Workflow.newActivityStub` 抛 non-workflow-thread）；`@ActivityImpl(workers)` 按 name 引用，需 `spring.temporal.workers` 显式定义 worker
  - 确定性铁律（HLD 9.2）：workflow 内只用 `Workflow.sleep`/`newTimer`/`currentTimeMillis`，禁 `Thread.sleep`/`Instant.now`
  - 测试：`DemoWorkflowIT`（starter 内存 test-server 端到端 Timer + Activity）、`ReplayTest`（`TestWorkflowEnvironment` 确定性）
- **本轮未做**：HLD 7 个业务 workflow（报名预留 / 结算窗口 / 争议裁决等，属 Epic 4-6，待 finance/trust 落地）、生产部署（dev-server 仅本地）、真实 Saga compensation 测试

### Epic 2 Slice 2E：草场身份域地基（Flyway + Organization）
- **Flyway 地基**（platform-java 全仓首个 schema 迁移机制，补 HLD「独立 Flyway 历史」缺口）：identity-service 引 `flyway-core` + `flyway-database-postgresql` + postgresql JDBC
  - `DataSourceConfig`：从 `DATABASE_URL` 派生 JDBC `DataSource`（`PGSimpleDataSource`，无池）+ **手动 `@Bean Flyway(initMethod=migrate)`**——Spring Boot `FlywayAutoConfiguration` 在纯 R2DBC 应用（无 spring-jdbc/Hikari）不触发，手动兜底
  - `baseline-on-migrate=true` + `baseline-version=0` 兼容 neon 已有 legacy 表（app_users/session）；`V1__add_organization.sql` 建 organization 表（`owner_account_id` 逻辑引用 app_users，无强制 FK）
- **Organization 实体端到端**：`Organization` record + `OrganizationRepository`（DatabaseClient 手写 SQL）+ `OrganizationController`（`POST/GET /api/organizations`，create 写 outbox `OrganizationCreated` 事件）
  - `CurrentAccountResolver`：封装 MeController 鉴权链路（cookie→sid→userId→AuthUser），供受保护端点复用
  - **建模决策**：Organization 直连 account（不引入 IdentityProfile 中间层，YAGNI）；复用 neon（逻辑隔离靠服务所有权，非物理库）
- 测试：`OrganizationControllerIT`（Flyway 跑 V1 + CRUD + outbox 事件 + cookie 鉴权端到端）；全量 identity-service 28 测试全绿
- **本轮未做**：Store / Membership / Store Membership / 三级权限粒度 / IdentityProfile 活动身份 / outbox 事件 version 持久化对齐（留后续 slice）

### Epic 2 Slice 2F：身份域 Store + Membership + 三级权限
- **Flyway V2**：`store`（org 下多门店）、`organization_membership`（org 级成员 + role，`UNIQUE(org,account)`）、`organization.permission_tier`（三级商家准入，默认 draft）；回填存量 org 的 owner 进成员表
- **Store**：`/api/organizations/{orgId}/stores`（POST 需 ADMIN、GET 需 MEMBER），写 outbox `StoreCreated`；`findByOrganizationAndId` 跨 org 隔离（越界 404）
- **Membership**：`/api/organizations/{orgId}/memberships`（POST 加 admin/member 需 OWNER、重复 409；GET 列成员；DELETE 移除 + last-owner 守卫 409），写 outbox `MembershipGranted`
- **三级权限**：`POST /api/organizations/{id}/permissions/grant` 单调升级（DRAFT/BASIC_PUBLISH/FINANCE_TRANSACTION），降级或同级 409，写 outbox `MerchantPermissionGranted`；本轮 owner 自授予（dev 地基，审核流走 HLD D-05）
- **OrgAuthorization**：组织级鉴权种子（HLD `authorization` 域）——成员表为主 + `owner_account_id` 兜底（org 创建时 best-effort 种 OWNER 行，seed 缺失也不锁死 owner）
- **修复 `DataSourceConfig.parse`（预存 bug，非本 slice 引入）**：原解析对无端口 neon URL 写出 `:-1` 且丢 `sslmode`，致容器启动失败；改为省略端口段（PG JDBC 默认 5432）+ 保留 `sslmode` 查询串（丢弃 JDBC 不识别的 `channel_binding`）。R2DBC 侧（`toR2dbcUrl`）本就处理查询串，无需改
- 测试：单例容器基座 `IdentityItSupport`（testcontainers，static 块启动一次、端口稳定，解多子类共享）+ StoreControllerIT / MembershipControllerIT / PermissionGrantIT + 枚举单测；identity-service 全量 **51 测试全绿**
- 端到端：容器重建 → Flyway V1+V2 在真实 neon **applied（now at version v2）** → app 启动健康
- **本轮未做**：Store-scoped Membership（HLD `store-membership` 域，门店粒度成员）/ IdentityProfile 活动身份（商家/推荐官切换）/ 权限审核工作流（D-05：材料/审核/额度/申诉）/ outbox 事件 version 持久化对齐

### Epic 2 Slice 2G：IdentityProfile 活动身份 + Store-scoped Membership
- **Flyway V3**：`identity_profile`（账号开通的商家/推荐官身份，UNIQUE(account,type)，merchant 可关联 org）、`account_active_identity`（账号级活动身份，一行/账号，NULL=消费者）、`store_membership`（门店粒度成员，UNIQUE(store,account)）
- **IdentityProfile**（`/api/me/identities` + `/api/me/active-identity`）：开通 merchant（可选 org，给了则校验 owner）/ recommender；激活须已开通（HLD「未开通先走开通流程」），同一时间仅一个（upsert 强制）；切回消费者（active 置 NULL）；outbox `IdentityOpened` / `ActiveIdentityChanged`
- **Store-scoped Membership**（`/api/organizations/{orgId}/stores/{storeId}/memberships`）：门店粒度成员增删列，管理需 org ADMIN+、列表需 MEMBER+（复用 OrgAuthorization），跨 org storeId → 404；outbox `StoreMembershipGranted`
- **建模决策**：活动身份存账号级（HLD 10.1 per-session/多设备规则属 D-08 延期）；门店成员管理 authz 复用 org 级（门店 MANAGER 级独立授权留后续）
- 测试：`IdentityTypeTest`/`StoreRoleTest` + `IdentityProfileControllerIT`/`StoreMembershipControllerIT`；identity-service 全量 **71 测试全绿**
- 端到端：容器重建 → Flyway V1+V2+V3 在真实 neon applied（now at v3）→ app 启动健康
- **本轮未做**：活动身份 per-session/审计/多设备（D-08）/ 商家开通资料完善+审核流 / 门店 MANAGER 级独立授权 / BFF 内部身份断言签发 / outbox 事件 version 持久化对齐

### Epic 2 Slice 2H：商家权限审核工作流（D-05 地基）
- **Flyway V4**：`merchant_permission_request`（org 申请升级 tier，含 materials json / status / reviewer / note）
- **申请侧**（`/api/organizations/{orgId}/permission-requests`）：owner 提交升级申请（requestedTier 须高于当前 org tier，否则 409）；MEMBER+ 可列；outbox `PermissionRequested`
- **审核侧**（`/api/admin/permission-requests`，平台 admin）：列 pending 队列 / 详情 / 审核（approve→`updatePermissionTier`+`MerchantPermissionGranted`；reject→tier 不变；终态→409）；outbox `PermissionReviewed`
- **平台 admin 门禁**：新增 `CurrentAccountResolver.requireAdmin`（`app_users.role=='admin'`，否则 403）—— identity-service 首个 admin guard
- **与 2F 共存**：2F owner 自授予 grant 保留为 dev/admin 快路径；审核流是正式业务路径，批准复用同一 `updatePermissionTier`
- 测试：`PermissionRequestStatusTest` + `PermissionRequestControllerIT`；identity-service 全量 **83 测试全绿**
- 端到端：容器重建 → Flyway V1–V4 在真实 neon applied（now at v4）→ app 启动健康
- **本轮未做**：D-05 完整规则（材料 schema/审核 SLA/额度/行业/申诉）/ under_review 领取分配 / 平台后台 MFA/再认证

## 七、续接方式（新会话怎么开）

