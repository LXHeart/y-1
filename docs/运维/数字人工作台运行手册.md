- **只跑受控面**：`grassland_dh.app.create_app(test_mode, surface)`——internal 控制面（health +
  INTERNAL01～04 最小实现）与 audio 面（仅精确 WS 路径，未到 C/D 认证合同一律 4401）。

```bash

#    intelligence.crt/key（SAN=intelligence-service）、runtime.crt/key（SAN=digital-human-runtime）、

#    scripts/acceptance/task-105-test-certificates.sh 的 openssl 参数（短命、SAN 对齐 K13.2）。

# 2) 按启用序列注入 env（.env.example 逐项；核心四开关默认全关）
#    DH_INTERNAL_ENABLED=true → DH_AUDIO_UPSTREAM=dh-runtime:9080 → DH_ENABLED=true
#    → DH_REAL_PROVIDERS_ENABLED=true（仅 H03 真实门禁通过后）
```

### 7.2 网络与端口

- 公开入口只 Nginx 精确 WS：`/api/digital-human/sessions/{uuid}/audio` 升级到 runtime 9080；
  SSE `/events` 逐块穿透不聚合；内部通道 `/internal/digital-human/` 恒 404（K07.2）。
- `DH_AUDIO_UPSTREAM` 空值=该路径 404（默认关闭）；置值后 nginx 经变量+resolver 运行期
  解析——runtime 未启动不会拖垮三入口（已用 nginx -t 两态验证，
  `test-artifacts/task-105/H/C105H-01/nginx-render-check.txt`）。上游值只允许 compose
  服务名，禁止客户端可控 host。
- 内部 mTLS 端口（9143/9443）与 content Redis 只在 `dh-internal` 容器网络（internal，
  无出站网关）；任何 compose 文件不得把它们 publish 到 0.0.0.0。
- TURN 只在 `--profile dh-turn` 后存在：监听 3478 tcp/udp + relay 段 49160-49200（有界，
  与 turnserver.conf.example 一致）；浏览器只拿 Java 签发的短期资格（120s），
  `turn-secret.txt` 永不下发客户端。排障：coturn 日志看 `allocate`/`401`（secret 轮换不齐
  会全 401——conf 内 `static-auth-secret-file` 指向的文件与 compose `dh-turn-secret`
  必须同源）；relay 不通先核对宿主防火墙是否放行 49160-49200/udp+tcp 与 conf 的
  `min/max-port`、`external-ip` 一致；TLS 回落（5349）证书路径在 conf 的 cert/pkey。

### 7.3 证书到期检测与轮换（mTLS）

```bash
# 到期检测（提前 7 天告警；<0 表示已过期）
for c in deploy/digital-human/secrets/*.crt; do
  printf '%s: ' "$c"; openssl x509 -checkend $((7*86400)) -noout -in "$c" || echo "需轮换"
done
# SAN 核验（必须与 K13.2 一致：runtime=digital-human-runtime；Java=intelligence-service）
openssl x509 -noout -ext subjectAltName -in deploy/digital-human/secrets/runtime.crt
```

轮换：双端证书由同一 CA 签发时可先换 runtime 侧（Java 信任 CA 不变）再换 Java 侧；
换 CA 时按「新 CA 追加信任→换证书→移除旧 CA」顺序滚动，期间已建 mTLS 连接不中断。
测试证书脚本幂等（checkend 复用未过期证书）。

## 9. 回滚与事件处置（#105H C105H-04）

关闭顺序（K10：关闭新建不阻断 end/结算/删除）：

1. `dh_catalog`：ADMIN02 置 `newSessionsAllowed=false`（停止新建/排队；在途会话继续走到终态）；
2. 等待活动/排队会话收尾或 ADMIN04 逐场 terminate（requestId+reason 留审计）；
3. 核对未知账务：ADMIN05 `?state=unknown` → ADMIN06 reconcile（只按确凿 provider 证据收口）；
4. UI/runtime 开关：`DH_ENABLED=false`（runtime 写路径 503）→ 需要时 `DH_AUDIO_UPSTREAM=` 清空
   （AI 入口 WS 路径 404，三入口不宕机）；
5. 回退兼容应用版本：保留新增 dh_* 表与账务行——**不执行 DROP 回滚 SQL**；
   旧 Java 版本缺 DH 清理器时保留兼容清理 worker 至零残留（`dh_cleanup` 全终态）再停。

故障注入演练（本地隔离）：`scripts/acceptance/task-105-chaos.ts --compose-project grassland-dh-test
--case <runtime-kill|java-isolation|redis-loss|provider-timeout|recording-disk-full>
--output test-artifacts/task-105/H04`（项目名白名单固定；每 case ≤60 秒观察+强制恢复）。
熔断阈值（5 分钟 session 失败率 >5% 且样本 ≥20、跨账号/重复扣费/原 mic 落盘任一 P0）→ 立即停新建
并告警；人工批准前不自动恢复。事件中 unknown 费用可留（不自动重放 provider），原 requestId 重试
不会二次收费（`dh_invocation` 唯一键 + 单次派发 CAS，DigitalHumanRecoveryIT 证明）。
