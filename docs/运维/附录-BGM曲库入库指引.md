# BGM 曲库入库指引

> 面向平台管理员与音乐素材运营；配套[任务书 #64](../任务书/草场任务书-64-视频制作管线重构.md)。2026-09-15 按治理台、管理接口和合成服务校准。
> 本文维护入库与下架流程；来源站点只是查找线索，许可必须按具体曲目、录音版本和实际使用方式核对。

## 一、曲库用途与当前边界

BGM 是平台运营资产：`bgm_track.object_key` 指向对象存储的 `bgm/{uuid}`，不进入用户素材配额，也不随用户账号删除。曲库初始为空；没有启用曲目时，成片合成跳过 BGM。

当前成片合成从**全部启用曲目随机选一首**。`BgmSelectionService` 已有情绪映射能力，但 `VideoCompositionService` 当前调用 `pick(null)`，没有传入 `bgm-advice.moodDirection.label`，也没有按任务的 `bgm_track_id` 固定选曲。因此，标签准确是入库要求，但暂不能承诺按分镜情绪命中或重合成后保持同一首曲子。

视频一口价中的镜头候选、重抽、TTS 和 BGM 不单独追加费用；本指引不调整视频计价规则。

## 二、入库标准

| 项目 | 要求 |
|---|---|
| 许可 | 优先 CC0 / 已确认公有领域的录音；其他商业授权须明确覆盖平台曲库使用、剪辑/循环/混音以及用户成片的商业发布 |
| 不接受的许可 | 当前不收要求署名（BY）、禁止商用（NC）、禁止改编或授权范围不清的曲目；把作者写进后台曲名不等于完成公开署名 |
| 格式 | MP3 / M4A，服务端检查文件头；改扩展名不能改变真实格式，仍须试听确认是完整可解码音频 |
| 大小 | 非空且不超过 10 MiB（10 × 1024 × 1024 字节；界面显示为 10MB） |
| 曲名 | 去除首尾空白后 1–100 字，建议“情绪-曲名-版本”，例如 `轻快-清晨市场-主旋律` |
| 情绪标签 | 至少一个，只选：轻快 / 温暖 / 治愈 / 燃 / 悬念 / 舒缓 / 国风 / 电子 |
| 音频质量 | 完整试听，无破音、口播水印或突兀截断；建议准备 1–3 分钟版本，并检查循环衔接 |

“免版税”不自动包含平台再授权、曲库分发或独立音频再分发权。只按已确认授权范围使用；成片中嵌入音乐与分发原始音频是不同用途。

### 来源与许可留档

| 来源线索 | 审核要求 |
|---|---|
| [Pixabay Music](https://pixabay.com/music/) | 按该录音的当前许可核对平台使用、成片商用和分发限制，不能仅凭“免费下载”入库 |
| [Free Music Archive](https://freemusicarchive.org/) | 仅筛选并确认 CC0 曲目；排除 CC-BY、NC 等不符合本指引的条目 |
| Musopen 等公有领域录音库 | 分别核对作品和具体录音的权利；古典作品公有领域不代表每个演奏录音都可自由使用 |
| 单独商业授权 | 保存合同或许可版本，并明确平台、终端用户成片和衍生处理的授权范围 |

原指引中“BY 曲在曲名尾注作者即可入库”与禁止 BY 的标准冲突，现统一执行上表。Incompetech 等来源中要求署名的免费授权版本不纳入默认入库范围；如取得符合要求的独立授权，按商业授权逐曲审核。

授权材料存放运营共享盘或受控工单。每首记录：曲目 ID、来源页、作者/权利人、具体录音版本、许可版本与取得日期、许可截图或授权凭证、审核人。当前上传界面不收集这些许可字段，上传成功不能替代人工审核。

## 三、上传与验收

1. 平台管理员进入治理台 → 管理后台 → “BGM 曲库”。
2. **上传前完成许可审核与整曲试听**。选择文件，填写曲名，勾选情绪标签，再提交。
3. 上传后确认列表出现新曲目、名称/标签/大小正确。曲目默认启用，当前上传界面没有“先存草稿”的选项。
4. 点击“试听”验证对象存储下载与实际播放；试听链接过期时重新获取。服务端用 ffprobe 尝试测时长，失败不会阻断入库，列表为空时长需要人工复核音频。
5. 保存曲目 ID 与许可材料的对应关系；在测试环境完成一段含 BGM 的成片试听，检查音量与循环。

每次入库确认：

- [ ] 许可覆盖本次用途，材料可追溯到具体录音。
- [ ] 曲名、八值标签、文件大小与听感一致。
- [ ] 完整曲目和对象存储试听均可播放。
- [ ] 成片中音乐音量合适，循环/尾部没有异常。
- [ ] 当前随机选曲的限制已纳入运营预期。

上传失败时先看具体错误：400 通常对应文件、大小、曲名或标签，权限不足需检查管理员身份；503“对象存储未启用”交由部署人员检查存储配置。记录必要的请求 ID 和错误信息，避免在反复重传时产生重复曲目。

## 四、修改、停用与删除

| 操作 | 当前行为与处理方式 |
|---|---|
| 改曲名或标签 | 治理台列表暂无编辑表单；管理接口 `PUT /api/admin/bgm-tracks/{id}` 已支持 `name`、`moodTags`、`enabled`，由有权限的管理员通过受控 API 操作，标签仍遵守八值标准 |
| 停用 | 列表点击“停用”，该曲不再参与之后的启用曲随机选择；已经合成的成片不会因此改写 |
| 删除有引用曲目 | 服务端统计 `video_production_task.bgm_track_id` 引用；有引用时返回 `deleted=false`、`disabled=true`，保留曲目行并停用 |
| 删除无引用曲目 | 删除曲目行；当前接口不会删除对象存储文件，也不等于完成空间回收 |

删除保护只识别数据库中已保存的曲目引用；当前随机选曲链路未将选中结果写入任务引用，**不能保证所有使用过的音乐都会触发删除保护**。不确定是否用过时先停用；授权撤回还需排查已生成成片及对外发布记录，不能以列表停用代替历史处置。

名称/标签更新请求体示例：

```json
{
  "name": "温暖-清晨市场-主旋律",
  "moodTags": ["温暖", "治愈"]
}
```

## 五、选曲与混音规则参考

以下是选曲服务接受情绪参数时的映射，**当前成片入口尚未传入该参数**。关键词按表格顺序取首个包含匹配；没有匹配标签曲目时退回任意启用曲。

| 情绪关键词 | 候选标签 |
|---|---|
| 轻快 | 轻快、电子 |
| 温暖 | 温暖、治愈 |
| 燃 | 燃 |
| 悬念 | 悬念 |
| 舒缓 | 舒缓、治愈 |
| 治愈 | 治愈 |
| 电子 | 电子 |
| 国风 | 国风 |
| 空值或其他 | 任意启用曲 |

例如“温暖治愈的夜晚”首先命中“温暖”。建议每个情绪准备 2–3 首，以增加曲库覆盖。

当前混音参数固定：

| 场景 | 参数 |
|---|---|
| 有配音 | 旁白音量 1.0，BGM 0.2 |
| 无配音 | BGM 0.9 |
| 长度处理 | BGM 短时循环（`-stream_loop -1`），随成片长度截断 |
