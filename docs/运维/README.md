## 推荐阅读顺序

- 本地开发：[首次运行](../../README.md#快速开始) → [日常重建](本地Docker清理与重建指南.md#二日常重建) → 按需清理；本地命令统一显式读取 `.env.docker`。
- 生产发布：[基础设施](生产发布与灾备运行手册.md#production-infrastructure) → [密钥](生产发布与灾备运行手册.md#production-secrets) → [观测](生产发布与灾备运行手册.md#production-observability)与[备份](生产发布与灾备运行手册.md#production-backup) → [发布门禁](生产发布与灾备运行手册.md#production-release) → 切流、回退和验收记录。
- 素材运营：先完成许可审核与试听，再上传启用；修改和下架按 BGM 指引执行。

## 合并与维护分工

原《生产 Kafka 与 Temporal 部署方案》的拓扑、客户端契约、首次验收和 Trace 说明已并入生产运行手册，避免与发布前置条件重复维护。[合并前原文](../归档/生产Kafka与Temporal部署方案（合并前来源）.md)留在归档，仅供追溯。

本地清理、生产发布和 BGM 运营的操作对象与数据影响不同，继续各自维护。BGM 文档保留原文件名以兼容已有引用。

维护时遵循：

- 运行行为以 Compose、脚本、配置和源码为准；服务数量、参数、界面能力变更时同步修改对应操作文档。
- 区分已实现行为、部署要求与历史实测。生产验收状态见[续接指南](../草场开发进度与续接指南.md)和真实工单，不从脚本存在或静态检查通过推断已上线。
- 凭据与受保护的生产证据保存在部署侧；本地输出放 `test-artifacts/<任务>/`，一次性脚本放 `scripts/local/`。
- 合并内容时保留归档来源，并同步[文档总索引](../文档总索引.md)与[目录迁移表](../架构/目录结构.md#旧路径迁移对照)。

文档改动后执行 `npm run docs:links` 和 `npm run docs:status`；这些是文档静态检查，不执行部署或业务验收。
