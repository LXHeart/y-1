# 草场任务书 #50：单店模式（推导制）+ 纯门店经理形态收敛

> 来源：2026-08-27 任务书 #49 收尾后与用户对齐「纯门店经理子账号」议题（#49 D12 遗留），设计讨论定稿。四点拍板：①推导制接受；②店长入口藏高级选项；③阶段不暂缓直接做（含纯门店经理收敛）；④存量零门店主体自动建默认店。
> 状态：**待实现**。
> 前置：#49（单一成员模型）已落地并本地栈验证。

## 目标

1. **单店商家零概念负担**：不问「单店还是多店」，模式由门店数量推导（≤1 = 单店模式，≥2 = 多店模式）；注册主体即自动拥有默认门店，建第二家店的动作本身就是切换。
2. **纯门店经理形态清零**：存量 store-only 商家（有门店成员关系、无组织层身份）一次性迁移升级为「主体 owner + 默认门店」，前端 store-only 特殊分支退役，全部商家共用一套权限模型与 #49 子账号能力。

## 核心原则（勿重开）

**单店不是另一种数据模型**：任务、KYB、门店媒体库、公开门店页全部挂在 store 实体上——「门店」永远存在，单店模式只是把唯一门店自动化 + 把多店管理 UI 藏起来。单店 → 多店是纯 UI 展开，零数据迁移、零权限变更。

## 决策表（已定死）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **推导制**：单店/多店不落库、不询问，前端按 `stores.length <= 1` 推导。建第二店即切换（notice 提示「已切换到多店管理」），删至一店自动降回 | 注册时选 = 新用户认知摩擦 + 选错必做切换功能；设置时选 = 没人主动进设置。推导把决策从用户身上拿走 |
| D2 | **注册即开店**：`POST /api/organizations` 同事务自动建默认门店（名 = 主体名，status=active）+ 发 `StoreCreated` outbox（与 StoreController 建店同款，审计/下游一致） | 单店用户从此不需要知道「建店」是一个操作 |
| D3 | **存量零门店主体自动补建默认店**（V46）：名 = 主体名 | 用户拍板④。补建后自动进入单店模式 |
| D4 | **单店 UI 收敛**（纯前端，按 D1 推导）：OrgTeamCard 门店管理区隐藏；建号表单门店下拉隐藏（隐式用唯一门店）；组织级建号角色默认**店员**，**店长藏进高级选项**（details 折叠，能力保留）；「我的门店」区提供「开分店」入口（展开建店表单，建完自动多店） | 用户拍板②；单店雇店长全权管理的场景真实存在，能力不砍 |
| D5 | **纯门店经理收敛**（V47 一次性迁移）：对每个 store-only 商家（存在 `store_membership` 的 manager 行、该账号无任何 `organization_membership` 行且不是任何 org 的 `owner_account_id`）补建主体：owner = 经理账号、name = 其最早门店名、permission_tier = **draft**（store-only 商家本无主体级 tier/KYB——`merchant_profile` 挂 organization，他们从未有过，等价不降级）、account_prefix 按规则生成、seed OWNER 成员行；**不动** store 行/门店认证/`merchant_profile`。多店 store-only（一人多店无主体）主体名取最早门店名，全部门店挂新主体。幂等重放 | 用户拍板③；一套权限模型，store-only 商家自动获得 #49 子账号能力（那些端点全挂组织身份） |
| D6 | **store-only 前端分支退役**：`GrasslandWorkbench` 的 `!activeOrgHasOrganizationAccess` 分支删除；`MerchantKybCard` 的 `storeOnly` prop 退役。防御：迁移后 `listOrganizations` 必含所有商家（owner 或成员），理论不再出现 store-only；万一出现按空态引导处理，不回退特殊分支 | 双形态维护成本清零；权限/子账号/审核开关全走组织口径 |
| D7 | **MyStoreScopeController 保留不动**：`listMyStoreScopes` 仍服务于工作台身份条的门店范围显示；收敛后经理 = owner，scope 查询语义不变 | 它不是 store-only 专属路径，退役收益低风险高 |

## 边界

- **不做**：permissionTier/Kyb 流程改动（store-only 升主体后按正常主体 KYB 引导补资料）；「我的门店」卡片的全新视觉设计（复用 MerchantKybCard 现有 store 呈现，只调入口层级）；多店模式 UI 任何变化。
- **不动**：`StoreAuthorization` 权限模型；#49 的子账号端点；`store`/`store_membership`/`merchant_profile` 表结构。

## 验收标准（整体）

1. **新注册零建店**：注册主体 → 工作台即见默认门店（名=主体名），单店模式无任何门店管理 UI。
2. **推导切换**：单店「开分店」建第二店 → 门店管理全量展开 + 切换提示；删至一店自动降回单店模式。
3. **建号极简**：单店模式建店员只填登录名+姓名；店长在高级选项中可选。
4. **存量收敛**：V46 后零门店主体清零；V47 后 store-only 商家清零（全部成为主体 owner，工作台五分节 + 子账号能力可用）。
5. **退役干净**：前端无 store-only 分支残留；后端 store 表/权限模型零改动。
6. **门禁全绿**：identity 全量 + 前端 test/typecheck/build + CI。
