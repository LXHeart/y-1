# 任务书 #44：创作结果增强追踪

> 生成日期：2026-08-19。交办对象：Qoder（独立开发代理，无会话上下文，本文自包含）。
> 仓库：当前 main（`ed51cf8`，工作区干净；任务书 #42/#43 为并行任务，互不依赖）。
> 来源：PRD §4.4「视频内容改编与素材生成——保存每次改编、提示词、模型、素材和版本关系」+「生成结果必须
> 经过用户确认后才能导出」。缺口：视频改编结果目前**只随 HTTP 响应返回、零持久化**（前端刷新即丢）；
> 五个视频复刻/改编生成端点的 提示词→模型→素材→产物 关系也无任何落库。进度指南暂无登记，完成后新增。

## 目标

1. **视频改编独立版本持久化**：每次 `POST /api/video-recreation/adapt-content`（独立/任务两模式）的完整
   结果落库为不可变版本行，用户可在前端查看历史改编、回看结果与提示词、把输入回填表单重跑
2. **生成关系追踪（lineage）**：视频复刻全部五个生成端点每次调用落一行
   「提示词 + 模型口径 + 输入素材摘要 + 产物引用」的 append-only 记录，可列表、可详情、可判断产物是否仍可用

**本期不做**（防扩散，勿顺手实现）：

- 改编结果的编辑/草稿状态机——版本即不可变行，要改就再生成一版（append-only 语义）
- 其他生成流接入 lineage（文章配图、朋友圈图、喜剧脚本、AI 中心各 SSE 流）——kind 枚举预留，按需另案
- 异步视频生成接入——`video_generation_job` 已有完整 job 记录（input_payload/model/result_url），不重复
- 生成图转正副本 / 延长 30min TTL / 服务端转存素材库——长期保存走前端「保存到素材库」（D5）
- lineage 的组织级管理视图与运营导出——运营审计走既有 ai_run 运行记录面板
- 分享/协作

## 决策表（已定死，勿重开）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 持久化模型 = **单表 append-only**（`creation_generation`，一行=一次生成=一个版本），不做 draft 式「可变当前行+版本快照」双层 | 改编产物不可变、无编辑语义；creation_draft 双层是为「自动保存会改」的文章场景设计的，这里不需要 |
| D2 | 覆盖面 = 五个端点：`adapt-content`（独立+任务两模式）+ 四个出图端点（asset 单/批、scene 单/批）；批量端点**一次调用一行**（result 存 images 数组） | 与「视频改编」PRD 条款对齐；视频生成的 job 表已覆盖 |
| D3 | 模型口径三分支记法：**任务模式**（`FrozenTextExecutionService`/`TaskImageGenerationService` 均有 ai_run）→ 冗余快照 provider/model/platform_model_version + ai_run_id；**独立平台模式** → `completeMultimodal` 换用 `completeMultimodalMeta` 并把 `MultimodalResult` 扩展出 provider/model（QwenClient 填充）+ 上游 run id；**BYOK 模式** → resolution=byok + BYOK config.model | 三个分支的模型信息来源不同，各自取最权威的一手值；冗余列让历史行不依赖 join 也可读 |
| D4 | lineage 写入 = **强一致**：insert 并入端点响应链，写失败则本次生成端点失败（500），不做 best-effort | 付费改编的价值包含留痕；半成功（图给了、lineage 丢了）比整体失败更难解释；单条 insert 失败率低 |
| D5 | 产物只存引用不存副本：lineage 行存 result_media_ids + URL 路径；生成图沿用既有 30min TTL，过期后详情标「已过期」；**长期保存 = 前端「保存到素材库」**（fetch 同源 imageUrl → blob → 既有 `uploadContentAssetFile`，零后端） | 不为追踪复制存储；PRD「确认后导出」语义 = 用户显式保存；generated-images URL 同源无 CORS |
| D6 | 读端点两个（`GET /api/creation-generations` 列表 keyset 分页 + `GET /{id}` 详情含媒体可用性），owner_account_id 隔离；新 edge 前缀 `/api/creation-generations` | 列表风格照 `AiRunController`；媒体可用性同库直查 `media_reference`（intelligence 内，无跨服务调用） |
| D7 | prompt 存**完整组装后的文本**（`VideoRecreationAdaptationPrompts.build` / `VideoRecreationPrompts.build*` 的输出），输入另存结构化 `input_summary` jsonb | 审计可复现：prompt 是发给模型的真实全文；结构化摘要供前端回填表单 |
| D8 | 前端不加新 AI 中心 tab：改编历史挂 `VideoAdaptationPanel`、图片产物挂 `VideoRecreationPanel` | 产物贴近生成入口；运行记录 tab 保持 run 维度不混 |
| D9 | lineage 读写**零积分**：读历史不扣分；写入随生成端点（生成本身的计费口径零改动） | 追踪是平台能力不是商品 |
| D10 | 接入点在**服务层**（`VideoRecreationAdaptationService`、`VideoRecreationImageService`、`TaskImageGenerationService.generateForBoundContext` 且仅 purpose=VIDEO_ASSET 时写），controller 与既有响应契约零改动 | runId/context 在服务内部天然可得；文章配图共用路径不受影响 |

## Stage 1 — intelligence：creation_generation 表 + 三接入点写入 + 读端点

**Migration `V33__creation_generation.sql`**（`IF NOT EXISTS`）：

```sql
CREATE TABLE IF NOT EXISTS creation_generation (
    id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_account_id      text NOT NULL,
    organization_id       text,
    kind                  varchar(32) NOT NULL
                          CHECK (kind IN ('video_adaptation', 'asset_image', 'scene_image')),
    mode                  varchar(16) NOT NULL CHECK (mode IN ('independent', 'task')),
    context_snapshot_id   uuid,              -- task 模式：冻结的创作上下文快照
    ai_run_id             uuid,              -- 平台 run（BYOK / 平台直连无 run 时为 null）
    resolution            varchar(16) NOT NULL CHECK (resolution IN ('platform', 'byok')),
    provider              varchar(64) NOT NULL,
    model                 varchar(128),
    platform_model_version int,
    upstream_run_id       varchar(128),      -- 上游 chat completion id（completeMultimodalMeta，可空）
    prompt_text           text NOT NULL,     -- 组装后发给模型的完整 prompt（D7）
    input_summary         jsonb NOT NULL DEFAULT '{}',
    input_media_ids       uuid[] DEFAULT '{}',
    result                jsonb NOT NULL,    -- 改编：normalizer 输出全文；出图：{images:[{mediaId,imageUrl,size,revisedPrompt?}]}
    result_media_ids      uuid[] DEFAULT '{}',
    created_at            timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_creation_generation_owner
    ON creation_generation(owner_account_id, created_at DESC);
```

**写入（新包 `creationlineage/`，`CreationGenerationRecorder` 服务 + `CreationGenerationRepository`）**：

- record 形状：`record(kind, mode, contextSnapshotId, aiRunId, resolution, provider, model, platformModelVersion, upstreamRunId, promptText, inputSummary, result, resultMediaIds, ownerAccountId, organizationId)`；insert 单条，写失败抛错中断端点（D4）
- 三个接入点（D10，controller 零改动）：
  1. `VideoRecreationAdaptationService`：`adapt()` 两分支与 `adaptTask()` 尾部各接一次。独立平台分支**先把 `ai.completeMultimodal` 换成 `completeMultimodalMeta`**，并把 `MultimodalResult` 扩展为 `(content, runId, provider, model)`（QwenClient 填充一手值；其他实现填 null）——注意 `completeMultimodalMeta` 已有调用方（Bilibili 分析）不受影响（record 加字段向后兼容）。BYOK 分支记 `resolution='byok'`、`provider=config.provider()`、`model=config.model()`。任务模式从冻结 run 快照冗余 provider/model/platformModelVersion + ai_run_id + context_snapshot_id
  2. `VideoRecreationImageService`：独立模式四类出图各接一次（kind=asset_image/scene_image，resolution='platform'，provider/model 取图像生成冻结配置的一手值——`FrozenImageGenerationConfigResolver` 同源读取）
  3. `TaskImageGenerationService.generateForBoundContext`：仅 `purpose == VIDEO_ASSET` 的调用写（文章配图路径零改动）；ai_run_id/platform_model_version 从内部 run 得出——需要把 runId 传出：新增内部 record 返回值（如 `GeneratedImageWithTrace(response, aiRunId, platformModelVersion)`）或在服务内直接回调 recorder，**既有公开响应契约不变**
- `input_summary` 定死：video_adaptation 存 `{topic, platform, referenceImageCount, customInstruction}`（照 `VideoRecreationAdaptationRequest` 字段裁剪）；asset_image 存 `{assetType, visualStyle, size, asset}`（批量加 `assets` 数组）；scene_image 存 `{overallStyle, size, scene}`（批量加 `scenes`）
- `result` 定死：改编=normalizer 输出 Map 原样；出图=`{images: [{mediaId, imageUrl, size, revisedPrompt}]}`（imageUrl 用端点原样返回值）；`result_media_ids` 同步收集

**读端点（`CreationGenerationController`，`/api/creation-generations`）**：

- `GET /api/creation-generations?kind=&limit=&before=`：caller 必须 owner 匹配；kind 可选过滤（非法值 400）；limit 默认 20 上限 50；`before` 为上一页末行 id（keyset：`WHERE (created_at, id) < (…) ` 或 id+created_at 组合，照 `AiRunController` 分页口径）；列表项只回摘要 `{id, kind, mode, provider, model, resultTitle(改编取结果标题字段/出图取张数), createdAt}`——**不回 prompt/result 全文**（列表轻量）
- `GET /api/creation-generations/{id}`：owner 不符/不存在统一 404；回全文（prompt_text、input_summary、result、model 口径各列）+ `resultMedia: [{mediaId, imageUrl, available}]`——available 由 `MediaReferenceRepository` 同库直查（active ∧ 未过期 ∧ 未删除）
- 响应白名单手写 map（LinkedHashMap），严禁整行序列化

**edge**：application.yml 注册 `/api/creation-generations` → intelligence，flag `EDGE_ROUTE_CREATION_GENERATIONS_INTELLIGENCE` 默认 true。

**测试**：
- Repository IT：owner 隔离、kind 过滤、keyset 分页顺序、迁移重放幂等（既有 OutboxRepositoryIT 会自动重放，DDL 必须 IF NOT EXISTS）

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`；全量 IT 堆已设 2g，单类绿全量挂先查堆/Docker 再怀疑代码
- intelligence **没有全局 ObjectMapper bean**——需要 JSON 就持服务本地 `new ObjectMapper()`；jsonb 读写用 `DatabaseClient` 手写 SQL + `::text` cast（照 `StoreProfileRepository`/settings 惯例）
- Reactor：`switchIfEmpty` 参数在 assembly 期求值，副作用调用包 `Mono.defer`；lineage insert 必须在生成成功的同一链上（`flatMap` 串联），别用 `subscribe()` 旁路（D4 会失效且丢错误）
- Flyway：新迁移一律 `IF NOT EXISTS`（OutboxRepositoryIT 迁移重放要求幂等）
- `uuid[]` 绑定照既有写法（`bind("ids", array)` + `ANY(CAST(:ids AS uuid[]))` 或直接 uuid[]，参考 `StoreProfileRepository.findPublicProfiles`）
- edge fail-closed：新前缀不进 RouteManifest 就是 404
- 请求 record 可选数值字段包装类型；响应白名单手写 map
- 前端 fetch 生成图 URL 是**同源**路径（`/api/article-generation/generated-images/…`）才能免 CORS 拿 blob——勿改成拼接外部域名
- 提交按语义拆分（建议：migration+repository / 三接入点写入+MultimodalResult 扩展 / 读端点+edge / 前端历史与保存 / docs 各一个 commit），commit message 中文、`feat(scope):` / `test(scope):` / `docs:` 风格
