## 一、项目概览

草场是「全功能营销工具库」产品，正在向「商家 × 推荐官任务撮合 + AI 内容创作」平台演进。当前仓库保留两套后端实现：

- **Java 平台**（默认 Compose 承载）：`platform-java/`，含统一入口 `edge-bff` 和 identity、marketplace、finance、trust、intelligence 五个已承载业务的领域服务
- **Legacy 后端**（回滚路径）：Express 5 + TypeScript，仍承载未迁移端点并接收显式关闭 Java route flag 后的回切流量

默认 Compose 栈由前端经 `edge-bff` 进入 Java 或 Legacy 路由所有者；具体回切通过对应 `EDGE_ROUTE_*` 开关显式设为 `false` 完成。

### 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3.5 + Vite + TypeScript |
| 后端（现有） | Express 5 + TypeScript + Pino + Zod |
| 后端（目标） | Java 25 + Spring Boot 4 + Spring Cloud Gateway |
| 数据库 | PostgreSQL |
| 页面抓取 | Playwright（Chromium） |
| HTML 解析 | Cheerio |
| 音频处理 | ffmpeg |
| 测试 | Vitest + Supertest（TS）/ JUnit 5（Java） |

## 二、环境准备

### 必需

- **Node.js 20+**（推荐 20.20.x）与 npm
- **PostgreSQL**（本地或远程，启用账号/积分/热点缓存时必需）

### 可选（按功能）

- **ffmpeg**：抖音音频提取
- **Playwright 浏览器**：抖音扫码登录增强 fallback，`npx playwright install chromium`
- **Java 平台本地构建**：JDK 25，`brew install openjdk@25`
- **Docker**：容器化部署与 Java BFF 验证

### 验证环境

```bash
node -v        # >= 20
ffmpeg -version
java -version  # 仅 Java 平台需要，>= 25
docker version # 仅 Docker 部署需要
```

## 三、快速开始：本地开发

### 1. 安装依赖

```bash
npm install
npx playwright install chromium   # 可选：抖音扫码登录增强
```

### 2. 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，至少配置：
#   DATABASE_URL=postgresql://用户:密码@主机:5432/库名
#   SESSION_SECRET=<至少 32 字符>
#   DOUYIN_PROXY_TOKEN_SECRET=<至少 32 字符>
#   BILIBILI_PROXY_TOKEN_SECRET=<至少 32 字符>
```

### 3. 初始化数据库

```bash
npm run db:migrate
```

迁移文件位于 `server/sql/`，按文件名顺序逐个事务执行。

### 4. 启动开发服务

```bash
npm run dev
```

- 前端 Vite：http://localhost:5173
- 后端 Express：http://localhost:3000
- Vite 开发代理把 `/api` 转发到 `localhost:3000`

> 不配置数据库时应用仍可启动，但无账号系统、积分和热点缓存。

### 其他开发命令

| 命令 | 说明 |
|---|---|
| `npm run dev:client` | 仅前端 |
| `npm run dev:server` | 仅后端（tsx watch 热重载） |

## 四、生产构建与启动

```bash
npm run build      # 前后端一起构建（vue-tsc + vite + tsc）
npm run start      # 生产模式启动后端（托管前端 dist/）
```

生产模式下后端同时托管前端静态文件，默认监听 3000。

## 五、管理员与账号

### 创建管理员

```bash
npm run admin:create
```

按提示填写邮箱、密码，创建 `admin` 角色账号。

### 注册流程（普通用户）

1. `GET /api/auth/captcha` 获取图形验证码
2. `POST /api/auth/send-code`（需正确图形验证码）发送邮箱验证码
3. `POST /api/auth/register`（需邮箱验证码）完成注册

新注册用户默认获得积分（`FREE_CREDITS_ON_REGISTER`，默认 3）。

### 登录与登出

- `POST /api/auth/login` 邮箱 + 密码登录
- `GET /api/auth/me` 获取当前用户
- `POST /api/auth/logout` 登出
- 登录失败有 per-IP 与 per-account-IP 限流

## 六、配置说明

### 环境变量

完整列表见 `server/src/lib/env.ts`。常用变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3000` | 后端端口 |
| `CORS_ORIGIN` | `http://localhost:5173,...` | 允许的前端来源 |
| `DATABASE_URL` | 空 | PostgreSQL 连接串 |
| `SESSION_SECRET` | 空 | Session 签名密钥（≥32 字符）|
| `SESSION_COOKIE_NAME` | `y1.sid` | Cookie 名 |
| `DOUYIN_PROXY_TOKEN_SECRET` | 必填 | 抖音代理 token 签名（≥32 字符）|
| `BILIBILI_PROXY_TOKEN_SECRET` | 必填 | B站代理 token 签名（≥32 字符）|
| `FFMPEG_PATH` | `ffmpeg` | ffmpeg 路径 |
| `PUBLIC_BACKEND_ORIGIN` | 空 | 后端公网地址（第三方回源用）|
| `FREE_CREDITS_ON_REGISTER` | `3` | 新用户赠送积分 |
| `LOG_LEVEL` | `info` | 日志级别 |

### AI 功能配置

AI 分析提供者与凭据由**服务端持久化设置**决定，浏览器不能直接调用第三方服务。配置优先级：服务端用户设置 > 环境变量默认值。

支持两类提供者：

- **Coze 工作流**：`COZE_ANALYSIS_BASE_URL` / `COZE_ANALYSIS_API_TOKEN`
- **Qwen（OpenAI 兼容）**：`QWEN_ANALYSIS_BASE_URL` / `QWEN_ANALYSIS_API_KEY` / `QWEN_ANALYSIS_MODEL`
- **图片生成**：`IMAGE_GENERATION_BASE_URL` / `IMAGE_GENERATION_API_KEY` / `IMAGE_GENERATION_MODEL`
- **视频制作脚本**：`VIDEO_PRODUCTION_SCRIPT_BASE_URL` / `VIDEO_PRODUCTION_SCRIPT_API_KEY` / `VIDEO_PRODUCTION_SCRIPT_MODEL`

> 文章生成仅支持 Qwen。

在「设置弹窗」中：

- 密钥留空保存 = 保留已保存的密钥
- 输入空格后保存 = 清空密钥
- 可用「模型验证」测试配置是否可用

### 首页热点配置

- **60s API**（默认）：抖音/微博/知乎，缓存 2 小时
- **ALAPI**：需 Token，抖音/微博/微信/小红书，缓存 5 分钟

## 七、功能模块使用

### 1. 视频提取分析（抖音 / Bilibili）

- 粘贴分享文本或链接 → 后端解析视频地址
- 预览 / 下载走后端签名代理，不暴露上游地址
- 抖音支持音频提取（ffmpeg）
- AI 视频分析（需登录、消耗积分）；视频时长 >10 分钟不支持分析

抖音登录增强（Playwright 扫码）仅作为 fallback，非默认路径。

### 2. 图片评价文案

上传图片（≤6 张）→ 选择平台（淘宝/大众点评）→ AI 生成评价（SSE 流式）→ 一键复制 / 导出飞书。

多步骤生成：草稿 → 文案优化 → 风格精修；支持评价风格记忆。

### 3. 爆款文章创作

主题 → 选平台（微信公众号/知乎/小红书）→ AI 生成标题 → 流式大纲 → 流式正文 → 按段落配图（推荐/搜索/AI 生成）。

### 4. 脱口秀创作

输入主题 → 仿风格流式生成脚本（需登录、消耗积分）。

### 5. 图片生成

文字描述 + 可选参考图 → AI 生成图片（支持 @mention）。

### 6. 视频内容改编

视频分析结果 → 分镜脚本（角色/场景/道具）→ 生成资产图/场景图（单张/批量）。

### 7. 视频制作

上传素材图片（≤9 张，base64，JSON body ≤10MB）+ 店铺信息 → AI 脚本生成（SSE 流式）→ 视频生成（Seedance，待对接）。

> 视频生成 API 当前为 stub，待后续对接。

### 8. 积分系统

- 新用户注册赠送积分
- 视频分析、图片评价、文章生成、脱口秀、图片生成、视频改编、视频制作脚本均消耗积分
- 积分扣减使用原子操作，防并发超扣
- 管理员可调整任意用户积分

### 9. 管理后台

仅 `admin` 角色可见（双重中间件认证）。功能：查看用户列表、调整积分。

### 10. 设置与主题

- 分析设置 + 首页设置弹窗（需登录）
- 主题：亮色 / 暗色 / 跟随系统（Header 切换按钮循环切换）

## 八、Docker Compose 部署

### 1. 准备配置

```bash
cp .env.docker.example .env.docker
# 编辑 .env.docker
```

### 2. 启动

```bash
docker compose --env-file .env.docker build
docker compose --env-file .env.docker up -d
```

- 前端容器（Nginx）：宿主机 `${FRONTEND_PORT:-8080}` → 80
- Nginx 把 `/api` 和 `/health` 统一代理到 `edge-bff:8080`
- Edge 按 RouteManifest 分流到 identity/marketplace/finance/trust/intelligence，未迁移路由回落 `backend:3000`
- Express `${BACKEND_PORT:-3000}` 与 Edge `${EDGE_BFF_PORT:-8081}` 只绑定 `127.0.0.1`，不能从公网绕过 Nginx
- 后端数据持久化在 `backend_data` volume

> Docker 部署**不包含** Playwright 浏览器登录增强。

### 3. 验证

```bash
docker compose --env-file .env.docker config --quiet
curl http://<host>:<FRONTEND_PORT>/health
curl -i http://<host>:<FRONTEND_PORT>/api/auth/captcha
```

### 4. Edge BFF 切流与回退

`edge-bff`（Spring Cloud Gateway WebFlux）是默认 API 入口。对象存储 presigned PUT `:9002` 是有意保留的直传例外。

```bash
# 本地构建 Java（需 JDK 25）
cd platform-java && ./gradlew clean build && cd ..

# 默认栈已包含 Edge 与五个 Java 领域服务
docker compose --env-file .env.docker up -d --build

# 验证 BFF 透明代理
curl -i http://localhost:8081/health
curl -i http://localhost:8081/api/auth/captcha
```

- BFF 本机诊断映射 `127.0.0.1:${EDGE_BFF_PORT:-8081}` → 容器 8080
- 逐路由回退：设置对应 `EDGE_ROUTE_*` 为 `false` 后 recreate `edge-bff`
- 当前已迁移 Java 路由默认开启，包括 Bilibili/Douyin 媒体、抖音热点和视频内容改编；视频改编使用平台级 Qwen，不读取用户级 BYOK 配置
- 整入口应急回退：设置 `API_UPSTREAM=backend:3000` 后以 `--no-deps` 只 recreate `frontend`
- TLS 在上游 LB/ingress 终止时设置 `PUBLIC_FORWARDED_PROTO=https` 和实际的 `TRUSTED_PROXY_CIDR`；禁止直接信任客户端转发头
- 不做自动 failover；整入口回退会让 Java 独占路径降级为 legacy 404
- 可观测性组件按需以 `--profile observability` 启动

详见 [旧 API 兼容契约矩阵](./草场旧API兼容契约矩阵.md) 与 [Java 微服务架构](./草场Java微服务技术架构与渐进迁移方案.md)。

## 九、Java 平台（草场目标架构）

### 目录结构

```
platform-java/
├── settings.gradle.kts          # Gradle 多模块根
├── gradle/libs.versions.toml    # 版本目录
├── services/
│   ├── edge-bff/                # 透明代理（已实现）
│   ├── identity-service/        # 账号、身份、组织、KYB、通知
│   ├── marketplace-service/     # 任务、履约、运营、套餐与消费订单
│   ├── finance-service/         # 托管、钱包、积分、消费者支付与双录账本
│   ├── trust-service/           # 争议、审判与客服终审
│   └── intelligence-service/    # AI 控制面、创作、媒体与热点
└── contracts/legacy-wire-fixtures/
```

### 构建与测试

```bash
cd platform-java
export JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home
./gradlew clean build          # 全部 6 模块
./gradlew :services:edge-bff:test   # 仅 BFF 契约测试
```

### 运行时约定

- 五个领域服务已承载身份、撮合、资金、争议和智能域的已迁移路由
- `edge-bff` 是默认且唯一的公网 API 服务入口
- 新草场领域数据直接进入 Java 服务，不写回旧库
- 详细迁移路线与状态见 [Java 微服务架构](./草场Java微服务技术架构与渐进迁移方案.md)

## 十一、常见问题与排错

### 启动相关

| 问题 | 解决 |
|---|---|
| 后端 503「认证不可用」 | 检查 `DATABASE_URL` 和 `SESSION_SECRET` 是否配置 |
| 注册收不到验证码 | 检查 `SMTP_*` 配置；本地可用邮件捕获服务 |
| 视频无法播放/下载 | 确认 `DOUYIN_PROXY_TOKEN_SECRET` / `BILIBILI_PROXY_TOKEN_SECRET` 与签发时一致 |
| 抖音音频提取失败 | 确认 `FFMPEG_PATH` 指向可用 ffmpeg |
| 视频分析超时 | 视频 >10 分钟不支持；可调 `VIDEO_ANALYSIS_API_TIMEOUT_MS`（默认 180s） |

### 配置相关

| 问题 | 解决 |
|---|---|
| AI 功能报「未配置」 | 在设置弹窗配置对应提供者；或设置环境变量默认值 |
| 文章生成报 provider 不支持 | 文章仅支持 Qwen，Coze 不支持自由文本 |
| 热点不更新 | 60s 缓存 2 小时；ALAPI 需配置 Token |
| 密钥保存后丢失 | 密钥留空 = 保留旧值；输入空格 = 清空 |

### Docker 相关

| 问题 | 解决 |
|---|---|
| `docker pull` 报 EOF | Docker Hub 网络波动，稍后重试或配置镜像加速 |
| 后端镜像构建失败 `tsc` | 先本地 `npm run build:server` 排查 TS 错误 |
| BFF 容器健康但 502 | 确认 `LEGACY_EXPRESS_BASE_URL` 指向可达的 backend（容器内 `http://backend:3000`）|

### Java 平台相关

| 问题 | 解决 |
|---|---|
| `./gradlew` 找不到 Java | `export JAVA_HOME=/opt/homebrew/opt/openjdk@25/...` |
| edge-bff 启动报 base-url 非法 | 确认 `LEGACY_EXPRESS_BASE_URL` 是合法 `http(s)://host` 且无 query/fragment |
| BFF 代理 SSE 卡住 | 确认未启用响应压缩；`X-Accel-Buffering: no` 已透传 |

## 十二、安全注意事项

- 浏览器**不能**直接调用第三方 AI/分析服务，凭据由服务端管理
- 视频/媒体预览下载走后端签名代理，不暴露上游真实地址
- `provider-url.ts` 维护 `TRUSTED_PUBLIC_API_SUFFIXES` 白名单，SSRF 私有 IP 检查
- 管理员路由需 `requireAuthenticatedUser` + `requireAdmin` 双重中间件
- 密码使用 scrypt/bcrypt 哈希存储，Session Cookie 签名
- 所有端点带基础限流，登录失败有独立限流

> ⚠️ `.env`、`.env.docker` 含密钥，勿提交到 Git。仓库中仅保留 `.env.example` / `.env.docker.example`。
