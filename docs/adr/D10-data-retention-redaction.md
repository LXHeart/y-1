# ADR-D10：数据保留、删除、导出、审计、证据脱敏和地域要求

## 决策记录（已采纳，2026-08-02）

采纳推荐方案 C（分级保留 + 主体权利）+ 全部默认值。**保留期阈值与高风险行业规则为 provisional，待法务/财务校准后定稿**：

1. **分级保留期（provisional）**：财务账本/交易/结算/退款 **≥10 年**（会计法+反洗钱取严）；不可变审计（`ops_case_audit`/`dispute`/finance Journal）对齐财务或永久；履约证据（截图/链接/AI 建议）任务结清+争议窗口后 **6–12 个月**；PII/KYB 材料账号存续期+注销后 **6 个月**；日志/Trace（含 request_id/IP）**30–90 天**；媒体按 purpose（履约附件按证据期，`media_reference` 已有 TTL）。
2. **账号注销：必须全部结清**——无 pending 履约/报名、余额提现/退还、无未结争议/应收方可注销；软删（标记 `deleted`、登录拒绝、PII 进保留期倒计时）→ 硬删（PII 保留期满）；合规记录（财务/争议/审计）保留但渲染脱敏「已注销用户」；注销请求记不可变审计。
3. **数据导出：仅个人资料 + 收支记录**（PIPL §45 可携带权，最小必要）——不含已脱敏证据/日志；异步生成（量大）+ 短期 presigned URL（复用 media 签名读）；导出本身记审计。
4. **证据脱敏**：争议详情、审判快照与后台争议列表已统一走 `CaseEvidenceRedactor`；日志/事件/错误**不记**密码/Cookie/完整 Key/支付敏感数据/未脱敏证据（硬规则，HLD §11.2）。
5. **高风险行业（医美/金融等）**：**provisional 先无特殊规则**，待法务按行业清单补更严保留/脱敏要求。
6. **境外 AI 出境评估：暂不立项**——当前境内闭环（部署/PG/Kafka/S3/Temporal 全境内），跨境条款 N/A；等 D-11 落地（BYOK/平台模型实际来源明确）后按需评估，本 ADR 不预批。

**解锁**：各服务 LLD 可按分级保留期设计 TTL/清理任务/归档；账号注销、数据导出作为 `GL-P3-IDENTITY-001`/`GL-P3-MERCHANT-001` 的合规模块；finance Journal/settlement/Payment 需支持 ≥10 年保留（不可变+归档冷存）。

**仍属实现层 / 待校准**：保留期具体数值待法务/财务定稿；高风险行业清单待法务；归档冷存选型（运维/`GL-P3-PLATFORM-001`）；账号注销、主体数据导出及全平台到期清理仍待实现。

## 背景

HLD §11.2 基础安全要求末尾 `TBD`：「数据保留、删除、导出、合规归档、地域和高风险行业规则」。PIPL（《个人信息保护法》）要求：处理目的达成后及时删除/匿名化（§47）、数据可携带权（§45）、敏感信息单独同意、存储期限最小必要。会计法/反洗钱法对财务与交易记录有**法定最低保留期**。trust 审判需脱敏案件（HLD §10.5）。本决策定**各数据类的保留期、账号注销、数据导出、证据脱敏、地域**口径，供各服务 LLD 统一落地。

## 当前代码现状

- **争议展示脱敏已实现（2026-08-12）**：证据提交时生成不可变 `redacted_ref`；文本、链接、截图句柄及争议理由统一脱敏；手机号、证件号、银行卡、邮箱、账号 UUID、姓名和地址有规则覆盖；当事人账号只以案件内稳定、跨案件不可关联的 HMAC 伪名展示。争议详情、审判快照和后台列表不返回真实开户账号；受控内部事件仍保留收件人账号用于通知路由，证据原文不进入事件流。
- **既有保留能力**：`media_reference`（Slice 8）有 TTL + 双 key 删除审计 + GC；争议证据有 provisional `retention_until`；`ops_case_audit`、`dispute_case`、finance Journal 为长期审计事实。
- **缺口**：无统一到期清理/匿名化任务；无账号注销流程（软删/硬删）；无主体数据导出接口；PII/KYB、日志/Trace 的生产保留策略与归档仍待部署和法务校准。
- **地域**：HLD §13 部署为境内 K8s + 境内托管 PG/Kafka/S3，数据不出境，**PIPL 跨境传输条款目前 N/A**。

## 方案与取舍

### 方案 A：统一最长保留期，全部数据保留 N 年后清理

所有数据一个保留期（如 5 年），到期统一清理。

- ✅ 简单。
- ❌ 违反「最小必要」——日志和媒体不需要 5 年，过度保留增加合规风险与存储成本；财务记录法定可能要求更长。一刀切不合理。**否决**。

### 方案 B：按数据类分级保留，对齐法定最低 + 业务最小必要（推荐）

按数据类分别定保留期，取法定最低与业务需要的**较长者**；到期自动清理或匿名化；合规审计类（财务账本、争议、运营审计）长期保留。

### 方案 C：B + 账号注销/导出/脱敏全套合规能力

在 B 的分级保留之上，补齐 PIPL 要求的「注销、导出、更正、脱敏」主体权利能力。

- ✅ 合规闭环。
- ❌ 能力多，但都是 PIPL 强制要求，不可省。**作为 B 的必要补全**。

## 推荐

**采纳方案 C（= B 的分级保留 + 主体权利能力）**。细则：

### 1. 分级保留期（⚙️ 供法务/财务校准）

| 数据类 | 推荐保留期 | 依据 |
|--------|-----------|------|
| 财务账本 / 交易 / 结算 / 退款记录 | ⚙️ **≥10 年** | 会计法（凭证/账簿）+ 反洗钱（5 年），取严 |
| 不可变审计（ops_case_audit、dispute、finance Journal） | 与财务保留期对齐（≥10 年）或永久 | 合规审计对象 |
| 履约证据（截图、链接、AI 建议） | 任务结清 + 争议窗口后 ⚙️ **6–12 个月** | 争议复核 + 审计，过期脱敏/删 |
| PII / KYB 材料（身份、门店真实性） | 账号存续期 + 注销后 ⚙️ **6 个月** | PIPL §47 删除义务；财务记录中必要的 PII 按财务保留期，但脱敏 |
| 日志 / Trace（含 request_id、IP） | ⚙️ **30–90 天** | 运营/安全审计最小必要 |
| 媒体素材（media_reference） | 已有 TTL 机制，按 purpose 分；履约附件按证据保留期 | Slice 8 既有 |

### 2. 账号注销（PIPL §44/§47）

- **注销前置**：账号注销前必须**结清**——无 pending 履约/报名、余额提现或退还、无未结争议/应收。
- **软删**：标记 `deleted`，登录拒绝，停止处理；PII 进入保留期倒计时。
- **硬删**：PII 保留期满后硬删个人资料/KYB 材料。
- **不删合规记录**：财务账本、争议、审计中的账号引用**保留**（法定），但渲染时脱敏为「已注销用户」。
- 注销请求记不可变审计。

### 3. 数据导出（PIPL §45 数据可携带权）

- 提供账号数据导出（个人资料、任务/履约历史、收支记录、已同意的日志摘要）为 JSON/CSV。
- **异步生成**（量大），生成完通知下载，导出件带短期 presigned URL（复用 media 三步上传/签名读）。
- 导出本身记审计（防滥用/取证）。

### 4. 证据脱敏（trust 争议展示路径已实现）

- 审判案件经 `CaseEvidenceRedactor` 脱敏后给审判官/客服/后台（HLD §10.5），**展示响应不含真实账号、PAN、手机号或原始媒体 ID**。
- 履约证据保存原始受控引用与提交时生成的不可变脱敏快照；展示只读脱敏快照，并保留来源角色、有效期和访问授权。
- 日志/Trace/事件/错误中**不记录**密码、Cookie、完整 Key、支付敏感数据、未脱敏证据（HLD §11.2 已约束，本 ADR 重申为硬规则）。

### 5. 地域

- **境内闭环**：部署、PG、Kafka、S3、Temporal 全境内（HLD §13），数据不出境，PIPL 跨境传输条款当前 N/A。
- **境外 AI 模型风险**：若未来 AI 能力（`AiCapabilityAdapter`）经境外模型，输入数据出境需重新评估 PIPL 跨境——**与 D-11 联动**：BYOK/平台模型若走境外，须单独跨境合规评估，本 ADR 不预批。

## 待你拍板

1. **各保留期阈值**（上表 ⚙️）需法务/财务按法定与业务最终校准——尤其是财务 ≥10 年与证据 6–12 个月。
2. **账号注销的结清门槛**：是否允许「有 pending 履约但委托完成」的注销，还是必须等全部履约结清？推荐后者（必须结清）。
3. **数据导出范围**：是否包含已脱敏的证据/日志，还是仅个人资料与收支？推荐后者（最小必要）。
4. **高风险行业**（PRD §商家准入的行业限制）：特定行业（如医美、金融）是否有更严的保留/脱敏要求？需法务按行业清单补。
5. **境外 AI 出境评估**是否现在立项（推荐不立项，等 D-11 落地后按实际模型来源评估）。

## 影响

- **解锁**：各服务 LLD 可按分级保留期设计 TTL/清理任务/归档；账号注销、数据导出可作为 `GL-P3-IDENTITY-001`/`GL-P3-MERCHANT-001` 的合规模块。
- **约束**：finance Journal、settlement、Payment 必须支持 ≥10 年保留（不可变 + 归档冷存）；media TTL 机制已满足部分，需补履约附件的「证据保留期」purpose；新增账号软删/硬删状态机 + 清理 Temporal 任务 + 数据导出异步 job。
- **波及**：trust 争议详情、审判与后台展示已统一脱敏；主体数据导出不包含争议证据。日志采集仍需按 30–90 天配置索引生命周期；`ops_case_audit`/dispute 审计长期保留仍需冷存归档策略（运维侧）。
- **跨服务**：保留期是各服务私有数据库的策略，不跨服务（HLD §6.1 database-per-service），但口径统一在本 ADR。

## 不在范围

- 跨境数据传输合规（当前 N/A，境外 AI 落地时单独评估）。
- 高风险行业准入细则（D-05）。
- 归档冷存的具体存储选型（运维/`GL-P3-PLATFORM-001`）。
- 数据加密（已在 GL-P0-SEC / Envelope Encryption for BYOK 覆盖）。
