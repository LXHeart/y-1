## 本次整理与内容归属

主PRD与使用说明的读者和用途不同，分别保留；新专题需求在批准实施后合并必要规则，不提前改变现有操作说明。重复内容按以下方式收拢：

- **账号与应用边界**：统一在 PRD 第一章定义，第十一章保留职责导航、消费者与治理规则，不再重复整段身份和 AI 说明。
- **任务与资金规则**：任务选择和合同要求放 PRD 第二、三章，资金流与退款边界集中在第八章，其他章节引用。
- **AI 需求与开放状态**：能力要求放 PRD 第四章，当前操作写在使用说明；历史迁移能力表改为能力与开放边界说明，具体进度回到任务书。
- **开发、部署、测试与排障**：原使用说明中的重复技术内容收拢到根 README、架构、运维和测试文档的现有入口；移除已失效的 Node 后端测试名、模型环境变量和旧设置操作。
- **待确认事项**：PRD 第十二章只保留仍需决策或外部验收的事项，已确认规则回归对应正文。

2026-09-15 的口径校准包含：注册与存量身份、成员直建、组织 AI 管理入口、付费互动停供、履约审稿与退出、48 小时核销冷静期、结算后退款禁令、7 天末次触达归因，以及图文工作台的默认关闭状态。依据链接保留在 PRD 对应章节。

## 维护约定

- PRD 写规则，使用说明写操作，任务书写交付与证据；调整业务规则时同步相应操作说明，避免三处出现互相矛盾的口径。
- 需求已确认、代码已实现、通过本地验证、生产已开放是不同状态，必须分别说明；真实资金仍受 D-01 与生产门禁约束。
- 供应商、价格、额度、超时和功能开关的实际值由配置与合同快照决定，不把试点默认值写成所有环境的承诺。
- PRD 保留既有章号与文件名，便于任务书继续引用；旧需求来源留在[归档](../归档/全功能营销工具库需求文档（合并前来源）.md)，不回抄为当前规则。

文档改动后执行 `npm run docs:links` 和 `npm run docs:status`；这两项检查不代表业务或生产验收。
