## 1. 产品定位与目标

在现有 AI 创作端新增“数字人工作台”：用户配置一个可使用的数字人角色，通过文字或麦克风与其实时交流，预览口播效果，按意愿保存文本或数字人输出视频，继续用于内容制作。

本产品首先服务**创作过程**，包括口播预演、提问整理、角色化创作辅助与素材生成。消费者公开客服、无人直播、真人克隆和组织知识问答属于后续扩展，不混入首期验收。上游功能存在不等于草场应全部直接开放。

### 1.1 用户价值

| 用户 | 当前问题 | 工作台提供的结果 |
|---|---|---|
| 个人创作者 | 只能看文本，难判断口播节奏与表达效果 | 通过可打断的数字人对话快速验证表达，保存可继续编辑的结果 |
| 推荐官 | 需要围绕创作主题反复问答、整理讲解稿 | 使用个人权限内的内容对话；一期不自动读取任务/商家资料 |
| 商家内容负责人 | 后续希望品牌讲解员使用正确资料和统一人设 | 后续组织阶段承接，依赖组织授权和资料版本；个人工作区不隐式获得组织数据 |
| 平台运营 | 需要限制资源成本、排查失败、撤下无权资产 | 受控配置、模型兼容信息、会话状态、配额与脱敏诊断 |

### 1.2 成功定义

首期合格的闭环是：授权进入 → 选择可用形象/音色 → 配置人设 → 查看限制与费用口径 → 建立会话 → 文字/语音输入 → 字幕和音视频回复 → 打断/继续 → 结束释放 → 按选择保存 → 在素材库找到结果。

仅能展示上游演示页、仅 Mock 可动、只有文本没有真实音视频、关闭页面后仍占用第三方会话/计费资源、用量无法对应账号，均不算可发布。

### 2.2 OpenTalking 的使用边界

研究基线固定为提交 `8c739a5a6f114daf71aeace832a668c3ad60f536`（提交日期 2026-09-04；2026-09-21 复核）。官方资料说明其负责实时对话编排及可插拔媒体后端，认证与 TURN 由集成方承担；本计划采用它的 Python 服务能力，保留草场 Vue 前端与 Java 业务权威。[来源 S01/S02]

上游会话 schema 存在 `user_id`，但这不是草场权限凭证；其内部 session_id、运行时配置、素材目录和下载接口均不得直接变成公网业务接口。上游的录制能力具有模型相关实现，草场将以适配器能力声明控制展示，不承诺所有渲染后端都支持相同功能。[来源 S03/S04]

既有上游研究区分框架与模型权重许可（来源S05/S06/S07）。v2.1不部署这些本地模型；验收转为第三方服务使用条款、输入/产物使用范围、数据保留/删除能力及人像/音色授权证据。开发链路只使用自有合成测试资产；缺少相应证据的服务/形象/音色不可对用户开放。


### 2.3 第二轮源码核实带来的修正

详细证据与固定提交锚点见[OpenTalking 接入核验](../reviews/OpenTalking源码核验与数字人接入差距-2026-09-21.md)。这里区分上游事实与草场目标，不用接口名称推断实现。

| 上游实际情况 | 草场产品决策 |
|---|---|
| 支持mock/local/direct_ws/omnirt，轻量模型可在进程内；部分接口注释仍称“全部外部推理” | 上游支持local不构成草场部署许可；草场只运行Fake与经现有控制面批准的第三方服务适配，禁止加载本地模型 |
| 默认CreateSessionRequest中agent_enabled、knowledge_enabled为true | 适配层显式false；不传persona_id/memory/knowledge引用，不挂原生管理路由 |
| 原生WS收PCM s16le、mono、16kHz；OpenAI-compatible STT会聚合并落临时WAV | 草场使用自己的WS鉴权/限流与内存WAV桥，禁调用落盘转写路径；先提供按键式短句对话 |
| 原生LLM仅吐文本delta，既有草场ChatChunk也不含usage | 新增有用量终帧的计量流，缺usage标待核对；不能用字符串长度或零token结算 |
| 上游speak已有command receipt/hash，但reservation→queue有崩溃窗口；owner_epoch不等于全链fencing | 草场持久幂等、派发状态、租约与turn代次为权威；未知请求不重发供应商 |
| 原生SSE是pub/sub转发，没有可靠历史id重放；活动session会persist，终态才TTL | 草场提供序号、快照和独立reaper，不把上游TTL当孤儿释放保证 |
| flashtalk_capture.mp4导出只写视频帧、mp4v，无音轨；另有offline bundle是不同流程 | 产品录制新增输出音视频分支；未验音轨/时间轴不能报录制完成 |
| 原生timing带text_preview；默认依赖含记忆与重模型包；mock默认仍可能请求真实语音/LLM | 测试必须全链Fake且出站白名单；移除内容日志、只加载批准模块，不把mock模型当零费用保证 |

### 2.4 首期模型来源与工作模式

**所有模型均来自第三方，不使用任何本地或自托管模型部署。** 统一通过现有模型配置使用与扩展，实施细则以共享契约K14为准。

1. 工作模式固定`conversation`，文字默认送LLM后播报；直接朗读脚本、上传音频驱动视频属于后续独立需求，不能把原生speak名称误解为朗读模式。
2. LLM使用现有`text`能力及个人platform/own总开关；STT固定平台`voice`，TTS固定平台`video_tts`，渲染使用现有控制面待扩展的平台`digital_human_render`能力。界面分项显示文本、转写、配音、渲染来源与费用，个人own不表示整场BYOK；不新增语音/渲染个人密钥白名单。
3. LLM首个可验真实协议限定现有`openai-completions`/`openai-compatible`；其他方言先显示不支持此实时组合，不修改其他创作工具能力。兼容协议不代表指定某一家付费厂商。
4. 数字人渲染及涉及模型的形象预处理全部调用第三方服务；不部署本地模型，不下载权重，不建设GPU推理服务。通过现有模型控制面新增`digital_human_render`平台能力及对应协议适配，复用模型/凭据/受信端点/主备/价格/审计；该能力为待实现扩展，不假称已经存在。无可用第三方配置时拒绝真实启动，不能回退本地模型。数字人目录只保存配置引用、兼容能力与验收证据，不另设供应商配置或env模型参数。
5. UI展示catalog批准档位及实测状态；默认无真实后端批准时“真实数字人尚未就绪”。不能通过拉伸低分辨率视频达成720p验收。

## 4. 角色、归属与权限

| 主体 | 查看预设 | 管理人设/自有形象 | 发起/控制会话 | 读记录/导出 | 管理系统配置 |
|---|---|---|---|---|---|
| 游客 | 可看静态介绍，不能占用真实服务 | 否 | 否，提示登录 | 否 | 否 |
| 已登录个人账号 | 仅已开放项 | 仅本人 | 仅本人且额度/并发允许 | 仅本人及已有素材授权允许的结果 | 否 |
| 其他账号/同组织同事 | 不因组织关系多获权限 | 不可访问他人个人资源 | 不可控制他人会话 | 不可读取 | 否 |

S1/S2 `scope=personal`、`organizationId=null`，由服务端依据 AI 个人入口确定，不能把浏览器当前商家身份直接当组织授权。组织凭据与组织预算不得被个人会话隐式使用。S3 的组织归属须来自既有权威上下文，不允许客户端任意传 orgId 切租户。

公开 ID 只用于定位，服务端每次控制、字幕订阅、媒体协商、录制下载均校验权限。越权对象统一 404 隐藏存在性；未登录 401；前端隐藏按钮不代替鉴权。

## 6. 页面和用户流程

### 6.1 信息架构

入口沿现有创作中心导航增加“数字人”工作区链接，路由确定为 `/digital-human`；对象恢复 `/digital-human?profileId=...&sessionId=...`。URL 仅存非敏感 ID 与视图状态，不含 token、提示词、字幕、人像地址或密钥。导航链接应保留导航语义，不假扮页内 tab。

工作台由四区组成：顶部“角色/连接状态/时长/结束”；中央数字人舞台；侧边“配置”与“对话记录”；底部“文字输入/麦克风/打断/录制”。主要空间留给预览与对话，不增加营销大横幅或多层装饰卡片。

个人角色列表是入口空态的直接下一步；没有可用后端时显示“数字人服务暂不可用”，保留已保存配置，不显示空素材误导为用户未创建。

### 6.2 首次创建

1. 登录后进入，查看可用预设与能力说明；不会自动申请麦克风权限或发起计费请求。
2. 选形象和音色，编辑角色；人设预览只展示配置，试听必须显式点击且经过额度检查。
3. 选择输入方式。未授予麦克风权限仍可文字对话；一期不请求摄像头。
4. 显示本次限时、使用的模型来源、计量口径、取消费用规则以及对话/录制是否保存。
5. 点击“开始对话”，进入检查→排队→连接→就绪。只有服务端允许并已建立有效媒体连接才可显示就绪。
6. 成功后允许输入；失败保留用户配置和单次重试入口，不自动无限重建。

### 6.3 会话进行中

- S1 固定为点击开始收音、再次点击提交；60秒自动提交。首期不自动VAD提交，避免噪声触发付费。浏览器分块上传不等于供应商流式转写；一期使用有界内存收音后整段转写，显示“收音中/识别中”，不伪造中间识别文字。
- 正在回复时，显式“打断并说话”先撤销旧轮次，再开启新采集。连续免手动插话属于后续增强，不作为首期暗含承诺。
- 输入和输出字幕分栏/分角色；未完成转写标“识别中”，最终识别文本才进入本轮输入。失败文字可编辑后重发。
- 配置在会话中只读；“修改角色”提示结束当前会话后应用，不能在途切模型/换声音造成计量错配。
- 对话快结束/余额不足显示明确倒计时或原因；禁止虚构百分比。主动结束按钮始终可用，不因其他提交中而禁用。

### 6.4 结束、保存与复用

“结束对话”立即关闭本地麦克风/播放，服务端显示“正在结束”至终态。默认仅短暂保存恢复所需信息；若未选择保存，结束后最多10分钟保留可主动保存的易失缓冲，到期清除；显式删除立即清除。用户可单独保存最终文字；S2 可录制数字人输出并生成待保存产物。

录制只覆盖显式开始之后运行时输出总线已接受的数字人画面与声音，不自动补录先前内容；它记录服务端媒体时间轴，不保证与某一浏览器扬声器的实际播放时刻完全一致。打断按服务端接受取消的时间截断，丢弃尚未发出的旧代次缓冲，不拼回取消内容。录制停止后经后端封装与校验，生成 MP4；SRT 仅含实际录制范围内的数字人字幕。

用户明确“保存到素材库”后创建受控媒体/素材。后续视频编辑从既有素材选择器选用；一期不自动建分镜、不复制所有对话进入画布、不自动提交履约。

“会话记录”是工作台内部的分页历史入口，区分已保存文字、录制待保存、已保存素材与仅有技术状态的会话；不可将未保存内容显示成仍可恢复。支持按时间/角色/状态筛选，查看用量、复制或导出本人已保存文字，删除保存内容。删除角色不连带删除用户已独立保存的素材；角色版本仍被运行会话引用时禁止删除。素材删除仍走既有库规则，不以删除会话代替。


### 6.5 字段、交互与上下文细则

| 对象 | 固定字段/限制 | 成功与失败行为 |
|---|---|---|
| 人设 | name 1～40、persona 1～4000、greeting 0～200 Unicode码点；tone=natural/professional/friendly；avatarId/voiceId/catalogVersion必填 | trim后校验，空白拒绝；乐观版本冲突保留输入并提示重新加载，不自动覆盖 |
| 形象处理 | 一个正面单人JPEG/PNG，≤10MiB、≤4096×4096；透明背景允许但必须可解码；0脸/多脸不支持 | 上传→检查→处理→可用；失败保留人设但不能开始，不接受zip/任意URL/路径 |
| 开场白 | 默认空；非空时媒体就绪后明确显示“播放开场白”按钮 | 显式点击才触发一轮TTS，不调用LLM；每会话只允许成功播放一次，重试使用原commandId |
| 文本 | trim后1～2000码点；每轮最多1024输出token、总输出≤8000码点 | 中文输入法合成中Enter不提交；Enter发送、Shift+Enter换行；responding时普通发送禁用，显式打断后再发 |
| 上下文 | 冻结系统人设+最近10个完整问答；全部消息UTF-8≤64KiB | 先逐对删除最旧问答；仍超限拒绝新轮；中断助手答案不回填为完整回答，无自动摘要、长期记忆 |
| 字幕 | 显示用户最终转写；助手区分生成中、已播报和已中断 | 草稿delta不用于SRT；保存可含中断文本并标interrupted，不能冒充已播完整内容 |
| 录制 | 每会话同时1段，最多2段，每段≤5分钟；产物≤200MiB | 失败不新增第二段补偿；接近上限提前封装并标partial；实际超限则失败并清临时文件，不修改旧视频上传上限 |
| 试听 | 固定试听句“你好，我是你的数字人创作助手，很高兴和你一起创作。”；每账号3次/分钟 | 一次只播一个，重新点击停止本地；费用遵守已派发取消规则；不开放用户任意试听文本 |

保存同意：开始前saveTranscript默认false；会话中可显式打开，仅将当时仍在缓冲中的最终文本与后续最终文本保存；关闭后停止后续落库，已保存部分保留，删除需独立操作。结束后仅在10分钟恢复窗内允许主动保存，过期返回410；用户删除后置内容墓碑，迟到回调不得再次写回。编辑中的人设/输入/字幕只留组件内存，不进localStorage/sessionStorage/IndexedDB；换号清空。刷新可凭公开sessionId查询本人状态，但不能恢复已丢失未提交文本。

错误恢复：401调用现有登录入口；404显示不存在/无权；409分别提示版本冲突、已有会话或旧控制权；402引导既有积分/预算入口；429保留配置并显示Retry-After；503给手动重试；网络中断先查会话/操作结果，不能换幂等键自动重新生成。一次性的已消费WS票据不自动复用。

## 7. 状态与资源生命周期

### 7.1 会话状态

| 状态 | 含义 | 可用操作 / 退出条件 |
|---|---|---|
| preparing | 已建业务记录，校验/预留运行资格 | 可结束；检查失败→failed |
| queued | 等待渲染槽位 | 显示队列状态，不能显示伪排位；取消→ending |
| connecting | Worker 初始化与媒体协商 | 可结束；超时→failed |
| ready | 连接可用且当前无输出 | 可输入/开始采集/录制 |
| listening | 用户明确开启采集 | 停止/提交/结束；没有上传音频就不产生转写用量 |
| responding | 转写/模型/配音/渲染中 | 可打断/结束；子阶段单独展示，不创建重复会话 |
| paused | 页面隐藏，停止采集与生成，暂留槽位 | 显示并重新校验后回ready；超过窗口→ending |
| reconnecting | 网络失联或刷新恢复 | 有界重连；不得重放收费请求；超时→ending |
| ending | 停止新调用并等待可观测的资源释放 | 查询终态；重复结束同一结果 |
| ended | 正常结束/超时结束 | 可查看本人保存结果、重新开新会话 |
| failed | 无法继续，资源清理仍被跟踪 | 显示原因与可重试动作，失败不等于已完成所有清理 |

会话状态、轮次状态、录制状态和结算状态分别保存。`ended` 不代表费用已确认，`recording completed` 不代表素材已入库；界面明确显示“费用待核对”“保存失败”等子状态。

### 7.2 暂定试点默认值

以下为可配置的**产品试点上限**，不是已实测的性能或价格。服务端响应有效配置，前端不另写一套；S0 测量后在版本评审中调整。

| 项目 | 规划默认 | 行为 |
|---|---|---|
| 每账号同时活跃会话 | 1 | 第二页创建返回现有会话提示，不能偷偷踢走第一页面 |
| 单次会话 | 10 分钟 | 首次ready起按服务端墙钟计时，隐藏/断网不延长；到时停止新输入并结束；排队/初始化单独限时 |
| 就绪空闲 | 120 秒 | 无输入/输出则结束；最后30秒提示 |
| 页面隐藏/断网恢复窗口 | 30 秒 | 立即停止麦克风和新生成；超过窗口关闭；计量只记录真实动作 |
| 心跳周期 / 失联检测 | 10 秒 / 30 秒 | 前端不可作为唯一清理来源，Worker有独立租约 |
| 队列等待 / 连接初始化 | 60 秒 / 90 秒 | 分阶段超时，取消资格；不重复排队 |
| 文字 / 人设长度 | 每轮2,000 / 角色说明4,000 Unicode码点 | 服务端422与字段提示，不能偷偷截断改变意思 |

| 自有形象图片 | JPEG/PNG，≤10MiB，尺寸≤4096×4096 | 检查解码/内容/权利声明；只存媒体ID，不接受远端任意URL |
| 列表分页 | 默认20、最大100 | 服务端游标分页；不一次拉全部历史 |

### 7.3 失活、刷新和双标签页

- 内部路由离开或 KeepAlive deactivated：立即停止本地采集、发送幂等结束，服务端租约兜底；返回只恢复人设与已保存结果，不自动恢复付费会话。
- 仅切浏览器标签页/锁屏：立即暂停采集、打断输出并发送幂等pause；服务端记录不可被普通心跳延长的30秒恢复截止时间，窗口内回来可显式resume并重新协商，超过窗口需新会话。若通知未送达则由失联租约兜底；断网采用同样有界窗口。
- 刷新只尝试恢复同一本人会话，轮次不重发。控制权使用服务端 lease epoch，恢复成功后旧连接立即失效。
- 第二标签页显示“已有进行中的会话”；用户显式接管后轮换 lease epoch、关闭旧连接，旧页保留已保存结果但不能继续采集/控制。不能仅依赖 BroadcastChannel 防并发。
- 换号、退出、冻结或撤权：本地同步停止所有 MediaStream tracks、取消读取、失效回调；服务端撤销通道资格，迟到音频/字幕不可写到新账号。

## 8. 计量、额度与费用

### 8.1 复用原则

沿用 D11 与当前 `AiExecutionService`：个人 BYOK/平台来源由服务端控制面决定，不新增个人使用组织密钥的旁路；普通用户不手填上游 `.env` 或 provider URL。数字人调用仅携带内部短期执行资格，长期密钥不进入浏览器、OpenTalking Redis、日志或会话配置文件。

按子调用记录 STT秒数、LLM输入/输出token、TTS秒数/字符（按供应商能力）、渲染秒数、录制/存储统计。各单位保持原义，不换算成虚构统一token。会话负责聚合展示，不另重复扣一笔整场费用。

### 8.2 结算规则

- 每个付费子调用在执行前走现有预留；成功按原价表与实际用量结算。会话总上限是资格限制，不与子调用预留重复扣账。
- 未派发的排队取消释放占用及未消耗预留；已经派发后的用户打断/主动结束沿现有用户取消不退规则，不改成“打断免费”。已成功完成的前序调用保留结果与计费。
- 明确供应商失败按既有失败补偿流程执行；网络超时且上游状态未知时不直接归失败退款，也不编造实际用量，进入 reconciliation_pending。
- 个人BYOK对该供应商调用不收平台AI费，仍记ai_run用量，但按#78当前代码豁免个人模型预算；工作台会话时长/资源额度仍生效。个人模型来源总开关为own时，所需key缺失返回own_key_missing，不回退平台；platform时不读取个人key。第三方渲染仍产生平台承担的供应商成本，不能因为LLM是BYOK就宣称整场无成本。
- S1默认只运行隔离测试栈的合成provider；真实联调必须使用已授权测试账号/额度，现有AI调用按D11记账，通过预先发放测试积分覆盖平台承担的试验成本，不加绕过账本的“免费模式”。S2的新渲染收费保持关闭，采用有硬上限的试点补贴；既有STT/LLM用户收费与TTS/渲染平台补贴成本在开始前分列；第三方渲染须进入原ai_run/价表/预算/结算链路，补贴不等于零成本，缺用量则pending。

一期按现有配音实现采用TTS平台资助（video_tts、feature=null）；不另造视频收费键。每场平台成本授权上限300分，包含已知及待核对预留，未整场预扣；试听每天每账号最多30分平台补贴成本，按UTC日统计。用户收费仅平台文本和转写，个人own文本另由供应商直接计费；UI区分用户收费、平台补贴成本和未知自有账单。具体预估/积分转换及90秒TTS段上限见共享契约K08.1。

界面同时展示“预估/已确认/待核对”口径，实际价目表版本冻结到会话/子调用。历史费用不能随配置更新变动。余额不足不再派发新调用；当前在途按已有规则完成或终止，失败保留恢复线索。

## 9. 数据、隐私、内容与许可

### 9.1 留存分类

| 数据 | 默认行为 | 删除/权限 |
|---|---|---|
| 麦克风原始音频 | 不落持久存储；仅转写所需有界缓冲 | 停止/结束释放；诊断日志不得收集音频 |
| 未保存字幕/上下文 | 仅会话与短期恢复缓冲；结束后最长10分钟清除 | 无法回读已清除文本；不以AOF/磁盘日志暗中长期保留 |
| 主动保存的对话 | 用户明确同意后保存最终文本；不保存隐藏推理 | 个人可删除/导出；沿既有个人内容生命周期，不另私定法定保留期 |
| 录制临时产物 | 用户显式录制；最长24小时待保存 | 到期物删；保存到素材库后按既有素材规则；下载必须鉴权 |
| 角色/形象/音色引用 | 保存版本与授权证据，不保长期密钥 | 禁用阻止新会话；已撤授权应终止受影响运行与新导出 |
| 用量与审计 | 最少必要的阶段/经济键/成本事实 | 沿D10/D11，内容删除不抹账；去除个人可识别内容 |

留存策略可配置但不得绕过现有注销/法定保留规则；生产隐私说明与实际供应商数据处理条款须对应后才开放。临时buffer的存储介质、Redis持久化/副本、备份与删除证明由计划中的数据卡验证。

### 9.2 内容与授权

持续提示“AI数字人生成”，不误导为真人在线。自有图片形象需声明拥有使用权或本人授权；一期不提供声纹克隆/摄像头模仿。系统预设记录权利来源、使用范围与到期状态；下架配置不能只从前端移除而仍允许直接ID调用。

人设与输入沿既有内容安全能力检查；回复在可播的文本分段送TTS前应用项目安全策略。网络检索、文件执行、支付和对外发送工具默认关闭。后续知识资料只能作为检索数据，不能覆盖系统权限/调用策略。

## 10. 非功能要求与目标指标

以下是**拟验收目标**，不是上游或本机实测。基准需固定后端版本、第三方provider/model及配置版本、服务区域/套餐、网络、分辨率、并发与音色，并报告冷启动和热启动两组。

| 指标 | 首期目标 | 测量方法 |
|---|---|---|
| 热会话建立 | P95≤10秒，不含排队 | 点击开始至媒体可用；冷启动单独记录且不超过配置初始化窗口 |
| 文字输入到首段可听输出 | P95≤3秒 | 服务端接受完整文本至浏览器首音；流式mock不能替代真实provider测量 |
| 语音结束到首段可听输出 | 10秒以内标准测试短句P95≤4秒 | 点击提交至首音，包含整段内存转写/LLM/TTS；60秒输入另报延迟，不冒充短句指标 |
| 打断 | 本地停止P95≤200ms；服务端停止旧轮新输出P95≤1秒 | 同时验证旧帧/音频队列被丢弃，不仅HTTP返回快 |
| 音画同步 | 偏差P95≤200ms | 取至少100个对齐采样；实播时间戳，不靠日志推算 |
| 真实渲染 | 验收档位720p，连续5分钟平均≥20fps | 低规格可另立降级档位，用户可见；不能测低档冒充目标档 |
| 正常结束资源释放 | P95≤5秒 | tracks/peer/worker槽位/调用均释放；结算延迟单独跟踪 |
| 失联释放 | 最后心跳后≤45秒 | 包含30秒租约失效和清理余量；kill浏览器验证 |
| 稳定性 | 100次连接建立成功率≥99%；30分钟连续轮次无持续资源增长 | 新建/结束及重连混合测试，不承诺生产SLA |
| 安全不变量 | 越权成功=0；重复收费=0；旧账号音画写回=0 | 自动化反例和故障注入，不能以统计百分比放宽 |

首次部署容量按 S0 实测批准，未压测时部署并发默认1，超过容量明确排队/拒绝。上述体验目标不达标先调整方案或明确修订需求，不能一边保留目标一边宣布验收通过。

当前AI入口Nginx禁止麦克风，实施时只在AI入口开放同源麦克风权限（camera仍禁用），用户端与治理台维持禁用；必须通过最终部署入口和HTTPS验证真实授权流程。

前端使用根 DESIGN.md 的主题、间距、字号、圆角、字体和断点；治理配置用 ops 规范。需要新增token先成对定义。普通文字对比度≥4.5:1、必要控件≥3:1；触控热区≥44×44px，键盘焦点可见，尊重减少动态效果。自动字幕不强制屏幕阅读器逐token朗读。
