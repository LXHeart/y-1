## 目标（PRD §2.2 任务类型 / §9 核实维度第 3 行）

- 任务类型三选一补全：图文种草、视频种草之外新增**点赞互动**
- 互动任务的凭证提交形态与自动核验分支（截图识别 + 链接验证）
- 复用既有 Verification v2 全套机器（append-only runs、人工 override、inconclusive 复核队列）

**核心建模判断（已论证）**：点赞互动不是新任务大类，是 `content_form` 的**第四个受控值 `interaction`**——它决定凭证形态与核验分支，而发布/报名/接受/确认/结算/争议链路与图文视频完全同构，全部复用。

## 规则决策包（Phase A 誊写为 ADR）

### R1 content_form 受控化

- 规范值集：`image | video | article | interaction`（null = 未指定，沿用现状）
- 写入口（create/update/revise）契约层校验值集；DB 层迁移先规范化存量（lower/trim，已知同义词归并，未知值置 null），再 `CHECK (content_form IN (...) OR content_form IS NULL) NOT VALID` + `VALIDATE CONSTRAINT`（镜像 V21 的两段式模式，避免锁表）
- Stage 0 先在 dev 库查 distinct 现值定同义词映射表

### R2 互动任务的任务侧配置

`TaskRequirements` 加可空结构块 `interaction`（**完全镜像 commissionLadder 的嵌套 record 模式**，自动随 task_version/creation-context 快照机器冻结，marketplace 不加新列）：

```json
"interaction": { "targetUrl": "https://...", "actionType": "like" }
```

- `actionType` 受控值：`like | favorite | follow`（**评论不做**——评论带 UGC 内容安全与 moderation 负担，ADR 登记后置）
- 交叉校验：`contentForm=interaction ⇔ requirements.interaction 非空`（单边违反 400）
- `targetUrl` 必须过既有可信 Host/SSRF 校验（复用核验引擎 link 检查同一套守卫）
- v1 单目标单次动作；「N 次互动/多目标/有效期跟踪」登记为后续（截图证据语义会翻倍，不首期背）

### R3 凭证形态（提交侧）

复用既有 submission 形状，语义重定义 + 一个新字段：

| 字段 | 互动任务语义 |
|---|---|
| `contentUrl`（既有，必填） | **被互动的目标帖子/账号链接**（不再是要发布的作品链接） |
| `platformHandle`（**新增，可空**） | 推荐官在该平台的账号标识；`contentForm=interaction` 时必填（契约分支校验，≤64 字符） |
| `mediaIds`（既有，上限 6） | **动作截图**（展示其账号已点赞/收藏/关注的界面截图），互动任务 ≥1 张（核验检查而非提交时硬拒，理由见 R4） |
| `note` | 自由备注 |

### R4 核验维度——与现有四类检查的关系（本 ADR 核心）

**不新建检查体系**。互动任务的检查表：

| 检查键 | 互动任务下的语义 | 变化 |
|---|---|---|
| `link_reachability` | 目标链接可达 | **复用零改动** |
| `platform_identity` | 目标链接域名 vs 任务平台一致 | **复用零改动**（输入取 contentUrl，天然成立） |
| `evidence_completeness` | `platformHandle` 非空 + 截图 ≥1 | **规则分支扩展**（图文/视频规则不变） |
| `ai_visual` | 原作品视觉检查 | 互动任务**跳过** |
| `interaction_screenshot`（**新检查键**） | 多模态模型识别截图：① 截图内容与目标帖子匹配；② 动作状态可见（已赞/已藏/已关注标记）；③ 截图账号与 `platformHandle` 一致 | **新增**：复用 ai_visual 的模型调用通道，换互动专用 prompt 与结构化判定（pass/fail/inconclusive + reason） |

- **不确定即人工**：模型不可用/低置信 → `inconclusive` → 既有 VERIFICATION 待判定队列 + 人工 override（GL-P2-ADMIN-004 链路原样吸收，与 PRD §9「各平台采集方式待确认」的谨慎一致）
- runs append-only、每次核验冻结输入、人工改判不改自动结果——全部沿用既有不变式
- 结算折叠到 `engagement_verification` 的规则不变（最差结果胜出）

### R5 明确不做

- 评论类互动（UGC moderation，后置）；多目标/次数/时长跟踪；平台官方 API 数据源（P1 真实指标项）；互动反作弊（同账号跨任务养号风控——登记风险，归风控域后续校准）
- 资金模式无特例：互动任务照常配 bounty/阶梯佣金，无 freebie 耦合

### R6 前端行为

- 发布表单：内容形式从自由文本输入改为**下拉**（图文/视频/文章/点赞互动）；选「点赞互动」时展示目标链接 + 动作类型两个字段（必填），其余要求字段照旧
- 推荐官提交面板：互动任务显示「平台账号标识」输入 + 截图上传提示文案（改 `EngagementSubmissionPanel` 文案与条件字段）
- 任务大厅：卡片显示「点赞互动」徽标；feed 的 contentForm 筛选对 `interaction` 值天然生效（后端零改动）
- **「围绕任务创作」入口对互动任务隐藏**（AI 创作不适用于无内容交付的任务；`openAcceptedTaskCreation` 处按 contentForm 分支）

### R7 通知与结算：零新增

`DeliverableSubmitted`/`VerificationChecked`/`VerificationOverridden` 及结算通知全部复用（#28 模式已在，勿重复加）。

## 验收标准

1. 商家选「点赞互动」发布：必填目标链接与动作类型；`contentForm` 与 `interaction` 块单边缺失 400；非互动任务带块也 400
2. 推荐官提交互动凭证：`platformHandle` 缺失 400；contentUrl=目标链接；截图经既有三步上传挂 mediaIds
3. 自动核验：互动任务跑 `link_reachability + platform_identity + evidence_completeness + interaction_screenshot` 四项（跳过 ai_visual）；模型 inconclusive 自动进人工复核队列，运营 override 后 runs 历史原样保留
4. 迁移后 CHECK 通过 VALIDATE；legacy 未知 content_form 值被置 null 且大厅可见性不受影响
5. 任务大厅筛选 contentForm=interaction 只见互动任务；徽标渲染；「围绕任务创作」入口隐藏
6. 既有图文/视频核验、结算、通知链路零回归

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`
- **核验 runs append-only**：任何新检查只增不改历史；人工 override 只写 override 表（版本单调），不碰自动结果
- **派生态 `@JsonIgnore`**：`interaction` 块若加便捷判断方法（如 `isInteraction()`），必须 `@JsonIgnore`——否则快照读回报「数据损坏」（is 前缀无参方法会被 Jackson 序列化成属性，本库已踩过）
- Jackson 3：请求 record 可选数值字段必须包装类型
- SSRF/可信 Host：targetUrl 与截图判定链接复用核验引擎既有守卫，**不得新写一套**
- 多模态调用是阻塞 IO：镜像 ai_visual 既有的执行边界（boundedElastic），不进 WebFlux 事件循环
- Reactor：`switchIfEmpty` 副作用包 `Mono.defer`；migration 版本号动手前 `ls` 确认
- 提交按语义拆分（建议：ADR / 受控化+配置块 / 提交契约+核验分支 / 前端 / docs 各一个 commit），中文 commit message、`feat(scope):` / `test(scope):` / `docs:` 风格
