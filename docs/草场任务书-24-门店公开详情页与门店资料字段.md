## 目标

把 `store_profile` 从 4 个业务字段扩成 PRD §2.1 完整门店资料，并打通三条消费链路（一次投入三头收益）：

1. **报名决策**：推荐官在任务大厅/任务详情能看到门店公开资料（名称、地址、品类、卖点、人均消费等）
2. **任务带入**：任务详情视图携带门店公开块
3. **AI 商家上下文**：品牌语气/必须强调/禁止表达/可使用标签冻结进任务创作上下文快照，注入各生成工作流 prompt

**本期不做**（防扩散，勿顺手实现）：

- 门店媒体库（门头/环境/菜单图）——intelligence media 集成，见 Stage 6 可选项
- 商家主体资料字段（品牌名/Logo/简介/经营分类）——独立缺口 #32
- 规范检查引擎消费 `forbidden_phrases`——可后续接进创作助手 task-coverage 的 gap/covered 帧

## Stage 1 — identity：数据模型 + 写侧

**Migration**（版本号先 `ls` identity 的 `db/migration` 取下一个）：给 `store_profile` 加列：

| PRD 字段 | 列 | 类型 | 约定 |
|---|---|---|---|
| 主营品类 | `categories` | `text[]` | 每项 trim、去空、去重，≤20 项、单项 ≤300 字（镜像 `TaskRequirements.items()` 的帽） |
| 特色产品/服务 | `signature_items` | `text[]` | 同上 |
| 推荐卖点 | `selling_points` | `text[]` | 同上 |
| 必须强调 | `must_emphasize` | `text[]` | 同上 |
| 禁止表达 | `forbidden_phrases` | `text[]` | 同上 |
| 可使用标签 | `allowed_tags` | `text[]` | 同上 |
| 品牌语气 | `brand_tone` | `text` | ≤500 字，blank→null |
| 价格区间 | `price_range` | `text` | ≤50 字自由文本（如 "¥30–¥80"） |
| 人均消费 | `average_spend_cents` | `integer` | 金额一律 cents（代码库铁律） |
| 交通/停车/预约/到店注意 | `visit_notes` | `text` | ≤1000 字 |

**写侧**：扩展现有 `UpdateStoreProfileRequest`（**新字段全用包装类型/可空**——Jackson 3 record primitive 陷阱，缺失 primitive 直接 400）和 `StoreController` 的 PUT 路径、`StoreProfileRepository`。

**守卫（不可妥协）**：

- 更新 SQL 必须按 `(organization_id, store_id)` 限定，跨组织统一 404（CLAUDE.md 明示的第二道闸）
- 营销字段**不得**改动 V22 的 KYB 审核 status/流程——先读 `StoreController` 现有 update 如何与审核列交互，保持行为不变；只有 address/phone 变更维持既有审核语义
- 空数组写 null 与 `[]` 等价（清空语义）

**测试**：repository IT（跨组织 404）、controller IT（断言缺失 401 / 组织外 404 / 新字段往返）、请求校验单测（帽与归一化）。

## Stage 2 — identity：公开读端点 + 内部批量端点

**公开端点** `GET /api/stores/{storeId}/public-profile`（identity）：

- 前置条件：store.status=active 且所属 organization 非 suspended，否则 404
- **响应白名单**（只回这些，严禁整行序列化）：storeName、address、phone、businessHours、description、categories、signatureItems、priceRange、averageSpendCents、visitNotes、sellingPoints、brandTone、mustEmphasize、forbiddenPhrases、allowedTags。**不回**：KYB 审核列、org owner、permission_tier、内部备注
- 鉴权：`resolveOptional`（登录即可看，未登录也放行——大厅浏览场景）；**不要**用组织角色守卫

**内部批量端点**（给 marketplace，`/internal/**` 树下，走服务断言，不在 `/api` 树，拒绝 `X-Forwarded-*`）：按 storeId 批量回上面的公开白名单字段（feed enrichment 用）。marketplace→identity 的断言密钥对已在 `deploy/security/identity-assertion-key-pairs.csv` 登记（门店坐标解析已在用），复用即可。

**Edge**：`/api/stores/**` 是新前缀——必须在 edge-bff `RouteManifest` 注册 + flag（建议 `EDGE_ROUTE_STORES_PUBLIC_IDENTITY` 默认 true），否则 fail-closed 404。内部端点不进 edge。

**测试**：公开端点 IT（未登录 200、suspended store 404、响应体断言**不含**审核列）、内部端点 IT（断言缺失 404/401）。

## Stage 3 — marketplace：任务带入 + 权威快照增强

1. **feed/详情轻量增强**：`TaskController` feed 与任务详情响应加 `store` 块（storeName、city、categories）——用 Stage 2 的内部批量端点一次拉整页 storeId（feed 是 keyset 分页，注意只对页内去重后的 storeId 批量调用，别逐行）。`distanceKm` 逻辑不动。
2. **权威任务快照增强（AI 三头的关键）**：找到 marketplace 暴露给 intelligence 的 accepted 报名权威任务快照内部端点（Slice 16 记录的 `/internal` task context），响应增加 `storeBranding` 块：

```json
"storeBranding": {
  "storeName": "...", "brandTone": "...",
  "mustEmphasize": ["..."], "forbiddenPhrases": ["..."],
  "allowedTags": ["..."], "sellingPoints": ["..."],
  "categories": ["..."], "signatureItems": ["..."]
}
```

   从 identity 内部端点取（同 batch client）。**不落 marketplace 新表、不改 V27 冻结触发器**——intelligence 侧 creation_context 本来就是「首次创建即不可变」，快照时点语义由 intelligence 保证，验证引擎（`CommissionLadders.fromTaskContextSnapshot` 读的 `task_application.task_context_snapshot`）零改动。

**测试**：feed enrichment 单测（内部 client mock、页内去重）、task context 端点 IT（accepted-only 守卫不变 + storeBranding 存在）、既有的 Slice 16-21 快照 IT 必须全绿（防回归）。

## Stage 4 — intelligence：创作上下文冻结 + prompt 注入

1. `creationcontext` 的快照 schema 加 `storeBranding`（快照表是 append/immutable，无 UPDATE 端点——保持）；首次创建冻住，之后不重读（幂等键不变：account/application/taskVersion/platform/contentForm）。
2. **prompt 注入**：找到各工作流消费创作上下文的公共组装点（Slices 17-21 已让文章/视频/图片评价/喜剧/视频复刻/朋友圈消费快照），在组装 task 要求的同一位置把 `brandTone / mustEmphasize / forbiddenPhrases / allowedTags` 拼进 context 文本（必须强调→要求覆盖；禁止表达→明确禁止；品牌语气→风格指令；可使用标签→建议标签池）。逐工作流核对，别只改一处。
3. （可选加分）商家模式「从门店创作」source：走 marketplace 新增的 `/internal/stores/{id}/branding`（由 marketplace 代理 identity，intelligence 只认 marketplace，不新增服务对）。

**注意**：intelligence **没有全局 ObjectMapper bean**，持服务本地实例；LLM 调用侧的扣分/退款路径零改动。

**测试**：快照含 storeBranding 且二次创建返回同一快照（不可变回归）；prompt 组装单测断言品牌语气/禁止表达出现在 prompt 文本；各工作流既有测试全绿。

## 代码库陷阱清单（必读）

- Java 构建：JDK 25（`JAVA_HOME=/opt/homebrew/opt/openjdk@25`），入口 `platform-java/` 下 `./gradlew`
- identity **没有全局 SecurityWebFilterChain**——每个新端点必须显式 `CurrentAccountResolver` / `OrgAuthorization`，漏一行=完全无鉴权
- Jackson 3：请求 record 可选数值字段必须包装类型；`is` 前缀无参方法会被序列化成属性（派生态加 `@JsonIgnore`）
- Reactor：`switchIfEmpty` 参数在 assembly 期求值，副作用调用包 `Mono.defer`
- edge fail-closed：新公网前缀不进 RouteManifest 就是 404；内部端点放 `/internal/**`，拒绝 `X-Forwarded-*`
- 金额一律 cents；migration 版本号动手前 `ls` 各服务 db/migration 确认最新
- 提交按语义拆分（建议：identity 数据模型+端点 / marketplace 增强 / intelligence 上下文 / 前端 / docs 各一个 commit），commit message 用中文、`feat(scope):` / `test(scope):` / `docs:` 风格
